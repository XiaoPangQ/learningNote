01 AI Agent 概述与核心概念

1.1 什么是 AI Agent

AI Agent（人工智能智能体）是一种能够自主感知环境、进行推理决策并执行动作以完成特定目标的 AI 系统。与传统的"问答式"大模型不同，Agent 具备以下核心特征：

  • 自主性（Autonomy）：无需人工逐步指令，能独立规划任务步骤
  • 反应性（Reactivity）：能感知环境变化并及时响应
  • 主动性（Proactivity）：不仅被动响应，还能主动采取行动实现目标
  • 社会性（Social Ability）：能与其他 Agent 或人类进行协作交互
简单理解：如果说大语言模型（LLM）是一个"超级大脑"，那 AI Agent 就是给这个大脑装上了"手和脚"——它不仅能思考和回答，还能调用工具、访问数据、执行操作，真正"把事情做完"。

1.2 Agent 与 LLM 的关系

大语言模型是 Agent 的"推理引擎"，但 Agent ≠ LLM。Agent 在 LLM 的基础上增加了：

能力维度纯 LLMAI Agent
知识范围训练数据截止日可实时检索/调用 API
行动能力只能输出文本可调用工具、执行代码、操作系统
记忆单轮/有限上下文窗口短期+长期记忆系统
规划无任务分解、多步推理、自我反思
协作独立多 Agent 协同工作

1.3 Agent 的典型应用场景

  • 智能客服：自动查询订单、处理退换货、多轮对话解决问题
  • 编程助手：理解需求、编写代码、运行调试、自动修复 Bug
  • 数据分析 Agent：自然语言提问→自动查数据库→生成图表和报告
  • 研究助理：自动搜索文献、总结要点、撰写综述
  • 自动化工作流：邮件处理、日程安排、文档生成、跨系统操作
  • RPA 升级版：智能理解界面、自适应流程变化

02 大语言模型基础

2.1 大语言模型是怎么工作的

大语言模型（Large Language Model）基于 Transformer 架构，通过在海量文本上训练，学会了预测"下一个 token"的能力。理解以下关键概念：

  • Token：文本的最小处理单位，可以是字、词或词的一部分。1 个汉字约占 1-2 个 token
  • 上下文窗口（Context Window）：模型一次能处理的 token 总量，如 GPT-4 支持 128K，Claude 支持 200K
  • Temperature：控制输出随机性，0 = 确定性输出，1+ = 更创造性
  • Top-p：核采样参数，限制候选 token 范围

2.3 调用 LLM API

几乎所有 Agent 开发的第一步都是学会调用 LLM API。以 OpenAI 兼容接口为例：

from openai import OpenAI

client = OpenAI(
    api_key="sk-your-api-key",
    base_url="https://api.openai.com/v1"  # 可替换为兼容端点
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "你是一个有帮助的助手。"},
        {"role": "user", "content": "解释什么是 AI Agent"}
    ],
    temperature=0.7,
    max_tokens=1000
)

print(response.choices[0].message.content)

关键参数说明

  • model：模型名称
  • messages：对话历史，包含 system / user / assistant 三种角色
  • temperature：0-2，越高越发散
  • max_tokens：最大输出 token 数
  • stream：是否流式输出
  • tools：Function Calling 工具定义（第7章详解）

2.4 System Prompt 的作用

System Prompt 是设定 Agent 身份、行为规则和输出格式的关键：

system_prompt = """你是一个专业的数据分析助手。

规则：
1. 回答前先分析用户问题的关键指标
2. 使用中文回答
3. 涉及数字时给出计算过程
4. 不确定时明确说明，不要编造数据
5. 输出格式：先结论，再分析，最后建议"""
经验法则：System Prompt 写得越清晰，Agent 行为越可控。好的 System Prompt 包含：角色定义、任务边界、输出格式、约束规则、示例。

2.5 Token 消耗与成本管理

Agent 多轮调用会快速消耗 token，需要关注：

  • 输入 token：system prompt + 对话历史 + 工具描述 + 检索内容
  • 输出 token：模型生成的回复
  • 成本优化：精简 prompt、及时裁剪历史、用小模型处理简单任务、缓存重复请求
# 查看 token 消耗
print(response.usage)
# CompletionUsage(completion_tokens=85, prompt_tokens=42, total_tokens=127)

# 估算成本（GPT-4o 示例）
input_cost = response.usage.prompt_tokens * 2.5 / 1_000_000   # $2.5/1M
output_cost = response.usage.completion_tokens * 10 / 1_000_000  # $10/1M
print(f"本次调用成本: ${input_cost + output_cost:.4f}")

03 提示词工程（Prompt Engineering）

3.1 为什么 Prompt 如此重要

在 Agent 开发中，Prompt 就是"编程"方式。同样的模型，好的 Prompt 和差的 Prompt 效果天差地别。Prompt Engineering 是 Agent 开发者的核心技能。

3.2 六大核心技巧

① 角色设定（Role Prompting）

# ❌ 差的 prompt
"帮我写一段产品文案"

# ✅ 好的 prompt
"你是一位有10年经验的 SaaS 产品营销专家，擅长写转化型文案。
请为我们的项目管理工具写一段官网首页的 Hero 文案，
目标用户是20-35人的技术团队，语气专业但不枯燥。"

② 少样本提示（Few-Shot Prompting）

请将用户反馈分类为：bug / feature / complaint / praise

示例：
输入："登录后页面白屏了" → bug
输入："希望能支持暗黑模式" → feature
输入："客服回复太慢了！" → complaint

现在分类："这个更新太赞了，速度快了很多！" →

③ 思维链（Chain of Thought, CoT）

# 添加 "让我们一步一步思考" 触发推理
"一个商店有苹果23个，卖出了8个，又进货了8个，
请问现在有多少个苹果？让我们一步一步思考。"

# 模型会输出推理过程，准确率显著提升

④ ReAct 模式（Reasoning + Acting）

这是 Agent 最核心的 Prompt 模式，让模型交替进行推理和行动：

Thought: 我需要知道北京的天气，应该调用天气查询工具
Action: get_weather
Action Input: {"city": "北京"}
Observation: 北京今天晴，25°C
Thought: 我已经知道了天气信息，可以回答用户了
Final Answer: 北京今天天气晴，气温25°C，适合外出。

⑤ 结构化输出

请以 JSON 格式输出，schema 如下：
{
  "sentiment": "positive | negative | neutral",
  "score": 0-100,
  "keywords": ["关键词1", "关键词2"],
  "summary": "一句话摘要"
}

用户评价："物流很快但包装破损了"

⑥ 自我反思（Self-Consistency / Reflection）

请先回答问题，然后检查你的回答：
1. 是否准确？
2. 是否有遗漏？
3. 是否可以改进？
如果发现问题，给出修正后的答案。

3.3 Prompt 设计框架：CRISPE

字母含义说明
CCapacity & Role设定角色和能力
RInput给清楚背景信息和输入
IInstruction明确要做什么
SOutput定义输出格式和风格
PExample给出示例（可选但推荐）
EExperiment多版本测试迭代

3.4 常见 Prompt 陷阱

  • 指令太模糊："帮我处理一下" → 说清处理什么、怎么处理、输出什么
  • 一次要求太多：一个 prompt 塞10个任务 → 拆成多个步骤
  • 忽略负面约束：只说做什么，不说不做什么 → 明确"不要编造URL"
  • 不提供上下文：模型不知道你的业务场景 → 补充必要背景
  • 过度依赖温度：用高 temperature 掩盖 prompt 问题 → 先优化 prompt

05 第一个 Agent

5.1 最简 Agent：从零理解

不依赖任何框架，用纯 Python 实现一个能对话的最简 Agent，理解其本质：

"""最简 Agent：一个能记住对话历史的聊天机器人"""
from openai import OpenAI
from config import Config

client = OpenAI(api_key=Config.OPENAI_API_KEY, base_url=Config.OPENAI_BASE_URL)

class SimpleAgent:
    def __init__(self, system_prompt: str):
        self.messages = [{"role": "system", "content": system_prompt}]

    def chat(self, user_input: str) -> str:
        # 1. 把用户输入加入历史
        self.messages.append({"role": "user", "content": user_input})

        # 2. 调用 LLM
        response = client.chat.completions.create(
            model=Config.MODEL_NAME,
            messages=self.messages,
            temperature=0.7
        )

        # 3. 获取回复并加入历史
        reply = response.choices[0].message.content
        self.messages.append({"role": "assistant", "content": reply})
        return reply

# 使用
agent = SimpleAgent("你是一个友好的编程助手，用简洁的中文回答。")
print(agent.chat("Python 中列表和元组的区别？"))
print(agent.chat("那各自的使用场景呢？"))  # 能记住上文
核心洞察：这就是 Agent 的雏形——维护 messages 列表 + 循环调用 LLM。后续所有复杂能力（工具调用、RAG、记忆）都是在这个循环上增加模块。

5.2 加入工具：能查天气的 Agent

给 Agent 一个工具，让它能获取实时信息：

import json

def get_weather(city: str) -> str:
    """模拟天气查询（实际中调用天气API）"""
    weather_data = {
        "北京": "晴，25°C", "上海": "多云，28°C",
        "广州": "雨，30°C", "深圳": "晴，29°C"
    }
    return weather_data.get(city, f"暂无{city}的天气数据")

# 工具定义（告诉 LLM 有什么工具可用）
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询指定城市的当前天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市名称"}
                },
                "required": ["city"]
            }
        }
    }
]

# 可用函数映射
available_functions = {"get_weather": get_weather}

def agent_run(user_input: str):
    messages = [
        {"role": "system", "content": "你是天气助手，需要时调用天气工具。"},
        {"role": "user", "content": user_input}
    ]

    while True:
        response = client.chat.completions.create(
            model=Config.MODEL_NAME,
            messages=messages,
            tools=tools
        )
        msg = response.choices[0].message
        messages.append(msg)

        # 如果模型要调用工具
        if msg.tool_calls:
            for tool_call in msg.tool_calls:
                fn_name = tool_call.function.name
                fn_args = json.loads(tool_call.function.arguments)
                print(f"🔧 调用工具: {fn_name}({fn_args})")

                result = available_functions[fn_name](**fn_args)
                messages.append({
                    "role": "tool",
                    "tool_call_id": tool_call.id,
                    "content": result
                })
        else:
            # 没有工具调用，返回最终回答
            return msg.content

# 测试
print(agent_run("北京和上海今天天气怎么样？"))

5.3 Agent 的基本循环

上面的代码揭示了所有 Agent 的核心运行模式——Agent Loop：

while not task_complete:
    1. 将当前状态（消息历史）发送给 LLM
    2. LLM 决定：直接回答 OR 调用工具
    3. 如果调用工具 → 执行工具，把结果加回消息历史 → 回到步骤1
    4. 如果直接回答 → 任务完成，返回结果
这个 while 循环就是 Agent 的"心跳"。理解了这个循环，就理解了 Agent 开发的本质。后续的 LangChain、LangGraph、Coze 等框架，本质上都是在帮你更好地管理这个循环。

6.2 规划模块（Planning）

规划是让 Agent 能处理复杂任务的关键。主要规划策略：

任务分解（Task Decomposition）

# Chain of Thought 分解
"写一份市场分析报告" →
  1. 确定目标行业和市场范围
  2. 搜索行业最新数据和趋势
  3. 分析主要竞争者
  4. 总结机会和风险
  5. 撰写报告

# Tree of Thoughts（思维树）
# 同时探索多个方案路径，评估后选择最优

自我反思（Self-Reflection）

# Reflexion 模式
1. 执行任务 → 得到结果
2. 自我评估：哪里做得不好？
3. 根据反思调整策略
4. 重新执行（最多 N 次）

6.3 记忆模块（Memory）

记忆类型范围实现方式示例
短期记忆单次对话消息历史列表当前对话上下文
工作记忆单次任务Scratchpad / 中间变量已完成的步骤、临时结果
长期记忆跨会话向量数据库 / 外部存储用户偏好、历史知识

6.4 工具模块（Tools）

工具是 Agent 与外部世界交互的接口。常见工具类型：

  • 信息获取：搜索引擎、网页抓取、数据库查询、API 调用
  • 代码执行：Python REPL、Shell、沙箱环境
  • 文件操作：读写文件、文档解析、格式转换
  • 通信工具：发送邮件、消息通知、创建日历事件
  • 业务工具：CRM、ERP、项目管理系统的 API

6.5 经典 Agent 架构模式

ReAct（Reason + Act）

最经典的 Agent 模式，交替进行推理和行动：

Question → Thought → Action → Observation → Thought → ... → Answer

Plan-and-Execute

先制定完整计划，再逐步执行：

Planner: 制定步骤列表 → Executor: 逐步执行 → Replanner: 根据结果调整

Router 模式

由一个"路由 Agent"判断意图，分发给专门的子 Agent：

用户输入 → Router → [客服Agent | 销售Agent | 技术Agent]
选型建议：简单任务用 ReAct，复杂多步任务用 Plan-and-Execute，多领域任务用 Router 模式。实际项目中常组合使用。

7.1 Function Calling 原理

Function Calling 是 OpenAI 推出的能力，让 LLM 能输出结构化的工具调用请求，而不是只能输出自然语言。开发者拿到请求后执行对应函数，再把结果返回给 LLM。

         → 开发者执行函数 → 返回结果 → LLM 生成最终回答

import concurrent.futures

def execute_tool_calls(tool_calls, available_functions):
    """并行执行多个工具调用"""
    results = {}

    def run_one(tool_call):
        fn = available_functions[tool_call.function.name]
        args = json.loads(tool_call.function.arguments)
        return tool_call.id, fn(**args)

    with concurrent.futures.ThreadPoolExecutor() as executor:
        futures = [executor.submit(run_one, tc) for tc in tool_calls]
        for future in concurrent.futures.as_completed(futures):
            call_id, result = future.result()
            results[call_id] = result

    return results

7.5 工具调用的错误处理

def safe_execute(func, **kwargs):
    """安全执行工具，错误信息返回给 LLM 让它自我修正"""
    try:
        result = func(**kwargs)
        return str(result)
    except Exception as e:
        # 返回错误信息而不是抛出异常，让 LLM 看到错误并调整
        return f"工具执行出错: {type(e).__name__}: {str(e)}。请检查参数后重试。"
重要：不要捕获异常后返回空字符串或"出错了"。把具体错误信息返回给 LLM，它通常能根据错误信息自行修正参数重试。

08 RAG 检索增强生成

8.1 为什么需要 RAG

LLM 的知识有截止日期，且无法访问私有数据。RAG（Retrieval-Augmented Generation）通过先检索相关文档，再让 LLM 基于检索结果回答，解决了这些问题：

  • ✅ 知识实时更新（检索最新文档）
  • ✅ 访问私有数据（内部文档、数据库）
  • ✅ 减少幻觉（答案有依据可追溯）
  • ✅ 成本可控（不需要微调模型）

8.2 RAG 完整流程

                        ┌──────────────┐
  文档 ──→ 切分 ──→ Embedding ──→ 向量数据库
                                              │
  用户提问 → Embedding → 向量检索 → Top-K 文档 → 拼接Prompt → LLM → 回答

9.1 Agent 为什么需要记忆

9.2 记忆的层次

┌─────────────────────────────────┐
│ 长期记忆（Long-term Memory）     │ ← 向量数据库，跨会话

├─────────────────────────────────┤

class ConversationMemory:
    def __init__(self, max_messages: int = 20):
        self.messages = []
        self.max_messages = max_messages

    def add(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})
        # 超出窗口时裁剪（保留 system message 和最近的消息）
        if len(self.messages) > self.max_messages:
            system_msg = self.messages[0] if self.messages[0]["role"] == "system" else None
            recent = self.messages[-(self.max_messages - 1):]
            self.messages = ([system_msg] if system_msg else []) + recent

    def get_messages(self):
        return self.messages

class SummaryMemory:
    """当对话过长时，用 LLM 生成早期对话的摘要"""

    def __init__(self, llm_client, threshold: int = 10):
        self.recent = []
        self.summary = ""
        self.threshold = threshold

    def add(self, role: str, content: str):
        self.recent.append({"role": role, "content": content})
        if len(self.recent) > self.threshold:
            self._summarize_old()

    def _summarize_old(self):
        # 把前一半对话交给 LLM 做摘要
        to_summarize = self.recent[:self.threshold // 2]
        self.recent = self.recent[self.threshold // 2:]

        summary_prompt = f"请简要总结以下对话的关键信息：\n"
        for msg in to_summarize:
            summary_prompt += f"{msg['role']}: {msg['content']}\n"

        resp = client.chat.completions.create(
            model=Config.MODEL_NAME,
            messages=[{"role": "user", "content": summary_prompt}],
            max_tokens=200
        )
        new_summary = resp.choices[0].message.content
        self.summary = (self.summary + " " + new_summary).strip()

    def get_messages(self):
        msgs = []
        if self.summary:
            msgs.append({"role": "system", "content": f"早期对话摘要：{self.summary}"})
        msgs.extend(self.recent)
        return msgs

class LongTermMemory:
    """用向量数据库存储和检索长期记忆"""

    def __init__(self, collection):
        self.collection = collection

    def save(self, user_id: str, content: str, metadata: dict = None):
        """保存一条记忆"""
        meta = metadata or {}
        meta["user_id"] = user_id
        self.collection.add(
            documents=[content],
            metadatas=[meta],
            ids=[f"{user_id}_{hash(content)}"]
        )

    def recall(self, user_id: str, query: str, top_k: int = 3):
        """检索相关记忆"""
        results = self.collection.query(
            query_texts=[query],
            n_results=top_k,
            where={"user_id": user_id}
        )
        return results["documents"][0] if results["documents"] else []

10 多 Agent 协作

10.1 为什么需要多 Agent

单个 Agent 面对复杂任务时容易"分心"和"能力不足"。多 Agent 协作借鉴了人类团队的工作方式：

  • 专业化：每个 Agent 专注一个领域，提示词更精准
  • 可维护：独立开发、测试、迭代
  • 可组合：不同 Agent 排列组合应对不同场景
  • 可靠性：一个 Agent 出问题不影响整体

① 层级式（Hierarchical）

          ┌──────────┐
          │ Manager  │ ← 分配任务、汇总结果
          └────┬─────┘
       ┌───────┼───────┐
       ▼       ▼       ▼
   ┌──────┐ ┌──────┐ ┌──────┐
   │研究员 │ │编程师 │ │审核员 │
   └──────┘ └──────┘ └──────┘

from langgraph.graph import StateGraph, END
from langgraph.graph.message import add_messages
from langchain_openai import ChatOpenAI

# 定义状态
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
    next_step: str

llm = ChatOpenAI(model=Config.MODEL_NAME)

def reason_node(state: AgentState) -> AgentState:
    """推理节点：调用 LLM 决定下一步"""
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

def tool_node(state: AgentState) -> AgentState:
    """工具节点：执行工具调用"""
    last_msg = state["messages"][-1]
    # ... 执行工具逻辑
    result = "工具执行结果"
    return {"messages": [{"role": "tool", "content": result}]}

def should_continue(state: AgentState) -> str:
    """条件边：决定继续调工具还是结束"""
    last_msg = state["messages"][-1]
    if hasattr(last_msg, "tool_calls") and last_msg.tool_calls:
        return "tool"
    return END

# 构建图
workflow = StateGraph(AgentState)
workflow.add_node("reason", reason_node)
workflow.add_node("tool", tool_node)

workflow.set_entry_point("reason")
workflow.add_conditional_edges("reason", should_continue)
workflow.add_edge("tool", "reason")  # 工具执行后回到推理

13 工作流与编排引擎

13.1 为什么需要工作流编排

简单 Agent 靠 LLM 自主决策（ReAct 循环），但在生产环境中，你可能需要：

  • 确定性流程：某些步骤必须按固定顺序执行
  • 条件分支：根据不同输入走不同路径
  • 并行执行：多个独立任务同时进行
  • 错误重试：失败后自动重试或降级
  • 人工审批：关键步骤需要人确认

工作流编排引擎就是解决这些问题的。

13.2 DAG 与状态机

两种主要的编排范式：

  • DAG（有向无环图）：如 Airflow、Prefect。流程固定，不支持循环。适合 ETL、数据管道
  • 状态机：如 LangGraph、Temporal。支持循环、条件跳转、持久化。适合 Agent

13.3 构建一个轻量工作流引擎

from typing import Callable, Any
import time

class WorkflowEngine:
    """极简工作流引擎：支持顺序、条件、重试"""

    def __init__(self):
        self.nodes = {}
        self.edges = {}
        self.entry = None

    def add_node(self, name: str, func: Callable):
        self.nodes[name] = func

    def add_edge(self, from_node: str, to_node: str, condition: Callable = None):
        self.edges.setdefault(from_node, []).append((to_node, condition))

    def set_entry(self, name: str):
        self.entry = name

    def run(self, initial_input: Any, max_retries: int = 2):
        current = self.entry
        data = initial_input
        visited = set()

        while current and current != "end":
            if current in visited:
                # 防止无限循环
                count = sum(1 for v in visited if v == current)
                if count > 10:
                    raise RuntimeError(f"工作流可能陷入循环: {current}")
            visited.add(current)

            # 执行节点（带重试）
            for attempt in range(max_retries + 1):
                try:
                    print(f"▶ 执行节点: {current} (尝试 {attempt+1})")
                    data = self.nodes[current](data)
                    break
                except Exception as e:
                    if attempt == max_retries:
                        print(f"✗ 节点 {current} 失败: {e}")
                        # 查找错误处理边
                        error_edges = [(n, c) for n, c in self.edges.get(current, [])
                                       if c and c.__name__ == "is_error"]
                        if error_edges:
                            current = error_edges[0][0]
                            break
                        raise
                    time.sleep(1 * (attempt + 1))
            else:
                continue

            # 查找下一个节点
            next_nodes = self.edges.get(current, [])
            if not next_nodes:
                break
            for next_node, condition in next_nodes:
                if condition is None or condition(data):
                    current = next_node
                    break
            else:
                break

        return data

"""人工审批节点：Agent 执行到关键操作时暂停，等待人工确认"""

class HumanApprovalNode:
    def __init__(self, notification_func):
        self.notify = notification_func
        self.pending = {}  # task_id → future

    def execute(self, data):
        task_id = data.get("task_id", str(hash(str(data))))

        # 通知人工审批
        self.notify(
            f"⚠️ 需要审批：\n操作：{data.get('action')}\n详情：{data.get('detail')}",
            task_id=task_id
        )

        # 暂停执行，等待审批结果
        # 生产环境中用持久化状态 + 回调机制
        approval = self._wait_for_approval(task_id)

        if not approval["approved"]:
            data["status"] = "rejected"
            data["reason"] = approval.get("reason", "")
        else:
            data["status"] = "approved"
        return data

    def approve(self, task_id: str, approved: bool, reason: str = ""):
        """人工调用此方法提交审批结果"""
        self.pending[task_id] = {"approved": approved, "reason": reason}

    def _wait_for_approval(self, task_id: str):
        # 简化实现：轮询等待
        import time
        while task_id not in self.pending:
            time.sleep(1)
        return self.pending.pop(task_id)

重要安全规则：

# 2. 输入过滤
import re
def sanitize_input(text: str) -> str:
    # 移除常见注入模式
    patterns = [
        r"ignore (all|previous) (instructions|prompts)",
        r"忽略(之前|所有|以上).*指令",
        r"system\s*prompt",
        r"你现在是",
    ]
    for p in patterns:
        text = re.sub(p, "[已过滤]", text, flags=re.IGNORECASE)
    return text

# 3. 输出检查
def check_output(output: str) -> bool:
    """检查输出是否包含敏感信息"""
    sensitive_patterns = [
        r"\b\d{18}\b",           # 身份证号
        r"\b1[3-9]\d{9}\b",      # 手机号
        r"sk-[a-zA-Z0-9]{20,}",  # API Key
        r"\b\d{16,19}\b",        # 银行卡号
    ]
    for p in sensitive_patterns:
        if re.search(p, output):
            return False  # 检测到敏感信息
    return True

from enum import Enum

class Permission(Enum):
    READ = "read"
    WRITE = "write"
    DELETE = "delete"
    ADMIN = "admin"

# 每个工具声明所需权限
TOOL_PERMISSIONS = {
    "search_knowledge_base": Permission.READ,
    "query_order": Permission.READ,
    "create_refund": Permission.WRITE,
    "delete_user": Permission.DELETE,
    "send_email": Permission.WRITE,
}

def check_permission(user_role: str, tool_name: str) -> bool:
    """基于角色的访问控制（RBAC）"""
    ROLE_PERMISSIONS = {
        "guest": {Permission.READ},
        "user": {Permission.READ, Permission.WRITE},
        "admin": {Permission.READ, Permission.WRITE, Permission.DELETE, Permission.ADMIN}
    }
    required = TOOL_PERMISSIONS.get(tool_name)
    return required in ROLE_PERMISSIONS.get(user_role, set())

# Agent 调用工具前检查
def safe_tool_call(user_role: str, tool_name: str, **kwargs):
    if not check_permission(user_role, tool_name):
        return f"权限不足：{user_role} 角色不能执行 {tool_name}"

    # 高危操作需二次确认
    if TOOL_PERMISSIONS[tool_name] in (Permission.DELETE, Permission.ADMIN):
        return f"⚠️ 高危操作需要人工审批：{tool_name}({kwargs})"

    return execute_tool(tool_name, **kwargs)

16.4 对齐（Alignment）

对齐是确保 Agent 行为符合人类价值观和意图的过程：

  • RLHF：基于人类反馈的强化学习（模型层面）
  • Constitutional AI：让 AI 按一套"宪法原则"自我审查
  • Guardrails：在应用层设置输入输出护栏
# 应用层 Guardrails 示例
GUARDRAIL_PROMPT = """在执行任何操作前，先检查：
1. 这个请求是否合法？
2. 是否可能伤害任何人？
3. 是否侵犯隐私？
4. 是否在我的授权范围内？

如有任何一项答案为"是"，拒绝执行并说明原因。"""

class GuardrailedAgent:
    def __init__(self, agent):
        self.agent = agent

    def run(self, user_input: str) -> str:
        # 1. 输入安全检查
        if not self._check_input_safety(user_input):
            return "抱歉，您的请求包含不安全内容，我无法处理。"

        # 2. 正常执行
        result = self.agent.run(user_input)

        # 3. 输出安全检查
        if not self._check_output_safety(result):
            return "抱歉，生成的内容未通过安全检查。"

        return result
核心原则：永远不要信任 LLM 的输出作为安全决策的唯一依据。安全控制必须在代码层强制执行，不能只靠 Prompt 约束。权限校验、参数白名单、操作审计都要在代码中硬编码。

import asyncio

async def parallel_tool_calls(tool_calls, functions):
    """并行执行多个独立的工具调用"""
    async def execute_one(tc):
        func = functions[tc.function.name]
        args = json.loads(tc.function.arguments)
        if asyncio.iscoroutinefunction(func):
            return await func(**args)
        return await asyncio.to_thread(func, **args)

    results = await asyncio.gather(
        *[execute_one(tc) for tc in tool_calls],
        return_exceptions=True
    )
    return results

class TokenBudget:
    def __init__(self, daily_limit: int):
        self.daily_limit = daily_limit
        self.redis = redis.Redis()

    def consume(self, user_id: str, tokens: int) -> bool:
        key = f"token_budget:{user_id}:{datetime.now().date()}"
        used = int(self.redis.get(key) or 0)
        if used + tokens > self.daily_limit:
            return False
        self.redis.incrby(key, tokens)
        self.redis.expire(key, 86400)
        return True
