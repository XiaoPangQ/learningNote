01 Docker 简介与核心概念

什么是 Docker

Docker 是一个开源的容器化平台，让开发者可以将应用及其依赖打包到一个轻量级、可移植的容器中，然后发布到任何支持 Docker 的机器上运行。容器之间相互隔离，共享宿主机内核。

📌 一句话理解
Docker = "构建、运送、运行任何应用"的开放平台。它解决了"在我机器上能跑"的经典问题。

为什么需要 Docker

一致性

开发、测试、生产环境完全一致，消除环境差异。

快速部署

秒级启动容器，镜像分层缓存让构建和分发极快。

资源高效

共享内核，比虚拟机轻量得多，单机可运行数百容器。

微服务友好

每个服务独立容器，便于扩展、更新和回滚。

容器 vs 虚拟机

  虚拟机架构                          容器架构
┌─────────────────────┐          ┌─────────────────────┐
│   App   │   App     │          │   App   │   App     │
│  Bins/Libs Bins/Libs│          │  容器A  │  容器B     │
├─────────┴───────────┤          ├─────────┴───────────┤
│      Guest OS       │          │      Docker         │
├─────────────────────┤          ├─────────────────────┤
│      Hypervisor     │          │    Host OS Kernel   │
├─────────────────────┤          ├─────────────────────┤
│   Host OS Kernel    │          │    Infrastructure   │
├─────────────────────┤          └─────────────────────┘
│   Infrastructure    │
└─────────────────────┘
  ↑ GB级，分钟级启动                  ↑ MB级，秒级启动
特性 虚拟机 容器
隔离级别 硬件级（完整 OS） 进程级（共享内核）
启动速度 分钟级 秒级/毫秒级
资源占用 GB 级 MB 级
性能损耗 较大（Hypervisor 层） 极小（接近原生）
操作系统 可运行不同内核 OS 必须与宿主机同内核
隔离强度 更强 较弱（但有安全加固手段）

核心概念

概念 说明
镜像 (Image) 只读模板，包含运行应用所需的代码、运行时、库、配置。分层构建，不可变。
容器 (Container) 镜像的运行实例，可读写。一个镜像可以启动多个容器。
仓库 (Registry) 存储和分发镜像的服务，如 Docker Hub、GHCR、Harbor。
Dockerfile 文本文件，包含构建镜像的指令序列。
Volume 持久化数据的机制，独立于容器生命周期。
Network 容器间及容器与外部通信的虚拟网络。
Docker Engine 核心运行时，包含 dockerd 守护进程和 containerd。
Docker Compose 定义和运行多容器应用的工具。

Docker 发展简史

  1. 2008 — Linux 容器（LXC）出现，基于 cgroups 和 namespace
  2. 2013 — DotCloud 公司开源 Docker， Solomon Hykes 发布，迅速引爆
  3. 2014 — Docker 1.0 发布；Kubernetes 由 Google 开源
  4. 2015 — OCI（开放容器倡议）成立，runc 捐赠给 OCI
  5. 2017 — Docker 企业版/社区版拆分；containerd 成为独立项目（CNCF）
  6. 2019 — Docker Desktop 商业化；K8s 弃用 Dockershim
  7. 2021 — Dockershim 正式从 Kubernetes 移除；containerd 成为主流运行时
  8. 2023+ — Docker 持续演进，BuildKit、Docker Scout、 WASM 支持等

02 安装与环境配置

Linux 安装（推荐方式）

# 官方一键脚本（最简单）
curl -fsSL https://get.docker.com | sh

# 启动并设置开机自启
sudo systemctl enable --now docker

# 将当前用户加入 docker 组（免 sudo）
sudo usermod -aG docker $USER
# 重新登录后生效

Ubuntu/Debian 手动安装

# 卸载旧版本
sudo apt remove docker docker.io containerd runc

# 安装依赖
sudo apt update
sudo apt install ca-certificates curl gnupg lsb-release

# 添加 Docker 官方 GPG 密钥
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# 添加仓库
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list

# 安装
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin

国内镜像加速

# /etc/docker/daemon.json
{

macOS / Windows

Mac 和 Windows 用户下载安装 Docker Desktop 即可，它内置了一个轻量 Linux 虚拟机来运行 Docker Engine。

03 镜像基础操作

3.1 获取镜像

# 拉取镜像（默认 latest 标签）
docker pull nginx

# 指定版本
docker pull nginx:1.25
docker pull ubuntu:22.04
docker pull python:3.12-slim

# 指定平台（Apple Silicon 拉取 amd64 镜像）
docker pull --platform linux/amd64 nginx

3.2 查看镜像

docker images                  # 列出本地镜像
docker image ls                # 同上（新语法）
docker images -a               # 包含中间层镜像
docker images -q               # 只显示镜像 ID
docker images --filter "dangling=true"  # 悬空镜像

# 查看镜像详细信息
docker inspect nginx:1.25
docker history nginx:1.25       # 查看镜像分层历史

3.3 镜像命名与标签

# 镜像命名规则
[registry/] [namespace/] repository [:tag]
# 示例
docker.io/library/nginx:1.25
ghcr.io/owner/repo:v1.0
myregistry.local:5000/myapp:latest

# 打标签（不复制镜像，只添加引用）
docker tag nginx:1.25 mynginx:v1
docker tag nginx:1.25 myregistry.local:5000/nginx:1.25

3.4 删除镜像

docker rmi nginx:1.25
docker image rm nginx:1.25

# 强制删除（有容器在使用时）
docker rmi -f nginx:1.25

# 批量清理悬空镜像
docker image prune

# 清理所有未被容器使用的镜像
docker image prune -a

# 批量删除所有镜像（慎用）
docker rmi -f $(docker images -q)

3.5 导出与导入

# 保存镜像为 tar 文件
docker save -o nginx.tar nginx:1.25
docker save nginx:1.25 | gzip > nginx.tar.gz

# 从 tar 文件加载镜像
docker load -i nginx.tar
docker load < nginx.tar.gz

3.6 镜像分层原理

Docker 镜像由多个只读层组成，每一层对应 Dockerfile 中的一条指令。层被缓存和复用，这是 Docker 镜像轻量和快速构建的关键。 

┌─────────────────────────┐
│  可写容器层 (临时)        │  ← 容器运行时创建
├─────────────────────────┤
│  CMD ["nginx", "..."]   │  ← 镜像层 4 (只读)
├─────────────────────────┤
│  COPY . /usr/share/...  │  ← 镜像层 3 (只读)
├─────────────────────────┤
│  RUN apt-get install    │  ← 镜像层 2 (只读)
├─────────────────────────┤
│  FROM ubuntu:22.04      │  ← 基础镜像层 1 (只读)
└─────────────────────────┘

04 容器基础操作

4.1 启动容器

# 基本启动（后台运行）
docker run -d --name web nginx

# 端口映射：宿主机端口:容器端口
docker run -d --name web -p 8080:80 nginx
docker run -d -p 8080:80 -p 8443:443 nginx

# 前台交互式运行
docker run -it --name myshell ubuntu:22.04 /bin/bash
# -i 保持 STDIN 打开，-t 分配伪终端

# 容器退出后自动删除
docker run --rm -it python:3.12 python

# 环境变量
docker run -d -e MYSQL_ROOT_PASSWORD=secret mysql:8

# 从文件加载环境变量
docker run -d --env-file .env myapp

# 设置容器重启策略
docker run -d --restart always nginx
# no | always | unless-stopped | on-failure[:max-retries]

# 设置主机名
docker run -d --hostname web1 nginx

4.2 查看容器

docker ps                    # 运行中的容器
docker ps -a                 # 所有容器（含已停止）
docker ps -q                 # 只显示容器 ID
docker ps -a --size         # 显示文件大小

# 查看容器详情
docker inspect web
docker inspect --format '{{.NetworkSettings.IPAddress}}' web

# 查看容器内进程
docker top web

4.3 容器生命周期

docker start web             # 启动已停止的容器
docker stop web              # 优雅停止（SIGTERM，10秒后 SIGKILL）
docker stop -t 30 web        # 等待 30 秒
docker restart web           # 重启
docker kill web              # 强制杀死（SIGKILL）
docker pause web             # 暂停（冻结进程）
docker unpause web           # 恢复
docker rename web newweb     # 重命名

# 删除容器
docker rm web
docker rm -f web            # 强制删除运行中的容器
docker container prune       # 清理所有已停止的容器

4.4 进入容器

# docker exec: 在运行中的容器中执行命令（推荐）
docker exec -it web /bin/bash
docker exec web cat /etc/os-release
docker exec -u root web apt update

# docker attach: 附加到容器主进程（不推荐，退出会停止容器）
docker attach web
# Ctrl+P, Ctrl+Q 可以安全 detach

# docker cp: 在容器和宿主机之间复制文件
docker cp ./localfile web:/tmp/
docker cp web:/etc/nginx/nginx.conf ./backup/

4.5 查看日志

docker logs web              # 查看日志
docker logs -f web          # 实时跟踪
docker logs --tail 100 web   # 最后 100 行
docker logs --since 1h web   # 最近 1 小时
docker logs -t web          # 显示时间戳

4.6 查看资源占用

docker stats                 # 实时资源监控（CPU/内存/网络/IO）
docker stats web db          # 指定容器
docker stats --no-stream    # 只输出一次结果

4.7 容器提交（慎用）

# 将容器的可写层提交为新镜像
docker commit -m "添加了 curl" -a "author" web mynginx:v1

# 注意：这不是推荐做法！应该用 Dockerfile 构建可复现的镜像

05 Dockerfile 详解

Dockerfile 基本结构

# 语法版本（BuildKit 特性）
# syntax=docker/dockerfile:1

# 基础镜像
FROM node:20-alpine

# 设置工作目录（不存在会自动创建）
WORKDIR /app

# 复制依赖清单（利用缓存）
COPY package.json package-lock.json ./

# 安装依赖
RUN npm ci --only=production

# 复制源代码
COPY . .

# 构建参数（构建时可传入）
ARG APP_VERSION=1.0.0
ENV APP_VERSION=$APP_VERSION

# 环境变量（运行时可用）
ENV NODE_ENV=production
ENV PORT=3000

# 暴露端口（仅文档作用，实际需要 -p）
EXPOSE 3000

# 数据卷声明
VOLUME ["/app/data"]

# 容器健康检查
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD wget -q --spider http://localhost:3000/health || exit 1

# 容器启动命令（shell 形式）
CMD ["node", "server.js"]

指令详解

FROM — 基础镜像

FROM ubuntu:22.04
FROM node:20-alpine          # alpine 更小
FROM scratch                # 空镜像（用于静态二进制）
FROM --platform=$BUILDPLATFORM golang:1.22 AS builder

RUN — 执行命令

# shell 形式（通过 /bin/sh -c 执行）
RUN apt-get update && apt-get install -y curl

# exec 形式（不经过 shell，信号处理更好）
RUN ["apt-get", "install", "-y", "curl"]

# 最佳实践：合并命令、清理缓存，减少层数和体积
RUN apt-get update && \
    apt-get install -y --no-install-recommends curl && \
    rm -rf /var/lib/apt/lists/*

COPY vs ADD

# COPY: 推荐，简单复制文件/目录
COPY . /app
COPY --chown=node:node . /app
COPY --from=builder /app/server .

# ADD: 有额外功能（自动解压 tar、支持 URL），但不推荐日常使用
ADD app.tar.gz /app/
ADD https://example.com/file /tmp/
💡 优先用 COPY
ADD 的自动解压和 URL 下载功能增加了不可预测性。除非确实需要自动解压 tar 文件，否则一律用 COPY。

ENV vs ARG

特性 ARG ENV
可用阶段 仅构建时 构建时 + 运行时
容器中可见 否 是
可被覆盖 --build-arg -e 或 docker-compose
典型用途 版本号、平台标识 配置、环境标识

CMD vs ENTRYPOINT

# CMD: 容器启动时的默认命令（可被 docker run 参数覆盖）
CMD ["nginx", "-g", "daemon off;"]

# ENTRYPOINT: 容器的入口程序（不会被覆盖，参数追加）
ENTRYPOINT ["docker-entrypoint.sh"]
CMD ["nginx", "-g", "daemon off;"]

# 组合使用：ENTRYPOINT 固定程序，CMD 提供默认参数
# docker run myimage → docker-entrypoint.sh nginx -g "daemon off;"
# docker run myimage bash → docker-entrypoint.sh bash

构建镜像

# 基本构建（-t 指定标签，. 是构建上下文）
docker build -t myapp:1.0 .

# 多标签构建
docker build -t myapp:1.0 -t myapp:latest .

# 指定 Dockerfile
docker build -f Dockerfile.prod -t myapp:prod .

# 传递构建参数
docker build --build-arg APP_VERSION=2.0 -t myapp:2.0 .

# 不使用缓存
docker build --no-cache -t myapp .

# 使用 BuildKit（更快、更强大）
DOCKER_BUILDKIT=1 docker build -t myapp .

# 查看构建过程详细输出
docker build --progress=plain -t myapp .

06 数据持久化

容器数据问题

容器的可写层在容器删除后数据丢失，且性能较差（需要存储驱动）。Docker 提供三种数据挂载方式：

方式 存储位置 生命周期 性能 适用场景
Volume /var/lib/docker/volumes/ 独立于容器 好（原生） 数据库、持久化数据（推荐）
Bind Mount 宿主机任意路径 跟随宿主机 好（直接映射） 开发时热重载、配置文件
tmpfs 宿主机内存 容器停止即消失 最好 敏感临时数据

6.1 Volume（数据卷）

# 创建数据卷
docker volume create mydata

# 列出数据卷
docker volume ls

# 查看详情
docker volume inspect mydata

# 使用数据卷启动容器
docker run -d -v mydata:/var/lib/mysql mysql:8

# 使用 --mount（更明确的语法，推荐）
docker run -d \
  --mount source=mydata,target=/var/lib/mysql \
  mysql:8

# 匿名卷（不指定名称，Docker 自动生成）
docker run -d -v /var/lib/mysql mysql:8

# 删除数据卷
docker volume rm mydata
docker volume prune

6.2 Bind Mount（绑定挂载）

# 将宿主机目录挂载到容器
docker run -d -v /host/path:/container/path nginx

# 只读挂载
docker run -d -v /host/config:/etc/nginx:ro nginx

# 使用 --mount 语法
docker run -d \
  --mount type=bind,source=$(pwd),target=/app \
  myapp

# 开发场景：挂载源码实现热重载
docker run -d \
  -v $(pwd):/app \
  -v /app/node_modules \
  -p 3000:3000 \
  mynodeapp npm run dev
⚠️ Mac/Windows 性能注意
Bind Mount 在 Mac/Windows 上通过虚拟机文件共享，I/O 性能较差。大型项目开发时，把 node_modules 等用匿名卷覆盖（如上例）可以避免反向挂载拖慢速度。

6.3 tmpfs

docker run -d \
  --tmpfs /tmp:rw,noexec,nosuid,size=100m \
  myapp

# 或使用 --mount
docker run -d \
  --mount type=tmpfs,destination=/tmp,tmpfs-size=104857600 \
  myapp

6.4 数据卷容器与共享

# 创建数据卷容器
docker create -v /data --name datastore busybox

# 其他容器共享数据卷（--volumes-from 已不推荐，建议用命名卷）
docker run -d --volumes-from datastore myapp

# 多个容器共享同一个命名卷
docker run -d -v shared:/data --name app1 myapp
docker run -d -v shared:/data --name app2 myapp

6.5 数据备份与迁移

# 备份数据卷到 tar 文件
docker run --rm \
  -v mydata:/source \
  -v $(pwd):/backup \
  busybox tar czf /backup/mydata_backup.tar.gz -C /source .

# 恢复数据卷
docker run --rm \
  -v newdata:/target \
  -v $(pwd):/backup \
  busybox tar xzf /backup/mydata_backup.tar.gz -C /target

07 网络管理

7.1 默认网络模式

模式 说明 适用场景
bridge 默认模式，容器通过虚拟网桥通信，NAT 访问外网 单机容器通信（默认）
host 容器直接使用宿主机网络栈，无隔离 高性能需求、不推荐生产
none 无网络，只有 lo 回环 安全隔离、不需要网络
container: 共享另一个容器的网络命名空间 Sidecar、调试
overlay 跨主机容器网络（需要 Swarm/K8s） 多机集群
macvlan 容器获得物理网络中的 MAC 地址 需要直连物理网络

08 Docker Compose

什么是 Docker Compose

Compose 是定义和运行多容器 Docker 应用的工具。通过一个 YAML 文件配置所有服务，一条命令即可创建和启动全部服务。适合开发环境、测试环境和单机生产部署。

安装

sudo apt install docker-compose-plugin

# 验证

docker-compose.yml 完整示例

# docker-compose.yml
services:
  web:
    build:
      context: ./web
      dockerfile: Dockerfile
      args:
        APP_VERSION: 2.0
    image: myapp-web:2.0
    ports:
      - "8080:80"
      - "443:443"
    environment:
      DB_HOST: db
      DB_PORT: 5432
      REDIS_HOST: redis
    env_file:
      - .env
    volumes:
      - ./web/src:/var/www/html
      - web-logs:/var/log
    networks:
      - app-net
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: "0.5"
          memory: 512M

  db:
    image: postgres:16-alpine
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: mydb
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    networks:
      - app-net
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U admin"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: always

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes --requirepass ${REDIS_PASSWORD}
    volumes:
      - redis-data:/data
    networks:
      - app-net
    restart: unless-stopped

volumes:
  pgdata:
  redis-data:
  web-logs:

networks:
  app-net:
    driver: bridge

11.5 OverlayFS 工作原理

           Overlay Mount Point
          ┌─────────────────────┐
          │   合并视图            │
          └──────────┬──────────┘
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
   ┌─────────────┐      ┌─────────────┐
   │  Upper Dir   │      │  Lower Dir   │
   │  (可写层)     │      │  (只读层)     │

   └─────────────┘      └─────────────┘

  读文件：先在 Upper 找，找不到再去 Lower
  写文件：Copy-Up — 从 Lower 复制到 Upper 再修改
  删除文件：在 Upper 创建 whiteout 标记

11.6 BuildKit

BuildKit 是 Docker 的下一代构建引擎，相比旧版构建器：

  • 支持 secrets 和 SSH 挂载（不留在镜像层）

  • 更精简的构建输出
# 使用 BuildKit 构建

12 资源限制与 cgroups

12.1 内存限制

# 限制内存 512MB（硬限制）
docker run -d --memory=512m nginx

# 内存+交换空间总限制
docker run -d --memory=512m --memory-swap=1g nginx
# memory-swap = memory + swap。设为与 memory 相同表示禁用 swap

# 软限制（内存充足时不强制）
docker run -d --memory-reservation=256m --memory=512m nginx

# OOM 优先级（-1000 到 1000，越低越不容易被 OOM kill）
docker run -d --oom-score-adj=-500 nginx
⚠️ OOM Killer
容器超出内存限制会被内核 OOM killer 直接杀死，进程退出码通常为 137。通过 docker inspect 查看 OOMKilled 状态确认。

12.2 CPU 限制

# 限制最多使用 1.5 个 CPU 核
docker run -d --cpus=1.5 nginx

# 绑定到特定 CPU 核心（0 和 1）
docker run -d --cpuset-cpus=0,1 nginx

# CPU 权重（相对权重，默认 1024，越高越优先）
docker run -d --cpu-shares=512 nginx

# Compose 中配置
deploy:
  resources:
    limits:
      cpus: "0.5"
      memory: 256M

14 镜像优化与多阶段构建

14.1 为什么要优化

更快构建

合理利用缓存，减少重复构建时间。

更小体积

减少拉取时间、存储成本和攻击面。

更安全

最小化镜像 = 更少组件 = 更少漏洞。

14.2 多阶段构建

# ========== 阶段1: 构建 ==========
FROM golang:1.22-alpine AS builder

WORKDIR /app

# 先复制依赖清单，利用缓存
COPY go.mod go.sum ./
RUN go mod download

# 复制源码并构建
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags="-s -w -X main.version=1.0" \
    -o /app/server .

# ========== 阶段2: 运行 ==========
FROM gcr.io/distroless/static-debian12

WORKDIR /app

# 只从构建阶段复制最终二进制
COPY --from=builder /app/server .

EXPOSE 8080
USER nonroot

CMD ["./server"]

14.3 选择小基础镜像

镜像 大小（解压后） 包管理器 适用场景
ubuntu:22.04 ~77 MB apt 需要完整环境
debian:bookworm-slim ~74 MB apt Debian 精简版
alpine:3.19 ~7 MB apk 极小（musl libc）
distroless/static ~2 MB 无 静态编译二进制
scratch 0 MB 无 完全自包含二进制

14.4 层缓存最佳实践

# ❌ 不好：每次代码变动都重新安装依赖
FROM node:20-alpine
WORKDIR /app
COPY . .
RUN npm install

# ✅ 好：先复制依赖清单，依赖不变就用缓存
FROM node:20-alpine
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .

# 1. 合并 RUN 指令，清理包管理器缓存

│  (网桥)       │               └──────────┘        └──────────┘
│              │                    │                   │
│  iptables    │◄──────── NAT (MASQUERADE) ──────────►│
│  (DNAT/SNAT) │
│              │
│  eth0        │◄──── 外网
└──────────────┘

当创建一个 bridge 网络时，Docker 会：

  1. 创建一个 Linux 网桥（如 br-xxxx）
  2. 为每个容器创建一对 veth pair，一端接入网桥，一端放入容器命名空间
  3. 通过 iptables NAT 规则让容器可以访问外网
  4. 通过 DNAT 规则实现端口映射（-p）

15.2 容器访问外部网络

容器访问外网通过 SNAT（源地址转换）：数据包从容器发出后，Docker 在 iptables 的 POSTROUTING 链将源 IP 改为宿主机 IP，回程数据包再改回来。

15.3 外部访问容器（端口映射）

-p 8080:80 在 iptables 的 PREROUTING/OUTPUT 链添加 DNAT 规则，将宿主机 8080 端口的流量转发到容器 IP 的 80 端口。 

# 查看 NAT 规则
sudo iptables -t nat -L -n -v

# 查看 Docker 创建的规则
sudo iptables -t nat -L DOCKER

15.5 Overlay 网络

Overlay 网络用于跨主机容器通信，基于 VXLAN 隧道技术。Docker Swarm 模式下自动管理，Kubernetes 中通常使用 Calico/Flannel/Cilium 等 CNI 插件。

16 容器编排与 Kubernetes

16.1 为什么需要编排

当容器数量增长到几十上百个，需要考虑：服务发现、负载均衡、滚动更新、自动扩缩容、故障自愈、配置管理、密钥管理……这些单靠 Docker 和 Compose 无法满足。

16.2 Docker Swarm（入门）

# 初始化 Swarm 集群
docker swarm init

# 工作节点加入（命令由 init 输出）
docker swarm join --token SWMTKN-xxx 192.168.1.10:2377

# 部署服务
docker service create --name web --replicas 3 -p 8080:80 nginx

# 扩缩容
docker service scale web=5

# 滚动更新
docker service update --image nginx:1.26 web

# 查看节点和服务
docker node ls
docker service ls

16.3 Kubernetes 核心概念

概念 说明
Pod 最小调度单元，包含一个或多个共享网络/存储的容器
Deployment 管理 Pod 的副本数、滚动更新和回滚
Service 为一组 Pod 提供稳定的网络访问入口（负载均衡）
Ingress HTTP/HTTPS 层路由，将外部流量路由到 Service
ConfigMap 非敏感配置管理
Secret 敏感信息管理（密码、密钥）
Namespace 资源隔离和配额
Node 工作节点（物理机/虚拟机）
Volume Pod 内存储（临时/持久）
StatefulSet 有状态应用管理（数据库等）
DaemonSet 每个 Node 运行一个 Pod（日志、监控代理）
Job/CronJob 一次性任务/定时任务

16.4 第一个 K8s Deployment

# nginx-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 200m
            memory: 256Mi
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 10
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-svc
spec:
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
kubectl apply -f nginx-deployment.yaml
kubectl get pods
kubectl get deployments
kubectl get svc
kubectl scale deployment nginx --replicas=5
kubectl set image deployment/nginx nginx=nginx:1.26

17.1 镜像标签策略

17.2 GitHub Actions 构建推送

# .github/workflows/build.yml
name: Build and Push Docker Image

on:
  push:
    branches: [main]
    tags: ['v*']

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ghcr.io/${{ github.repository }}
          tags: |
            type=ref,event=branch
            type=semver,pattern={{version}}
            type=sha,prefix=sha-
            type=raw,value=latest,enable={{is_default_branch}}

      - name: Build and push
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

17.3 生产环境最佳实践

镜像管理

  • 使用固定版本标签，禁止生产使用 latest
  • 多阶段构建，最小化运行时镜像
  • 定期更新基础镜像，扫描漏洞
  • 使用镜像签名（Docker Content Trust / Cosign）
  • 设置镜像拉取策略为 IfNotPresent

运行时

  • 资源限制（requests + limits）防止资源争抢
  • 健康检查（livenessProbe + readinessProbe）
  • 优雅关闭：捕获 SIGTERM，设置合理 terminationGracePeriod
  • 日志输出到 stdout/stderr，由日志收集器统一处理
  • 使用 restart: unless-stopped / always
  • 配置和密钥通过环境变量/Secret 注入，不打包进镜像

安全

  • 非 root 运行，只读根文件系统
  • 最小 Capabilities，Seccomp/AppArmor
  • 镜像漏洞扫描门禁（阻断高危漏洞）
  • 网络策略限制容器间通信
  • 不在环境变量中传递密钥（用 Secret 挂载文件）

高可用

  • 多副本部署，跨节点分布（pod anti-affinity）
  • 滚动更新 + 自动回滚
  • 配置 PodDisruptionBudget 保证最少可用副本
  • 使用 HPA 自动扩缩容

17.4 优雅关闭示例

#!/bin/bash
# docker-entrypoint.sh — 优雅关闭

term_handler() {
  echo "收到 SIGTERM，开始优雅关闭..."
  # 停止接收新请求，完成存量请求
  kill -TERM "$child" 2>/dev/null
}

trap term_handler SIGTERM SIGINT

# 启动主进程
node server.js &
child=$!
wait "$child"

💡 核心心法
Docker 的学习关键是理解"一个容器一个进程"和"不可变基础设施"的理念。不要把容器当虚拟机用（不要在容器里装一堆服务），保持容器的单一职责和无状态性。动手实践 > 看文档，边做边查最快。
