第一篇：入门篇（打地基）

1.React 是什么

一句话：React 是 Facebook（现 Meta）开发的用于构建用户界面的 JavaScript 库。注意它只是「库」不是「框架」——它管视图，路由/状态/请求等你自己搭配。

React 像一盒乐高积木：你不用一块大橡皮雕刻整座雕像，而是用小积木（组件）一块块拼出页面。坏了哪块换哪块，复用方便。

核心思想（三条命根子）

思想 含义 小白理解
组件化 页面由可复用组件拼成 页面 = 组件 + 组件 + 组件
声明式 你描述「数据长什么样」，React 帮你更新 画设计图，不用自己砌墙
单向数据流 数据从父→子流动，不回流 水只能往低处流，追问题好查

React vs Vue 速览（学过 Vue 的看这里）

对比项 React Vue
写法 JSX（JS 里写 HTML） 模板 template
状态 useState，不可变更新 ref/reactive，可变
定位 只管视图的「库」 渐进式「框架」
上手 概念少、但 JS 要扎实 模板指令多、上手快
组件拼乐高，声明画设计图； 数据单向流，React 只是库。

2.快速上手

小白推荐用 Vite 创建项目（比老牌 CRA 快很多）。只需装了 Node。 

npm create vite@latest my-react-app -- --template react
cd my-react-app
npm install
npm run dev

浏览器打开终端提示的地址（一般是 http://localhost:5173），看到转动 logo 就成功了。

项目目录速记

文件/目录 作用
index.html 页面入口，挂载点 <div id="root">
src/main.jsx JS 入口，把 App 组件挂到 root
src/App.jsx 根组件，你从这开始写
src/components/ 放你自己拆的组件

最小可运行组件

function App() {
  return <h1>你好，React！</h1>
}

export default App
React 组件本质就是一个返回 JSX 的函数。函数名首字母必须大写（小写会被当成 HTML 标签）。

3.JSX 语法（重中之重）

JSX = 在 JavaScript 里写类 HTML 的语法。它不是真的 HTML，是 React.createElement 的语法糖，但写起来像 HTML 就行。

为什么不直接用 React.createElement？因为它嵌套写起来又长又丑，JSX 让你像写 HTML 一样直观，编译后还是变成 createElement。

JSX 核心规则（记住能少踩 80% 的坑）

规则 说明 正确示例
1. 返回单根 一个组件只能返回一个根元素 用 <>...</> 包裹
2. class→className 因为 class 是 JS 关键字 <div className="box">
3. 表达式用 {} 动态值放花括号里 {user.name}
4. 属性驼峰 onclick→onClick、for→htmlFor onClick={handle}
5. 布尔/null 不渲染 false、null、undefined 不显示 {flag && <p>显示</p>}
6. 标签必须闭合 单标签也要自闭合 <img /> <br /> 
function Greet({ name }) {
  return (
    <>
      <h1 className="title">你好 {name}</h1>
      <p>现在是 {new Date().toLocaleTimeString()}</p>
    </>
  )
}
JSX 里写注释要用 {/* 注释 */}，不能直接写 <!-- -->。
单根 class 改名，花括号塞表达式； 标签全闭合，属性走驼峰。

4.组件与 Props

组件就是返回 JSX 的函数；Props 就是外部传进来的数据（像函数参数）。

组件 = 函数，Props = 函数参数。父组件调用子组件时，像传参一样把数据塞进去。 
// 子组件：接收 props
function Welcome({ name, age = 18 }) {
  return <p>{name}，今年 {age} 岁</p>
}

// 父组件：传 props
function App() {
  return <Welcome name="小明" age={20} />
}
要点 说明
解构接收 常用 { name } 解构 props，写起来干净
默认值 age = 18 给默认值
只读 Props 是只读的，子组件不能改 props
可传任意类型 字符串、数字、函数、对象、JSX 都行
为什么 props 只读？保证单向数据流——数据从父来、子只消费，问题永远能顺藤摸瓜找到源头。

5.事件处理

React 事件写法类似原生，但用驼峰 onClick，且传入的是函数而不是字符串。 

function Btn() {
  function handleClick(e) {
    alert('点了！')
    e.stopPropagation()  // 阻止冒泡
  }
  return <button onClick={handleClick}>点我</button>
}

常见事件

事件 触发
onClick 点击
onChange 输入框内容变化
onSubmit 表单提交（需 e.preventDefault()）
onMouseEnter / onLeave 鼠标移入/移出
传函数时不要写成 onClick={handleClick()}（带括号会立即执行一次）。要传引用不带括号；要传参则用箭头包裹：onClick={() => del(id)}。

6.条件渲染

React 没有 v-if，用 JS 的 if / 三元 / && 来控制。 

// 1. 三元：二选一
{isLogin ? <Logout/> : <Login/>}

// 2. 逻辑与 &&：满足才显示
{hasMsg && <Badge />}

// 3. 提前 return：列表为空直接不渲染
function List({ items }) {
  if (items.length === 0) return <p>暂无数据</p>
  return <ul>{items.map(...)}</ul>
}
&& 左边必须是布尔。若写 {count && <P/>} 而 count=0，会渲染出一个 0 字符在页面上。改成 {count > 0 && ...} 更安全。
三元二选一，逻辑与做开关； 为空早 return，布尔才用 &&。

7.列表渲染

React 用 .map() 把数组变成一组 JSX，每个元素必须给唯一 key。 

const todos = [
  { id: 1, text: '吃饭' },
  { id: 2, text: '睡觉' }
]

function TodoList() {
  return (
    <ul>
      {todos.map(t => <li key={t.id}>{t.text}</li>)}
    </ul>
  )
}
为什么必须 key？React 用 key 判断「哪些项是同一个」。增删时它能精准复用对应 DOM，避免错位。用稳定唯一 id，不要用数组 index（顺序变动会错乱）。
需要「序号」展示时，map 第二个参数就是索引：.map((t, i) => ...)，但展示用可以，不要拿它当 key。

8.表单与受控组件

受控组件 = 表单的值由 React state 控制，输入框变成「数据的投影」。

普通输入框像「自记自账的小本子」，内容它自己管；受控组件像「对讲机」，输入框只是个麦克风，真正的内容存在 state 这个总台。 
import { useState } from 'react'

function Form() {
  const [text, setText] = useState('')
  return (
    <input
      value={text}                         // 值来自 state
      onChange={e => setText(e.target.value)} // 输入同步回 state
    />
  )
}
表单项 取值方式
text / textarea e.target.value
checkbox e.target.checked
select e.target.value
多选 checkbox 组 用数组 state + 判断包含
表单很多字段时别一个个写 state，可以放一个对象 state，或直接用现成库 react-hook-form。
第二篇：进阶篇（玩转 Hooks）

9.State 与 useState

State = 组件内部的、会变化、变化后触发重新渲染的数据。useState 是给它赋值的 Hook。

普通变量像「黑板字」，改了 React 不知道；state 像「连了屏幕的输入」，一改屏幕自动刷新。 
import { useState } from 'react'

function Counter() {
  const [count, setCount] = useState(0)  // 初值 0
  return <button onClick={() => setCount(count + 1)}>{count}</button>
}

useState(0) 返回一个数组：第 0 项是当前值，第 1 项是修改函数。我们用解构起名 count / setCount。

更新规则：不可变！

React 的对象/数组 state 必须换一个新对象才算更新，直接改原对象不会触发渲染。 
// ❌ 错：直接改原对象，React 不感知
user.age = 20
setUser(user)

// ✅ 对：拷贝一份再改
setUser({ ...user, age: 20 })

// ✅ 数组也是
setList([...list, newItem])          // 加
setList(list.filter(x => x.id !== id)) // 删
setList(list.map(x => x.id === id ? {...x, done:true} : x)) // 改

函数式更新（基于上一次的值）

为什么连续多次 setCount(count+1) 可能只加一次？因为同一轮里 count 还是旧值。用函数式更新 setCount(c => c+1)，React 保证每次都拿「最新值」。
state 连屏幕，改它就重渲染； 对象数组要换新，函数更新防取旧。

10.副作用 useEffect

副作用 = 那些「不纯」的操作：发请求、操作 DOM、设定时器、订阅。组件渲染本身要纯（同样的输入同样的输出），副作用放到 useEffect 里。

渲染函数是「拍照」（每次数据变就拍一张快照），useEffect 是「拍完之后要做的事」（洗照片、发朋友圈）。 
import { useState, useEffect } from 'react'

function Profile({ id }) {
  const [user, setUser] = useState(null)

  useEffect(() => {
    fetch('/api/user/' + id).then(r => r.json()).then(setUser)
  }, [id])   // 依赖数组：只有 id 变了才重跑

  return <p>{user ? user.name : '加载中...'}</p>
}

依赖数组的三种情况

写法 执行时机 慎用程度
不传依赖 每次渲染后都跑 ⚠️ 易死循环
空数组 [] 只在挂载后跑一次 ✅ 常用于发初始请求
[a, b] a 或 b 变了才跑 ✅ 最常用

清理函数

定时器、订阅等要在卸载时清掉，否则内存泄漏。return 一个清理函数： 

useEffect(() => {
  const timer = setInterval(() => console.log('tick'), 1000)
  return () => clearInterval(timer)  // 卸载时执行
}, [])
最大的坑：忘了写依赖或依赖写错，导致无限循环请求。建议配 ESLint 的 exhaustive-deps 规则自动提醒。
副作用放 effect，依赖数组控时机； 空数组跑一次，清理函数防泄漏。

11.Hooks 进阶全家桶

Hook 作用 口诀
useRef 存「不触发渲染」的值 / 拿 DOM 引用 存箱子或抓手
useMemo 缓存计算结果 算贵才缓存
useCallback 缓存函数引用 函数别重造
useContext 跨层读 Context 数据 跨层不用透传

useRef 两种用法

const inputRef = useRef(null)
useEffect(() => inputRef.current.focus(), [])  // 1.操作DOM
<input ref={inputRef} />

const timer = useRef(null)   // 2.存可变值但不触发渲染
timer.current = setInterval(...)

useMemo / useCallback

// 缓存昂贵计算
const sorted = useMemo(() => heavySort(list), [list])

// 缓存函数，避免子组件因新函数引用而重渲染
const handle = useCallback(() => {...}, [dep])
为什么要缓存？父组件每次渲染都新建函数，传给子组件时 props 引用变了 → 子组件无谓重渲染。useCallback 让引用稳定。
别滥用！缓存本身有开销。只在「计算真的很贵」或「传给用了 memo 的子组件」时才用，否则更慢。

12.自定义 Hook

把可复用的状态逻辑抽成一个 use 开头的函数。这是 React 复用逻辑的核心方案。 

// hooks/useFetch.js
import { useState, useEffect } from 'react'
export function useFetch(url) {
  const [data, setData] = useState(null)
  const [loading, setLoading] = useState(true)
  useEffect(() => {
    setLoading(true)
    fetch(url).then(r => r.json()).then(d => { setData(d); setLoading(false) })
  }, [url])
  return { data, loading }
}

// 用法
function Page() {
  const { data, loading } = useFetch('/api/user')
  return loading ? <p>加载中</p> : <div>{data.name}</div>
}
命名必须 use 开头，这是 React 识别 Hook 的规则（也方便 ESLint 校验依赖）。

13.组件通信方式

场景 方案 说明
父→子 props 最基础
子→父 父传回调函数，子调用 props 传函数
兄弟间 状态提升到共同父 把共享数据放父组件
跨多层 Context 主题/用户信息等
全局/复杂 状态库（Redux/Zustand） 见第 17 节 
// 子→父：父传函数
function Child({ onAdd }) {
  return <button onClick={() => onAdd(1)}>加</button>
}
function Parent() {
  const [n, setN] = useState(0)
  return <><Child onAdd={setN} /><p>{n}</p></>
}
父子靠 props，兄弟往上提； 跨层用 Context，全局上状态库。

16.React Router 路由

React 没有内置路由，官方推荐 React Router（v6+）。用 Vite 模板可一步到位：npm create vite@latest -- --template react 后再 npm i react-router-dom。 

import { createBrowserRouter, RouterProvider, Link } from 'react-router-dom'
import Home from './Home'
import User from './User'

const router = createBrowserRouter([
  { path: '/', element: <Home /> },
  { path: '/user/:id', element: <User /> }
])

function App() {
  return <RouterProvider router={router} />
}
概念 说明
Link 不刷新页面的跳转 <Link to="/home">
动态路由 /user/:id，组件用 useParams() 取 id
useNavigate 代码里跳转 navigate('/home')
嵌套路由 children 配置 + <Outlet /> 出口
懒加载 element 用 React.lazy 分包

17.状态管理

方案 特点 何时用
useState + Context 内置、无依赖 中等量、低频更新（主题/用户）
Zustand 极简、不用 Provider、API 友好 ✅ 新手首选
Redux Toolkit 规范、生态成熟、DevTools 强 大型团队项目

Context 最小示例

const ThemeCtx = createContext('light')
// 提供
<ThemeCtx.Provider value="dark"><App/></ThemeCtx.Provider>
// 消费
const theme = useContext(ThemeCtx)
Context 的值变化会让所有消费它的组件全部重渲染，高频变化的数据（如频繁刷新的列表）不适合放 Context，用 Zustand 更好。

Zustand 最小示例

import { create } from 'zustand'
const useStore = create((set) => ({
  count: 0,
  inc: () => set(s => ({ count: s.count + 1 }))
}))
// 组件里
const count = useStore(s => s.count)
const inc = useStore(s => s.inc)
简单用 Context，复杂上 Zustand； Redux 生态强，但样板代码长。

18.数据请求 React Query

请求别只写 useEffect+fetch，React Query（TanStack Query）帮你管缓存、loading、重试、自动刷新。 

import { useQuery } from '@tanstack/react-query'
function User({ id }) {
  const { data, isLoading } = useQuery({
    queryKey: ['user', id],
    queryFn: () => fetch('/api/user/'+id).then(r => r.json())
  })
  if (isLoading) return <p>加载中</p>
  return <p>{data.name}</p>
}
同一个 queryKey 再请求会直接用缓存，秒开；window 重新聚焦还能自动刷新。请求逻辑该放这而不是 useEffect。

20.Next.js 与 SSR

Next.js 是 React 的全栈框架，补齐了路由、SSR/SSG、API 路由等 React 不带的能力。

渲染方式 说明 适合
CSR 客户端渲染 浏览器请求后再 JS 渲染 后台管理系统
SSR 服务端渲染 服务器返回已渲染好的 HTML SEO 重要的内容站
SSG 静态生成 构建时生成静态页 博客、文档
App Router（Next 13+）用 Server Components，能直接在组件里写查数据库的代码，大幅简化全栈开发。

21.原理：Fiber 与虚拟 DOM

虚拟 DOM = 用 JS 对象描述真实 DOM 的树。数据变 → 生成新虚拟树 → 与旧树Diff 比对 → 只把差异更新到真实 DOM。

为什么不用真实 DOM？因为直接操作真实 DOM 很慢（涉及布局重排），JS 对象比对很便宜。先比对象、最后只改必要的 DOM。

Fiber 架构（React 16+）

  • 把渲染工作拆成一个个小单元（Fiber），可中断、可恢复。
  • 好处：渲染大组件树时不会长时间卡死主线程，能优先处理用户输入等高优任务。
  • 这是 React 18 并发特性的底座。

Diff 三大策略（启发式）

策略 含义
1. 同层比较 只比同一层节点，不跨层
2. 类型不同直接替换 类型变就整个重建子树
3. key 复用 靠 key 判断兄弟节点是否同一个
虚拟 DOM 是对象，Diff 同层比差异； Fiber 可中断，key 定复用。

22.React 18 并发特性

特性 作用 小白理解
自动批处理 多次 setState 合并成一次渲染 多步操作只刷一次屏

23.面试口诀与速查表

问题 一句话答案
JSX 是什么 JS 里写类 HTML，编译成 createElement
为什么 key 不能用 index 顺序变动会错位、复用错误
props 和 state 区别 props 外来只读，state 内部可变触发渲染
为什么 state 要不可变更新 换新引用 React 才感知变化、也好做时间旅行
useEffect 依赖空数组 只在挂载后跑一次，常发初始请求
useMemo vs useCallback 缓存值 vs 缓存函数
受控组件 表单值由 state 控制
Fiber 是什么 可中断可恢复的渲染单元，并发底座
虚拟 DOM 优势 JS 对象比对便宜，最后才改真实 DOM
状态管理选型 简单 Context，复杂 Zustand，大型 Redux
组件是函数，Props 是参数； state 连屏幕，改它要换新； 副作用进 effect，依赖定时机； 虚拟 DOM 做 Diff，Fiber 可中断； 数据请求上 Query，状态管理看规模。
