第一篇：入门篇（认识抓包）

1.抓包是什么

一句话：抓包 = 把客户端和服务器之间收发的网络数据包「拦截下来查看」。HTTP 抓包就是看它们「聊了什么」。

抓包像在邮局里安插一个「中转站」：每封来往的信件都先经过中转站，工作人员抄录一份再原样转发。你就能看到信件内容、寄件人、收件人、时间。

抓包能干什么（四大用途）

用途 说明 例子
接口调试 看请求参数、响应结果对不对 排查前后端联调 bug
分析接口 搞懂 App/网页调了哪些接口 给爬虫找数据来源
改包重放 篡改请求/响应，验证边界 测试、调试
安全分析 检查是否有敏感信息泄露 渗透测试（需授权）

抓包的基本原理：代理

绝大多数 HTTP 抓包工具都是「代理（Proxy）」：你让流量先经过工具，工具再转发给服务器，于是工具就能看到全部内容。 

客户端  ──▶  抓包工具(代理)  ──▶  服务器
  │              │记录请求/响应          │
  └──◀──────────◀──────────────────────┘
为什么不直接抓网线？因为系统网络很底层、数据多且乱。用代理把流量「引流」到一个工具里，只看你关心的 HTTP，清晰可控。
抓包本质是代理，流量中转看全程； 调试接口析数据，改包重放做验证。

2.工具全景与选型

市面工具很多，先分清「层次」——有的只抓 HTTP/HTTPS，有的能抓到底层 TCP/UDP。

工具 层级 平台 适合 一句话定位
浏览器 F12 HTTP/HTTPS 全平台 网页调试 零安装，最常用
Fiddler HTTP/HTTPS Windows 为主 Windows 抓包 经典、插件多
Charles HTTP/HTTPS Win/macOS 跨平台、移动端 界面友好、易上手
Wireshark 全协议(TCP/UDP) 全平台 底层网络分析 网卡级深抓
mitmproxy HTTP/HTTPS 全平台 命令行、脚本化 程序员的瑞士军刀
Burp Suite HTTP/HTTPS 全平台 安全测试 渗透测试标配

新手选型建议

  • 只调试网页 → 先用浏览器 F12，够用。
  • 要抓电脑上所有程序/App → Windows 用 Fiddler，Mac 用 Charles。
  • 要抓手机 App → Charles 或 Fiddler（跨设备代理）。
  • 要命令行批量处理 → mitmproxy。
  • 要安全测试 → Burp Suite（务必有授权）。
网页抓包 F12，电脑抓包 F 与 C； 手机也靠 C 或 F，底层深挖 Wireshark。

3.浏览器 F12 DevTools

不用装任何东西，浏览器按 F12（或右键→检查），切到 Network（网络） 面板就能抓网页请求。这是最该先掌握的。

F12 的 Network 面板像「网站的前台流水账」，每条请求的来龙去脉、花了多久、返回了什么都记在案。

使用步骤

  1. 按 F12 打开开发者工具，点 Network 标签。
  2. 勾选 Preserve log（保留日志，跳页不清空）。
  3. 刷新页面，就能看到一堆请求。
  4. 点某条请求，右侧看 Headers（请求头/响应头）、Payload（提交的数据）、Response（返回内容）。

面板分区速查

标签 看什么
Headers 请求 URL、方法、状态码、请求头/响应头
Payload / Request POST 提交的参数（表单/JSON）
Preview / Response 返回的数据（可预览 JSON）
Timing 各阶段耗时（定位慢在哪）

过滤请求

顶部 Filter 输入框可筛选；点 XHR / Fetch 只看接口请求（爬虫找接口必用）。

Network 里看到 XHR 类型 + 返回 JSON 的，就是「接口」——爬虫/逆向最喜欢这种，见第 14 节。

4.Fiddler 入门

Fiddler 是 Windows 上最经典的抓包工具（免费）。装上后默认就能抓电脑上走系统代理的 HTTP 流量。

快速上手步骤

  1. 下载安装 Fiddler（官网或 Fiddler Classic）。
  2. 打开后，左边列表就是抓到的请求。
  3. 点一条请求，右侧 Inspectors 查看请求/响应详情。

界面关键概念

概念 作用
左侧会话列表 所有被抓到的请求
Inspectors 查看请求/响应内容
Filters 按域名/类型过滤
Composer 手动构造、重发请求
AutoResponder 拦截并返回自定义内容（改包）
HTTPS 解密 Tools → Options → HTTPS 勾选 Decrypt
Fiddler 默认只抓 HTTP，要抓 HTTPS 需在设置里开启解密（第 6 节细讲），并安装它的根证书。
Fiddler 快捷键：F12 暂停/恢复抓包（避免抓太多），底部状态栏显示当前捕获数量。

5.Charles 入门

Charles 是跨平台（Win/Mac）的抓包工具，界面友好、对移动端抓包支持好，是 Mac 用户的首选。

快速上手步骤

  1. 安装 Charles，启动后会自动抓电脑的 HTTP 流量。
  2. 左侧树形列表按域名分组显示请求。
  3. 点请求，右侧 Contents / Headers 查看详情。

Charles 特色功能

功能 入口 用途
SSL 解密 Proxy → SSL Proxying Settings 抓 HTTPS
断点改包 Proxy → Breakpoints 拦截修改请求/响应
本地映射 Tools → Map Local 用本地文件替换响应
弱网模拟 Proxy → Throttle Settings 模拟慢网络
重写规则 Tools → Rewrite 批量改请求/响应
Charles 的 树形分组 + 搜索 对移动端海量请求特别友好，抓 App 接口用它很顺手。
Charles 是付费软件（有试用），Mac 上想免费可用 mitmproxy；Windows 上免费可选 Fiddler。
第二篇：进阶篇（抓 HTTPS 与移动端）

6.HTTPS 抓包原理

这是抓包进阶的关键一课。很多新手抓不到 HTTPS 就卡在这。

HTTP 是「明信片」，路上谁都能看；HTTPS 是「上锁的快递箱」，只有收发双方有钥匙。抓包工具要「开箱看内容」，就得伪装成收件人——这叫中间人（MITM）。

中间人 MITM 原理

  1. 客户端本要连服务器，被代理工具截胡。
  2. 工具假装自己是服务器，用自己签发的证书和客户端建立 HTTPS 连接。
  3. 工具再以真实客户端身份连服务器。
  4. 于是工具能解密两边的内容，客户端也「以为」自己在连真的服务器。

要让 MITM 成功，必须做两步

步骤 作用 Fiddler/Charles 位置
① 开启 SSL 解密 让工具去拦截 HTTPS 工具设置里勾选 Decrypt
② 信任根证书 让客户端信任工具的假证书 安装并信任 CA 证书
信任了抓包工具的证书后，理论上它能解密你机器上所有 HTTPS 流量。用完记得关闭 SSL 解密、卸载证书，别在公共电脑随便装。
HTTPS 是上锁箱，中间人来做局； 先开解密再装证，用完记得都清理。

7.移动端抓包

抓手机 App 的通用思路：手机连和电脑同一个 WiFi → 把手机的代理指向电脑 → 在手机上装信任证书。

Charles 抓手机步骤

  1. 电脑和手机连同一个 WiFi。
  2. Charles 里查看电脑 IP：Help → Local IP Address。
  3. 手机 WiFi 设置里，代理设为「手动」，填入电脑 IP 和端口（默认 8888）。
  4. 手机浏览器访问 chls.pro/ssl 下载并安装证书。
  5. iOS 还需在「设置→通用→关于本机→证书信任设置」里开启信任。
  6. 回到 Charles，手机上操作 App，就能看到请求了。
平台 证书注意点
iOS 装完证书要手动开启信任，否则不生效
Android 7+ 默认只信任系统证书，App 可能需 root 或用调试版
Android 7 以下 装用户证书即可
现代很多 App 做了「SSL Pinning」（证书锁定），装了证书也抓不到，这是常见抓包失败原因，见第 15 节。
手机抓包三件套：同网代理加证书； iOS 记得开信任，安卓高版本要费劲。

8.抓包实战

实战一：分析一个接口

  1. 打开抓包，操作 App/网页触发某功能。
  2. 在工具里找到对应请求。
  3. 看 URL + 方法：是 GET 还是 POST。
  4. 看 请求参数：哪些是必须的。
  5. 看 响应：数据长什么样、字段含义。

实战二：断点改包

Charles 中右键请求 → Breakpoints，下次该请求会被「暂停」，你改完再放行。

改什么 目的
改请求参数 测试不同输入、越权、边界
改响应内容 模拟服务端返回特定数据（如改价格、改状态）

实战三：重放请求（Composer）

把抓到的请求「再发一次」，不用重新操作界面。Fiddler 用 Composer，Charles 右键 Repeat。

改包、重放、越权测试只在自己项目或已获授权的系统上做。对他人系统未授权改包测试属于攻击行为，违法。
先找请求看三样，断点改包验边界； 重放请求免重操作，授权之内才安全。

9.过滤与搜索

抓包最大的痛点是「请求太多」。学会过滤和搜索，效率翻倍。

通用过滤维度

维度 Fiddler Charles
按域名 Filters → Hosts 底部 Filter 输入框
按类型 Filters → Request Headers Structure 树形查看
关键词搜索 Ctrl+F Find（Ctrl+F）
只看某类 按响应大小/状态码 按域名分组折叠
Charles 的底部 Filter 输入框支持直接输域名或关键词；点 🔍 还能全文搜索请求和响应内容，找接口字段超好用。

10.弱网模拟

测试 App 在慢网下的表现（转圈、超时、断线重连），抓包工具能「人为把网速调慢」。

弱网模拟像给网络「限流的水龙头」，你想模拟 2G、3G、丢包，扭一扭开关就行，不用真的去地下室找信号。

Charles 弱网设置

  1. Proxy → Throttle Settings 勾选启用。
  2. 选择预设（如 3G）或自定义带宽/延迟/丢包率。
  3. 再操作 App，观察它在慢网下的表现。
参数 含义
Bandwidth 带宽 传输速度上限
Latency 延迟 每个包的响应时间
Packet loss 丢包率 模拟网络不稳、丢数据
弱网测试是移动端质量保障的必修课，配合抓包看「卡顿时刻到底哪个请求慢了」最直观。

11.Wireshark 深度抓包

前面工具只抓 HTTP；Wireshark 抓的是网卡层面的所有流量（TCP/UDP/DNS/ARP…），能看清「数据在网络上真实长啥样」。

Fiddler/Charles 是「快递站看包裹面单」，Wireshark 是「高速路口看每辆车的车牌、载重、去向」——更底层、更原始。

快速上手

  1. 打开 Wireshark，选择要抓的网卡（如 WLAN / Ethernet）。
  2. 点开始，就能看到一个个数据包。
  3. 顶部绿色过滤框输入表达式过滤，如 http、tcp.port == 80。

必会过滤表达式

http                        # 只看 HTTP
tcp.port == 443             # 只看 443 端口的 TCP
ip.addr == 192.168.1.100    # 只看某 IP
dns                         # 只看 DNS 查询

经典场景：TCP 三次握手

过滤 tcp.port == 80，能看到 SYN → SYN+ACK → ACK 三个包，理解「建立连接」的过程。

Wireshark 用于底层网络排查（连不上、丢包、慢、DNS 问题），日常接口调试用 F12/Fiddler/Charles 就够了。

12.mitmproxy 脚本化

mitmproxy 是命令行抓包工具，最大优势：能用 Python 脚本自动处理流量。程序员批量抓包、自动化改包的利器。

安装：pip install mitmproxy

三个入口

命令 说明
mitmproxy 命令行交互界面
mitmweb 浏览器网页界面（可视化）
mitmdump 无界面，配合脚本跑 
# addon.py —— 一个自动改响应的脚本
from mitmproxy import http

def response(flow: http.HTTPFlow):
    # 命中某接口时，把返回内容替换掉
    if "api/price" in flow.request.pretty_url:
        flow.response.text = '{"price": 0}'
# 运行：加载脚本抓包
mitmdump -s addon.py
mitmproxy 能一键导出 HAR/JSON、批量拦截、自动加签名，是「把抓包变成自动化」的最佳选择。

13.Burp Suite 安全测试

Burp Suite 是安全测试（渗透测试）领域的事实标准，核心仍是抓包代理，但多了扫描、爆破、重放等安全功能。

⚠️ Burp Suite 是安全测试工具，只能用于自己拥有或已获书面授权的系统。未授权对他人网站做扫描/爆破属于违法行为，可能构成「非法侵入计算机信息系统」。

核心模块速览

模块 用途
Proxy 抓包、改包、重放（同 Charles）
Repeater 手动反复发送改过的请求
Intruder 批量爆破参数（字典攻击）
Scanner 自动扫描漏洞
Decoder 加解密、编码转换
普通开发者了解 Proxy + Repeater 就够用了；深入安全测试请走正规学习路径，并牢记授权前提。

14.抓包配合爬虫

抓包是逆向 App/网页接口的钥匙。很多「爬不到」的数据，靠抓包找到接口后直接调接口就能拿到。

通用套路

  1. 打开抓包工具，操作目标 App/网页。
  2. 在请求里找到返回数据的那条接口（XHR / 返回 JSON）。
  3. 分析它的 URL、方法、参数、请求头。
  4. 用代码（Python requests）模拟这个请求。
  5. 处理 签名/加密参数（进阶，可能需逆向 JS/App）。 
import requests

# 抓包得到的接口信息，用代码复现
url = 'https://api.example.com/list'
headers = {
    'User-Agent': '...',        # 从抓包复制
    'Authorization': 'Bearer ...',  # 从抓包复制 token
    'sign': '...',              # 签名参数（抓包看规律）
}
resp = requests.get(url, headers=headers, params={'page': 1})
print(resp.json())
接口通常有签名（sign）、时间戳、token等反爬参数。这些参数靠「抓包看规律」能猜出简单的；复杂的需要逆向 JS/App 算法，这已属于进阶逆向领域，且务必遵守法律红线。
抓包找接口，代码来模拟； 参数带签名，逆向看规律。

15.技巧与常见问题

问题 原因 解决
抓不到 HTTPS 没开 SSL 解密 开启 Decrypt + 装证书
装证书也抓不到 App 做了 SSL Pinning 需处理证书锁定（进阶）
手机抓不到 代理没设对/不同网 确认同 WiFi、IP、端口
请求太多看不过来 没过滤 用域名过滤 + 搜索
本地 localhost 抓不到 本地流量不走代理 改 hosts 或工具配置
抓完流量变卡/断网 代理未关闭/证书残留 关代理、卸证书

进阶小技巧

  • 先过滤再抓：设置好域名过滤，避免垃圾流量。
  • 导出 HAR：抓包结果存成 .har，方便分享/分析。
  • 抓完必清理：关闭 SSL 解密、移除证书、关代理，避免影响日常上网。

16.安全与合规红线

三条铁律（务必遵守）：① 只抓自己的流量或已获授权的系统；② 不抓取、不存储他人隐私数据（账号、密码、身份证等）；③ 不用抓包能力对他人系统做攻击、越权、爆破。抓包本身是中性技术，用在哪决定了对错。

使用抓包工具的良好习惯

习惯 为什么
用完关代理 防止流量持续被拦截、影响上网
用完卸证书 防止机器上所有 HTTPS 被解密
公共电脑不装证书 避免别人窃取你的加密流量
授权内测试 合法合规的底线
抓包技术本中立，授权之内才可为； 用完关闭卸证书，隐私安全记心间。

学习路线建议（15 天实战）

阶段 天数 重点任务
入门 1–4 用 F12 抓 3 个网页接口；装 Fiddler/Charles 抓电脑流量
进阶 5–10 搞定 HTTPS 解密、手机 App 抓包、断点改包、弱网模拟
精通 11–15 学 mitmproxy 脚本化、Wireshark 底层分析，做一个「抓包找接口」小项目
终极心法：先抓通 → 再过滤 → 再改包 → 再脚本化。每次只攻一个工具、一个场景，抓包靠的是「动手折腾」而不是死记。记住：合法合规，授权之内。
