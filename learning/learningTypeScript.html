01入门篇

01TypeScript 是什么：为什么 JavaScript 需要类型

📖 一句话理解 TypeScript

TypeScript 是 JavaScript 的超集（superset）。它给 JS 加上了静态类型系统，并在编译时通过 tsc 编译成纯净 JS。

三大核心收益：① IDE 智能提示 — 写错就报错；② 重构安全 — 改一处全局找引用；③ 自带文档 — 类型即注释。

当前最新主线版本是 TypeScript 5.x（重大变化：装饰器进入 stage 3、全新的类型系统性能优化 10x、const 类型参数、using 资源释放）。

1.1 TypeScript vs JavaScript 关键差异

维度 JavaScript TypeScript
类型系统 动态类型 静态类型（编译时检查）
运行方式 浏览器/Node 直接执行 先 tsc 编译成 JS 再运行
错误发现 运行时报错 编译时智能提示报错
重构 改一处担心炸全局 IDE 联动改名字精确到引用
文件后缀 .js .ts（逻辑）/ .d.ts（声明）
生态支持 所有 JS 库 主流库都自带类型；老库加 @types 包
学习曲线 入门平缓 类型心智模型需要时间

1.2 第一个 .ts 文件：三步跑起来

1安装 tsc：npm i -D typescript
2写代码：hello.ts
3编译运行：npx tsc hello.ts && node hello.js 
// hello.ts —— TS 的最小可运行示例
function greet(name: string, age: number = 18): string {
  return `Hello, ${name} (${age}岁)!`;
}

// TS 编译期就会拦住以下错误：
// greet(123);         // ❌ 类型“number”不能赋给“string”
// greet('Tom', '20'); // ❌ 字符串不能赋给数字参数
console.log(greet('TypeScript'));
console.log(greet('小明', 25));
💡 为什么类型是"免维护的文档"

看接口 type Api = { url: string; method: 'GET' | 'POST'; retries?: number } —— 你立即知道字段名、合法取值、可选性。类型即文档，且永远不会过期。

⚠️ TS 不会让代码更短，但会让代码更稳

刚开始写 TS 时会觉得啰嗦——每个变量都要标类型。但越大的项目，类型收益越明显。10 行代码看不出区别，1 万行就回不去了。

🧠 速记口诀

TS 是 JS 加类型，类型即文档、类型即约束、类型即测试（编译通过即类型正确）。
大项目必收益，小项目可渐进；先理解再说，别急着写。

02环境搭建与 tsconfig 配置

📖 两种主流搭建方式

① 裸 tsc：直接 tsc file.ts，适合学习和小工具；
② Vite + ts-loader/swc：现代工程标配，配 ESLint + Prettier 一键起。

2.1 最快跑通：tsc + Node

# 全局或项目安装
npm i -D typescript @types/node

# 初始化配置
npx tsc --init

# 编译并运行
npx tsc index.ts && node index.js

# 开发模式：watch 自动重编译
npx tsc --watch

2.2 tsconfig.json 核心字段速查

字段 作用 推荐值
target 编译到哪个 ES 版本 ES2020（现代浏览器）
module 模块方案 ESNext（Vite/Node ESM）
strict 全家桶严格模式（推荐开） true
noImplicitAny 禁止隐式 any true
strictNullChecks 区分 null/undefined true
esModuleInterop 允许 import 默认值 true
skipLibCheck 跳过 .d.ts 检查（提速） true
forceConsistentCasingInFileNames 大小写敏感 true
resolveJsonModule 支持 import json true
isolatedModules 单文件可独立编译（Vite 需要） true
baseUrl / paths 路径别名 "@/*": ["src/*"]
jsx React JSX 处理 "react-jsx"（React 17+）
💡 一份开箱即用的 tsconfig

99% 的项目直接用 create-vite 起步，把 strict: true 打开即可。千万别从 0 写 tsconfig，先抄一份业界主流的再按需改。

2.3 Vite 启动一个 TS + React 项目

cd my-app
npm i
npm run dev      # http://localhost:5173

2.4 编译器版本 & 升级

# 查看版本
npx tsc --version

# 升级到最新版
npm i -D typescript@latest

# VSCode 设置里指定每工作区 TS 版本，避免插件用全局旧版
# "typescript.tsdk": "./node_modules/typescript/lib"
⚠️ 五个常见坑

① @types/xxx 没装 → 类型 any；② tsconfig.json 在子目录 → 配置不生效；③ Vite 不需要装 ts-loader（内部用 esbuild）；④ skipLibCheck 一定要开，否则大型项目卡顿；⑤ 老项目上 TS 不要全开 strict，逐文件 // @ts-check 渐进启用。

🧠 速记口诀

tsc 起手：--init 生成配置 → --watch 增量编译 → strict 一键开。
工程化：用 Vite 别裸配；类型包：装 @types/xxx；老项目：渐进开 strict。

03入门篇

03基础类型与类型注解

📖 TS 的类型世界观

所有变量、形参、返回值都要标类型。JS 的类型是「运行时才知道」，TS 是「写代码时就锁定」。

类型声明语法：const x: type = value；类型推断能省则省，不要处处加 : type。

3.1 11 种基础类型速查

类型 说明 示例
string 字符串 let s: string = 'hi'
number 整数/小数/NaN/Infinity let n: number = 3.14
boolean 布尔 let ok: boolean = true
null / undefined 空值 let u: undefined = undefined
void 无返回值 function f(): void {}
never 永不返回（抛错/死循环） function err(): never { throw new Error() }
any 任意类型（放弃检查） let v: any = 123
unknown 安全的 any（用前需 narrowing） let u: unknown = JSON.parse(...)
object 非原始类型 let o: object = {}
Array<T> / T[] 数组 let a: number[] = [1,2]
Tuple 固定长度+类型 let t: [string, number] = ['a', 1]
enum 枚举 enum Color {Red, Green}
bigint / symbol 大整数 / 唯一值 let b: bigint = 100n

3.2 any vs unknown：宁用 unknown

let v: any = 4;
v.toUpperCase(); // ❗编译不报错，但运行炸！

let u: unknown = 4;
u.toUpperCase();
//      ~~~~~~~~ 编译直接报错：u 是 unknown 类型
if (typeof u === 'string') {
  u.toUpperCase(); // ✅ narrowing 后才允许
}
⚠️ any 像毒品，用一次爽一直用一直烂

实在要用请用 unknown 替代，配合 typeof/instanceof/type guard 收紧。严格项目的红线：禁止 any、禁止 @ts-ignore。

3.3 联合类型 + 字面量 + 类型别名

// 联合类型：可以是多种类型之一
type Status = 'pending' | 'success' | 'error';
let s: Status = 'pending';
// s = 'fail'  // ❌ 'fail' 不在字面量里

// 字面量类型（数字、布尔、字符串）
type Dice = 1 | 2 | 3 | 4 | 5 | 6;
type Bool = true | false;

// 类型别名（type alias）
type UserId = string & { readonly __brand: 'UserId' }; // 品牌类型防 ID 串号

// 数组：两种写法等价
const arr1: Array<number> = [1, 2, 3];
const arr2: number[] = [1, 2, 3];

// 元组：固定结构
const tuple: [string, number, boolean] = ['Tom', 18, true];
tuple[0].toUpperCase();  // ✅ string 方法
tuple[1].toFixed(2);    // ✅ number 方法

// 对象类型
interface User { name: string; age?: number }  // age 可选
type  User2 = { name: string; age?: number };

3.4 类型断言（as / 尖括号）

// 1. as 关键字（推荐）
const a = document.getElementById('app') as HTMLElement;
const b = (JSON.parse(s) as User).name;  // 编译期相信你

// 2. 尖括号（不与 JSX 混用）
const c = <User>JSON.parse(s);

// 3. const 断言（字面量变只读精确类型）
const center = { x: 10, y: 0 } as const;
// type 是 { readonly x: 10; readonly y: 0 }

// 4. ! 非空断言（小心用！）
function f(el?: HTMLElement) {
  el!.click(); // 告诉 TS el 一定不为 undefined
}
💡 三个"看起来像但不一样"易错点

① any、unknown、never 的关系：unknown 是安全的 top type；never 是 bottom type，没有值可赋；
② interface 和 type 99% 相同，但前者可以 extends、后者可以联合；
③ readonly 修饰符只防改但不防深改，深度只读用 as const 或工具类型 Readonly<T>/DeepReadonly<T>。

🧠 速记口诀

标类型：能省则省（TS 会推断），无法推断再显式标。
any 让位 unknown，联合让位字面量，函数返回值必标。

04入门篇

04接口与类型别名

📖 interface vs type：什么时候选哪个

原则：对象/类优先用 interface（可扩展），联合/工具/映射优先用 type。两者 99% 重叠，不小心混用也不算错。

4.1 interface 三种角色

角色 示例 特点
对象形状 interface User { name: string; age: number } 声明对象的字段集合
类实现 class Admin implements User { ... } 强制类遵循结构
API 契约 interface Api { list(): ListRes } 对外暴露的签名

4.2 可选 / 只读 / 索引签名

interface User {
  id: string;
  name: string;
  age?: number;               // 可选（undefined | T）
  readonly createdAt: number; // 只读
  email?: string;
}

// 索引签名：动态键
interface StringDict {
  [k: string]: string;
}

// 嵌套对象 + 数组
interface ApiList<T> {
  code: number;
  data: T[];
  msg: string;
}

const u: User = { id: '1', name: 'Tom', createdAt: Date.now() };
// u.id = '2';  // ❌ readonly 不能赋值
// u.age = 18;  // ✅ 可选字段可以单独赋值

4.3 接口合并 & 继承（VS 类型别名不支持）

// 同名接口自动合并
interface Box { width: number }
interface Box { height: number }
interface Box { scale?: number }
const b: Box = { width: 100, height: 200, scale: 2 };

// 继承多个
interface ButtonProps extends BaseProps, HTMLElementAttrs {
  size: 'small' | 'medium' | 'large';
}

// type 别名能更强大（union / 条件类型等）
type Maybe<T> = T | null | undefined;
type EventHandler = (e: MouseEvent) => void | Promise<void>;

4.4 鸭子类型（结构化类型）

// TS 看"形状"不看名字
interface Named { name: string }
function greet(n: Named) { return `Hi, ${n.name}!` }

class Person {
  constructor(public name: string, public age: number) {}
}

greet(new Person('Tom', 18));  // ✅ 形状对就行，不在乎是 class 还是对象
greet({ name: 'Jerry' });      // ✅ 字面量直接传
💡 可选字段 vs 默认值

age?: number 等价于 age?: number | undefined，但有 exactOptionalPropertyTypes: true 时只能为 undefined（不能显式 undefined）。
解构默认值：const { age = 18 } = user; 提供默认值；
运行时检查：'age' in user 用 in 操作符判断字段是否存在（避坑 undefined 字段赋过的情况）。

4.5 type & interface 选型表

场景 推荐 理由
声明对象/组件 props interface 可继承、错误信息更友好
联合类型 / 工具类型 type interface 不能做 union/条件
需要同名合并 interface type 会重复声明报错
需要实现类 interface class implements Interface
函数签名 / 元组 type 更简洁
声明映射 / 条件类型 type interface 不支持
🧠 速记口诀

对象的字 interface，工具联合 type；同名合并不乱，鸭子类型帮大忙。
小项目选哪个都行；大项目统一约定，团队达成一致即可。

05函数类型与高级签名

📖 函数是 JS 一等公民，TS 函数也是类型系统的一等公民

函数类型四要素：① 参数（位置/必选/可选/默认/剩余）；② 返回值（显式/推断/void/never）；③ this（Function.call/箭头）；④ 重载。

5.1 函数五种写法

写法 语法 特点
函数声明 function f(x: number): number { return x } 有 hoisting，可重载
函数表达式 const f = function(x: number): number { ... } 无 hoisting
箭头函数 const f = (x: number): number => x * 2 无 this/use arguments
方法缩写 const o = { f(x: number) {} } 对象里的方法
Function 类型 const f: (x: number) => number = ... 显式标注函数类型变量

5.2 形参全家族

// 1. 必选 + 可选 + 默认值 + 剩余
function fn(a: string, b?: number, c = 10, ...rest: any[]): void {
  console.log(a, b, c, rest);
}
fn('hi');         // ✅ b 省略即 undefined
fn('hi', 1, 2, 3, 4);

// 2. 解构 + 默认值（必填可缺失就变成 undefined）
function config(opts: { host: string; port?: number; auth?: { u: string; p: string } }) { ... }

// 3. this 显式类型
interface This { name: string }
function show(this: This) { return this.name }
const bound: (this: This) => string = show.bind({ name: 'Tom' });

// 4. 函数类型
type Callback = (data: string, code: number) => Promise<boolean>;

5.3 函数重载：先声明后实现

// 重载签名（只是声明）
function pad(input: string, length: number): string;
function pad(input: number): string;
function pad(input: any, length?: number): string {
  if (typeof input === 'string') return input.padEnd(length ?? 0, '*');
  if (typeof input === 'number') return String(input);
  throw new Error('invalid');
}
pad('hi', 5);  // string
pad(42);       // number

5.4 void vs never：返回值终结类

类型 语义 典型场景
void 没有显式 return 事件回调 (e) => { e.preventDefault() }
undefined 显式返回 undefined 与 void 不同，调用方按 undefined 处理
never 不可能有返回值 抛错的函数 / 死循环 / exhaustive check 
// never 用在判穷尽分支
function assertNever(x: never): never {
  throw new Error('unhandled case: ' + JSON.stringify(x));
}
type Color = 'red' | 'green' | 'blue';
function describe(c: Color) {
  switch (c) {
    case 'red':   return 'warm';
    case 'green': return 'fresh';
    default: return assertNever(c); // 加新色时这里爆错提示
  }
}

5.5 常见陷阱

⚠️ 五大坑

① 默认值只能是最后一个？错——剩余参数前任意可选参数都能有默认值；
② function add(a,b) { return a+b } 看似宽松但参数默认不限数量，需要 noUnusedParameters 拦；
③ void 返回值函数赋给变量后，变量类型仍是 void，不能解构；
④ 重载顺序：最具体的签名排在前面，最后一行才放实现签名；
⑤ 箭头函数没有自己的 arguments，需要剩余参数 ...args 替代。

🧠 速记口诀

函数签名四件套：参数 + 返回 + this + 重载。
不返走 void，必抛写 never，重载前具体后通用。

06泛型入门与类型参数

📖 泛型 = 类型版的函数参数

把"类型"当参数传给"类型函数"，在调用时再用具体类型替换。写一次代码，适配任意类型又不丢类型安全。

三大场景：函数/接口/类。

6.1 三类泛型

形式 语法 说明
泛型函数 function id<T>(x: T): T { return x } 类型参数写在调用签名里
泛型接口 interface Box<T> { value: T } 声明契约的可变类型
泛型类 class Container<T> { constructor(public v: T) {} } 实例类型由调用决定
泛型约束 function id<T extends object>(x: T) 约束类型参数必须满足
泛型默认值 class Container<T = unknown> 默认就 fallback

6.2 五个常见泛型写法

// 1. 泛型函数：自动推断
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}
first([1, 2, 3]);          // T 推断为 number
first(['a', 'b']);         // T 推断为 string

// 2. 显式传参 + 默认值
function fromArray<T = string>(arr: T[]): T[] { return arr; }
fromArray(['x']);          // T 默认 string

// 3. 泛型约束 extends
function getKeys<T extends object>(obj: T): Array<keyof T> {
  return Object.keys(obj) as Array<keyof T>;
}

// 4. keyof + 索引访问
function pluck<T, K extends keyof T>(obj: T, keys: K[]): T[K][] {
  return keys.map((k) => obj[k]);
}
pluck({ a: 1, b: 'x' }, ['a', 'b']); // (string|number)[]

// 5. 泛型接口
interface ApiResponse<T> {
  code: number;
  msg: string;
  data: T;
}
type User = ApiResponse<{ name: string; age: number }>;

6.3 上下文推断（推荐）：少写显式参数

// 不需要显式 id<number>(42)，从参数自动推断
function id<T>(x: T): T { return x }
id(42);        // T 推断为 number
id('hi');      // T 推断为 string

// 缺点：上下文推断失败时要显式
function combine<T>(a: T, b: T): T[] { return [a, b] }
// combine('x', 1);    // ❌ T 不能同时是 string 和 number
combine<string | number>('x', 1); // ✅ 显式联合

6.4 实战案例：泛型请求函数

async function request<T>(url: string, opts?: RequestInit): Promise<T> {
  const res = await fetch(url, opts);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json() as Promise<T>;
}

// 接口定义
interface User { id: string; name: string; age: number }

// 调用处指定返回类型，IDE 全程补全
const user = await request<User>('/api/users/1');
console.log(user.name.toUpperCase());  // ✅ 类型确定
💡 不要为了用泛型而用泛型

若仅一处调用且类型已知，写死类型更可读。只有重复模式（多类型共用代码）才用泛型。

6.5 疑难解答

症状 方案
T 在联合类型下不扩展 <T extends Base> 给约束
类 new 一个泛型 {new(): T} 约束构造类型
嵌套泛型看着头大 写成有名字的 type alias，别直接嵌
通用工具太多看着乱 用 Pick/Omit/Partial 而非重写
条件分支 T 不存在 用 T extends U ? X : Y 条件类型
🧠 速记口诀

泛型是类型参数：能传 string/number/boolean，也能传"约束后的 T"；
上下文优先推断，约束+默认值护安全，不为了泛型而泛型。

07进阶篇

07类与面向对象加强

📖 TS 的 class 比 ES6 多了类型和修饰符

TS class 多了：访问修饰符（public/private/protected）、readonly、参数属性、抽象类、implements、getter/setter。

7.1 类成员四件套

成员 修饰符 说明
字段 public/private/protected/readonly 类内/子类/外部可见性
方法 同字段 类上挂的函数
构造器 — 无访问修饰符默认 public

7.2 完整示例

// 接口契约
interface Flyable { fly(): void }
interface WakeAble { wake(): void }

// 抽象类
abstract class Animal {
  constructor(public name: string, protected age: number) {}
  abstract eat(food: string): void;
  speak() { console.log(`${this.name} 发出叫声`) }
}

// 实现一个具体动物

  private static ids = 0;
  static getCount() { return Cat.ids; }
  readonly birthday = new Date();

  constructor(name: string, age: number, private breed: string) {
    super(name, age);
    Cat.ids++;
  }

  eat(food: string): void {
    console.log(`${this.name} 在吃 ${food}`);
  }

  // 多接口方法
  fly(): void { console.log(`${this.name} 跳得很高假装在飞`) }
  wake(): void { console.log(`${this.name} 伸个懒腰`) }

  // getter/setter 可拦截
  get info(): string { return `${this.name}/${this.breed}/${this.age}岁` }
  set info(v: string) { /* 不允许修改 */ throw new Error('readonly') }
}

    return this;

  }
}

📖 类型守卫：从宽类型收窄到窄类型的过程

类型守卫（type guard）是一种把联合类型收窄到具体类型的函数或表达式。它是 TS 类型体操的第一课。

9.1 常用类型守卫速查

守卫 用法 收窄结果

9.2 四种原始守卫

function padLeft(value: string, padding: number | string): string {
  if (typeof padding === 'number') {
    return ' '.repeat(padding) + value;  // padding 收窄为 number
  }
  return padding + value;                  // padding 收窄为 string
}

interface Fish   { swim(): void; kind: 'fish' }

  return (pet as Fish).swim !== undefined
}

function move(pet: Animal) {
  if (isFish(pet)) {
    pet.swim();   // pet 收窄为 Fish

  }
}

📖 工具类型 = 类型系统里的轮子

工具类型（utility types）是 TS 自带或自己手写的对类型做 transform 的类型函数。掌握它们等于拿到类型系统的瑞士军刀。

10.1 16 个必知工具类型速查

名称 效果 手工实现

11装饰器与元数据

📖 装饰器是 TC39 stage 3，正在收尾

装饰器（Decorator）是一种在类/方法/属性/参数上加注解的语法，可在不修改原代码的前提下注入行为或元数据。

注意：TS 5 默认仍采用实验性装饰器（legacy/旧方案），使用需 experimentalDecorators: true。新方案（标准 stage-3）只需 target: ES2022+ 默认支持。

11.1 5 种装饰器位置

位置 签名 用途
类装饰器 @dec(target) 改类/替换构造器
方法装饰器 @dec(target, name, descriptor) AOP 增强（鉴权/日志）
访问器装饰器 同方法 拦截 getter/setter
属性装饰器 @dec(target, name) 打 tag 元信息
参数装饰器 @dec(target, name, index) DI 容器用

11.2 三个最常见的装饰器

// 1. 方法日志装饰器
function Log(target: any, name: string, desc: PropertyDescriptor) {
  const original = desc.value;
  desc.value = function (...args: any[]) {
    console.log(`[${name}] called with`, args);
    const r = original.apply(this, args);
    console.log(`[${name}] returns`, r);
    return r;
  };
}

class Calc {
  @Log
  add(a: number, b: number) { return a + b; }
}
new Calc().add(1, 2); // 输出调用与返回日志

// 2. 防抖装饰器（带工厂）
function Debounce(ms: number) {
  return function (_: any, __: string, desc: PropertyDescriptor) {
    let timer: any;
    desc.value = function (...args: any[]) {
      clearTimeout(timer);
      timer = setTimeout(() => desc.value!.apply(this, args), ms);
    };
  };
}

class UI {
  @Debounce(300)
  onSearch(q: string) { console.log('search', q); }
}

// 3. 类装饰器：加版本号
function Version(v: string) {
  return <T extends { new (...args: any[]): {} }>(target: T) => {
    return class extends target {
      version = v;
    };
  };
}
@Version('1.0')
class Service {}
console.log(new Service());

⚠️ 装饰器的坑

① 装饰器执行顺序：同一方法多个装饰器，从下往上包装、自上而下调用；
② 装饰器只能用在类内部，不能装饰普通函数（函数会 hoist）；
③ 老装饰器与新装饰器签名不同，迁移请确认 TS 版本；
④ descriptor.value 在装饰器里改写后，原方法不再单独存在。

    const routes = Reflect.getMetadata('routes', target.constructor) ?? [];
    routes.push({ method: 'GET', path, handler: name });
    Reflect.defineMetadata('routes', routes, target.constructor);
  };
}

  desc.value = function (...args: any[]) {
    if (!currentUser.isAdmin) throw new Error('Forbidden');

  };

// promisify: 用泛型 + Omit 自动包装
function promisify<Args extends any[], R>(
  fn: (...a: [...Args, cb: (e: Error | null, r?: R) => void]) => void,
): (...a: Args) => Promise<R> {
  return (...a: Args) => new Promise((res, rej) => {
    fn(...a, (err, r) => err ? rej(err) : res(r as R));
  });
}

// 超时包装（防 API 永不返回）
function timeout<T>(p: Promise<T>, ms: number): Promise<T> {
  return new Promise((res, rej) => {
    const t = setTimeout(() => rej(new Error('timeout')), ms);
    p.then((v) => { clearTimeout(t); res(v) })
     .catch((e) => { clearTimeout(t); rej(e) });
  });
}

并行多个独立请求 Promise.all + 元组解构
并行但允许部分失败 Promise.allSettled
抢答用最快的 Promise.race / any
需要取消 AbortController + signal
错误优先返回 Result<T, E> 模式
节流尾请求 debounce + AbortSignal
⚠️ 五大坑

① await 后的代码就是同步，但它把 promise 链扁平化了，性能可优化空间变小；
② 滥用 await 把独立请求串行化，体验变差；
③ 不接 try/catch 时未捕获 async 错误被吞掉；
④ 异步函数里抛错能进 .catch，但同步逻辑抛错也要保护；
⑤ forEach 不等待 async 函数！要用 for ... of 或 Promise.all(map)。

🧠 速记口诀

并 all，败 any，成 allSettled，快 race。
try/catch unknown narrowing 必做；AbortController 取消。

13类型体操与条件类型

📖 类型体操就是用类型写"逻辑"

用 extends、infer、T[K]、keyof 等组合出接收类型、产出类型的过程。
三分技术，七分命名，好的 type 别名比什么都重要。

13.1 四件基础语法

// 1. 条件类型：如果 T extends U 则 X else Y
type IsString<T> = T extends string ? true : false;
type A = IsString<'hi'>;    // true
type B = IsString<42>;      // false

// 2. infer 推断：把"未知部分"挖出来
type GetReturnType<F> = F extends (...args: any[]) => infer R ? R : never;
type FirstArg<F> = F extends (x: infer A, ...args: any[]) => any ? A : never;

// 3. 映射类型：批量改键值
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

// 4. 索引访问：从类型里取片段
type ValueOf<T> = T[keyof T];
type IdOf<T> = T extends { id: infer U } ? U : never;

13.2 八道经典类型题及答

// 1. 实现 Exclude
type MyExclude<T, U> = T extends U ? never : T;

// 2. 实现 Pick
type MyPick<T, K extends keyof T> = { [P in K]: T[P] };

// 3. 函数第 N 个参数
type NthArg<F, N extends number> =
  Parameters<F> extends [...infer _ , infer L] // 占位法
    ? N extends 0 ? L : never
    : never;

// 4. 元组转联合
type TupleToUnion<T extends any[]> = T[number];

// 5. 元组转对象
type TupleToObject<T extends readonly [string, any][]> =
  { [K in T[number] as K[0]]: K[1] };

// 6. 类型转全大写下划线
type CamelToSnake<S extends string> =
  S extends `${infer A}${infer B}`
    ? B extends Lowercase<B>
      ? `${A}${CamelToSnake<B>}`
      : B extends Capitalize<infer X>
        ? `${A}_${Lowercase<X>}`
        : `${A}${CamelToSnake<B>}`
    : S;

// 7. 联合转交叉
type UnionToIntersection<U> =
  (U extends any ? (x: U) => void : never) extends
  (x: infer I) => void ? I : never;

// 8. Filter tuple by type
type Filter<T extends any[], U> =
  T extends [infer F, ...infer R]
    ? F extends U ? [F, ...Filter<R, U>] : Filter<R, U>
    : [];
type R = Filter<[1, 'a', true, 2], number> // [1, 2]

13.3 递归三式

// 1. 递归解 Promise
type DeepAwait<T> =
  T extends Promise<infer U> ? DeepAwait<U> : T;

// 2. 深度只读
type DeepReadonly<T> =
  T extends object
    ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
    : T;

// 3. 字符串逆序（用 infer + 递归）
type Reverse<S extends string> =
  S extends `${infer A}${infer B}`
    ? `${Reverse<B>}${A}`
    : '';

13.4 不可分发 vs 可分发条件类型

// 默认是"分发"的：联合的每个分支都套一次条件
type ToArray<T> = T extends any ? T[] : never;
type X = ToArray<string | number>;  // string[] | number[]

// 包一层 tuple 就变成"不可分发"
type ToArraySingle<T> = [T] extends [any] ? T[] : never;
type Y = ToArraySingle<string | number>; // (string|number)[]

13.5 体操解题四步法

1看输入输出：手写若干输入看期望输出
2画类型分解图：把结构拆成 A + infer B
3加约束防飞：extends keyof X 防范上游
4递归终止：留好 base case
⚠️ 越深越容易掉进坑

递归 50 层就报"Type instantiation is excessively deep"。能避免深嵌套就避免，必要时引入中间类型变量。

💡 用 Playground 调类型

官方 TS Playground（tsplay.dev）可以鼠标悬停查看类型推导。遇到体操题第一时间打开 Playground 来验证，别靠脑子推。

🧠 速记口诀

extends 三元，infer 挖参，map 改键，递归终止；
分发是个坑，tuple 包一层防。

  E extends `${infer N}.${infer A}` ? { ns: N; action: A } : never;

14.3 字符串加 / 删某段

// 前缀加 on
type On<S extends string> = S extends `on${infer R}` ? S : `on${Capitalize<S>}`;
type T1 = On<'click'>;   // 'onClick'

// 去掉指定前缀
type StripPrefix<S extends string, P extends string> =
  S extends `${P}${infer R}` ? R : S;
type T2 = StripPrefix<'onClick', 'on'>;  // 'Click'

// Camel -> Snake
type ToSnake<S extends string> =
  S extends `${infer A}${infer B}`
    ? B extends Uncapitalize<B>
      ? `${A}${ToSnake<B>}`
      : `${A}_${Lowercase<B>}` extends infer R extends string ? R : never
    : S;

14.4 路径/路由类型

// 从路径里抽出 :id 占位
type Params<Path extends string> =
  Path extends `${string}:${infer N}/${infer R}`
    ? { [_ in N]: string } & Params<`/${R}`>
    : Path extends `${string}:${infer N}`
      ? { [_ in N]: string }
      : {};

type P = Params<'user/:id/post/:postId'>;     // { id: string; postId: string }

18.6 自检 30 题（会一半算优秀）

⚠️ 六大常见错误

① 全 any 写完 — 没起到 TS 作用；
② 全部 interface，连联合都没法表达；
③ 滥用 as，类型雪花飘；
④ 装 @types/xxx 后忘了用；
⑤ 完全不开 strict，还在用隐式 any；
⑥ 把 enum 当字符串用 vs 用 string 字面量。

18.8 写在最后：写"为人写"的代码

💡 类型即文档，代码即承诺

类型不必追求"炫技"，而是追求"让下一个看代码的人少踩坑"。
写出好的类型，比写出聪明的算法更显功力。

🧠 全书速记口诀

基础类型 → 接口类型 → 高级类型 → 体操类型 → 工程化，这五层就是 TS 学习金字塔。
写类型时多问一句"下一个看的人能不能秒懂"，这才是真正的精通。

持续学习，永不止步。
