01 嵌入式系统概述

什么是嵌入式系统

嵌入式系统是嵌入到设备内部、为特定功能设计的专用计算机系统。 它以应用为中心，以计算机技术为基础，软硬件可裁剪，对功能、可靠性、成本、体积、功耗有严格要求。

📌 一句话理解
通用电脑（PC）是「什么都能干的瑞士军刀」，嵌入式系统是「只会一招但练到极致的专才」——洗衣机、电饭煲、汽车、无人机里跑的都是它。

嵌入式系统的组成

┌─────────────────────────────────────┐
│           应用层（App）               │
│      业务逻辑 · 算法 · 用户界面        │
├─────────────────────────────────────┤
│  中间层：文件系统 · 协议栈 · GUI      │
├─────────────────────────────────────┤
│  系统层：RTOS / 嵌入式 Linux / 裸机   │
├─────────────────────────────────────┤
│  硬件层：MCU/MPU · 存储器 · 外设接口  │
└─────────────────────────────────────┘
层次 包含内容 典型例子
硬件层 处理器、存储器、电源、接口电路 STM32、ESP32、i.MX6
系统层 裸机 / RTOS / 嵌入式 Linux FreeRTOS、RT-Thread、Linux
中间层 驱动抽象、协议栈、组件库 LwIP、FatFs、LVGL

裸机、RTOS、嵌入式 Linux 怎么选

典型芯片 51、STM8 STM32、ESP32 i.MX、全志、树莓派
🧠 速记口诀
「裸机简单实时强，RTOS 多任务帮忙，Linux 生态大而全，按需选型不慌张」

应用领域

消费电子

智能手表、耳机、家电、玩具——量大、成本敏感、低功耗。

工业控制

PLC、变频器、传感器——强调可靠性与实时性。

汽车电子

ECU、BMS、ADAS——功能安全（ISO 26262）要求极高。

物联网

智能门锁、网关、环境监测——低功耗 + 联网是核心。

02 硬件基础与开发板

MCU 与 MPU 的区别

维度 MCU（单片机） MPU（微处理器）
集成度 CPU+RAM+Flash+外设全集成 只有 CPU，外挂存储与外设
RAM/Flash KB 级 MB～GB 级
是否跑 Linux 一般不跑（无 MMU） 跑 Linux/Android
功耗 μA～mA 级 百 mA 级以上
代表 STM32、ESP32、NXP LPC Cortex-A 系列、i.MX、RK3568
🧠 速记口诀
「MCU 一片全搞定，MPU 外挂才能行；要跑 Linux 找 A 核，省电实时 M 核赢」

常见 ARM Cortex 内核

  • Cortex-M0/M0+：超低功耗入门核，M0+ 是史上能效比最高的核之一
  • Cortex-M3：经典主流，全 Thumb-2 指令
  • Cortex-M4：带 DSP 指令，可选单精度 FPU
  • Cortex-M7：高性能，6 级流水线，带 Cache 与双精度 FPU
  • Cortex-A 系列：应用处理器，带 MMU，跑 Linux/Android
  • Cortex-R 系列：实时处理器，用于硬盘控制器、汽车安全件
📌 一句话理解
M = Microcontroller（单片机）、A = Application（应用/Linux）、R = Real-time（实时硬核）。M 系列是嵌入式入门主线。

必须懂的硬件常识

术语 含义 为什么重要
高电平/低电平 3.3V/5V 为高，0V 为低 数字世界的 1 和 0
上拉/下拉电阻 把引脚默认拉到高/低电平 防止引脚悬空「乱漂」
开漏输出 只能拉低，靠上拉输出高 I2C 总线就是开漏 + 上拉
推挽输出 高低都能主动驱动 GPIO 默认输出模式
datasheet / 参考手册 芯片数据手册 / 外设详解 嵌入式的「武功秘籍」，先查再问

入门开发板推荐

STM32F103C8T6

「最小系统板」几十元，资料全网最多，学 Cortex-M 标准起点。

ESP32

自带 WiFi/蓝牙，适合物联网方向，ESP-IDF + Arduino 双生态。

树莓派

嵌入式 Linux 入门神器，学驱动、系统构建的首选。

正点原子/野火

⚠️ 避坑提示
不要陷入「收集开发板」的怪圈。一块 STM32 最小系统板 + 面包板 + 杜邦线 + 几个传感器（不到 100 元）足以完成入门阶段 90% 的练习。买十块板不如吃透一块板。

03 嵌入式 C 语言核心

嵌入式 C 与普通 C 的区别

嵌入式 C 直接操作寄存器和内存地址，对资源极度敏感：没有充裕的堆、没有操作系统兜底、 每个字节都要精打细算。以下知识点是嵌入式面试与实战的绝对核心。

① volatile——嵌入式第一关键字

告诉编译器「这个变量随时可能被意想不到地改变，每次都去内存读，别优化」。三大使用场景：

  • 外设寄存器（硬件随时改写）
  • 中断服务程序与主循环共享的变量
  • 多任务共享的全局变量
volatile uint32_t *reg = (uint32_t *)0x40020014;  // 指向 GPIO 寄存器

// 不加 volatile 时，编译器可能把 while 循环优化成
// "读一次后死循环"，加上后每次都真正读内存
while (*reg & 0x01) {          // 等待标志位置零
    // busy wait
}

② 位操作——寄存器的手术刀

// 置位第 3 位（其它位不动）
REG |= (1 << 3);

// 清零第 3 位
REG &= ~(1 << 3);

// 翻转第 3 位
REG ^= (1 << 3);

// 判断第 3 位是否为 1
if (REG & (1 << 3)) { ... }

// 清零低 4 位再赋值（配置寄存器常用）
REG = (REG & ~(0xF << 4)) | (val << 4);
🧠 速记口诀
「置 1 用或，清 0 用与取反，翻转用异或，判断用与」——|、&~、^、& 四兄弟记牢。

③ static 与 extern

用法 作用域 生命周期 典型用途
static 全局变量/函数 仅本 .c 文件 整个程序 模块私有，防止命名污染
static 局部变量 仅本函数 整个程序 函数内记忆状态
extern 变量 跨文件共享 整个程序 在 .h 声明、.c 定义

④ 结构体对齐与 sizeof

struct Bad {
    char  a;    // 1 字节 + 3 字节填充
    int   b;    // 4 字节
    char  c;    // 1 字节 + 3 字节填充
};              // sizeof = 12！浪费 6 字节

struct Good {
    int   b;    // 4 字节
    char  a;    // 1 + 1 + 填充 2
    char  c;
};              // sizeof = 8，省 1/3
⚠️ 避坑提示
对齐规则：成员偏移必须是其自身大小（或 pack 值）的整数倍，总大小是最大成员的整数倍。RAM 只有几十 KB 时，「大成员在前、小成员在后」能实打实省内存；通信协议结构体慎用 #pragma pack 压缩（性能与原子性会受影响）。

⑤ 指针与内存分区

STM32 典型内存布局（Flash 高地址 → 低地址）
┌──────────────┬──────────────────────────┐
│  .data       │ 已初始化全局/静态变量      │
│  .bss        │ 未初始化全局/静态变量(清零)│
│  堆 Heap ↑   │ malloc 从这里向上长       │
│      ...     │ 自由空间                  │
│  栈 Stack ↓  │ 局部变量从 RAM 顶向下长    │
├──────────────┼──────────────────────────┤
│  .text       │ 代码（在 Flash 中）       │
│  .rodata     │ const 常量、字符串         │
└──────────────┴──────────────────────────┘
🚨 经典错误
① 返回局部变量地址（栈帧已销毁）；② 中断里 malloc/printf（不可重入）；③ 数组越界写穿栈；④ 忘记 volatile 导致轮询死循环。嵌入式没有段错误提示，往往直接 HardFault 或复位，排查更难。

⑥ 回调函数与状态机

嵌入式没有丰富的框架，回调 + 状态机就是最常用的「设计模式」： 

// 状态机：按键消抖
typedef enum { KEY_UP, KEY_DOWN } key_state_t;

void key_scan(void) {
    static key_state_t st = KEY_UP;
    static uint8_t cnt = 0;

    switch (st) {
    case KEY_UP:
        if (read_pin() == 0) {          // 检测到按下
            if (++cnt >= 5) st = KEY_DOWN;  // 连续 5 次才确认
        } else cnt = 0;
        break;
    case KEY_DOWN:
        if (read_pin() == 1) { st = KEY_UP; cnt = 0; }
        break;
    }
}

04 开发环境与交叉编译

什么是交叉编译

在 x86 的 PC 上编译出 ARM 平台能运行的代码，就叫交叉编译。 因为目标板资源太少（可能没有屏幕、键盘、甚至跑不动编译器），编译必须在宿主机（Host）完成，产物下载到目标机（Target）运行。 

┌─────────────┐  交叉编译器    ┌─────────────┐
│ 宿主机 Host │ ───────────→ │ 目标机 Target│
│ PC (x86)    │  arm-gcc ...  │ STM32 / 开发板│
│             │ ←───────────  │ 串口打印日志  │
└─────────────┘  串口/SWD调试  └─────────────┘

两条主流工具链

路线 IDE / 工具 编译器 适合人群
MCU 图形化 Keil MDK / STM32CubeIDE armcc / arm-none-eabi-gcc 初学者，点按钮就能编译烧录
Makefile / CMake VSCode + GCC 工具链 arm-none-eabi-gcc 进阶玩家，工程化、可版本管理
嵌入式 Linux Ubuntu + SDK aarch64-linux-gnu-gcc 系统层开发

GCC 交叉编译常用命令

# 编译单个文件（Cortex-M4，软浮点）
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -mfloat-abi=soft \
    -O2 -Wall main.c -o main.o -c

# 链接 + 生成 hex/bin
arm-none-eabi-gcc main.o startup.o -T stm32.ld -o firmware.elf
arm-none-eabi-objcopy -O ihex firmware.elf firmware.hex
arm-none-eabi-objcopy -O binary firmware.elf firmware.bin

# 查看 ELF 信息
arm-none-eabi-readelf -h firmware.elf     # 读头
arm-none-eabi-nm firmware.elf             # 看符号与地址
arm-none-eabi-size firmware.elf           # text/data/bss 大小

编译到运行的完整流程

  1. 预处理（.i）：展开 #include、#define——「文本替换」
  2. 编译（.s）：C → 汇编
  3. 汇编（.o）：汇编 → 机器码目标文件
  4. 链接（.elf）：按链接脚本（.ld）分配地址，合并段
  5. 格式转换（.hex/.bin）：生成烧录文件
  6. 烧录：ST-Link / J-Link / DAP-Link 下载到 Flash
  7. 调试：SWD/JTAG 在线断点调试
🧠 速记口诀
「预编汇链转烧调，七步成环不能少；hex 记地址 bin 纯数据，elf 调试是王道」

烧录与调试器

  • ST-Link：STM32 官方，便宜（十几元），够用
  • J-Link：支持芯片最全、速度快，贵但强
  • DAP-Link / CMSIS-DAP：开源方案，VSCode 生态友好
  • 串口 ISP：不用调试器，Bootloader 进下载模式（出厂最常用）
⚠️ 避坑提示
「芯片连不上」排查三板斧：① 调试器驱动装了吗；② SWDIO/SWCLK/RESET 接线对吗（还共地了吗）；③ 芯片被低功耗或复用关掉了 SWD 引脚吗（用「连接复位模式 Under Reset」救砖）。

05 GPIO 与中断

GPIO 八种模式（以 STM32 为例）

模式 缩写 典型用途
推挽输出 OUTPUT_PP 驱动 LED、控制信号（默认输出）
开漏输出 OUTPUT_OD I2C 总线、电平转换、线与
复用推挽 AF_PP USART/SPI 等外设引脚
复用开漏 AF_OD I2C 外设复用
浮空输入 INPUT_FLOATING 外部信号已确定电平
上拉输入 INPUT_PULLUP 按键检测（默认高，按下低）
下拉输入 INPUT_PULLDOWN 按键（默认低）
模拟输入 ANALOG ADC 采样、低功耗
🧠 速记口诀
「输出推挽最常用，开漏线与配 I2C；输入按键上拉接，模拟采样选 AN」

寄存器点亮 LED（标准库/HAL 之前先懂原理）

// 1. 开 GPIOA 时钟（RCC 寄存器置位）
RCC->AHB1ENR |= (1 << 0);

// 2. 配置 PA5 为输出模式（MODER 第 10~11 位 = 01）
GPIOA->MODER = (GPIOA->MODER & ~(3 << 10)) | (1 << 10);

// 3. 输出低电平点亮 LED（BSRR 写 0 清零对应位）
GPIOA->BSRR = (1 << (5 + 16));  // 置低
// GPIOA->BSRR = (1 << 5);  // 置高

中断：嵌入式的心跳

中断处理完整流程

  1. 外设产生事件 → 中断控制器（NVIC）收到请求
  2. CPU 执行完当前指令，保存现场（自动压栈 xPSR/PC/LR 等）
  3. 查中断向量表找到对应服务函数（ISR）入口
  4. 执行 ISR（越短越好）
  5. 恢复现场，回到被打断处继续执行

外部中断按键（HAL 库风格）

// 初始化：PA0 上升沿中断，带下拉
GPIO_InitTypeDef g = { .Pin = GPIO_PIN_0, .Mode = GPIO_MODE_IT_RISING,
                       .Pull = GPIO_PULLDOWN };
HAL_GPIO_Init(GPIOA, &g);
HAL_NVIC_SetPriority(EXTI0_IRQn, 2, 0);
HAL_NVIC_EnableIRQ(EXTI0_IRQn);

// 中断服务函数：HAL 回调统一入口
void HAL_GPIO_EXTI_Callback(uint16_t pin) {
    if (pin == GPIO_PIN_0) {
        flag_key = 1;          // 只置标志，不做耗时操作！
    }
}
🚨 中断三大铁律
① ISR 越短越好——只置标志/拷数据，业务放主循环；② 不要在 ISR 里用 printf、malloc、delay（不可重入/阻塞）；③ 共享变量必须 volatile，多字节共享要关中断保护。

NVIC 优先级：抢占与子优先级

  • 抢占优先级（Preempt）：数值越小越优先，可以打断正在执行的低优先级中断——「嵌套」
  • 子优先级（Sub）：同时挂起时谁先执行，但不能嵌套
  • STM32 用 4 位分组，常用「全部给抢占」（NVIC_PRIORITYGROUP_4）
🧠 速记口诀
「抢占能嵌套，子级排排队；数字越小事越急，现场保存不能亏」

06 定时器与 PWM

定时器是什么

定时器本质是一个按固定节拍自增的计数器，数到设定值（ARR 自动重装载）就产生更新事件/中断。 它是嵌入式里最重要的外设：延时、PWM、输入捕获、编码器、时间片轮转全靠它。

定时时间计算（必考必用）

// 定时时间 T = (ARR + 1) × (PSC + 1) / TIMxCLK
// 例：72MHz 主频，想 1ms 中断一次
// 72MHz / (PSC+1) = 计数频率；取 PSC = 71 → 1MHz（1μs 数一次）
// 1ms = 1000 次 → ARR = 999

TIM2->PSC = 71;    // 预分频：72MHz/72 = 1MHz
TIM2->ARR = 999;   // 计 1000 次溢出 → 1ms
TIM2->CR1 |= 1;     // 使能计数器
🧠 速记口诀
「PSC 分频定节奏，ARR 装满就溢出；周期等于两者积，除以时钟别记错」——T = (ARR+1)(PSC+1)/f。

PWM：脉宽调制

PWM 用固定频率、可变占空比的方波「模拟」出连续效果：调光、调速、舵机、蜂鸣器、开关电源全靠它。 

占空比 = CCR / (ARR + 1)
CCR=750 → 75% 占空比
        ┌──────┐      ┌──────┐
───────┘      └──────┘      └──  1000 次计数（ARR=999）
|←  750 →|←250 →|

占空比越大 → LED 越亮 / 电机越快 / 平均电压越高

PWM 呼吸灯示例

// TIM3 CH1 (PA6) 输出 20kHz PWM
TIM_OC_InitTypeDef oc = { .OCMode = TIM_OCMODE_PWM1,
                          .Pulse  = 0,
                          .OCPolarity = TIM_OCPOLARITY_HIGH };
HAL_TIM_PWM_ConfigChannel(&htim3, &oc, TIM_CHANNEL_1);
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);

// 主循环：0→999→0 来回扫，实现呼吸效果
int d = 0, dir = 1;
while (1) {
    d += dir;
    if (d >= 999 || d <= 0) dir = -dir;
    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, d);
    HAL_Delay(2);
}

定时器家族分工

类型 特点 典型用途
基本定时器 只能定时中断 时基、DAC 触发
通用定时器 PWM、输入捕获、编码器 电机、测频、超声波
高级定时器 带死区互补输出、刹车 三相电机、H 桥
SysTick Cortex-M 内核自带 24 位 RTOS 心跳、HAL_Delay
看门狗 IWDG 独立时钟，不复位就咬死 程序跑飞自救
⚠️ 避坑提示
① 高级定时器输出 PWM 必须同时使能主输出（MOE 位 / HAL_TIMEx_...）；② HAL_Delay 依赖 SysTick 中断，在 SysTick 优先级更低的中断里调用会死锁；③ 看门狗要在主循环「喂」，不要在定时器中断里喂（否则程序卡在中断里也饿不死狗）。

三大总线一览

维度 UART I2C SPI
线数 2（TX/RX） 2（SCL/SDA） 4（SCK/MOSI/MISO/CS）
速率 ≤ 1Mbps 常见 115200 100k/400k/3.4M 几十 Mbps
拓扑 点对点 一主多从（地址寻址） 一主多从（片选选中）
典型器件 调试串口、GPS、模块 传感器、EEPROM、OLED Flash、屏幕、SD 卡
硬件要求 电平匹配即可 开漏 + 上拉电阻 推挽直连
🧠 速记口诀
「串口两点一对一，I2C 两线带地址，SPI 四线片选快，慢速省线高速 SPI」

UART：万能调试口

  • 帧格式：起始位(1) + 数据位(8) + 校验位(可选) + 停止位(1)
  • 常见坑：波特率不匹配 → 乱码；TX/RX 交叉连接；共地！
  • printf 重定向：重写 fputc（Keil）或 _write（GCC）即可用 printf 调试
// 串口中断接收：收到就存环形缓冲区
void USART1_IRQHandler(void) {
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_RXNE)) {
        uint8_t ch = huart1.Instance->DR & 0xFF;
        ringbuf_put(&rb, ch);          // 环形缓冲，防丢包
    }
}

// 通用帧解析：帧头 0xAA + len + data + 校验和
int frame_parse(uint8_t byte) {
    static uint8_t buf[64], idx = 0, len = 0;
    if (idx == 0 && byte != 0xAA) return -1;  // 等帧头
    buf[idx++] = byte;
    if (idx == 2) len = byte;
    if (idx == len + 3) {              // 收满一帧
        idx = 0;
        return check_sum(buf, idx) ? 0 : -1;
    }
    return -1;
}

I2C：两线带地址

通信时序四步曲

  1. 起始条件：SCL 高时 SDA 由高拉低
  2. 寻址：主发 7 位地址 + 读/写位，从机回 ACK
  3. 数据传输：每字节后跟 ACK/NACK，SCL 高时 SDA 必须稳定
  4. 停止条件：SCL 高时 SDA 由低拉高
⚠️ 避坑提示
① 上拉电阻必须有（4.7kΩ 常用），否则总线拉不高；② 地址 7 位 vs 8 位写法要分清（8 位地址 = 7 位左移一位 + R/W）；③ 总线卡死（从机拉死 SDA）的救法：手动发 9 个 SCL 时钟让从机释放 SDA 再发 STOP。

SPI：四线跑得快

  • CPOL：空闲时钟电平；CPHA：第 1 还是第 2 个边沿采样 → 组成 4 种模式（Mode 0~3）
  • 主从 CS 拉低选中，传输是全双工（发一个字节同时收一个字节）
  • 读 Flash 状态寄存器等场景要发 dummy 字节「换」数据
// SPI 读 W25Q128 Flash 的 JEDEC ID（模式 0，软 CS）
uint8_t spi_rw(uint8_t tx) {
    while (!(SPI1->SR & SPI_SR_TXE));   // 等发送空
    SPI1->DR = tx;
    while (!(SPI1->SR & SPI_SR_RXNE)); // 等接收满
    return SPI1->DR;
}

CS_LOW();
spi_rw(0x9F);                    // 读 ID 命令
uint8_t mid  = spi_rw(0xFF);    // dummy 换回数据
uint8_t type = spi_rw(0xFF);
CS_HIGH();

08 ADC/DAC 与传感器

ADC 核心概念

  • 分辨率：12 位 ADC → 4096 档；量化电压 = Vref / 4096
  • 采样时间：信号源内阻大就加长采样时间，让采样电容充满
  • 参考电压 Vref：精度天花板，最好用独立基准芯片（如 TL431）
  • 采样定理：采样率 ≥ 2 倍信号最高频率（工程上留 5~10 倍）

09 RTOS 与 FreeRTOS

为什么需要 RTOS

裸机的「大 while 循环 + 中断」在任务变多后会陷入回调地狱：任务间时序耦合、 阻塞操作拖垮全局。RTOS 用任务 + 优先级抢占调度把每个业务独立成任务， 实时性由调度器保证——「系统永远在运行最高优先级的就绪任务」。

核心概念

概念 一句话理解
任务（Task） 独立函数 + 私有栈，各有优先级
调度器 抢占式：高优先级就绪立刻抢 CPU
时间片 同优先级任务轮流执行（可关）
信号量 计数器，用于同步与互斥
互斥锁 带优先级继承的二元信号量，保护共享资源
队列 线程安全的消息管道（生产者-消费者）
事件组 多个 bit 的事件标志，可多条件等待
任务通知 轻量级定向通知，比信号量快 45%

多任务数据采集（FreeRTOS 实战模板）

// 队列：传感器任务 → 显示任务
QueueHandle_t xQueueTemp;

void task_sensor(void *arg) {
    float t;
    for (;;) {
        t = read_temperature();
        xQueueSend(xQueueTemp, &t, 0);      // 发队列
        vTaskDelay(pdMS_TO_TICKS(500));        // 500ms 周期
    }
}

void task_display(void *arg) {
    float t;
    for (;;) {
        if (xQueueReceive(xQueueTemp, &t, portMAX_DELAY)) {
            oled_show_temp(t);                   // 阻塞等数据，不空转
        }
    }
}

int main(void) {
    hardware_init();
    xQueueTemp = xQueueCreate(8, sizeof(float));
    xTaskCreate(task_sensor,  "sensor",  256, NULL, 2, NULL);
    xTaskCreate(task_display, "display", 512, NULL, 1, NULL);
    vTaskStartScheduler();                       // 永不返回
}

优先级翻转与优先级继承

经典场景：低优先级任务持有锁 → 高优先级任务等锁 → 中优先级任务抢占低任务 → 高任务反被中任务间接卡住。解决方案：互斥锁（Mutex）自带优先级继承—— 持有者临时继承等锁最高任务的优先级，尽快跑完释放。

🚨 RTOS 三大死法
① 在中断里调用非 FromISR API（必须用 xQueueSendFromISR 等）；② 互斥锁不能在 ISR 用（优先级继承依赖任务上下文）；③ 栈溢出——开 configCHECK_FOR_STACK_OVERFLOW = 2 + 钩子函数捕获。
🧠 速记口诀
「任务优先级抢占忙，队列传信锁护乡；中断要用 FromISR，栈溢出钩子来帮忙」

存储器全家福

类型 特点 典型用途
SRAM 快、贵、断电丢 MCU 内部 RAM（变量/栈/堆）
Flash NOR 随机读快、按块擦写 存代码（片内 Flash / W25Q 系列）
EEPROM 字节级改写、寿命长 配置参数（AT24C02）

Flash 读写铁律：先擦后写、按页写

// STM32 内部 Flash：擦除 Sector → 编程（写入前必须擦）
HAL_FLASH_Unlock();

FLASH_EraseInitTypeDef e = {
    .TypeErase = FLASH_TYPEERASE_SECTORS,
    .Sector    = FLASH_SECTOR_11,
    .NbSectors = 1,
    .VoltageRange = FLASH_VOLTAGE_RANGE_3,
};
uint32_t err;
HAL_FLASHEx_Erase(&e, &err);                 // 整块擦成 0xFF

HAL_FLASH_Program(FLASH_TYPEPROGRAM_WORD,
                  0x080E0000, 0x12345678);  // 按字写入
HAL_FLASH_Lock();
⚠️ 避坑提示
① Flash 只能把 1 写成 0，改写必须先擦；擦的最小单位是页/扇区，写是页/字；② 写参数别用「每次直接写」，用追加 + 标记或磨损均衡（EEPROM 模拟）；③ STM32 运行中擦写自己的 Flash，若代码在同一个 Bank 会停住总线——把擦写代码放 RAM 或双 Bank。

OTA：固件在线升级

双分区（A/B）方案流程

  1. 设备运行在 App 分区 A，检查服务器版本
  2. 下载新固件到 备份分区 B，边收边校验 CRC
  3. 写入升级标志到 EEPROM/备份寄存器，复位
  4. Bootloader 检查标志：有效则搬 B → A（或直接跳 B）
  5. 新固件自检 + 上报版本；失败则回滚旧分区
Flash 布局（双分区方案）
┌───────────────┐ 0x08000000
│  Bootloader   │  负责校验、搬运、跳转
├───────────────┤
│  App 分区 A    │  当前运行固件
├───────────────┤
│  App 分区 B    │  下载暂存区
├───────────────┤
│  参数区        │  标志位、版本、配置
└───────────────┘
🧠 速记口诀
「双区轮流坐庄，下载先校验，标志定去留，失败能回滚」——OTA 四要素：双分区、校验、标志、回滚。

11 低功耗设计

功耗从哪来

  • 动态功耗 ∝ 电压² × 频率 × 翻转率——降频降压最有效
  • 静态/漏电流——休眠时主导，与温度、工艺相关
  • 外设功耗——传感器、无线模块往往比 MCU 本体耗电大得多

STM32 低功耗模式对比

模式 CPU 典型电流 唤醒方式
Sleep 停 几 mA 任意中断
Stop 停，1.8V 域保留 几十 μA EXTI 外部中断
Standby 停，RAM 丢 几 μA WKUP 引脚/RTC/IWDG 复位
Shutdown 全断 几百 nA WKUP/复位

电池供电的温度采集器（周期唤醒模板）

while (1) {
    // ① 唤醒后干活
    sensor_power_on();
    float t = read_temperature();
    sensor_power_off();          // 用完立刻断电！

    lora_send_frame(t);          // 上报

    // ② 配 RTC 闹钟 5 分钟后唤醒
    HAL_RTC_SetAlarm_IT(&hrtc, &alarm5min, RTC_FORMAT_BIN);

    // ③ 进 Stop 模式，等中断唤醒
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);

    SystemClock_Config();        // ④ 唤醒后恢复时钟（关键！）
}
⚠️ 低功耗五大坑
① Stop 唤醒后时钟回落到 HSI，必须重配；② 引脚悬空会「漏电」——未用引脚设模拟输入；③ 调试口 SWD 引脚开着也耗电；④ 上拉电阻上有电平差就有电流（电阻别乱加）；⑤ 万用表测 μA 级要用串联采样电阻 + 示波器看动态波形。
🧠 速记口诀
「降频降压砍动态，休眠断电治漏流；未用引脚设模拟，唤醒先把时钟修」

12 通信协议进阶 CAN/USB/以太网

CAN 总线：汽车的血管

  • 差分两线（CAN_H/CAN_L），抗干扰强，最远 10km@5kbps

  • 错误处理：CRC 校验 + 错误计数器，坏节点自动「离线」隔离

14 设备驱动开发

Linux 驱动的世界观

Linux 驱动的核心思想：「一切皆文件」。应用程序不管底层是 GPIO 还是传感器， 统一用 open / read / write / ioctl / close 系统调用访问设备文件， 驱动负责把系统调用「翻译」成硬件操作。

字符设备驱动骨架（内核模块）

#include <linux/module.h>
#include <linux/fs.h>
#include <linux/cdev.h>

static dev_t devno;
static struct cdev my_cdev;

static ssize_t my_read(struct file *f, char __user *buf,
                        size_t n, loff_t *off)
{
    int val = gpio_get_value(25);      // 读 GPIO 电平
    if (copy_to_user(buf, &val, sizeof(val)))
        return -EFAULT;                   // 拷贝到用户空间
    return sizeof(val);
}

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .read  = my_read,
};

static int __init my_init(void)
{
    alloc_chrdev_region(&devno, 0, 1, "mydev");  // 申请设备号
    cdev_init(&my_cdev, &my_fops);
    cdev_add(&my_cdev, devno, 1);                    // 注册字符设备
    return 0;
}

static void __exit my_exit(void)
{
    cdev_del(&my_cdev);
    unregister_chrdev_region(devno, 1);
}

module_init(my_init);
module_exit(my_exit);

驱动三大子系统速览

子系统 解决什么 关键接口
platform 总线 无总线设备（SoC 内外设）与驱动的匹配 probe / remove、of_match_table
GPIO 子系统 换芯片不用改代码 gpiod_get / gpiod_set_value
input 子系统 按键、触摸统一上报事件 input_report_key / input_sync
⚠️ 驱动开发避坑
① 内核空间不能直接用用户态指针，必须 copy_to_user/copy_from_user；② 驱动崩溃会带崩整个内核（oops/panic），打印用 printk，级别要看 dmesg；③ 「先写用户态模拟，再下沉到内核」能大幅降低调试成本——能用 sysfs/libgpiod 就别急着写内核模块。
🧠 速记口诀
「一切设备皆文件，open read 就能玩；probe 匹配才上电，copy 用户保安全」

15 调试与性能优化

硬件调试三件套

逻辑分析仪

看数字时序（I2C/SPI/UART），几十元的 USB 8 通道足够入门。

示波器

看模拟波形：电平、毛刺、上升沿、PWM 死区。

JTAG/SWD 调试器

断点、单步、看寄存器与内存、HardFault 定位。

HardFault 排查流程（MCU 必备技能）

  1. 调试器暂停，看 PC/LR 落在哪个函数附近
  2. 读 SCB->CFSR：区分总线错误/用法错误/存储错误
  3. 读 SCB->HFSR：FORCED 位说明下层异常升级而来
  4. 出栈看压栈的 PC（异常返回地址）定位出错指令
  5. 常见根因：野指针、栈溢出、未对齐访问、除零、函数指针为空
// HardFault 中断里：手动取压栈的 PC/LR（Cortex-M3/M4）
void HardFault_Handler(void) {
    volatile uint32_t *stk;
    __asm volatile("tst lr, #4      \n"
                 "ite eq          \n"
                 "mrseq %0, msp   \n"
                 "mrsne %0, psp   \n"
                 : "=r"(stk));
    // stk[6]=PC, stk[5]=LR, stk[7]=xPSR —— 打印/断点分析
    while (1);
}

根文件系统方案对比

方案 特点 适合
BusyBox 手工 极小（几 MB），学习原理 入门理解 RootFS
Buildroot 菜单化整体构建，上手快 中小型产品
Yocto 层与配方体系，可维护可复现 大型商业化项目

📌 一句话理解
Buildroot 是「一键套餐」，Yocto 是「中央厨房体系」——前者快速出餐，后者适合长生命周期产品线持续迭代。

init 进程与服务自启动

  • 内核最后启动 /sbin/init（PID 1），读 /etc/inittab 或 systemd
  • BusyBox init：inittab 中 ::sysinit:/etc/init.d/rcS 跑初始化脚本
  • systemd：systemctl enable/disable 管理服务单元
  • 应用开机自启三招：rcS 脚本 / systemd service / inittab respawn（崩溃自动拉起）
🧠 速记口诀
「U-Boot 搬内核，kernel 挂根fs；init 是 PID1，respawn 崩溃能回魂」

核心链路

  2. 定时器 PWM + H 桥驱动电机（高级定时器死区互补）

// 位置式 PID：u = Kp*e + Ki*Σe + Kd*(e-e_last)
typedef struct { float kp, ki, kd, sum, last; } pid_t;

float pid_calc(pid_t *p, float target, float actual) {
    float err = target - actual;
    p->sum += err;
    if (p->sum > 500) p->sum = 500;     // 积分限幅（抗饱和）
    float out = p->kp * err + p->ki * p->sum
               + p->kd * (err - p->last);
    p->last = err;
    return out;
}

18 学习路线与资源

四阶段成长路线

  1. 筑基期（1~2 月）：C 语言强化（指针/位操作/volatile）+ 数电常识 + STM32 裸机外设逐个点亮
  2. 进阶期（2~3 月）：FreeRTOS + 通信协议 + 做完 1~2 个完整项目 + 学会用示波器/逻辑分析仪
  3. 分化期（3~6 月）：选方向深挖——电机控制（FOC）/ 低功耗物联网 / 嵌入式 Linux 驱动 / 汽车电子
  4. 精通期（持续）：系统构建（Yocto）、性能优化、功能安全（MISRA C / ISO 26262）、架构设计能力

方向怎么选

方向 核心技术 特点
物联网 RTOS + 无线协议 + 低功耗 + 云平台 岗位多，门槛适中
电机/电源 PID/FOC、高级定时器、硬件理解 越老越吃香，门槛高
嵌入式 Linux 驱动、内核、BSP、系统构建 天花板高，需求旺盛
汽车电子 Autosar、CAN/LIN、功能安全 薪资高，流程重

学习方法论

  • datasheet 先行：遇到外设问题，第一反应是查参考手册，而不是搜博客
  • 单元验证：每个外设先写最小可运行 demo（打印寄存器值），再集成进项目
  • 量化一切：周期、功耗、内存占用都量出来，优化有据可依
  • 版本管理：从第一个工程就上 Git，外设驱动封装成可复用模块
  • 写博客复盘：踩过的坑写下来，比看十篇教程记得牢
🧠 总口诀
「C 语言打地基，寄存器外设练手感；RTOS 学调度，Linux 见天地；项目复盘加量化，嵌运高手就是你」
📌 最后的话
嵌入式的学习曲线前陡后缓：前 3 个月最痛苦（软硬件问题交织、资料分散），熬过去后每个新芯片、新协议都是「换汤不换药」。核心能力只有一条——面对黑盒问题时的系统性排查能力：分层定位（硬件？驱动？逻辑？），逐段验证，缩小包围圈。这比背 100 个 API 更值钱。
