01 网络安全概述与职业发展

1.1 什么是网络安全

网络安全（Cybersecurity）是指通过技术、管理和法律手段，保护计算机系统、网络、数据和服务免受未经授权的访问、攻击、破坏或泄露。其核心目标可概括为 CIA 三元组：

属性 英文 含义 典型威胁
机密性 Confidentiality 信息不被未授权者获取 数据泄露、窃听
完整性 Integrity 数据不被非法篡改 中间人篡改、勒索病毒
可用性 Availability 服务和数据随时可访问 DDoS 攻击、硬件故障

在此基础上，现代安全还扩展了可认证性（Authenticity）、不可否认性（Non-repudiation）和可控性（Controllability）。

1.2 网络安全的领域划分

  • 网络基础设施安全：防火墙、IDS/IPS、VPN、网络隔离
  • 终端安全：杀毒软件、EDR、主机加固、移动设备管理
  • 应用安全：Web 安全、代码审计、API 安全、移动 App 安全
  • 数据安全：加密、DLP、数据分类分级、备份恢复
  • 身份与访问管理（IAM）：SSO、MFA、零信任、最小权限
  • 云安全：云配置审计、容器安全、Serverless 安全
  • 安全运营：SOC、SIEM、威胁情报、应急响应

1.3 网络安全职业方向

1.4 学习路线图

网络安全的学习路径建议分为四个阶段：

  1. 基础阶段：计算机网络 → 操作系统（Linux/Windows）→ Web 基础 → 编程语言（Python）
  2. 入门阶段：HTTP 协议 → Web 漏洞原理 → 常用安全工具 → 简单渗透测试
  3. 进阶阶段：内网渗透 → 密码学 → 逆向工程 → 云安全 → 二进制漏洞
  4. 专业阶段：选定方向深入（红队/蓝队/研究/架构）→ 实战演练 → CTF → 行业认证
学习建议：不要一上来就用工具"跑漏洞"。先花 2-3 个月打好网络和系统基础，理解协议和原理，后期学漏洞会事半功倍。

  • 入门级：CompTIA Security+、CEH（道德黑客）
  • 进阶级：OSCP（渗透测试黄金认证）、CISSP（安全管理）

2.2 TCP 三次握手与四次挥手

TCP 是面向连接的可靠传输协议，理解握手和挥手过程是分析端口扫描和 DoS 攻击的基础。

三次握手（建立连接）

客户端                    服务端
  |--- SYN, seq=x ------->|   (1) 客户端发送 SYN
  |                        |
  |<-- SYN, ACK, seq=y, ack=x+1 ---|   (2) 服务端回复 SYN+ACK
  |                        |
  |--- ACK, ack=y+1 ------>|   (3) 客户端回复 ACK
  |                        |
  |===== 连接建立 =========|

四次挥手（断开连接）

客户端                    服务端
  |--- FIN, seq=u ------->|   (1) 主动关闭方发送 FIN
  |<-- ACK, ack=u+1 ------|   (2) 被动方回复 ACK
  |                        |   (被动方可能还有数据要发送)
  |<-- FIN, seq=v ---------|   (3) 被动方发送 FIN
  |--- ACK, ack=v+1 ------>|   (4) 主动方回复 ACK
  |                        |
  |===== 连接断开 =========|

2.6 ARP 协议与欺骗原理

ARP（地址解析协议）用于将 IP 地址解析为 MAC 地址。由于 ARP 无状态、不认证，攻击者可发送伪造的 ARP 应答实现中间人攻击。 

# 查看 ARP 缓存
arp -a
ip neigh show

# ARP 欺骗原理（使用 arpspoof）
arpspoof -i eth0 -t 192.168.1.100 192.168.1.1

# 开启 IP 转发（Linux）
echo 1 > /proc/sys/net/ipv4/ip_forward

# 防御：静态 ARP 绑定 / DAI（动态 ARP 检测）
arp -s 192.168.1.1 aa:bb:cc:dd:ee:ff

3.1 Linux 安全基础

用户与权限管理

# 用户管理
useradd -m -s /bin/bash alice    # 创建用户
passwd alice                     # 设置密码
usermod -aG sudo alice           # 加入 sudo 组

# 文件权限

# 查看 SUID/SGID 文件（提权排查）
find / -perm -4000 -type f 2>/dev/null
find / -perm -2000 -type f 2>/dev/null

# sudo 配置
visudo
# alice ALL=(ALL) NOPASSWD: /usr/bin/apt

Linux 提权常见路径

  • 内核漏洞：Dirty COW (CVE-2016-5195)、PwnKit (CVE-2021-4034)
  • SUID 程序：查找 find / -perm -4000，利用 GTFOBins
  • sudo 配置错误：sudo -l 查看可执行的特权命令
  • 计划任务：/etc/crontab、/var/spool/cron/
  • 可写的 /etc/passwd：直接添加 root 权限用户
  • capability 配置不当：getcap -r / 2>/dev/null

4.4 HTTPS 与 TLS

HTTPS = HTTP + TLS/SSL，提供加密传输、身份认证和完整性保护。

  • TLS 1.2：目前广泛支持，推荐配置
  • TLS 1.3：最新标准，更快更安全（1-RTT 甚至 0-RTT）
  • SSL 3.0/TLS 1.0/1.1：已废弃，存在 POODLE、BEAST 等漏洞 
# 测试目标 TLS 配置
nmap --script ssl-enum-ciphers -p 443 example.com

# 使用 openssl 测试连接
openssl s_client -connect example.com:443 -tls1_2
openssl s_client -connect example.com:443 -tls1_3

# 检查证书信息
openssl x509 -in cert.pem -text -noout

4.5 同源策略与 CORS

同源策略（Same-Origin Policy）是浏览器最核心的安全机制，协议+域名+端口三者相同才为同源。CORS（跨域资源共享）是放宽同源策略的机制。

危险配置：Access-Control-Allow-Origin: * 配合 Access-Control-Allow-Credentials: true 会导致任意网站可携带用户凭证跨域访问，是严重漏洞。

05 安全法律法规与道德规范

5.1 中国网络安全法律体系

法律 实施时间 核心要点
《网络安全法》 2017-06-01 网络运营者安全义务、关键信息基础设施保护、个人信息保护、网络安全等级保护
《数据安全法》 2021-09-01 数据分类分级、重要数据保护、数据出境安全评估、数据交易监管
《个人信息保护法》 2021-11-01 告知同意原则、最小必要原则、个人权利（查阅/删除/可携带）、跨境传输
《密码法》 2020-01-01 核心密码/普通密码/商用密码分类管理
《关键信息基础设施安全保护条例》 2021-09-01 CII 识别、运营者责任、年度检测评估

5.2 刑法相关条款

  • 第 285 条：非法侵入计算机信息系统罪、非法获取计算机信息系统数据罪、非法控制计算机信息系统罪
  • 第 286 条：破坏计算机信息系统罪（包括植入病毒、DDoS 等）
  • 第 287 条：利用计算机实施金融诈骗、盗窃等犯罪
  • 第 253 条之一：侵犯公民个人信息罪
法律红线：未经授权对任何系统进行扫描、渗透、漏洞测试均属违法。即使"只是看看"，只要进入了计算机信息系统或获取了数据，就可能触犯刑法第 285 条。务必在书面授权范围内开展安全测试。

5.3 等保 2.0

网络安全等级保护（等保）是中国网络安全的基本制度：

  • 第一级：自主保护（一般损害）
  • 第二级：指导保护（严重损害）— 多数企业系统
  • 第三级：监督保护（特别严重损害）— 重要系统，需每年测评
  • 第四级：强制保护（极其严重损害）— 关键信息基础设施
  • 第五级：专控保护 — 国家级核心系统

5.4 白帽道德规范

  • 获得书面授权后再测试，明确测试范围和时间窗口
  • 不下载、不泄露、不篡改目标数据，验证漏洞后立即停止
  • 不使用影响业务的测试手段（如 DDoS、社工真实员工）
  • 漏洞通过负责任披露渠道报告，给厂商合理修复时间
  • 遵守《网络安全法》和平台漏洞披露规则（如 CNVD、CNNVD）
  • 不利用已发现的漏洞谋取私利或进行勒索

5.5 国际法规与框架

  • GDPR（欧盟通用数据保护条例）：全球最严格的数据保护法规，最高罚款全球营收 4%
  • CCPA（加州消费者隐私法）：消费者数据知情权和删除权
  • ISO 27001：信息安全管理体系（ISMS）国际标准
  • NIST CSF：美国国家标准与技术研究院网络安全框架（识别/保护/检测/响应/恢复）
  • MITRE ATT&CK：对抗战术与技术知识库，已成为行业标准

7.3 渗透测试标准流程

渗透测试是在授权条件下模拟攻击者评估系统安全性的过程。标准流程如下：

  1. 前期交互（Pre-engagement）：确定范围、目标、时间窗口、授权书、测试类型
  2. 情报收集（Reconnaissance）：被动收集 + 主动扫描，梳理攻击面
  3. 威胁建模（Threat Modeling）：分析资产价值、可能的攻击路径
  4. 漏洞分析（Vulnerability Analysis）：自动化扫描 + 手动验证
  5. 渗透利用（Exploitation）：验证漏洞、获取访问权限
  6. 后渗透（Post-exploitation）：提权、横向移动、权限维持、数据获取
  7. 报告（Reporting）：漏洞详情、风险等级、修复建议、复测验证

7.4 渗透测试类型

类型 测试者已知信息 模拟场景 优点 缺点
黑盒测试 无内部信息 外部攻击者 真实模拟外部攻击 覆盖面有限、耗时
白盒测试 完整内部信息（源码、架构、凭证） 内部人员/代码审计 覆盖率高、发现深层问题 不模拟真实攻击
灰盒测试 部分信息（低权限账号） 普通用户提权 平衡真实性和深度 —

7.5 漏洞验证与 PoC

扫描器发现的漏洞必须手动验证，排除误报。验证时遵循最小影响原则：

# SQL 注入验证（布尔盲注）
http://example.com/news?id=1 AND 1=1  → 正常页面
http://example.com/news?id=1 AND 1=2  → 异常/空页面

# XSS 验证（使用唯一标识，不弹 alert）
http://example.com/search?q=<svg onload=console.log(document.domain)>

# 命令注入验证（DNS 外带，不执行危险命令）

# SSRF 验证（访问内网元数据服务）

openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -pubout -out public.pem

# RSA 加解密
openssl rsautl -encrypt -inkey public.pem -pubin -in data.txt -out enc.bin

9.4 哈希与密码存储

# 哈希算法
# MD5     — 128 位，已不安全（碰撞攻击）
# SHA-1   — 160 位，已不安全（SHAttered）
# SHA-256 — 256 位，当前推荐
# SHA-3   — 最新标准，不同结构
# BLAKE2  — 高性能替代

# 计算哈希
echo -n "password" | sha256sum
echo -n "password" | md5sum
hashcat -m 0 hash.txt wordlist.txt    # MD5 破解
hashcat -m 1000 hash.txt wordlist.txt # NTLM 破解
hashcat -m 2500 capture.hccapx wordlist.txt  # WPA2

# 密码安全存储（重要！）
# ❌ 错误：直接存 MD5/SHA256（可彩虹表破解）
# ✅ 正确：使用专门密码哈希算法

# bcrypt（自带盐，可调成本因子）
import bcrypt
hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12))
bcrypt.checkpw(password.encode(), hashed)

# Argon2（密码哈希竞赛冠军，当前最推荐）
from argon2 import PasswordHasher
ph = PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4)
hash = ph.hash("password")
ph.verify(hash, "password")

# PBKDF2（系统内置，无需额外库）
import hashlib
dk = hashlib.pbkdf2_hmac('sha256', password, salt, 100000)

10 网络攻击与防御

10.1 DoS / DDoS 攻击

拒绝服务攻击通过耗尽目标资源使其无法正常服务。DDoS 是分布式版本，利用大量傀儡机同时攻击。

层次 攻击类型 原理 防御
网络层 SYN Flood 发送大量 SYN 不完成握手 SYN Cookies、连接数限制
网络层 UDP Flood 大量 UDP 包占满带宽 带宽清洗、ACL
网络层 ICMP Flood (Smurf) 大量 ping 包 禁止 ICMP、限速
放大攻击 DNS/NTP/Memcached 伪造源 IP，利用小请求获得大响应 关闭开放递归、源认证
应用层 HTTP Flood (CC) 大量合法 HTTP 请求 WAF、验证码、频率限制
应用层 Slowloris 慢速发送占满连接池 超时设置、反向代理

10.2 中间人攻击（MITM）

# 常见 MITM 技术

16.1 应急响应流程

16.5 数字取证

数字取证（Digital Forensics）是科学地收集、保全、分析和呈现数字证据的过程。

  • 取证原则：保全原始证据、记录完整链条（Chain of Custody）、最小化改动

16.6 勒索软件应急

  1. 立即隔离：断开受感染主机网络（不要关机，保留内存证据）
  2. 确定范围：识别感染主机数量、加密文件类型、勒索信内容
  3. 识别家族：加密文件扩展名、勒索信样式，上传 ID Ransomware 识别
  4. 阻断传播：禁用共享、关闭 SMBv1、隔离 VLAN、修改所有密码
  5. 清除恢复：重装系统 → 恢复备份（离线备份）→ 部署 EDR → 补丁更新
  6. 报告：72 小时内向有关部门报告（《网络安全法》要求）
不要支付赎金：支付赎金不保证恢复数据，还会助长犯罪。优先从离线备份恢复，使用 No More Ransom 项目的免费解密工具。

18 安全架构设计与职业规划

18.1 零信任架构

零信任（Zero Trust）的核心原则：从不信任，始终验证（Never Trust, Always Verify）。不依赖网络边界，每次访问都需要认证和授权。

传统边界安全 零信任安全
内网即可信 内外网均不可信
一次认证，全网通行 每次访问都验证
基于网络位置授权 基于身份和上下文授权
粗粒度访问控制 最小权限 + 微隔离
静态策略 动态风险评估

零信任关键组件

  • 身份中心：统一身份（SSO + MFA），人的身份是新边界
  • 设备信任：设备合规状态检查（补丁、加密、EDR）
  • 持续验证：每次请求认证，非一次性登录
  • 微隔离：工作负载间细粒度访问控制（不是网络可达就能访问）
  • 动态策略：结合用户角色、设备状态、位置、行为风险动态决策

18.2 纵深防御

纵深防御（Defense in Depth）使用多层安全控制，任何单层失效不会导致整体失守。

# │ 数据安全：加密、DLP、备份     │
# ├─────────────────────────────┤
# │ 身份安全：MFA、IAM、零信任    │
# ├─────────────────────────────┤
