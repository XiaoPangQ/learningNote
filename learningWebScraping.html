第一篇：入门篇（打地基）

1.爬虫是什么

一句话：爬虫（网络爬虫 / Web Crawler）是一段**自动从网页上批量抓取数据**的程序。

爬虫像你派了个「机器人助理」去网站：帮你打开网页 → 找到你要的信息 → 抄下来 → 带回来整理成表格。手动抄 100 页要一天，爬虫几秒搞定。

爬虫的四个步骤（牢记，贯穿全文）

步骤 动作 对应工具
① 发起请求 向网页要数据 requests
② 获取响应 拿到网页 HTML/JSON response.text / json()
③ 解析数据 从 HTML 里抠出内容 正则 / BeautifulSoup / XPath
④ 保存数据 存到文件或数据库 CSV / Excel / SQLite
务必先知道：爬虫本身是技术，但爬取不当可能违法。三条底线：① 不爬个人隐私/账号数据；② 不绕过付费墙、不攻击服务器（高并发 DDoS）；③ 遵守 robots.txt 和网站服务条款。更多见第 21 节。
请求响应再解析，最后保存四步走； 爬虫技术本中立，合法合规是前提。

2.HTTP 基础

爬虫本质是在和网站「说 HTTP 话」。懂一点 HTTP，遇到问题才看得懂报错。

HTTP 像「点菜」：你（客户端）拿着菜单（URL）对服务员（服务器）说「给我来一份首页」，服务员按你的要求（请求头）上菜（响应），并告诉你这道菜的状态（状态码）。

核心三要素

要素 说明 示例
URL 网址，定位资源 https://example.com/news
方法 Method GET 取数据 / POST 提交 GET、POST
请求头 Headers 附带的信息（身份、浏览器） User-Agent、Cookie

必背状态码

状态码 含义 爬虫常见场景
200 成功 正常拿到数据
301/302 重定向 页面跳转了
403 禁止访问 被反爬拦截了
404 找不到 URL 写错
418/429 被识别/限流 请求太频繁了
500 服务器错误 网站挂了
二百成功，三百跳转，四百客户端，五百服务器。

3.requests 库入门

requests 是 Python 最常用的 HTTP 库，发请求简单到一行。

安装：pip install requests

import requests

# 1. 发起 GET 请求
resp = requests.get('https://example.com')

# 2. 看状态码
print(resp.status_code)      # 200

# 3. 获取内容（两种）
print(resp.text)             # 字符串（HTML 源码）
print(resp.content)          # 字节（图片/文件用这个）

# 4. 带参数请求
resp = requests.get('https://api.example.com/search',
                    params={'q': 'python', 'page': 1})
print(resp.url)  # 看拼接后的地址
print(resp.json())  # 响应是 JSON 时直接转字典

GET 与 POST

方法 用途 参数放哪
GET 取数据（搜索、浏览） params（拼到 URL 后面）
POST 提交数据（登录、表单） data 或 json（放请求体） 
# POST 提交表单
resp = requests.post('https://example.com/login',
                     data={'username': 'tom', 'password': '123'})

一定要加超时

不加 timeout，遇到卡死的网站会永远等下去。养成习惯：requests.get(url, timeout=10)。

4.正则表达式

正则 = 一套「匹配字符串模式」的规则，用来从 HTML 文本里抠数据。HTML 很规整时好用，太复杂就别硬来（改用第 5 节 BeautifulSoup）。

高频元字符

符号 含义 示例
. 任意字符（除换行） a.c 匹配 abc
* 前一个重复 0 到多次 ab* 匹配 a、ab、abb
+ 前一个重复 1 到多次 ab+ 匹配 ab、abb
? 前一个 0 或 1 次 colou?r 匹配 color/colour
\d 数字 \d+ 匹配一串数字
\w 字母数字下划线 \w+ 匹配单词
[abc] 字符集 匹配 a 或 b 或 c
( ) 分组，用来「抓取」 (\d+) 提取数字
.*? 非贪婪，尽量少匹配 爬虫最爱用 
import re

html = '<title>今日新闻</title>'

# 用分组 () 抓取标签里的内容
m = re.search(r'<title>(.*?)</title>', html)
print(m.group(1))  # 今日新闻

# 抓取所有数字
text = '价格 99 元，销量 1200 件'
print(re.findall(r'\d+', text))  # ['99', '1200']
点星问加元字符，\d\w 记牢靠； 括号分组来抓取，.*? 非贪婪。

5.BeautifulSoup 解析

BeautifulSoup（bs4）：把 HTML 变成可查询的「树」，用 find / select 精准定位元素，比正则好维护。

安装：pip install beautifulsoup4 lxml 

from bs4 import BeautifulSoup
import requests

html = requests.get('https://example.com').text
soup = BeautifulSoup(html, 'lxml')   # 解析成树

# 1. 按标签找（第一个）
title = soup.find('h1')
print(title.text)

# 2. 按 class / id 找
box = soup.find('div', class_='content')   # 注意 class 后要加下划线

# 3. CSS 选择器（最推荐，前端同学友好）
items = soup.select('ul.list > li')          # 找所有 li
for li in items:
    print(li.text.strip())

# 4. 找多个 + 取属性
links = soup.find_all('a')
for a in links:
    print(a.get('href'))                      # 取链接
    print(a.text.strip())                     # 取文字

常用选择对照

需求 方法
找第一个 soup.find('标签')
找所有 soup.find_all('标签')
CSS 选择器 soup.select('#id .class')
取文字 元素.text
取属性 元素.get('href')
两个坑：① class 是 Python 关键字，要写成 class_；② 用 CSS 选择器时 select_one 返回第一个，select 返回列表。

6.JSON 数据处理

很多网站数据不是 HTML，而是通过接口返回 JSON（本质就是 Python 的字典/列表）。这种反而最好爬。 

import requests

resp = requests.get('https://api.example.com/data')
data = resp.json()   # 直接转成字典/列表

# JSON 结构里取数据：一层层用键
items = data['data']['list']
for it in items:
    print(it['title'], it['price'])
HTML 像「已经摆盘上桌的菜」，要挑菜叶子（解析）；JSON 像「后厨直接给的食材清单」，拿来就能用，干净又省事。

怎么找到 JSON 接口？

  1. 打开浏览器 F12（开发者工具）→ Network（网络）标签。
  2. 刷新页面，找 XHR / Fetch 类型的请求。
  3. 点进去看 Response（响应），是 JSON 就赚到了——直接 requests 模拟这个接口即可。
HTML 要解析，JSON 拿来就用； F12 找接口，爬虫省一半。

7.第一个完整爬虫

把前面四步串起来，写一个抓取「某网站标题」的完整示例（用 httpbin 这种练习站最安全）。 

import requests
from bs4 import BeautifulSoup
import time

def fetch_page(url):
    # 伪装浏览器 + 超时
    headers = {'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64)'}
    resp = requests.get(url, headers=headers, timeout=10)
    resp.raise_for_status()   # 状态码非 200 直接报错
    return resp.text

def parse(html):
    soup = BeautifulSoup(html, 'lxml')
    titles = [a.text.strip() for a in soup.select('h2')]
    return titles

def save(data, filename='result.txt'):
    with open(filename, 'w', encoding='utf-8') as f:
        f.write('\n'.join(data))

if __name__ == '__main__':
    url = 'https://example.com'
    html = fetch_page(url)
    titles = parse(html)
    save(titles)
    print(f'抓取完成，共 {len(titles)} 条')
    time.sleep(1)   # 礼貌爬取：稍作停顿
好习惯清单：① 加 User-Agent 伪装；② 加 timeout；③ 加 try/except 容错；④ 加 sleep 别把别人服务器打挂；⑤ 尊重 robots.txt。
第二篇：进阶篇（更高效）

8.XPath 与 lxml

XPath = 一套在 XML/HTML 里「按路径」找节点的语法，速度快、表达能力强。

安装：pip install lxml

from lxml import html as lh

doc = lh.fromstring(html_text)

# 常用 XPath 写法
titles = doc.xpath('//h2/text()')                # 所有 h2 的文字
hrefs  = doc.xpath('//a/@href')                  # 所有 a 的链接
first  = doc.xpath('//div[@class="box"]/p/text()') # 按属性筛选

XPath 速查

语法 含义
//div 任意层级的 div
/div/p 直接子级路径
[@class="x"] 属性筛选
/text() 取文字
/@href 取属性值
//li[1] 第 1 个 li
contains(@class,'x') 属性包含
BeautifulSoup 好懂、XPath 好写。新手：简单用 bs4，复杂结构、追求速度用 XPath。

9.请求头与反爬基础

很多网站靠「你是不是真人浏览器」来判断要不要拦你。最简单对策：带上完整请求头。 

headers = {
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36',
    'Referer': 'https://example.com/',   # 从哪个页面跳来的
    'Accept-Language': 'zh-CN,zh;q=0.9',
}
resp = requests.get(url, headers=headers, timeout=10)
请求头 作用
User-Agent 告诉服务器你是什么浏览器
Referer 来源页，防爬图片/盗链常用
Cookie 身份凭证（登录态）
X-Requested-With 标记是否 Ajax 请求
User-Agent 是基础中的基础，但只靠它不够。真正的反爬是多方位的（IP 频率、行为、验证码），见第 17、19 节。

10.会话与 Cookie 登录

登录后才能看的页面，需要带上「登录凭证」。用 Session 自动保存 Cookie，全程保持登录态。

Cookie 像「游乐园手环」。你买票（登录）后戴上，之后每个项目（请求）只要抬手亮手环（自动带 Cookie）就能进，不用反复买票。 
import requests

s = requests.Session()   # 关键：用会话保持 Cookie

# 1. 先登录（POST 提交账号密码）
login_data = {'username': 'tom', 'password': '123456'}
s.post('https://example.com/login', data=login_data)

# 2. 再访问需要登录的页面，自动带上 Cookie
resp = s.get('https://example.com/profile')
print(resp.text)

Cookie 两种处理方式

方式 场景
Session 自动管理 正常登录流程（推荐）
手动复制 Cookie 字符串 自己账号已登录，直接 F12 复制 Cookie 填进 headers
⚠️ 用 Cookie 爬取自己账号允许的数据没问题；但爬取他人隐私数据、批量注册账号等是违法的，坚决不做。

11.分页与翻页爬取

列表数据通常分多页，关键是找出页码规律，用循环抓全。 

import requests
from bs4 import BeautifulSoup

def get_page(page):
    url = f'https://example.com/list?page={page}'   # 页码拼进 URL
    return requests.get(url, timeout=10).text

all_data = []
for page in range(1, 11):          # 抓 1~10 页
    html = get_page(page)
    soup = BeautifulSoup(html, 'lxml')
    for item in soup.select('.item'):
        all_data.append(item.text.strip())
    print(f'第 {page} 页完成')
三种翻页形态别搞混：① URL 带页码（?page=2，最好爬）；② 滚动加载（下拉才出数据，要找接口）；③ 「下一页」按钮（循环提取下一页链接直到没有）。
抓取要留神：加 time.sleep(1) 间隔，别几十页连打把对方服务器冲垮。

12.多线程多进程加速

爬虫大部分时间在「等网络」。单线程像一个人排队打水，多线程 = 好几个人同时打水，能数倍提速。

单线程：一个人挨个去 10 家店买咖啡。多线程：雇 10 个人同时各去一家店，总时间≈最慢的那家。 
import requests
from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    return requests.get(url, timeout=10).status_code

urls = ['https://example.com'] * 20   # 20 个任务

# 开 5 个线程同时爬
with ThreadPoolExecutor(max_workers=5) as pool:
    results = pool.map(fetch, urls)
    print(list(results))
方案 适用 注意
多线程 threading IO 密集（网络请求） ✅ 爬虫首选
多进程 multiprocessing CPU 密集（大量计算） 爬虫少用
线程池 ThreadPoolExecutor 任务量大 ✅ 简单好用
多线程不是越多越快——开太多会被网站封 IP。合理控制并发数（一般 5~10），并控制频率。

13.异步 asyncio + aiohttp

比多线程更省资源的「并发」方案：单线程内用协程，等待时不占用线程，能同时开几百上千个请求。

安装：pip install aiohttp

import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as resp:
        return resp.status

async def main():
    urls = ['https://example.com'] * 100
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, u) for u in urls]
        results = await asyncio.gather(*tasks)
    print(len(results))

asyncio.run(main())
为什么异步快？多线程靠「多个人」，异步靠「一个人同时等很多个」。等待时 CPU 去干别的，几乎不浪费，所以能轻松扛上千并发。
选择：数据量几百页 → 多线程够用；需要成百上千并发 → 上 aiohttp。异步代码难一点，先吃透再上。

15.Selenium 动态渲染

有些页面数据是 JS 动态渲染的，requests 拿到的是空壳。这时用 Selenium 驱动真实浏览器，等页面渲染完再抓。

安装：pip install selenium（还需浏览器驱动） 

from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome()          # 打开浏览器
driver.get('https://example.com')

# 等元素出现再取
title = driver.find_element(By.CSS_SELECTOR, 'h1').text
items = driver.find_elements(By.CSS_SELECTOR, '.item')
for it in items:
    print(it.text)

driver.quit()   # 用完记得关
定位方式 示例
CSS 选择器 By.CSS_SELECTOR, '.class'
XPath By.XPATH, '//div[@id="x"]'
文本 By.LINK_TEXT, '下一页'
Selenium 慢、耗资源、易被反爬识别，只适合「少量动态页」。现代项目更推荐第 16 节的 Playwright。

16.Playwright 自动化

Playwright 是微软出的现代浏览器自动化工具，比 Selenium 更快、更稳、功能更强（可拦截网络、等待更智能）。

安装：pip install playwright 然后 playwright install 

from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)   # headless 无界面
    page = browser.new_page()
    page.goto('https://example.com')
    page.wait_for_selector('.item')              # 等元素出现

    titles = page.locator('.item').all_text_contents()
    print(titles)
    browser.close()
Playwright 杀手锏：能拦截接口响应直接拿 JSON，能模拟点击、输入、滚动，是动态页爬取的现代首选。

17.反爬与应对

反爬是「网站拦你」和「你设法正常抓」的博弈。常见反爬手段及对策：

反爬手段 现象 对策
User-Agent 校验 403 带真实 UA
IP 频率限制 429 / 封 IP 降速 + IP 代理池
验证码 弹验证码 打码平台 / 降低频率 / 手动
登录校验 跳登录页 Session + Cookie
JS 动态渲染 拿到空 HTML Playwright / 找接口
浏览器指纹 识别自动化 Playwright 隐藏特征

IP 代理示例

proxies = {'http': 'http://127.0.0.1:7890', 'https': 'http://127.0.0.1:7890'}
resp = requests.get(url, proxies=proxies, timeout=10)
应对反爬要克制：降低频率、尊重对方是最优解。过度对抗（撞验证码、暴力破解）可能触碰法律。

18.Scrapy 框架

当爬虫规模变大（几百个站点、几百万数据），手写 requests 太累。用 Scrapy 框架统一管理：调度、下载、解析、去重、持久化一条龙。

安装：pip install scrapy

# 命令行创建项目
scrapy startproject myproject
scrapy genspider example example.com
# spiders/example.py（核心爬虫逻辑）
import scrapy

class ExampleSpider(scrapy.Spider):
    name = 'example'
    start_urls = ['https://example.com']

    def parse(self, response):
        for title in response.css('h2::text').getall():
            yield {'title': title}   # 产出数据，自动存
Scrapy 自带的去重、并发、pipeline、中间件非常完善，是企业级爬虫标准方案。中小项目 requests 够用，大项目上 Scrapy。

19.反爬破解思路

遇到爬不到，按这个「排查顺序」走，能解决 90% 问题：

  1. 先看状态码：403 带 UA；429 降速；404 查 URL。
  2. 比对请求头：F12 把浏览器真实请求头全复制过来。
  3. 看是不是动态渲染：F12 找 XHR 接口，直接 requests 那个接口。
  4. 看是不是要登录：Session 或复制 Cookie。
  5. 看是否限 IP：降速 + sleep + 代理。
  6. 最后才是 Playwright 模拟真实浏览器。
先状态后请求，再接口再登录； 降速加代理，最后上浏览器。

爬下来的数据常常有空格、重复、格式乱，需要清洗。

# 去空格、去空行
clean = [t.strip() for t in raw if t.strip()]

# 列表去重（保序）
seen = set()
unique = []
for x in data:

# 用 pandas 更省事
import pandas as pd

21.法律红线与 robots.txt

三条铁律（务必遵守）：① 不爬个人隐私、账号密码、通讯录等敏感数据；② 不绕过付费墙、不攻击服务器、不搞高并发 DDoS；③ 遵守 robots.txt 和网站条款。违法的典型：爬取公民个人信息、破解登录、破坏计算机信息系统。

robots.txt

网站根目录的 robots.txt 声明了「哪些可以爬、哪些不让爬」。礼貌的爬虫会先看它。 

# 访问 https://example.com/robots.txt 常见内容
User-agent: *        # 对所有爬虫
Disallow: /admin/    # 禁止爬 /admin/
Disallow: /private/  # 禁止爬 /private/
Allow: /public/      # 允许爬 /public/
robots.txt 是「君子协定」不是法律，但遵守它是基本礼仪；而爬取隐私/攻击服务器则直接违法，两者性质完全不同。
