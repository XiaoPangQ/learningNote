01嵌入式基础与行业认知

Q1什么是嵌入式系统？它的核心特征是什么？🔥 高频

嵌入式系统是以应用为中心、以计算机技术为基础、软硬件可裁剪，对功能、可靠性、成本、体积、功耗有严格要求的专用计算机系统。

  • 本质：软件固化在硬件里的专用计算机，藏在设备内部「看不见的电脑」
  • 组成：嵌入式处理器（CPU/MCU）+ 外围硬件 + 嵌入式软件（裸机 / RTOS / Linux）+ 交叉开发环境
  • 四大特征：专用性（按应用定制）、资源受限（内存/存储/功耗小）、实时性（对外部事件及时响应）、软硬结合（要懂寄存器与电路）
  • 例子：手机、路由器、汽车 ECU、智能手表、冰箱控制器、无人机飞控、工业 PLC
「看不见的电脑，按需裁剪，讲究快、省、稳」——应用中心 + 可裁剪 + 三约束（功能/功耗/成本）
Q2嵌入式系统和通用计算机有什么区别？🔥 高频
对比项嵌入式系统通用计算机（PC）
用途专用，为特定功能定制通用，各种软件都能跑
资源存储/内存小，KB~MB 级大，GB~TB 级
实时性强，微秒级响应要求弱，不保证硬实时
功耗毫瓦~瓦级，常电池供电几十瓦~几百瓦
开发交叉编译，软硬联调本机编译运行
升级多为 OTA 远程升级或现场烧录随时装软件

一句话：PC 是「什么都能干的通用工具」，嵌入式是「专精一件事的定制机器」。

「专用省电还实时，通用全能耗电高」
Q3MCU、MPU、SoC 有什么区别？🔥 高频
  • MCU（微控制器）：CPU + 片上 Flash + SRAM + 丰富外设（GPIO/定时器/ADC/UART/I2C/SPI），单芯片跑裸机或 RTOS，如 STM32、GD32、AVR
  • MPU（微处理器）：纯 CPU 核心，无或少片上存储，需外挂 DDR + Flash，跑嵌入式 Linux 等复杂 OS，如 i.MX6ULL、RK3568、树莓派芯片
  • SoC（片上系统）：MPU + GPU/DSP/NPU/基带等专用模块集成在单芯片，强调多媒体与 AI 算力，如高通骁龙、海思麒麟、全志 V3s

选型口诀：简单控制用 MCU，跑系统用 MPU，要算力多媒体用 SoC。

「MCU 全家桶一芯跑裸机，MPU 光杆司令外挂内存，SoC 全家桶加装 GPU 算力」
Q4Cortex-M、Cortex-A、Cortex-R 系列各有什么特点？怎么选？🔥 高频
系列定位特点典型场景
Cortex-M微控制器低功耗、中断快、指令精简、价格低家电、电机、传感器、TWS 耳机
Cortex-R实时处理器硬实时 + 高可靠，容错、锁步核汽车制动、硬盘控制器、基站
Cortex-A应用处理器高性能、MMU、可跑 Linux/Android手机、平板、网关、HMI 大屏
  • M 追求省（功耗/成本），R 追求稳（实时/可靠），A 追求强（性能/生态）
  • 是否带 MMU 是分水岭：M/R 一般无 MMU 跑裸机/RTOS，A 有 MMU 才能跑 Linux
「M 省钱，R 求稳，A 求强；有无 MMU 定乾坤」
Q5裸机、RTOS、嵌入式 Linux 三种开发方式怎么选？🔥 高频
方式特点适用场景
裸机main 里大循环 + 中断，简单可控、资源占用最少逻辑简单、单任务流、成本极敏感
RTOS多任务调度 + 信号量/队列，实时性好、模块化多任务并发、强实时、中等复杂度
嵌入式 Linux多进程/线程 + 文件系统 + 网络协议栈，功能强、生态大需要 GUI、网络、复杂应用、大量存储
  • 升级路线：裸机 → RTOS（FreeRTOS）→ Linux，复杂度、资源需求递增
  • 选型三问：功能多不多？实时要求多高？内存够不够？
「简单裸机，多任务 RTOS，复杂全能上 Linux」

Q8什么是寄存器？为什么嵌入式开发要直接操作寄存器？
  • 寄存器：CPU 与外设通信的窗口，是芯片内部一组有特定地址的存储单元，控制外设的配置、状态、数据
  • 每个外设 = 一组寄存器（控制寄存器 CR、状态寄存器 SR、数据寄存器 DR），读写寄存器就是配置外设
  • 操作方式：通过地址映射——将寄存器地址强转成指针读写，如 *(volatile uint32_t *)0x40021000 = val
  • 为什么手动操作：① 理解底层原理；② 效率最高；③ 库/HAL 封装出问题时能排查；④ 部分场景（启动、中断）必须直接用
// 把地址 0x40021000 当作 volatile uint32_t 指针来读写
#define RCC_CR (*(volatile uint32_t *)0x40021000)
RCC_CR |= (1U << 0);      // 置位第 0 位（开启时钟）
「寄存器是外设的门牌号，地址映射 + volatile + 位操作三件套」

02C 语言与编译链接

Q9volatile 关键字的作用？嵌入式里哪些场景必须用？🔥 高频
  • 作用：告诉编译器该变量可能被意外修改，每次访问都从内存重新读取，禁止优化到寄存器缓存
  • 三个经典场景：① 硬件寄存器（外设寄存器值会变）；② 中断服务程序修改的全局变量；③ 多线程/多任务共享变量
  • 反例：裸机里 while (flag == 0); 等中断置位 flag，若不加 volatile，编译器可能优化成死循环或只读一次
volatile 不能保证原子性，也不能解决多线程互斥——它只解决「读不到最新值」的可见性问题。
「寄存器、中断、多线程，三个场景找 volatile；防优化、读最新，仅此而已不背锅」
Q10指针和数组有什么关系？什么时候两者不能互换？🔥 高频
  • 数组名是指向首元素的常量指针，可以 arr[i] 与 *(arr+i) 互换
  • 区别：① 数组名不能自增/赋值（常量），指针可以；② sizeof 不同——数组是整个数组字节数，指针是地址大小（4/8 字节）
  • 传参退化：数组作为函数参数退化为指针，形参里写 int a[] 等价于 int *a
  • 嵌入式中常见坑：把数组传给函数后 sizeof(a)/sizeof(a[0]) 算错长度
「数组名是常量指针，传参就退化成指针；sizeof 一个真大一个假大」
Q11指针数组和数组指针有什么区别？
  • 指针数组：int *p[5]——「数组里装指针」，5 个 int* 元素，[] 优先级高于 *
  • 数组指针：int (*p)[5]——「指向数组的指针」，p 指向含 5 个 int 的数组
  • 记忆：看谁跟谁结合——p 先跟 [] 结合是数组（装指针），先跟 * 结合是指针（指向数组）
  • 嵌入式中：指针数组常用于字符串表（命令表/菜单表），数组指针用于二维数组行指针
const char *cmd_table[] = {"led_on", "led_off", "help"}; // 指针数组：命令表
int matrix[3][4];
int (*row)[4] = matrix;   // 数组指针：指向每行 4 个 int
「谁先结合谁当家：[] 先＝数组装指针，* 先＝指针指数组」
Q12什么是函数指针？嵌入式中哪里会用到？🔥 高频
  • 函数指针：指向函数的指针变量，定义如 int (*fp)(int, int)，通过 fp(1, 2) 或 (*fp)(1, 2) 调用
  • 典型用途：① 回调函数（定时器超时回调、按键事件回调）；② 中断向量表（跳转到 ISR 地址）；③ 驱动抽象层（结构体里放函数指针实现接口多态）；④ 状态机迁移表
  • 经典驱动抽象：struct ops { int (*init)(void); int (*read)(uint8_t *buf, uint32_t len); }; 不同硬件填不同实现
typedef int (*callback_t)(int event, void *arg);
void register_event(callback_t cb) { g_cb = cb; }
// 上层注册：register_event(on_button_pressed);
「函数指针是函数的名片，回调、中断表、驱动多态全靠它」
Q13C 程序的内存分区有哪些？各存放什么？🔥 高频
分区存放内容特点
栈 Stack局部变量、函数参数、返回地址编译器管理，自动分配释放，向下增长
堆 Heapmalloc 动态分配程序员管理，手动释放，向上增长
全局/静态区全局变量、static 变量程序启动初始化，整个生命周期存在
常量区字符串常量、const 数据只读，修改会崩溃
代码区编译后的机器指令只读，存放 Flash 中

嵌入式视角：栈、堆在 RAM，代码区在 Flash；局部变量没初始化是随机值，全局/static 默认0。

「栈堆全局常量代码，五区各司其职；栈自动、堆手动、全局活到老」
Q14位操作有哪些技巧？如何置位、清位、翻转、判断？🔥 高频
// 置位第 n 位
REG |= (1U << n);
// 清位第 n 位
REG &= ~(1U << n);
// 翻转第 n 位
REG ^= (1U << n);
// 判断第 n 位是否为 1
if (REG & (1U << n)) { ... }
// 连续多位置位
REG |= (0x0F << 4);      // 第 4~7 位写 1111
// 取出某段位（第 4~7 位）
uint8_t val = (REG >> 4) & 0x0F;
  • 技巧：置 1 用或、清 0 用与 + 取反、翻转用异或、判断用与
  • 寄存器操作常配合 volatile 防优化；多字节芯片注意寄存器宽度（8/16/32 位）
「置 1 用或，清 0 用与取反，翻转用异或，判断用与，取出用移位加与」
Q15static 和 const 在嵌入式开发中怎么用？
  • static 三种语义：① 修饰局部变量——延长生命周期到程序结束，只初始化一次，值保持；② 修饰全局变量/函数——限定本文件可见（内部链接）；③ 修饰函数内部使用，避免命名冲突
  • const：① 修饰变量——只读，编译期检查；② 修饰指针——const int *p（指向的内容只读）vs int *const p（指针本身只读）
  • 嵌入式典型用法：static 隐藏驱动内部状态机变量；const 定义查表（正弦表、字形码表）放在 .rodata（Flash），节省 RAM
  • 注意：const 变量在嵌入式里也可能放 Flash，直接强转写它会导致 HardFault
「static 管可见性和生命周期，const 管只读；表放 Flash 省 RAM」
Q16C 程序编译链接分哪几个阶段？每个阶段做什么？🔥 高频
  1. 预处理：展开 #include / #define / #ifdef，删除注释，生成 .i 文件（gcc -E）
  2. 编译：C 代码 → 汇编代码 .s（gcc -S），做语法/语义检查与优化
  3. 汇编：汇编代码 → 机器码 .o 目标文件（gcc -c），含未解析的符号
  4. 链接：把多个 .o 与库合并，解析符号地址，按链接脚本（.ld）布局生成最终 .elf / .bin / .hex

嵌入式特有：链接脚本决定 Flash 起始地址、RAM 布局、中断向量表位置；编译选项 -mcpu / -mthumb / -ffunction-sections 等与芯片强相关。

「预编汇链四步走：展开、翻译、变码、对号入座」
Q17什么是结构体字节对齐？如何计算结构体大小？🔥 高频
  • 对齐规则：每个成员的偏移量必须能被自身大小整除，结构体总大小必须能被最大成员大小整除（按最大对齐数取整）
  • 编译器默认按最大成员对齐（4 字节对齐），可通过 #pragma pack(1) 或 __attribute__((packed)) 紧凑打包
  • 嵌入式中对齐的意义：① 节省 RAM/Flash（尤其通信协议报文结构体）；② 硬件对齐要求（DMA 缓冲区、某些外设要求 4 字节对齐）
struct msg { char a;   // 偏移 0
             int  b;   // 偏移 4（补齐 3 字节）
             char c;   // 偏移 8
           };          // 总大小 12（对齐到 4）
// pragma pack(1) 后：1+4+1 = 6 字节
协议报文结构体必须考虑对齐 + 大小端，否则不同平台解析出错；建议用 __attribute__((packed)) 并做好字段顺序定义。
「偏移能被自己整除，总长按最大对齐；通信报文防对齐，packed 打包最稳」

Q18什么是栈溢出？嵌入式里怎么检测和防止？🔥 高频
  • 栈溢出：栈空间被用完，写入越过栈顶（向堆/全局区方向覆盖），导致变量被改、返回地址损坏、程序跑飞
  • 常见原因：递归过深、局部大数组（如 char buf[1024]）、中断嵌套深、RTOS 任务栈设太小
  • 检测方法：① 栈填充 0xAA/0x55 哨兵模式（编译器支持，如 --stack_usage、Keil 栈填充）；② 栈顶放魔术字（canary），定期检查是否被改写；③ RTOS 的栈溢出钩子 vApplicationStackOverflowHook
  • 防止：估算最大调用深度、用静态数组代替递归、任务栈按 1.5~2 倍裕量设置
// FreeRTOS 栈溢出钩子：任务栈踩穿时由调度器回调
void vApplicationStackOverflowHook(TaskHandle_t xTask, char *pcTaskName) {
    // 记录任务名、关闭中断、进入死循环等看门狗复位
    taskDISABLE_INTERRUPTS();
    for (;;) { }
}
「大数组、深递归、中断嵌套，栈三怕；哨兵 + 钩子 + 裕量，三防」
Q19嵌入式里能用 malloc 吗？有什么坑？🔥 高频
  • 能用但要谨慎：MCU 上堆很小、无 MMU，malloc 容易出现碎片化、分配失败、不可重入问题
  • 三大坑：① 内存碎片——频繁小分配/释放后大块申请失败；② 忘记 free——内存泄漏最终系统崩溃；③ 不确定执行时间——实时任务中 malloc 可能耗时不可控
  • 工程实践：① 启动时一次性分配（池化）；② 静态分配（编译期确定）；③ 专用内存池管理（固定块大小，无碎片）；④ 断言检查分配结果
  • FreeRTOS 用 pvPortMalloc 并支持多种堆实现（heap_4 带合并防碎片）
「实时任务别 malloc，池化静态最安心；分配必查空，用完必 free」
Q20什么是大端小端？怎么判断？通信时要注意什么？🔥 高频
  • 小端：低字节存低地址（x86、ARM 默认）；大端：高字节存低地址（网络字节序、部分协议）
  • 判断方法：联合体 union { uint16_t u; uint8_t b[2]; }，看 b[0] 是低字节还是高字节
  • 通信注意：网络字节序 = 大端；发送前转网络序 htons/htonl，接收转主机序 ntohs/ntohl；自研协议要明确字节序并在文档写明
// 判断本机大小端
int is_little_endian(void) {
    union { uint16_t u; uint8_t b[2]; } t = { .u = 0x1234 };
    return t.b[0] == 0x34;   // 低地址是低字节 = 小端
}
// 大小端互转
uint16_t swap16(uint16_t v) { return (v << 8) | (v >> 8); }
「低字节低地址是小端（先来的是小弟）；网络序是大端，协议里白纸黑字写清楚」
Q21Flash 存储有什么特性？读写要注意什么？🔥 高频
  • 特性：① 断电不丢（非易失）；② 读快写慢；③ 必须先擦后写，且擦除按扇区/页为单位（如 4KB），擦除后全变 0xFF；④ 擦写寿命有限（约 1 万~10 万次）
  • 写操作：只能把 1 写成 0（编程），要把 0 变回 1 必须擦除整扇区
  • 工程注意：① 磨损均衡——参数存储不要总写同一扇区（轮流/备份）；② 掉电保护——写参数先擦后写过程中掉电会损坏，用双备份 + 标志位或写日志方式；③ 写 Flash 时关中断或搬代码到 RAM 执行（部分芯片边写边取指会卡死）
「先擦后写、整页擦除、寿命有限；双备份防掉电，均衡磨损保寿命」

Q24怎么确定堆栈大小？栈设多大合适？
  • 栈大小：取决于函数调用深度 + 局部变量 + 中断嵌套；中断栈要单独考虑（M3/M4 的 MSP 栈）
  • 方法：① 编译器报告（-fstack-usage、Keil 的 Stack Usage）；② 实际压力测试（跑满所有路径，填充 0xAA 后看剩余）；③ 按最坏情况加 30%~100% 裕量
  • 堆大小：按 malloc 峰值估算 + 裕量；不使用动态内存可设 0
  • 裸机默认栈在链接脚本设置（如 Stack_Size EQU 0x400）；RTOS 每个任务独立栈
「估算 + 实测 + 裕量三件套；栈看调用链，堆看分配峰值」
Q25什么是内存保护？MPU 有什么用？
  • MPU（Memory Protection Unit）：ARM Cortex-M3/M4 以上可选的内存访问保护硬件，可划分多个内存区域并设置访问权限（读/写/执行、特权/用户态）
  • 作用：① 检测非法访问（越界、写只读区）触发 MemManage Fault；② 任务间隔离（RTOS 里防任务互相踩内存）；③ 内核与用户代码隔离
  • 对比：Linux 用 MMU（虚拟地址 + 权限 + 页表），MCU 用 MPU（物理地址 + 区域权限，无虚拟内存）
  • 注意：配置 MPU 的区域大小必须是 2 的幂，且需与缓存/总线对齐
「MPU 管物理地址的权限，MMU 管虚拟地址的映射；MCU 防越界靠 MPU」

04中断与定时器

Q26中断的处理流程是怎样的？🔥 高频
  1. 触发：外设/内部事件产生中断请求（置位中断标志）
  2. 响应：CPU 完成当前指令后，保存现场（压栈 PC、PSR、寄存器、LR 等）
  3. 查找向量：根据中断号查中断向量表，得到 ISR 入口地址
  4. 跳转执行：进入 ISR（中断服务函数），硬件自动关同级中断
  5. 恢复现场：ISR 返回（BX LR），出栈恢复寄存器，继续被打断的程序

Cortex-M 特殊：硬件自动压栈（8 个寄存器）、自动使用 MSP 主栈，中断延迟固定且很短（12 周期）；ISR 返回用特殊 EXC_RETURN 值。

「触发→响应→查表→执行→恢复；现场保存好，回来不迷路」
Q27中断服务函数里有哪些禁忌？🔥 高频
  • 尽量短小：只做置标志、拷贝数据、清中断标志，耗时处理放主循环/任务里
  • 禁忌清单：① 不用 printf/串口阻塞打印（耗时且不可重入）；② 不做 malloc/free（非可重入）；③ 不调用非可重入函数；④ 不死循环/长延时（delay()）；⑤ 不访问被主流程同时操作的共享变量（需临界区保护）
  • RTOS 中：中断里只能用 FromISR 后缀 API（xQueueSendFromISR、xSemaphoreGiveFromISR），不能直接调用普通 API
  • 清中断标志必须在 ISR 内完成，否则中断反复触发死循环
「中断里三不做：不打印、不 malloc、不 delay；只置标志快进快出，FromISR 记心头」
Q28中断和轮询有什么区别？什么时候用哪个？🔥 高频

「稀事件、要实时、求省电用中断；密事件、省事用轮询；标志位桥接两世界」
Q29什么是中断嵌套和中断优先级？Cortex-M 怎么配置？🔥 高频
  • 中断优先级：多个中断同时触发时的响应顺序；中断嵌套：高优先级中断可以打断低优先级 ISR 的执行
  • Cortex-M 的 NVIC：优先级分组（抢占优先级 + 子优先级），数值越小优先级越高（与直觉相反！）
  • 特殊优先级：PendSV（RTOS 任务切换，最低）、SysTick（系统节拍）、NMI（不可屏蔽）、HardFault（默认最高级别故障）
  • 配置注意：① 中断里能被更高优先级打断；② 优先级相同的不嵌套；③ 临界区用 __disable_irq() 或 BASEPRI 屏蔽指定优先级以下的中断
「数值越小越优先，抢占能嵌套、同级不嵌套；PendSV 垫底给 RTOS 让路」
Q30按键抖动怎么产生的？怎么消抖？🔥 高频
  • 抖动：机械触点闭合/断开瞬间反复通断，持续约 5~20ms，导致一次按键被误判多次
  • 硬件消抖：RC 低通滤波 + 施密特触发器 / RS 触发器；适合按键少、要求高
  • 软件消抖：① 简单延时（检测到按下 delay 10~20ms 再确认）；② 状态机消抖（推荐，不阻塞主流程）；③ 定时器周期采样 N 次一致才确认
  • 注意：软件消抖应配合边沿触发 + 定时器，避免在 ISR 里 delay 阻塞
「抖动 20 毫秒，延时确认或状态机；ISR 里别 delay，定时采样最优雅」
Q31定时器的工作原理？PSC 和 ARR 怎么算？🔥 高频
  • 定时器 = 计数器 + 时钟源 + 比较/捕获逻辑：按固定频率计数（CNT），计到目标值（ARR）产生更新事件/中断，清零重新计
  • PSC（预分频）：把时钟源频率降下来；ARR（自动重装载）：计数的目标值
  • 公式：定时频率 = 时钟频率 ÷ (PSC+1) ÷ (ARR+1)，如 72MHz、PSC=7199、ARR=999 → 72M÷7200÷1000 = 10Hz（100ms 一次）
  • 位数注意：16 位定时器 PSC/ARR 最大 65535，长定时需级联或软件计数扩展
// 72MHz 主频，PSC=7199 (7200 分频 → 10kHz)，ARR=999 (计 1000 次 → 100Hz)
// 中断频率 = 72MHz / (7199+1) / (999+1) = 100 Hz，即每 10ms 中断一次
TIM_TimeBaseInitTypeDef init = {0};
init.TIM_Prescaler     = 7199;   // PSC
init.TIM_Period        = 999;    // ARR
init.TIM_CounterMode   = TIM_CounterMode_Up;
HAL_TIM_Base_Init(&htim);
「PSC 分频定节奏，ARR 装满就溢出；(PSC+1)(ARR+1) 一分，中断频率就出来」
Q32什么是 PWM？怎么用定时器输出 PWM？占空比怎么算？🔥 高频
  • PWM（脉冲宽度调制）：固定周期内改变高电平占的比例（占空比），等效于输出「可调的平均电压」
  • 原理：定时器 CNT 与比较寄存器 CCR 比较——CNT < CCR 输出高，CNT ≥ CCR 输出低；ARR 决定周期，CCR 决定占空比
  • 占空比 = CCR ÷ (ARR+1)，如 ARR=999、CCR=500 → 50%
  • 应用：LED 调光、电机调速（配合 H 桥）、蜂鸣器、舵机控制（50Hz、0.5~2.5ms 脉宽）
  • 注意：PWM 频率选高（>20kHz）避免电机啸叫；切换占空比要平滑防电流冲击
「周期看 ARR，占空比看 CCR；CCR 一比高电平，LED 电机全靠它」
Q33什么是看门狗？独立看门狗和窗口看门狗有什么区别？🔥 高频
  • 看门狗：独立计数器，超时未被喂狗（重载）就复位系统，用于程序跑飞/死循环时自动恢复
  • IWDG 独立看门狗：用独立 RC 时钟（LSI），不受主时钟影响，喂狗窗口宽（超时前随便喂），最可靠；一旦开启无法软件关闭
  • WWDG 窗口看门狗：用主时钟（APB1），必须在特定时间窗口内喂狗——喂太早（窗口没到）或太晚（超时）都复位，能检测程序跑太快或卡死
  • 工程要点：喂狗放在主循环关键点（不是中断里），保证「关键路径没死」；调试时可用 DBGMCU 冻结看门狗
「IWDG 独立 RC 随便喂，WWDG 窗口期早喂晚喂都复位；喂狗喂在主循环」
Q34什么是 SysTick？它有什么用？
  • SysTick：Cortex-M 内核自带的24 位递减定时器，每个 M 核都有，不占外设定时器资源
  • 三大用途：① RTOS 系统节拍（FreeRTOS 默认用 SysTick 产生 tick 中断驱动调度）；② 软件延时（HAL_Delay 基于 SysTick）；③ 时间基准/计时（HAL_GetTick 毫秒计数）
  • 注意：SysTick 优先级影响延时精度（被更高优先级中断打断会漂移）；中断里不要调用依赖 SysTick 的 delay（会死锁）
「SysTick 是内核自带秒表，RTOS 节拍、延时、GetTick 全靠它」

05通信协议

Q35UART 的工作原理？波特率怎么理解？🔥 高频
  • UART（通用异步收发器）：异步串行通信，收发各一根线（TX/RX），共地，点对点
  • 帧格式：起始位（低电平 1 位）+ 数据位（5~8 位，常用 8）+ 校验位（可选）+ 停止位（1/2 位）；空闲时 TX 保持高电平
  • 波特率：每秒传输的符号数（bit/s），双方必须一致；波特率越高每一位时间越短（9600 → 每位约 104μs，115200 → 约 8.7μs）
  • 异步 vs 同步：UART 靠起始位同步（无时钟线），I2C/SPI 有时钟线（同步）；接收端用波特率时钟采样每个位
  • 常见坑：乱码多为波特率不匹配 / 电平不匹配（TTL vs RS232）/ 校验位不一致
「异步靠起始位，波特率定采样节奏；起停数校验五件套，两边对齐才不乱码」
Q36I2C 总线的工作原理？有什么特点？🔥 高频
  • 两线制：SCL（时钟）+ SDA（数据），都是开漏 + 上拉电阻，支持一主多从/多主，靠7 位地址寻址（可挂 100+ 设备）
  • 时序：起始条件（SCL 高时 SDA 下降沿）→ 发送地址 + R/W → 从机 ACK → 数据字节（高位在前）→ 停止条件（SCL 高时 SDA 上升沿）
  • 仲裁：多主机同时发时，边发边读 SDA，发现电平与自己不同就退让；时钟拉伸：慢从机拉低 SCL 让主机等待
  • 特点：引脚少、速率中等（标准 100k/快速 400k/高速 3.4M），适合传感器、EEPROM、显示屏
  • 坑：SDA/SCL 没有上拉会卡死；总线被拉低常见于从机复位异常，用 9 个时钟脉冲 释放总线
「两线开漏加上拉，起始停止靠边沿；地址寻址 + ACK，仲裁退让不打架」
Q37SPI 总线的工作原理？有哪四种模式？🔥 高频
  • 四线制：SCLK（时钟）+ MOSI（主出从入）+ MISO（主入从出）+ CS（片选），全双工、同步、高速（几十 MHz）
  • 通信模型：主机发时钟并移位，同时收发；CS 拉低选中从机，一主多从靠多根 CS
  • 四种模式 = CPOL（时钟极性）+ CPHA（相位）：CPOL 决定空闲电平（0 低/1 高），CPHA 决定采样沿（0 第一个边沿/1 第二个边沿）
  • 模式选择看从机手册，不匹配会读到错位数据；常见 FLASH/屏是 Mode 0 或 Mode 3
  • 对比 I2C：SPI 更快、全双工、无仲裁/应答（靠协议层确认），引脚多一根 CS；适合 Flash、SD 卡、高速传感器
「四线全双工，CS 选人；CPOL 定空闲，CPHA 定采样沿，模式 0/3 最常见」

Q39CAN 总线有什么特点？和 UART/485 比强在哪？🔥 高频
  • 两线差分（CANH/CANL），多主、广播式总线，报文带 ID 优先级，非破坏性仲裁（ID 小的先发）
  • 特点：① 抗干扰强（差分信号，工业/车载恶劣环境）；② 错误处理完善（CRC、位填充、错误帧、节点自动离线）；③ 无主从，任意节点可发；④ 速率最高 1Mbps（CAN FD 可达 5M+）
  • 报文格式：帧 ID + 数据段（8 字节）+ CRC + 应答；标准帧 11 位 ID，扩展帧 29 位 ID
  • 应用：汽车（ECU 网络）、工业控制、医疗器械
  • 对比 RS485：485 靠主从轮询无仲裁，CAN 天然多主实时、错误处理更强
「差分抗扰、ID 仲裁、错误自愈，CAN 是车载工业的硬汉总线」
Q40RS485 通信的原理和注意事项？
  • RS485：差分信号（A/B 两线电平差表示 0/1），半双工、多点（一主多从，最多 32 节点，可加中继扩展），最长 1200m，抗干扰强
  • 与 RS232 区别：RS232 是单端电平 ±12V，点对点、15m 内；RS485 差分、远、多节点
  • 工程要点：① 需要 MAX485 等收发器转换电平；② 发送/接收方向切换（DE/RE 控制，发送完要关发送）；③ 终端电阻 120Ω 接总线两端（匹配阻抗防反射）；④ 总线空闲态要保证（A 高 B 低，否则收到乱码）
  • 协议上常配合 Modbus RTU（主从查询，地址+功能码+CRC16）
「差分远距离多节点，120 欧终端匹配，收发切换要记得；Modbus 定协议」
Q41USB 协议的基本概念？嵌入式里怎么用？
  • USB：四线（VBUS/GND/D+/D-），主从（Host/Device）体系，支持热插拔、枚举（主机识别设备并加载驱动）
  • 核心概念：端点（Endpoint）→ 管道（Pipe）→ 接口（Interface）→ 配置（Configuration）；传输类型四种：控制（枚举）、批量（大数据）、中断（小数据周期）、同步（音视频实时）
  • 嵌入式用法：① MCU 做 Device（USB 转串口 CDC、U 盘 MSC、HID 键鼠、声卡）；② 做 Host（接 U 盘、键盘）；③ OTG 双角色
  • 注意：USB 需要晶振精度（48MHz 时钟）、枚举失败多为时钟/上拉电阻问题
「枚举问身份、端点传数据、四种传输对号入座；时钟要准、上拉要有」
Q42什么是波特率误差？会产生什么影响？
  • 波特率误差：实际波特率与理论波特率偏离的程度（%），由时钟源误差 + 分频取整误差造成
  • 影响：发送端和接收端波特率不一致时，采样点逐渐偏移，位越多偏差累积越大，最终采样到错误电平→乱码/丢帧
  • 容限：UART 一般要求误差 ±2% 以内（起始位重新对齐，每帧只累积一帧内误差）
  • 优化：① 选整数分频接近的时钟（如外部晶振）；② 用高精度晶振（±20ppm vs ±1% RC）；③ 官方工具算 USARTDIV
「误差 2% 是红线，晶振选准、分频取整，乱码先查波特率」
Q43自研设备间通信协议，你会怎么设计？
  • 基本框架：帧头 + 长度 + 类型/命令 + 数据 + 校验 + 帧尾（可选：版本、序列号、时间戳）
  • 帧头/帧尾：固定魔数（如 0xAA 0x55），用于找帧边界；数据里若可能撞帧头需转义（0x7E → 0x7D 0x5E）或长度定界
  • 校验：简单场景 校验和/异或；重要数据 CRC16/CRC32；对抗性环境加加密 + 认证
  • 健壮性：解析时做长度上限、帧超时检查；收一帧回一 ACK，超时重传
  • 已有成熟协议优先复用：Modbus、MQTT、BLE GATT、私有基于 JSON/Protobuf
「头长类数校验尾，七件套齐全；转义防撞头，超时重传保可靠」

Q45怎么用状态机实现按键消抖？（手写思路）🔥 高频
  • 思路：把按键采样做成有限状态机，状态：空闲 → 按下确认（去抖）→ 按下保持 → 松开确认（去抖）→ 空闲
  • 每次定时器（如 5~10ms）采样一次，连续 N 次同一电平才切换状态，过滤抖动毛刺
  • 优点：不阻塞主循环、不吃中断，同时可扩展短按/长按/双击检测
// 按键状态机：每 10ms 调用一次
typedef enum { K_IDLE, K_DEBOUNCE_DOWN, K_HOLD, K_DEBOUNCE_UP } key_state_t;
void key_scan(void) {
    static key_state_t st = K_IDLE;
    static uint8_t cnt = 0;
    uint8_t lvl = GPIO_ReadPin(KEY_PIN);      // 0 表示按下
    switch (st) {
        case K_IDLE:
            if (lvl == 0) { cnt = 0; st = K_DEBOUNCE_DOWN; }
            break;
        case K_DEBOUNCE_DOWN:                 // 连续 3 次(30ms)确认按下
            if (lvl == 0) { if (++cnt >= 3) { st = K_HOLD; key_event(PRESSED); } }
            else          { st = K_IDLE; }
            break;
        case K_HOLD:
            if (lvl == 1) { cnt = 0; st = K_DEBOUNCE_UP; }
            break;
        case K_DEBOUNCE_UP:                   // 连续 3 次确认松开
            if (lvl == 1) { if (++cnt >= 3) { st = K_IDLE; key_event(RELEASED); } }
            else          { st = K_HOLD; }
            break;
    }
}
「四态状态机，连续采样三次定生死；不阻塞、可扩展长短按」
Q46ADC 的分辨率、参考电压、采样时间怎么理解？🔥 高频
  • 分辨率：N 位 ADC 把参考电压分成 2^N 份，如 12 位 → 0~4095；分辨率越高，能分辨的电压越细
  • 参考电压 Vref：转换满量程对应电压，数字值 = 输入电压 ÷ Vref × 2^N；Vref 抖动直接引入误差
  • 采样时间：采样保持电容充电需要时间，时间太短 → 采样不准（高阻源更明显）；软件/硬件触发、连续/单次模式
  • 抗噪：① 软件滤波（多次采样取平均/中值）；② 模拟地 AGND 与数字地 DGND 处理；③ 采样避开开关噪声时刻；④ 用 DMA 批量搬运
  • 计算示例：12 位、Vref=3.3V，读 2048 → 1.65V
「量程分 2 的 N 次方，读值乘 Vref 除满量程；采样充电要够久，滤波抗噪不能省」
Q47什么是 DMA？用 DMA 有什么好处？🔥 高频
  • DMA（直接存储器访问）：外设与内存之间直接搬运数据的硬件通道，不经过 CPU，搬完才中断通知
  • 好处：① CPU 被解放（不用逐字节读写）；② 搬运快（总线级速度）；③ 降低中断频率（一次搬一批）
  • 典型场景：串口收长数据、ADC 连续采样、内存拷贝、外设间搬运（SPI→内存）
  • 配置要点：① 方向（外设→内存 / 内存→外设 / 内存→内存）；② 数据宽度（8/16/32 位）；③ 单次 vs 循环模式（环形缓冲，用半传输/传输完成中断）；④ 缓冲区要固定地址（局部变量可能被优化或栈变动）
  • 坑：DMA 与 CPU 竞争总线、缓存一致性（部分芯片需清理/失效 Cache）
「DMA 是搬家公司，CPU 只等电话；循环模式配半中断，环形缓冲收不停」
Q48中断 + DMA 的组合怎么用？以串口接收为例
  • 组合套路：DMA 负责搬运，空闲中断/半满中断负责通知，CPU 只在「一批数据到了」时才处理
  • 串口接收长数据：① 开启 DMA 循环接收到环形缓冲；② 开 IDLE（空闲）中断——一帧发完总线空闲即触发；③ 中断里算本次收了多少字节，交给解析；④ 解析完成更新读指针
  • 优点：高速数据流（如 GPS 1kHz 输出）CPU 占用极低，不丢字节
  • 注意：DMA 写缓冲与 CPU 读要同步指针（防读写冲突），帧边界靠超时/空闲检测
「DMA 扛数据、IDLE 报帧完、CPU 只解析；指针同步防冲突」
Q49什么是输入捕获？能用来做什么？
  • 输入捕获：定时器检测引脚边沿（上升/下降），记录触发时刻的 CNT 值并产生中断/事件
  • 用途：① 测频率/周期——两次上升沿的 CNT 差值 ÷ 计数频率；② 测脉宽——上升沿到下降沿差值；③ 解码协议（红外 NEC、PWM 输入、编码器）；④ 电机转速（霍尔/编码器脉冲）
  • 实现：先配定时器为捕获模式，中断里记录前后两次值相减；注意计数器溢出要软件扩展位数
「边沿一到记 CNT，两次相减得周期；测速测宽解码全都能」

07RTOS 基础

Q52为什么要用 RTOS？和裸机有什么区别？🔥 高频
  • 裸机（前后台）：主循环轮询 + 中断，一个死循环，任务多了实时性差（耗时任务阻塞其他任务）、模块耦合强
  • RTOS：多个独立任务按优先级抢占调度，任务间用队列/信号量通信，实时性有保证、模块化清晰
  • RTOS 带来：① 实时性——高优先级任务就绪立即抢占；② 模块化——每个功能一个任务；③ 时间片——同级任务轮流跑；④ 阻塞 API——任务等待时让出 CPU，低功耗友好
  • 代价：资源开销（每个任务独立栈）、调试复杂（优先级/竞态/优先级翻转）、学习成本
「裸机一个大循环，RTOS 一堆小任务抢 CPU；要实时要解耦就上 RTOS」
Q53RTOS 的任务状态有哪些？调度规则是什么？🔥 高频
  • 任务状态：运行（Running）/ 就绪（Ready）/ 阻塞（Blocked）/ 挂起（Suspended）；任务通过 delay、队列、信号量 进入阻塞，被 resume 进入挂起
  • 调度规则：优先级抢占式——永远运行最高优先级就绪任务；同级任务按时间片轮转（如 1 tick 切换）；任务阻塞/结束→让出 CPU
  • tick：系统节拍（如 1ms），定时器中断里检查就绪列表，决定是否切换任务（PendSV 中完成切换）
  • 注意：高优先级任务一直就绪 → 低优先级任务饿死（starvation）；任务里别写长死循环（不让出 CPU）
「运行就绪阻塞挂起四态；最高优先级先跑，同级轮流转，阻塞就让位」

Q56什么是优先级翻转？怎么解决？🔥 高频
  • 优先级翻转：高优先级任务 H 等一个互斥量，而它被低优先级任务 L 持有，L 又被中优先级任务 M 抢占——结果 H 反而在等 M 跑完，高优先级任务被「降级」等待
  • 危害：实时性被破坏，H 的截止时间可能被错过（航天案例：火星探路者）
  • 三大解法：① 优先级继承（推荐）：H 等待时，把 L 临时提升到 H 的优先级，L 尽快释放锁后恢复（FreeRTOS 互斥量自带）；② 优先级天花板：持锁任务直接设为系统最高优先级；③ 关闭中断/禁止调度（临界区，只适合极短操作）
  • 工程建议：互斥量保护区尽量短，别在锁里做耗时操作
「高等低、低被中等抢，优先级翻转就发生；继承提上去、锁区做短点」
Q57RTOS 里死锁怎么产生？怎么避免？
  • 死锁四条件：互斥、持有并等待、不可剥夺、循环等待——缺一不可
  • RTOS 典型：任务 A 持锁 1 等锁 2，任务 B 持锁 2 等锁 1 → 互相等死
  • 避免方法：① 锁顺序一致（所有任务按相同顺序获取多把锁）；② 一次只持一把锁；③ 超时获取（xSemaphoreTake(..., timeout) 拿不到就退出）；④ 用互斥量替代自旋等待；⑤ 加锁区尽量短
  • 排查：看调度器当前哪个任务阻塞在哪个信号量（FreeRTOS 用 uxTaskGetSystemState 或 IDE 调试视图）
「锁顺序一致、只拿一把、超时放弃；死锁四条件断一个就破」
Q58什么是临界区？RTOS 里怎么保护共享资源？
  • 临界区：访问共享资源且不能被并发打断的代码段，保护手段：关中断、禁止调度、互斥量
  • 三种手段对比：① 关中断（taskENTER_CRITICAL）：最强，但影响实时性（延迟所有中断），只用于极短代码；② 挂起调度器（vTaskSuspendAll）：中断照常，只是不切任务；③ 互斥量：任务级互斥，可阻塞、保护时间长，但中断里不能用
  • 注意：中断与任务共享变量也要保护——中断里读写的变量，任务侧要么关中断要么原子操作
  • 常见错误：临界区里调用阻塞 API、嵌套关中断忘记配对
「短代码关中断，任务级挂调度，长保护上互斥量；中断共享变量别裸奔」
Q59RTOS 任务栈和内存怎么管理？
  • 每个任务创建时分配独立栈（FreeRTOS 的 xTaskCreate 动态 / xTaskCreateStatic 静态）；栈大小单位是字（32 位机 1 字 = 4 字节），如 256 字 = 1KB
  • 任务栈放哪：动态创建从堆（FreeRTOS 的 heap 区）分配，静态创建由用户提供数组；RAM 紧张时用静态 + 链接脚本规划
  • 堆实现选择：heap_1（不释放，最省）、heap_2（释放但易碎）、heap_4（合并空闲块防碎片，推荐）、heap_5（多段内存）
  • 栈大小估算：函数调用深度 × 局部变量 + 中断嵌套开销，给 1.5~2 倍裕量，配合溢出钩子检测
「一任务一栈，动态用 heap_4，静态自己供数组；裕量给足加钩子」
Q60FreeRTOS 常用的钩子/配置项有哪些？
  • 常用回调钩子：① vApplicationStackOverflowHook——栈溢出回调；② vApplicationIdleHook——空闲任务钩子（可做低功耗/喂狗）；③ vApplicationTickHook——tick 中断钩子（短小操作）；④ vApplicationMallocFailedHook——内存分配失败回调
  • 关键配置宏（FreeRTOSConfig.h）：configTICK_RATE_HZ（节拍频率）、configMINIMAL_STACK_SIZE、configTOTAL_HEAP_SIZE（堆大小）、configUSE_PREEMPTION（是否抢占）、configCHECK_FOR_STACK_OVERFLOW（栈溢出检查等级）
  • 调试：uxTaskGetStackHighWaterMark 查看任务栈剩余峰值，vTaskList 打印所有任务状态
「溢出、空闲、malloc 失败三钩子常驻；tick 频率和堆大小是命根子」

08嵌入式 Linux

Q62嵌入式 Linux 系统由哪几部分组成？🔥 高频
  • 四大件：① Bootloader（U-Boot）→ ② 内核（Kernel）→ ③ 根文件系统（rootfs）→ ④ 应用程序
  • 启动流程：ROM 固化代码 → SPL → U-Boot → 加载内核 → 内核挂载根文件系统 → 运行 init → 启动应用
  • 各层职责：Bootloader 初始化硬件、加载内核；内核管理进程/内存/驱动/文件系统；rootfs 提供目录结构与用户程序；应用层做业务
  • 对比 MCU 裸机：Linux 把「一个程序跑到底」变成多进程 + 文件系统 + 权限隔离，开发像 PC 一样用
「引导→内核→根文件→应用，四件套启动一条龙」
Q63什么是交叉编译？为什么要交叉编译？🔥 高频
  • 交叉编译：在一种架构（x86 主机）上编译出另一种架构（ARM 目标板）可运行的程序
  • 为什么：目标板资源有限（算力弱、无编译环境、无足够存储），编译工具链（gcc）跑不起来；主机资源充足，编译器交叉生成目标代码
  • 工具链形式：arm-linux-gnueabihf-gcc（前缀 = 目标架构-厂商-系统-浮点）；前缀决定目标平台
  • 开发流程：主机交叉编译 → 拷贝到板子（NFS/SD 卡/烧录）→ 板子运行调试；依赖库也要交叉编译（sysroot 指向目标库路径）
  • 常见坑：在 x86 上编出来在 ARM 上「No such file or directory」（动态库缺失）、段错误（架构/浮点 ABI 不匹配）
「主机编、板子跑，工具链前缀定乾坤；库也得交叉编，sysroot 别搞错」
Q64U-Boot 的作用？启动内核前做什么？
  • U-Boot：嵌入式最常用的 Bootloader，作用：初始化硬件（时钟/DDR/串口）→ 加载内核到内存 → 传启动参数（bootargs）→ 跳转执行
  • 常用命令：printenv / setenv / saveenv（环境变量）、tftp / mmc / nand（加载镜像）、bootm / bootz / booti（启动内核）、md / mw（内存读写调试）
  • 关键环境变量：bootcmd（自动启动命令）、bootargs（传给内核的参数：console=ttyS0,115200 root=/dev/mmcblk0p2）
  • 启动方式：SD 卡 / eMMC / NAND / 网络 TFTP 加载——开发期常用 TFTP 加快迭代
「U-Boot 是临门一脚：点硬件、搬内核、传参数、踢上场」
Q65内核移植/裁剪一般做什么？
  • 移植步骤：① 获取BSP/厂商内核（Linux 官方 + 厂商补丁）；② 配置 defconfig（厂商默认配置）；③ 修改设备树适配自家硬件（外设、引脚、内存）；④ 编译生成 zImage/uImage + dtb；⑤ 验证启动与驱动
  • 裁剪目的：① 减小体积（Flash 小）；② 加快启动（省初始化）；③ 减少攻击面（安全）
  • 裁剪手段：make menuconfig 去掉不用的驱动/子系统；内置（y）/模块（m）/不编（n）三选；配合 initramfs 或精简 rootfs
  • 启动优化：裁剪内核 + 精简文件系统 + 跳过不必要的服务 + 并行初始化，可把启动压到秒级
「BSP 打底、DTS 适配、menuconfig 裁剪；瘦身快启又安全」
Q66什么是设备树（Device Tree）？有什么用？🔥 高频
  • 设备树：用树状文本（DTS）描述板级硬件信息的机制，编译成 dtb 二进制，内核启动时解析——「硬件配置与内核代码分离」
  • 为什么出现：以前硬件配置写死在内核源码（arch/arm/mach-xxx），换块板子就得改内核重编；设备树让同一内核适配不同板子
  • 节点结构：/ { soc { uart0: serial@40001000 { compatible = "vendor,uart"; reg = ...; }; }; };
  • 关键概念：compatible（匹配驱动）、reg（地址范围）、interrupts（中断号）、pinctrl（引脚复用）
  • 驱动匹配：设备树节点 compatible ↔ 驱动的 of_device_id，匹配成功即 probe
「DTS 是硬件的简历，compatible 对暗号，驱动认亲就 probe」
Q67字符设备驱动的基本框架？用户态怎么访问？🔥 高频
  • 字符设备 = 按字节流访问的设备（LED、GPIO、传感器）；框架：注册设备号 → 填充 file_operations → 注册字符设备 → 生成 /dev 节点
  • 核心 file_operations：open / read / write / ioctl / release——用户态 open()/read()/write() 会调用到驱动对应函数
  • 用户态访问：open("/dev/led0", O_RDWR) → write(fd, ...) / ioctl(fd, CMD, ...) → close(fd)
  • 现代方式：设备树匹配 + platform_driver（probe 里做资源获取）；寄存器操作用 ioremap 或 of_iomap
static const struct file_operations my_fops = {
    .owner   = THIS_MODULE,
    .open    = my_open,
    .read    = my_read,
    .write   = my_write,
    .ioctl   = my_ioctl,
};
static int __init my_init(void) {
    alloc_chrdev_region(&devno, 0, 1, "mychrdev");  // 1. 申请设备号
    cdev_init(&my_cdev, &my_fops);                 // 2. 绑定操作集
    cdev_add(&my_cdev, devno, 1);                  // 3. 注册设备
    device_create(cls, NULL, devno, NULL, "mydev");// 4. 生成 /dev/mydev
    return 0;
}
module_init(my_init);
「申请号、绑 ops、注册设备、建节点，四步上岗；用户 open/read/write 直通驱动」

Q69什么是根文件系统？常用哪些？
  • 根文件系统 rootfs：内核启动后挂载的根目录 "/"，包含目录结构（/bin /etc /lib /dev /proc /sys）+ 用户程序 + 动态库 + 配置文件
  • 关键目录：/bin /sbin（可执行程序）、/lib（动态库）、/etc（配置）、/dev（设备节点）、/proc /sys（虚拟文件系统，内核信息）、/mnt /root /tmp
  • 制作方式：BusyBox（精简命令集 + init，最常用）、Buildroot（一键生成工具链+内核+rootfs）、Yocto（可定制发行版，重）
  • 存储：initramfs（打包进内核，内存运行，适合快速启动）、eMMC 分区、NFS（开发期网络挂载）
  • 启动首进程：内核找到 init（BusyBox init 或 systemd），按 /etc/inittab 拉起服务
「rootfs 是板子的家：目录、程序、库、配置齐活；BusyBox 轻量、Buildroot 一键」
Q70嵌入式 Linux 上常用的调试手段有哪些？
  • 应用层：printf/gdb（-g 编译）、strace（系统调用跟踪）、top/ps（资源）、valgrind（内存泄漏，板子上跑可能太重）
  • 驱动层：printk + dmesg（分级日志）、/proc /sysfs debugfs 暴露调试接口、ftrace/kprobe（函数跟踪）、kgdb（内核断点）
  • 硬件/底层：串口 console、逻辑分析仪/示波器、U-Boot 的 md/mw 读内存、JTAG
  • 系统问题：dmesg 看 oops（驱动崩溃地址 + 调用栈）、free（内存）、strace -p PID 看进程卡在哪、/proc/interrupts 看中断是否风暴
「应用 gdb、驱动 printk、底层示波器；oops 看栈、strace 看卡点」

09电源与低功耗

Q71低功耗设计有哪些思路？🔥 高频
  • 总原则：能睡就睡、能省就省、唤醒越少越好——功耗 = 工作时间 × 工作电流 + 睡眠时间 × 睡眠电流
  • 六大思路：① 时钟：不用的外设时钟及时关闭（RCC 门控）、降频运行；② 外设：用不到的模块断电（GPIO 关、外设 disable）；③ 睡眠策略：空闲进 Stop/Standby，事件驱动唤醒而非轮询；④ 外设电路：选低功耗器件、负载电阻拉高阻、MOS 断外设电源；⑤ 软件：中断唤醒 + 主循环 idle 钩子、合并唤醒次数、降采样频率；⑥ 电源效率：DCDC 比 LDO 效率高、动态调压（DVFS）
  • 指标：平均功耗 = 峰值 × 占比 + 睡眠 × 占比，按电池容量算续航（mAh ÷ 平均 mA）
「关时钟、断外设、快进快出睡眠态；唤醒合并、采样降低、DCDC 提效率」
Q72STM32 的睡眠、停机、待机模式有什么区别？🔥 高频
模式CPU时钟/外设唤醒源唤醒后
Sleep 睡眠停时钟照跑，外设可用任意中断立即继续（最快）
Stop 停机停全部时钟停，SRAM 保留EXTI/唤醒引脚/RTC系统时钟需重新配置
Standby 待机停全停，SRAM 丢失（只留备份域）WKUP 引脚/RTC/复位相当于复位重启（最省电）
  • 选型：短暂空闲 Sleep，较长空闲 Stop，超长待机 Standby；电流量级：Sleep μA~mA、Stop μA 级、Standby 亚 μA 级
  • 关键坑：Stop 唤醒后必须重新配置时钟（HAL_RCC_ClockConfig），否则外设异常；调试器会干扰睡眠（用 DBGMCU 配置）
「睡、停、待三档：睡最浅立刻醒，停要重配时钟，待最省却要重启」
Q73怎么测量系统功耗？怎么分析电流曲线？
  • 测量手段：① 万用表串联测平均电流（粗）；② 示波器 + 采样电阻（1Ω）测动态电流波形；③ 专用功耗分析仪/电流探头（μA 精度）；④ 板载检测电路
  • 分析要点：① 看唤醒瞬间的尖峰（RF 发射、Flash 写、外设启动）是否过大/过长；② 看睡眠电流是否稳定（漏电流、悬空引脚、LDO 空耗）；③ 按场景分段（运行/短睡/深睡）统计占比算平均功耗
  • 常见「偷电」元凶：悬空 GPIO 漏电、上拉电阻太大耗电反而不高（下拉合理）、LED 限流、稳压器静态电流、外设未关时钟
「串联测平均、示波器看波形、分析仪抠 μA；悬空引脚和外设时钟是偷电大户」
Q74低功耗模式下有哪些唤醒源？唤醒后要注意什么？
  • 唤醒源：EXTI 外部中断（按键/传感器中断）、RTC 闹钟/唤醒定时器、UART/通信中断（如 LPUART）、WKUP 专用引脚、比较器
  • 设计要点：① 唤醒源本身的功耗——传感器中断引脚常开但传感器自身电流要小；② 边沿 vs 电平——电平唤醒可能反复触发，用边沿 + 软件去抖；③ 唤醒后状态恢复——时钟重配、外设重初始化、标志位处理
  • RTC 定时唤醒 + 外部事件唤醒组合，实现「周期巡检 + 事件响应」的低功耗架构
「外部中断、RTC、WKUP 三主力；唤醒后先重配时钟再干活」
Q75低功耗和看门狗冲突吗？怎么处理？
  • 冲突：看门狗要周期喂狗，但睡眠时 CPU 停转无法喂，睡眠久了看门狗超时强制复位——产品反复重启
  • 处理方案：① RTC 周期唤醒喂狗——睡一段时间唤醒喂一次再睡（最常用）；② 独立看门狗超时设 > 最大睡眠周期（睡眠前先喂，醒后立刻喂）；③ 用窗口看门狗 + 关闭调试冻结，配合唤醒策略；④ 有的芯片支持看门狗在低功耗模式下自动冻结/暂停（如某些系列）
  • 工程原则：低功耗产品要保证「系统活着」的语义不被睡眠破坏——要么睡眠窗口小于看门狗超时，要么有唤醒喂狗机制
「睡觉前喂饱狗，RTC 定时叫醒再喂；狗超时大于最长睡眠期」
Q76什么是时钟树？系统时钟怎么配置？
  • 时钟树：芯片内部时钟源 → PLL → 总线分频 → 外设时钟的分配结构；所有外设时钟都来自这个树
  • 时钟源：HSI（内部 RC）/ HSE（外部晶振）/ LSI / LSE（低速 32.768kHz RTC）；PLL 倍频得到高速系统时钟
  • 典型链路：HSE 8MHz → PLL ×9 → SYSCLK 72MHz → AHB 72M → APB1 36M（÷2）/ APB2 72M；外设时钟从 AHB/APB 再分频（UART 波特率由 APB 时钟算）
  • 注意：超频/欠频、外设分频错误会导致外设跑飞；换外部晶振要改 HSE_VALUE 和 PLL 配置；低功耗切换时钟源
「源→PLL→AHB→APB→外设，一条树链分到底；换晶振必改 PLL，分频错了外设疯」
Q77电源方案怎么选？LDO 和 DCDC 有什么区别？
对比LDO（低压差线性）DCDC（开关电源）
原理线性降压，多余能量变热电感开关斩波，能量转换
效率压差越大效率越低（Vout/Vin）高（85%~95%），与压差关系小

  • 工程组合：电池 → DCDC（主电压）→ LDO（模拟/低噪支路）；每路注意去耦电容、ESR、上电时序（多电压轨先核后外设）
「LDO 干净但热，DCDC 高效但有纹波；大电流 DCDC、模拟支路 LDO、上电时序要排好」

  • 输出通道：UART 重定向（fputc 到串口）最常用；也可用 SWO（SWD 单线）、USB CDC、SEGGER RTT（J-Link 高速，不占 UART）
  • 实现：重定向 fputc/_write；关优化（-O0 或 --no_std_redirect）避免 printf 失效；MCU 需启用 MicroLib 或精简版 printf 省资源
  • 工程化：① 分级日志（LOG_DEBUG/INFO/WARN/ERR 宏，条件编译控制）；② 加时间戳/任务名；③ 异步发送（中断/DMA 队列）防阻塞；④ 发布版关掉调试日志（省空间省时间）
  • 坑：printf 不可重入——中断里别调；没接串口硬件时 printf 会阻塞等待发送导致程序卡死
「分级宏 + 时间戳 + 异步发送；中断别 printf，发布关日志」
Q80程序进 HardFault 怎么排查？🔥 高频
  • HardFault 常见原因：野指针/空指针解引用、数组越界写坏返回地址、栈溢出、访问非法地址（未使能时钟的外设）、写只读区域（const/Flash）、除零、未对齐访问
  • 排查四步：① 看 PC 值——在 HardFault_Handler 里读 LR/PC（或从栈帧恢复），PC 落在哪个函数；② 看 LR 与调用栈——反汇编（addr2line / IDE 反汇编窗口）定位到 C 代码行；③ 看哪个指针/数组——检查嫌疑函数里最近操作的指针；④ 复现路径——加日志缩小范围
  • 工程防护：① 开编译器栈检查 + 看门狗；② 指针用前判空；③ 外设访问前确认时钟已开；④ 用 MPU 保护；⑤ 保留 HardFault 现场 dump（PC/LR/寄存器存 Flash）便于事后分析
// HardFault 现场保存：进中断先抓寄存器再复位，事后查 Flash
void HardFault_Handler(void) {
    fault_rec.pc = __get_IPSR() ? 0 : 0;  // 用汇编抓 PC/LR/SP
    __asm volatile("MRS R0, MSP\n\t"
                   "MRS R1, PSP\n\t"
                   "STR R0, [SP, #-4]! ...");
    save_to_flash(&fault_rec);            // 掉电/复位前落盘
    NVIC_SystemReset();
}
「PC 定位、LR 看栈、指针开查；野指针越界访问未使能时钟是三大元凶」
Q81在线调试（断点/单步）有哪些技巧？有什么局限？
  • 技巧：① 硬件断点 vs 软件断点（Flash 程序用硬件断点，数量有限）；② 条件断点（满足条件才停，如 i==100）；③ 数据断点/监视点（变量被改写时触发——查「谁改了它」神器）；④ 单步 + 反汇编看底层；⑤ 运行到光标/跳到光标；⑥ 在线修改内存/变量（强测分支）
  • 局限：① 硬件断点数量少；② 时序敏感代码（中断、通信时序）打断后行为变化（heisenbug）；③ 优化代码调试困难（变量被优化）；④ 睡眠模式下调试器断不开；⑤ 不能测死锁/竞争类问题
  • 替代：日志 + 状态 dump + 单元测试覆盖逻辑
「条件断点省事、数据断点抓改写者；时序敏感代码别打断，靠日志说话」
Q82嵌入式代码怎么做单元测试？🔥 高频
  • 单元测试：把纯逻辑模块（算法、协议解析、状态机、计算）单独拿出来在主机（PC）上测试，不依赖硬件
  • 框架：Unity / Ceedling（轻量 C）、CMock（mock 硬件接口）、GoogleTest（C++）、自制断言宏
  • 策略：① 硬件无关层（HAL 抽象接口）——被测代码调 HAL，测试时 mock 掉 HAL；② 用编译器在 PC 上编译（可移植代码）；③ 数据驱动测试（输入表 + 期望输出表）
  • 覆盖重点：协议解析边界、状态机全路径、溢出/负数边界、时序逻辑（用虚拟时间）；配合覆盖率工具（gcov）看 line/branch 覆盖
「逻辑抽出来，HAL 接口 mock 掉，PC 上跑 Unity；边界、状态机、覆盖率三件套」
Q83静态分析工具能发现什么问题？
  • 静态分析：不运行代码，通过语法/数据流/控制流分析找出潜在 bug 和风格问题
  • 能发现：① 空指针/野指针；② 数组越界；③ 未初始化变量；④ 资源泄漏（malloc 未 free）；⑤ 死代码/不可达分支；⑥ MISRA-C 违规（汽车/安全行业规范：禁 goto、限深嵌套、类型转换显式化）；⑦ 未定义行为
  • 工具：PC-lint / Coverity / Clang-Tidy / Cppcheck（开源）、编译器 -Wall -Wextra -Werror 开启告警
  • 落地：CI 里自动跑 + 告警清零；静态分析 + 代码评审 + 单元测试三道防线
「不跑代码就揪 bug：空指针越界未初始化；MISRA-C 安全线，CI 里自动查」
Q84示波器和逻辑分析仪分别用来查什么问题？
  • 示波器：看模拟信号——电压波形、时序、毛刺、纹波、上升沿过冲；适合查：电源纹波、PWM 波形、串口电平、晶振起振、EMI 噪声
  • 逻辑分析仪：看数字信号多位——同时抓多路 0/1 并协议解码（UART/I2C/SPI/CAN）；适合查：协议时序、命令交互、地址/数据错位、总线仲裁
  • 使用要点：① 触发设置（边沿/协议触发）抓「出事前」的数据；② 采样率 ≥ 信号带宽 5~10 倍；③ 探棒接地要短（否则引入噪声）；④ 差分信号（CAN/485）用差分探头
「示波器看模拟波形，逻辑分析仪解码数字协议；触发抓现场，采样率给足」
Q85嵌入式项目怎么做版本管理和回归测试？
  • 版本管理：Git 管理代码 + 固件版本号（V1.2.3）写入代码/Flash，OTA 和现场升级靠版本号判定；编译信息（时间、commit hash）打印到 boot log
  • 分支策略：开发分支 + release 分支 + 打 tag；硬件版本（板卡 rev）与固件版本要联动记录（同一固件兼容多板卡用宏/配置）
  • 回归测试：改一个功能后跑全量用例防「修好这个坏了那个」；做法：① 自动化测试脚本（Python + pytest + 串口/HIL）跑指令用例；② 硬件在环（HIL）：真实板卡 + 模拟激励；③ 压力/老化测试（长时间运行、反复上下电）
  • CI 落地：代码提交 → 编译 + 静态分析 + 单元测试（PC 上）→ 构建固件 → 部署到测试台跑回归
「版本号三连 + commit 烙印，OTA 认号不认人；HIL + 自动化回归，压力老化兜底」

11安全与可靠性

Q86OTA 升级方案怎么设计？掉电中断怎么办？🔥 高频
  • 经典方案：双分区（A/B 镜像）——App A 运行，新固件下载到 App B，校验通过后切换启动标志，下次启动跑 B；A 保留作回滚
  • 流程：下载 → 校验（CRC/SHA）→ 写入 Flash → 置升级标志 → 重启 → bootloader 判断 → 切分区 → 运行 → 上报成功 → 清除旧分区
  • 掉电保护：① 升级状态存非易失标志（如「正在升级中」位），启动时检测：若新固件校验失败/启动失败 → 自动回滚旧分区；② 写 Flash 分块 + 每块校验；③ 升级过程不覆盖 bootloader
  • 进阶：增量升级（差分）、签名校验（防篡改）、升级失败自动恢复 + 上报服务器、升级窗口（避免关键时刻升级）
「A/B 双分区保命，标志位记录进度，校验不过自动回滚；bootloader 永远不动」
Q87什么是安全启动（Secure Boot）？🔥 高频
  • 安全启动：从信任根（ROT）开始逐级验证的启动链——ROM 代码验证 bootloader，bootloader 验证固件签名，任何一级校验失败即拒绝启动
  • 技术要点：① 非对称签名——固件用私钥签名，芯片内置公钥验签（防篡改/防伪造）；② 哈希链——逐级计算哈希对比；③ 防回滚——版本号单调递增，禁止降级（防降级攻击）；④ 安全烧录——读保护（RDP）+ 调试口锁定，防止提取固件
  • 硬件支持：安全区/可信执行环境（TEE）、OTP 熔丝存公钥、加密加速器；STM32 的 RDP + 选项字节、NXP 的 HAB
  • 作用：防止固件被篡改、被逆向、被克隆，是物联网安全的基础
「信任根起手，私钥签名公钥验，逐级哈希防篡改，版本防回滚，调试口锁死」
Q88嵌入式里常用哪些加密算法？怎么选？

Q89怎么提高嵌入式系统的可靠性？🔥 高频
  • 可靠性手段分层：防（设计）→ 检（检测）→ 恢复（自愈）
  • 硬件层：看门狗、电源监控（欠压复位）、冗余设计（双备份/热备）、去耦滤波、ESD/EMC 防护、宽温器件
  • 软件层：① 看门狗 + 任务健康检查；② 数据校验（CRC、双份存储互比对）；③ 关键参数掉电保护（双备份 + 标志位）；④ 输入边界检查（长度/范围）；⑤ 错误处理全覆盖（else 分支、异常路径）；⑥ 状态机防非法迁移
  • 恢复策略：软复位 → 系统重启 → 进入安全模式（保留诊断信息）；故障记录（错误码存 Flash）便于现场分析
「防检恢复三层：看门狗兜底、校验保数据、冗余保功能；故障留痕好分析」
Q90什么是功能安全？ISO 26262 是什么？
  • 功能安全：系统在发生故障时仍能安全降级/停机，不危害人身与环境——「出了错也不能出人命」
  • ISO 26262：汽车电子功能安全标准，核心是 ASIL 等级（A/B/C/D 从低到高，D 最严），按危害严重度、暴露率、可控性评估
  • 实现手段：① 冗余（双通道/锁步核）；② 自检（RAM 测试、Flash CRC、时钟监控、CPU 寄存器测试）；③ 安全机制（看门狗、电压监控、错误处理）；④ 开发流程（需求追踪、代码评审、测试覆盖率要求、工具认证）
  • 其他领域：工业 IEC 61508、医疗 IEC 62304——理念相通：安全生命周期 + 安全完整性等级（SIL）
「出故障也要安全：冗余 + 自检 + 看门狗；ASIL 定等级，流程文档齐步走」
Q91什么是 EMC/ESD？软件上能做什么？
  • EMC（电磁兼容）：设备不干扰别人（EMI 发射） + 不怕别人干扰（EMS 抗扰）；ESD（静电放电）是其中一种，人体接触/空气放电可能打坏芯片
  • 硬件对策：屏蔽、接地、滤波（磁珠/电容）、TVS/ESD 保护器件、PCB 布局（阻抗、回流路径、隔离）
  • 软件对策：① GPIO 滤波（输入滤波、消抖）；② 看门狗兜底（干扰导致跑飞自动恢复）；③ 关键数据冗余/校验（RAM 里双份，Flash 里校验）；④ 通信帧 CRC + 超时重发；⑤ 上电自检（RAM/Flash/时钟）；⑥ 异常中断（BusFault 等）处理函数兜底
  • 测试：静电枪、浪涌、辐射/传导骚扰测试（认证级）
「硬件滤波屏蔽接地，软件看门狗 + 数据校验 + 自检兜底；干扰来了能自愈」
Q92怎么防止固件被抄板/被破解？
  • 固件防护手段：① 读保护 RDP（锁定调试口，防读出 Flash）；② 固件加密存储（启动时解密运行）；③ 代码混淆/加壳（对抗静态分析）；④ 关键算法放安全芯片/加密 MCU；⑤ 防调试检测（检测调试器连接）；⑥ OTP 熔丝烧死配置
  • 防抄板联动：① 芯片唯一 ID 绑定——固件校验 MCU 唯一 ID，非法芯片跑不起来；② 安全启动 + 签名（防换芯片）；③ 一机一密（每台设备密钥不同）
  • 局限认知：没有绝对安全——目标是提高破解成本到「不值得破解」；物理攻击（去封层、探针）只能靠安全芯片对抗
「读保护 + 加密存储 + 唯一 ID 绑定 + 签名启动，四道锁；没有绝对安全，只有不值得破解」
Q93什么是容错设计？双机热备怎么做？
  • 容错：系统局部故障时整体仍能工作或安全降级，通过冗余 + 表决 + 故障隔离实现
  • 冗余级别：① 部件冗余（双电源、双存储）；② 整机冗余（双机热备/冷备）；③ 信息冗余（校验、双份存储、ECC）
  • 双机热备：A 机主、B 机备，心跳（heartbeat）互相监测；A 故障 → B 自动接管（切换 IP/总线控制权），A 恢复后同步状态再切回
  • 嵌入式实现要点：① 心跳超时阈值（防误判）；② 切换原子性（同一时刻只有一个主）；③ 状态同步（增量同步）；④ 主备仲裁机制（谁拿总线控制权）
「冗余 + 心跳 + 仲裁，主挂了备顶上；切换要原子，状态要同步」

12场景题与故障排查

Q94程序跑飞（PC 跳到乱地址）怎么排查？🔥 高频
  • 跑飞原因：① 栈溢出/数组越界覆盖了返回地址；② 野指针写坏函数指针/中断向量；③ 硬件干扰（强电磁）破坏 RAM；④ 中断里改共享变量导致状态错乱；⑤ 未初始化指针调用
  • 排查步骤：① 看跑飞后 PC 落在哪（HardFault/死循环处打印 PC）；② 反查调用栈（LR 链）；③ 检查嫌疑点：最近的大数组/缓冲区操作（memcpy 长度）、悬空指针、中断与主流程共享变量；④ 用数据断点监控返回地址被写的瞬间；⑤ 对照 map 文件看 PC 落在哪个函数附近
  • 防护：栈检查 + 看门狗 + MPU + 关键结构体加 magic 字段校验；所有中断向量表兜底（未用中断填死循环）
「PC 落地查 map，LR 链找现场；数组越界和野指针是头号嫌疑，数据断点抓现行」
Q95系统反复重启/复位，怎么定位？🔥 高频
  • 先区分复位来源：电源复位 / 看门狗复位 / 软复位 / 引脚复位——读 RCC 复位标志寄存器（RCC_CSR） 判断
  • 看门狗复位：查主循环是否卡死（喂狗点没执行）——用日志记录最后一次运行到哪；常见：死循环、长阻塞（printf 等不到）、任务饿死
  • 电源问题：电压跌落（电池没电、负载过重、DCDC 不稳）、欠压复位（BOR）——示波器看 VDD 波形
  • 程序问题：HardFault 里直接调复位、未初始化变量触发异常、看门狗初始化后没喂
  • 排查技巧：① 上电打印 boot 原因（复位标志）；② 不同阶段喂不同颜色的 LED/写日志标志；③ 去掉看门狗单独跑，区分「程序问题」还是「狗咬的」
「先看复位标志分来源，狗咬查卡点、欠压测电源、程序错看 HardFault」
Q96栈溢出会有什么症状？怎么快速判断？
  • 症状：① 局部变量莫名被改（被越界的别的函数覆盖）；② 函数返回后行为异常/跑飞；③ 表现随机——有时好有时坏（取决于调用路径）；④ 中断里一开大数组就崩
  • 快速判断：① 断点在「可疑处」看SP 是否接近栈底/顶；② 编译器栈填充 + 查看未用区域是否还是 0xAA（Keil/IDE 栈窗口）；③ FreeRTOS 看 uxTaskGetStackHighWaterMark；④ 增大栈后问题消失 = 栈不够
  • 根治：找最大调用深度 + 最大局部变量的路径（通常是大数组 + 深嵌套 + 中断嵌套叠加），优化：大缓冲改静态/全局或堆、递归改循环、减少中断嵌套
「变量莫名变、返回就跑飞、时好时坏——九成是栈被踩；加大栈一试便知」
Q97I2C 总线卡死（SDA 一直被拉低）怎么办？🔥 高频
  • 现象：主机发数据无 ACK 响应、SDA 恒为低、通信中断——通常是从机处于异常状态把 SDA 锁住（如从机复位后状态机错乱）
  • 现场救法：给 SCL 连打 9~16 个时钟脉冲，让卡住的从机状态机走到「空闲」，释放 SDA（ST 官方推荐）；或复位从机（电源/复位引脚）；硬件上重初始化 GPIO 为上拉输入
  • 软件防卡死：① 所有 I2C 操作加超时（HAL 的 Timeout 参数）；② 检测到总线忙先发 STOP 再重试；③ 从机侧加看门狗/错误恢复；④ 硬件上 SDA/SCL 加串联电阻防闩锁
  • 根治：查从机上电时序（主机先于从机启动时从机可能未就绪）、上拉电阻值（太小驱动不足/太大过慢）、从机固件 bug
「SDA 锁低是常态病：9 个时钟脉冲救回来；操作全加超时，从机加看门狗」
Q98整机功耗比设计值高很多，怎么排查？
  • 排查套路（从大到小）：① 先量整机电流确认差异量级；② 模块级断电法——逐个断开外设模块（传感器/无线/显示屏）找「大头」；③ 软件排查：是否真的进入睡眠（睡眠标志、电流波形）、外设时钟是否关闭、GPIO 是否悬空（浮空输入漏电）、是否有任务一直在唤醒系统
  • 常见元凶：① 睡眠模式配错（Stop 没进去/频繁被唤醒）；② 唤醒源太频繁（定时器 1ms 唤醒一次等于没睡）；③ 外设睡眠电流大（无线模块没关）；④ GPIO 浮空或驱动 LED 常亮；⑤ LDO 静态电流、电阻分压网络常通电
  • 工具：功耗分析仪看时间占比；波形看唤醒频率是否过高
「整机→模块→软件三段查；唤醒太频繁、GPIO 悬空、外设没关是三大偷电贼」
Q99串口收到乱码/数据错位，怎么排查？🔥 高频
  • 排查清单（按概率排序）：① 波特率不匹配（最常见，尤其两边都用内部 RC 时钟）；② 电平不匹配（TTL 直连 RS232、3.3V 对 5V）；③ 校验位/停止位/数据位配置不一致；④ 共地问题（两设备地电位不同）；⑤ 线缆过长/干扰（换双绞/屏蔽、降波特率）；⑥ 软件：接收缓冲溢出丢字节、中断里处理太久漏帧
  • 验证手段：① 示波器/逻辑分析仪解码波形看实际波特率（数一位的宽度）；② 发固定 0x55（01010101）看波形；③ 双方都设相同配置 + 短接线测试排除硬件
  • 长帧数据错位但短帧正常：接收端处理不及时丢字节，用 DMA + 环形缓冲或提高中断处理效率
「乱码先查波特率电平校验，示波器数位宽见真章；错位是丢字节，DMA 环形缓冲来救」
Q100定时器计时不准/有漂移，原因有哪些？
  • 原因：① 时钟源不准——内部 RC（HSI）误差可达 ±1%~2%，要求高的用外部晶振（HSE）；② 晶振负载电容不匹配/起振不稳；③ 分频配置错误（PSC/ARR 算错）；④ 中断延迟——定时器中断被高优先级中断长时间打断，软件计数会漂；⑤ 温度变化（晶振频漂）
  • 排查：用示波器/频率计量实际中断频率；对比 SYSCLK 实际值
  • 解决方案：① 高精度场景用 TCXO/晶振 + 校准；② 用 RTC 或 GPS/网络对时周期校正；③ 软件补偿（测量误差系数）；④ 长定时用硬件定时器级联减少软件计数误差；⑤ 关掉无关中断对计时的干扰（BASEPRI）
「RC 不准换晶振，分频算错仔细查，中断干扰用 BASEPRI；要求高上 TCXO 加对时」
Q101掉电后 Flash 里存的参数丢了/损坏了，怎么解决？🔥 高频
  • 根因：写 Flash 需要先擦后写、按页操作，写入过程中掉电（擦了一半/写了一半）→ 数据损坏；或参数频繁写同一地址 寿命耗尽
  • 方案：① 双备份存储——存两份 + 校验，读时校验失败用备份；② 标志 + 数据 + CRC 结构：写时先写「新数据 + CRC」再写「有效标志」，掉电后读标志判断新旧；③ 写日志（log）模式——每次写追加到新位置，启动时扫描最新有效记录（类 Flash 文件系统，如 LittleFS）；④ 磨损均衡——轮换扇区
  • 掉电检测：用电源监测（PVD/BOR）检测电压跌落，预留毫秒级时间把关键数据写完（先关中断、关外设，紧急写 Flash）
「双备份 + CRC + 有效标志，掉电不怕半截数据；PVD 提前察觉，轮换扇区延寿命」
Q102RTOS 里某个任务不跑了/系统卡死，怎么排查？
  • 排查工具：① vTaskList 打印所有任务状态——看卡住的任务在 Blocked（等什么）/ Ready（没被调度）；② 调试器看任务栈——卡在哪个函数；③ 看 tick 是否还在走（SysTick 被关/卡死则全系统停）
  • 常见原因：① 等队列/信号量但没人 give（逻辑错误，查生产者）；② 优先级饥饿——高优先级任务死循环，低优先级永远不跑；③ 死锁——两个任务互相等锁；④ 任务栈溢出悄悄踩坏；⑤ 中断里调用普通 API 卡死；⑥ 临界区没退出（关中断后忘了开）
  • 排查顺序：看状态列表 → 看等什么资源 → 查谁该给没给 → 查优先级/死锁
「vTaskList 先看状态，Blocked 查谁欠资源，Ready 查优先级；临界区没退、中断调 API 都是坑」

typedef struct {
    uint8_t *buf;          // 缓冲区
    uint32_t head;         // 写指针（生产者）
    uint32_t tail;         // 读指针（消费者）
    uint32_t size;         // 容量（2 的幂便于取模）
} ringbuf_t;

void rb_init(ringbuf_t *rb, uint8_t *buf, uint32_t size) {
    rb->buf = buf; rb->head = 0; rb->tail = 0; rb->size = size;
}
int rb_is_full(ringbuf_t *rb) {
    return ((rb->head + 1) % rb->size) == rb->tail;   // 留一格判满
}
int rb_write(ringbuf_t *rb, uint8_t data) {
    if (rb_is_full(rb)) return -1;                     // 满则丢弃
    rb->buf[rb->head] = data;
    rb->head = (rb->head + 1) % rb->size;
    return 0;
}
int rb_read(ringbuf_t *rb, uint8_t *data) {
    if (rb->head == rb->tail) return -1;               // 空则返回失败
    *data = rb->buf[rb->tail];
    rb->tail = (rb->tail + 1) % rb->size;
    return 0;
}
  • 考察点：判空判满（留一格）、取模回绕、单生产者单消费者下无需加锁（中断与主循环各写一头）
  • 优化：size 取 2 的幂时 % size 可换成 & (size-1)
「head 写 tail 读，留一格判满，取模回绕；一头中断一头主循环，天然免锁」

node_t *reverse_list(node_t *head) {

    while (cur) {
        nxt = cur->next;      // 先存下一个
        cur->next = prev;     // 掉头
        prev = cur;           // 前移
        cur = nxt;
    }

}

    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return 1;
    }
    return 0;
}

// CRC8（多项式 0x07，初始值 0x00）——通信协议常用
uint8_t crc8(uint8_t *data, uint32_t len) {
    uint8_t crc = 0x00;
    for (uint32_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (int j = 0; j < 8; j++) {
            if (crc & 0x80) crc = (uint8_t)((crc << 1) ^ 0x07);
            else            crc = (uint8_t)(crc << 1);
        }
    }
    return crc;
}
// 使用：发送方算 crc8 附在帧尾；接收方算出的 crc 应为 0 或相等
  • 原理：把数据当作多项式，除以生成多项式取余；逐位异或模拟除法
  • 考察点：移位方向、多项式选择（协议规定）、初值/结果异或——各协议 CRC 变体不同，按手册来
「逐位异或模拟除法，移位异或多项式；算法固定查手册，变体别搞混」

static uart_st_t st = S_HEAD1;
static uint8_t  rx_buf[64], idx = 0, len = 0, sum = 0;

void uart_rx_byte(uint8_t b) {            // 每收到一字节调用
    switch (st) {
        case S_HEAD1: if (b == 0xAA) st = S_HEAD2; break;
        case S_HEAD2: st = (b == 0x55) ? S_LEN : S_HEAD1; break;
        case S_LEN:
            if (b <= 64) { len = b; idx = 0; sum = b; st = S_DATA; }
            else          { st = S_HEAD1; }              // 长度非法复位
            break;
        case S_DATA:
            rx_buf[idx++] = b; sum += b;
            if (idx >= len) st = S_CHK;
            break;
        case S_CHK:
            if (b == sum) { /* 帧有效：处理 rx_buf */ }
            st = S_HEAD1;                                // 无论对错回到找头
            break;
    }
}

Q108手写：简易时间片轮转调度器
// 非抢占式时间片轮询：定时器每 1ms 置 task_ready，主循环按轮次执行
#define TASKS_MAX 4
typedef struct {
    void (*fn)(void);
    uint16_t period;       // 执行周期（ms）
    uint16_t counter;      // 递减计数器
} task_t;
static task_t tasks[TASKS_MAX];
static uint8_t  task_cnt = 0;

void sched_add(void (*fn)(void), uint16_t period_ms) {
    if (task_cnt >= TASKS_MAX) return;
    tasks[task_cnt].fn = fn; tasks[task_cnt].period = period_ms;
    tasks[task_cnt].counter = period_ms; task_cnt++;
}
void sched_tick(void) {                    // 定时器中断里调用（1ms）
    for (uint8_t i = 0; i < task_cnt; i++)
        if (tasks[i].counter) tasks[i].counter--;
}
void sched_run(void) {                     // 主循环里调用
    for (uint8_t i = 0; i < task_cnt; i++) {
        if (tasks[i].counter == 0) {
            tasks[i].fn();                 // 注意：fn 内不能阻塞太久
            tasks[i].counter = tasks[i].period;
        }
    }
}
// main: 定时器 1ms 中断调 sched_tick；主循环调 sched_run
  • 考察点：周期调度思想、任务表、非阻塞要求——这是裸机「软定时器」的常见实现
「任务表 + 计数递减，到期执行再重装；回调别阻塞，1ms 节拍驱动」

// 二分查找（数组必须有序）：返回下标，找不到返回 -1
int binary_search(int *a, int n, int target) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // 防 (lo+hi) 溢出
        if (a[mid] == target) return mid;
        else if (a[mid] < target) lo = mid + 1;
        else                     hi = mid - 1;
    }
    return -1;
}

// 选择排序：每轮找最小放前面，O(n^2)，适合小数组
void selection_sort(int *a, int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[min]) min = j;
        int t = a[i]; a[i] = a[min]; a[min] = t;
    }
}
  • 考察点：边界（lo<=hi）、防溢出取中、排序稳定性；嵌入式数据量小，简单排序够用
「取中防溢出，边界闭区间；选择排序找最小换前面」
