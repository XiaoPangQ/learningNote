01语言基础与编译链接

Q1C++ 从源码到可执行文件经历哪几个阶段？🔥 高频

四阶段：预处理 → 编译 → 汇编 → 链接。

  • 预处理（gcc -E）：处理 #include / #define / #ifdef，展开宏与头文件，生成 .i 文件
  • 编译（-S）：词法/语法/语义分析 + 优化，生成汇编代码 .s
  • 汇编（-c）：汇编代码转机器码，生成目标文件 .o（含符号表、重定位信息）
  • 链接：合并各 .o 与库，符号解析 + 重定位，生成可执行文件

常见链接错误：undefined reference（符号未定义）、multiple definition（重复定义，头文件里定义非 inline 函数/变量是典型原因）。

「预编汇链」四部曲；头文件只放声明，定义放 .cpp 就不重定义
Q2C 和 C++ 有什么区别？🔥 高频
维度CC++
范式面向过程面向过程 + 面向对象 + 泛型
类型检查较弱（void* 随意转）更严格（强类型、函数必须声明）
内存malloc/freenew/delete + 智能指针 RAII
函数不支持重载支持重载（名字修饰 name mangling）
标准库精简（stdio/stdlib）STL 容器算法流
异常无（错误码/setjmp）try/catch 异常机制
  • C++ 几乎完全兼容 C 语法，但思维范式不同
  • C++ 依旧保留高性能系统级能力，同时提供抽象不损失性能（zero-overhead）
「C 是刀，C++ 是瑞士军刀」：面向过程升级为 OOP + 泛型
Q3C++ 标准版本如何演进？各版本核心特性？
  • C++98/03：第一个正式标准；STL、string、auto_ptr
  • C++11（现代 C++ 起点）：auto、lambda、智能指针、右值引用/移动语义、nullptr、range-for、thread、constexpr、enum class
  • C++14：小版本修补——泛型 lambda、auto 返回值、make_unique
  • C++17：结构化绑定、if constexpr、optional/variant/string_view、并行算法、折叠表达式
  • C++20（四大件）：concepts、ranges、coroutines、modules，还有三路比较 <=>
「98 打底，11 革命，14 修补，17 实用，20 四大件」
Q4static 关键字有哪几种用法？🔥 高频
  • 静态局部变量：存放在全局/静态区，只初始化一次，函数退出仍保留值（C++11 保证初始化线程安全）
  • 静态全局变量/函数：内部链接，仅本编译单元（.cpp）可见，避免命名冲突
  • 类静态成员变量：所有对象共享一份，须在类外定义（C++17 可 inline 声明）
  • 类静态成员函数：无 this 指针，只能访问静态成员，可用「类名::」直接调用
「局部保命、全局限本、成员共享、函数无 this」四用法
Q5const 关键字有哪些用法？🔥 高频
  • 修饰变量：只读，定义时必须初始化
  • 修饰指针：指针常量与常量指针（详见指针章节，口诀「左定值右定针」）
  • 修饰函数参数：const std::string& 传参避免拷贝又防修改
  • 修饰成员函数：不修改成员变量（mutable 例外），const 对象只能调 const 函数
  • 修饰返回值：防止返回值被当左值修改
「变针参函返」五处 const；成员函数尾 const = 只读承诺
Q6const 和 constexpr 有什么区别？
  • const：运行期只读承诺——「初始化后不能改」，但初始值可以是运行期变量
  • constexpr：编译期常量/常量表达式——「编译期就能算出」，可用于数组大小、模板参数
  • constexpr 函数：传编译期常量则在编译期求值（可当内联用），传运行期变量退化为普通函数
「const 只读，constexpr 编译期」；要进模板/数组维度必须 constexpr
Q7#define、const、inline 各适合什么场景？
  • #define 宏：预处理文本替换——无类型检查、不进符号表、有副作用陷阱（如 MAX(i++, j) 展开出错），仅适合条件编译与简单常量
  • const/constexpr：有类型、有作用域、可调试，定义常量首选
  • inline 函数 / 模板：替代宏函数，有类型检查且避免副作用
「常量用 const，函数用 inline，宏只留给条件编译」
Q8extern "C" 的作用是什么？🔥 高频

C++ 支持函数重载，编译器会对函数名做名字修饰（name mangling）（如 foo(int) 变成 _Z3fooi）；C 不修饰，直接用原名。

  • extern "C"：告诉 C++ 编译器「这段代码按 C 方式修饰符号」——让 C++ 能链接 C 编译的库（反之亦然）
  • 典型用法：C 头文件中被 C/C++ 共用时加条件宏包裹
  • 被 extern "C" 修饰的函数不能重载（C 无重载）
#ifdef __cplusplus
extern "C" {        // C++ 编译器才认识这段
#endif
void c_api_init();  // 按 C 规则生成符号，不参与重载
#ifdef __cplusplus
}
#endif
「C++ 名字会变装，extern "C" 卸妆再链接」
Q9inline 关键字的本质是什么？一定会被内联吗？🔥 高频
  • 本质是对链接器的建议（ODR 豁免）：允许多个编译单元中出现同一函数定义而不报重复定义
  • 是否真正内联展开由编译器决定——递归、循环、函数体大都不展开；优化选项（-O2）也影响
  • 类内定义的成员函数隐式 inline
  • 现代 C++ 更推荐 inline 表达「头文件可安全重复定义」（如 inline 变量、模板）
「inline 是建议不是命令；防重定义比内联更重要」

02数据类型与内存模型

Q10C++ 程序的内存分区是怎样的？🔥 高频
  • 代码区（text）：机器指令，只读共享
  • 全局/静态区：全局变量、static 变量；C++11 后细分为已初始化 .data 与未初始化 .bss（bss 不占文件体积）
  • 常量区：字符串字面量等只读数据（rodata）
  • 堆（heap）：new/malloc 手动管理，向高地址增长，分配慢但空间大
  • 栈（stack）：局部变量、函数参数、返回地址，向低地址增长，自动回收、快但有限（默认 1~8MB）
「代码、全局、常量、堆、栈」五区；栈快而小，堆大而慢
Q11sizeof(空类)、sizeof(含虚函数的类) 是多少？为什么？🔥 高频
  • 空类 sizeof = 1：保证每个对象有唯一地址（两个对象不能同址）
  • 含虚函数的类 = 指针大小（64 位为 8）：对象里存一个 vptr 指向虚函数表
  • 继承空基类：空基类优化（EBO）下可为 0
  • 静态成员、成员函数不占对象空间；成员函数在代码区共享
「空类为 1 保地址，虚类多一个 vptr 8 字节」
Q12什么是内存对齐？为什么需要？🔥 高频
  • 规则：成员偏移须是其自身对齐数（min(成员大小, #pragma pack 值)）的整数倍；结构体总大小是最大对齐数的整数倍
  • 为什么：CPU 按字长（如 8 字节）取数，未对齐访问在 x86 上变慢、在 ARM 上直接崩溃；对齐还能保证原子访问
  • 优化技巧：按成员大小从大到小排列可减少填充
  • #pragma pack(1) 取消填充——网络协议/文件格式场景用，代价是访问变慢
struct Bad {           // sizeof = 16（填充 6+2 字节）
    char  c;           // 偏移 0，填充 1~7
    double d;          // 偏移 8
    short s;           // 偏移 16，尾部填充 2
};
struct Good {          // sizeof = 16 但只填充 1 字节
    double d;
    short  s;
    char   c;          // 尾部填充 5（保证数组连续时也对齐）
};
「对齐是 CPU 的口味」：成员大到小排，体积更紧凑
Q13如何判断机器是大端还是小端？
  • 小端：低字节放低地址（x86、主流 ARM 默认）；大端：高字节放低地址（网络字节序）
  • 判断：用指针或联合体看首字节
int x = 1;
bool little = *(char*)&x == 1;  // 首字节是 1 → 小端
  • 网络传输用 htonl/ntohl 系列统一为大端（网络字节序）
「小端低低、大端高低」；x86 全家都是小端
Q14整型溢出与隐式转换有哪些坑？
  • 有符号溢出是未定义行为（UB），编译器可能直接优化掉你的溢出检查
  • 无符号回绕是良定义的：0u - 1 得到 4294967295
  • 经典坑：无符号与有符号混算会整体提升为无符号，for (unsigned i = n-1; i >= 0; --i) 永远循环
  • 隐式转换链：bool → char → int → long → double，窄化转换丢精度（列表初始化 {} 会直接报错，= 不报）
  • 安全写法：溢出前先判断（如 a > INT_MAX - b），或用更宽类型
「有符号溢出是 UB，无符号回绕是规定，混合运算变无符号」
Q15为什么浮点数不能用 == 直接比较？怎么判断 NaN？🔥 高频
  • 浮点数按 IEEE754 用二进制科学计数法存储，0.1 无法精确表示（0.1 + 0.2 != 0.3）
  • 正确比较：差值小于容差 fabs(a - b) < 1e-9；同数量级才可比，量级悬殊要相对误差
  • NaN 不等于任何值包括自己：x != x 为真即 NaN（标准库 std::isnan 更清晰）
  • ±0 相等但符号位不同；inf 参与运算的规则要了解
「浮点无精确，比差不比值；NaN 六亲不认连自己都不等」
Q16char*、char[]、std::string 有什么区别？
  • char* p = "abc"：指向常量区字符串，修改 p[0] 是 UB（应声明为 const char*）
  • char a[] = "abc"：数组在栈上拷贝一份，内容可修改，sizeof = 4（含 '\0'）
  • std::string：自动管理内存、可变长、含长度字段（O(1) 取 size），c_str() 暴露 C 接口
  • string 内部小字符串优化（SSO）：短字符串直接存对象内，不分配堆
「字面量在常量区别改，数组是拷贝随便改，string 全自动」
Q17struct 和 class 有什么区别？union 是什么？🔥 高频
  • 唯一语法区别：struct 默认 public 继承与成员，class 默认 private
  • 习惯约定：struct 表示纯数据聚合（POD），class 表示有行为封装的对象
  • union：所有成员共享同一块内存，大小 = 最大成员；同一时刻只有一个成员有效；带构造函数的成员让 union 变复杂（C++11 起需手动管理生命周期）
  • union 典型场景：协议字段复用、类型双关（但严格来说双关应走 memcpy）
「struct 默认公，class 默认私；union 共床不同房」
Q18enum 和 enum class 有什么区别？
  • 旧 enum：枚举值泄漏到外层作用域、隐式转 int、无法指定底层类型
  • enum class（C++11）：作用域限定（Color::Red）、不隐式转整型、可指定底层类型（enum class Color : uint8_t）
  • 新代码一律用 enum class，防命名冲突与误转换
「枚举类有三宝：限作用域、禁隐转、定底层」

03指针与引用

Q19指针和引用的区别？🔥 高频
维度指针引用
本质存地址的变量（占 8 字节）对象的别名（语法层面不是对象）
可否为空可 nullptr必须初始化且不能为空
可否重指向可改变指向绑定后不可换目标
多级有多级指针 int**无「引用的引用」
运算可 ++/-- 做指针算术无算术
  • 底层实现上引用通常也是指针，但语义上编译器可优化
  • 选择：可空用指针、不可空用引用；输出参数两者皆可，现代 C++ 倾向引用
「指针自由可为空，引用忠心不变节」
Q20什么是野指针和悬垂指针？如何避免？🔥 高频
  • 野指针：未初始化的指针，指向随机地址——定义指针必须立即初始化（nullptr）
  • 悬垂指针（dangling）：指向的内存已被释放（delete 后继续用、返回局部变量地址、容器扩容后旧迭代器）
  • 避免三板斧：① delete 后置 nullptr；② 不返回局部对象地址；③ 用智能指针 + RAII 让所有权显式化
  • 工具：AddressSanitizer（-fsanitize=address）可当场抓到 use-after-free
「未初始化是野，释放后是垂；置空、别返回局部、智能指针保平安」
Q21有了智能指针，为什么还要懂裸指针？
  • 智能指针本身内部就是裸指针，性能热点（游戏引擎、嵌入式）常刻意用裸指针 + 明确生命周期
  • 大量历史代码库与 C 接口（操作系统、驱动、第三方库）全是裸指针
  • 非拥有场景：观察指针（不管理生命周期）用裸指针或引用更轻量、语义更清楚
  • 面试考察的本质：内存模型与生命周期理解
「拥有用智能，观察用裸/引用」——所有权思维
Q22指针数组与数组指针的区别？
  • int* a[10]：指针数组——数组，10 个 int* 元素
  • int (*a)[10]：数组指针——指针，指向「含 10 个 int 的数组」（常用作二维数组参数）
  • 读法：跟优先级走，[] 优先级高于 *，括号改变结合
  • 同理区分：函数指针 int (*f)(int) 与指针函数 int* f(int)
「名先跟谁就是谁」：先跟 [] 是数组，先跟 * 是指针
Q23const int*、int* const、const int* const 分别是什么？🔥 高频
  • const int* p（常量指针）：指向常量的指针，不能通过 p 改值，但 p 可换指向
  • int* const p（指针常量）：指针本身是常量，指向不能换，值可通过 p 修改
  • const int* const p：两者都锁死
  • 记忆法：const 在 * 左边修饰值，在 * 右边修饰指针
int a = 1, b = 2;
const int* p1 = &a;   // *p1 只读，p1 可改
int* const p2 = &a;   // p2 只读，*p2 可改
const int* const p3 = &a;  // 全只读
p1 = &b;              // OK
// p2 = &b;           // 编译错误
「左定值、右定针、左右都定全锁死」
Q24函数指针是什么？回调怎么写？
  • 函数指针：指向函数入口地址的变量，用于把「行为」当参数传
  • 回调三件套：typedef 简化声明 → 注册 → 触发时调用
  • 现代替代：std::function + lambda 类型安全且能携带状态
void onEvent(int code) { /* ... */ }

void registerCallback(void (*cb)(int)) { cb(42); }

int main() {
    registerCallback(onEvent);          // C 风格
    registerCallback([](int c) {        // lambda 隐式转函数指针
        // 无捕获 lambda 可转
    });
}
「函数名即地址，回调传行为」
Q25this 指针是什么？
  • 隐含于每个非静态成员函数的指针参数，指向调用者对象，编译器把 obj.f() 转成 f(&obj)
  • 静态成员函数没有 this，因此不能访问非静态成员
  • const 成员函数里 this 是 const T*，这就是它只读的原因
  • *this 解引用得到对象本身；返回 *this 支持链式调用
「谁调用，this 指谁；static 无 this」
Q26NULL 和 nullptr 的区别？
  • NULL 在 C++ 里是整数 0：重载 f(int) 与 f(char*) 时，f(NULL) 会调 int 版本——违背直觉
  • nullptr 是独立类型 std::nullptr_t，只能转成指针类型，重载解析永远选指针版本
  • C++11 起一律用 nullptr，代码里出现 NULL 视为待改进
「NULL 是 0 会走错门，nullptr 是真空指针」
Q27void* 有什么用？C++ 的四种 cast？
  • void*：通用指针——可存任何地址但不能解引用/做指针算术，是 C 风格接口（malloc、线程参数）的通用货币
  • static_cast：普通相关类型转换（int→double、void*→T*），编译期检查
  • dynamic_cast：多态类型向下安全转换，失败返回 nullptr（指针）或抛异常（引用）
  • const_cast：增删 const（小心 UB）
  • reinterpret_cast：位模式重解释，最危险，只用于底层
「静态算术、动态多态、const 管 const、reinterpret 重解释」

Q28构造函数有哪几种？默认构造、拷贝构造、移动构造的触发时机？🔥 高频
  • 默认构造：无参构造；成员有默认值初始化时用
  • 拷贝构造：T(const T&)——以值传参、以值返回、用已有对象初始化新对象时触发
  • 移动构造：T(T&&)（C++11）——用将亡值（std::move 结果、临时对象）初始化时触发，窃取资源不深拷贝
  • 委托构造：C++11 允许构造函数调用另一个构造函数复用逻辑
  • 编译器生成规则：Rule of Five——你定义了析构/拷贝/移动任一个，其余默认版本通常被删除或不合适，需一起处理
「值传递触发拷贝，move 触发移动」；Rule of Five 五件套一起管
Q29深拷贝与浅拷贝的区别？会带来什么问题？🔥 高频
  • 浅拷贝：逐位复制指针值——两个对象指向同一块堆内存
  • 后果：析构时双重释放崩溃；一方修改另一方跟着变
  • 深拷贝：复制指针的同时再申请内存复制内容，两对象完全独立
  • 编译器默认生成的拷贝构造/赋值是浅拷贝；类持有裸资源（指针/文件句柄）时必须自定义（或直接用 string/vector/智能指针，让成员自己管自己——Rule of Zero）
「浅拷共享必双删，深拷独立各管各」；能 Rule of Zero 就别 Rule of Five
Q30为什么基类析构函数要声明为虚函数？🔥 高频
  • 用基类指针 delete 派生类对象时：析构非虚 → 只调基类析构 → 派生类新增资源泄漏（UB）
  • 虚析构 → 从最派生类开始逐层正确析构
  • 经验法则：类要作为基类被多态使用 → 析构函数 public virtual；不作为基类 → 析构不虚且类可加 final
  • protected 非虚析构：允许派生但不允许通过基类指针删除（接口隔离场景）
class Base {
public:
    virtual ~Base() = default;  // 基类必备
};
class Derived : public Base {
    std::vector<int> data;       // 100MB
};
Base* p = new Derived;
delete p;   // 虚析构：先 ~Derived 再 ~Base，data 正确释放
「基类析构必虚，否则 delete 半途而废」
Q31explicit 关键字有什么用？
  • 禁止隐式转换：单参构造函数默认可用作隐式转换符，容易造成意外构造
  • 如 void f(MyStr s)，f("abc") 能编译——若 MyStr 构造加了 explicit 就必须显式 f(MyStr("abc"))
  • 现代建议：单参构造一律加 explicit（C++20 起甚至推荐多参构造也加）
「explicit 挡住隐式换乘」
Q32为什么用初始化列表？成员初始化顺序由什么决定？🔥 高频
  • 必须在列表初始化的成员：const 成员、引用成员、无默认构造的成员、基类构造
  • 效率：列表直接构造；构造体内赋值是「先默认构造再赋值」两步，多一次开销
  • 顺序陷阱：初始化顺序由成员声明顺序决定，与列表书写顺序无关——列表里用前一个成员初始化后一个时要小心
class T {
    int a;
    int b;
public:
    T(int v) : b(v), a(b) {}   // 危险！实际先 a(b)，此时 b 未初始化
};
「声明定顺序，列表只是名单」；const/引用/无默认构造必须走列表
Q33类的静态成员有什么特点？
  • 静态成员变量：类外共享一份，须类外定义（C++17 可 inline static 在类内定义）
  • 静态成员函数：无 this，只能访问静态成员；类名::函数() 直接调用
  • 静态成员不占对象空间，不计入 sizeof
  • 用途：对象计数器、全局单例句柄、工厂注册表
「静态成员类共有，函数没有 this 手」
Q34友元（friend）是什么？友元函数、友元类、友元成员函数？
  • 友元函数：非成员函数却能访问类私有成员——典型用于 operator<< 打印（左边是 ostream 不能写成成员）
  • 友元类：整个类的成员函数都可访问本类私有成员
  • 特点：单向、不传递、不继承、不受 public/private 位置影响
  • 使用原则：为运算符重载与紧耦合协作类使用，不做后门
「友元是单恋：我给你开门，你不用给我开」
Q35讲一下 C++ 对象的完整生命周期？
  • 构造顺序：虚基类 → 基类（声明序）→ 成员（声明序）→ 自身构造函数体
  • 析构顺序：完全相反（构造函数体 → 成员逆序 → 基类逆序）——栈式回退
  • 作用域结束 / delete / 异常展开时析构自动执行（RAII 的根基）
  • 临时对象（如函数返回值）在完整表达式结束处析构
  • 成员析构顺序与初始化列表写法无关，只看声明顺序
「构造披外套，析构脱外套」——顺序严格互逆

05封装继承多态

Q36C++ 三大特性是什么？分别解决什么问题？🔥 高频
  • 封装：public/private/protected 控制访问，隐藏实现、暴露接口，降低耦合（get/set、不变量保护）
  • 继承：代码复用 + 建立 is-a 关系，派生类扩展/特化基类（优先组合而非继承）
  • 多态：同一接口、不同行为——编译期多态（重载/模板）与运行期多态（虚函数）
  • 三者配合：封装守住边界，继承搭起层次，多态实现「一处调用，处处扩展」
「封装藏、继承传、多态变」

Q38什么是菱形继承？虚继承如何解决？🔥 高频

菱形继承：B、C 都继承 A，D 再同时继承 B、C——D 里含有两份 A，访问 A 成员产生二义性。

  • 虚继承（B、C 声明 virtual public A）：D 中只保留一份 A 子对象，由虚基类表/指针机制保证共享
  • 代价：虚基类对象大小增加、最派生类负责构造虚基类、访问多一次间接寻址
  • 工程建议：接口（纯虚类）多继承没问题；带状态的多重继承容易踩菱形坑，优先「单继承 + 多接口」
「菱形两份打架，虚继承凑一份」
Q39多态的实现原理？静态多态与动态多态的区别？🔥 高频

典型std::max、模板容器Shape::draw() 派生类各自实现
  • 动态多态三要素：虚函数 + 继承 + 基类指针/引用调用，缺一不可
  • 模板是「编译期生成不同函数」——零运行时开销，但代码膨胀
「重载模板编译定，虚函数运行查表定」
Q40讲讲虚函数机制：vtable 和 vptr 是怎么工作的？🔥 高频
  • 虚函数表（vtable）：每个「含虚函数的类」一张，编译期生成，存放在只读数据区，表项是各虚函数入口地址（派生类覆盖后表项指向自己的实现）
  • 虚表指针（vptr）：每个对象里一个隐藏指针（构造时由编译器写入），指向所属类的 vtable
  • 调用过程：p->f() → 取 p 的 vptr → 查表得到 f 地址 → 间接调用
  • 多继承时对象内可能有多个 vptr；虚继承再加虚基类表指针
  • 代价：对象 +8 字节、调用间接一层、阻碍内联与去虚化（devirtualization 优化）
「一类一表，一对象一针；调函数先查表再跳转」
Q41哪些函数不能是虚函数？为什么构造函数不能是虚的？
  • 构造函数不能虚：虚函数调用依赖对象里的 vptr，而 vptr 正是构造函数运行时才写入的——鸡生蛋问题；且构造时静态类型明确无需多态
  • 静态成员函数不能虚：没有 this，没有对象可查表
  • 普通函数/友元不能虚：不在类作用域内
  • 内联函数理论上可虚但多态调用时内联失效；模板成员函数可以虚（有实体即可）
  • 「虚构造」的替代：克隆函数 clone()（虚函数返回自身拷贝）——原型模式
「构造无虚因为先有对象才有表；想虚构造用 clone」
Q42override 和 final 关键字有什么用？
  • override（C++11）：显式声明「我要覆盖基类虚函数」——签名写错（const 丢了、参数不同）直接编译报错，否则会默默变成新函数埋下 bug
  • final：修饰虚函数禁止进一步覆盖；修饰类禁止继承（利于去虚化优化）
  • 规范：所有覆盖函数都写 override，不再被继承的类/函数加 final
「override 防手滑，final 封棺」
Q43dynamic_cast 和 RTTI 是什么？typeid 有什么用？
  • RTTI（运行时类型识别）：编译器在 vtable 附近存类型信息（type_info）支撑动态转型
  • dynamic_cast：多态类型间安全向下转型——失败时指针得 nullptr、引用抛 std::bad_cast；要求基类至少有一个虚函数
  • typeid：返回 type_info，可比较是否同类型、取名字（.name() 输出因编译器而异）
  • 设计提示：大量 dynamic_cast 往往说明多态设计有问题，应把差异下沉为虚函数
「dynamic_cast 摸底，失败指针空引用抛」
Q44重载、重写（覆盖）、隐藏的区别？🔥 高频
概念发生位置条件绑定
重载 Overload同一作用域函数名同、参数不同编译期
重写 Override派生类覆盖基类虚函数 + 签名相同运行期（虚表）
隐藏 Hiding派生类 vs 基类同名即隐藏（非虚或签名不同）编译期按静态类型
  • 隐藏最坑：派生类只要出现同名函数（哪怕参数不同），基类所有同名重载版本全部被隐藏；用 using Base::f; 引入恢复
  • 区分口诀：看作用域 + 是否虚 + 签名
「同名同域是重载，虚同签名是重写，跨域同名全隐藏」

Q46new 失败怎么处理？nothrow new 是什么？
  • 默认：分配失败抛 std::bad_alloc，用 try/catch 捕获
  • nothrow new：new (std::nothrow) T 失败返回 nullptr（老代码/嵌入式风格）
  • 构造函数内 new 失败：构造未完成、析构不会执行——已构造的成员会析构，裸指针成员泄漏 → 又一个用智能指针的理由
  • new[] 内部会额外存元素个数（多分配 4/8 字节）供 delete[] 用——这就是不能 delete 释放 new[] 的原因
「默认抛异常，nothrow 返空；构造半途而废靠智能指针兜底」
Q47如何检测和预防内存泄漏？🔥 高频
  • 预防优先：智能指针管所有权、RAII 封装资源、容器代替裸数组（Rule of Zero）
  • 检测工具：
    • Linux：valgrind --leak-check=full（精确但慢 10~30 倍）
    • 编译期插桩：AddressSanitizer / LeakSanitizer（-fsanitize=address,leak，快，CI 友好）
    • Windows：CRT 调试堆 _CrtDumpMemoryLeaks、VLD、Dr.Memory
  • 常见泄漏点：异常路径漏 delete、智能指针循环引用、容器缓存无限增长、回调注册未注销
  • 「只增不减」的内存曲线 + 长跑压测是最直接的泄漏信号
「预防靠 RAII，检测靠 valgrind/ASan」
Q48栈溢出和堆溢出分别是什么？怎么排查？
  • 栈溢出：递归太深、大局部数组（如 int a[10*1024*1024]）、默认栈 1~8MB 用尽 → 段错误 SIGSEGV；对策：改迭代/尾递归、大对象放堆、ulimit -s 调栈（治标）
  • 堆溢出两种含义：① 写越界破坏堆元数据（malloc 元信息被踩，报 "corrupted double-linked list"）；② 内存耗尽（bad_alloc / OOM killer）
  • 排查：ASan 一抓一个准；堆破坏可用 electric fence / _CrtCheckMemory 定位
「栈溢看递归，堆溢查越界」
Q49内存池是什么？为什么能提升性能？
  • 原理：一次性向系统申请大块内存，之后分配从池里切分/复用，避免频繁走 malloc（用户态↔内核态切换、锁竞争）
  • 固定大小块：所有块同尺寸，用空闲链表 O(1) 分配回收，且天然解决碎片
  • 适用：高频小对象（网络连接、节点、消息）； STL 有 std::pmr::memory_resource（C++17）可插拔分配器
  • 注意：内存池自己也要防泄漏与线程安全（thread_local 池可免锁）
「一次批发，零售免谈」——空闲链表 O(1)
Q50什么是 RAII？为什么说它是 C++ 最重要的思想？🔥 高频

RAII（Resource Acquisition Is Initialization）：把资源（内存、文件、锁、连接）的生命周期绑定到栈对象——构造获取、析构释放。

  • 好处：异常安全（栈展开必调析构）、忘不了释放、代码无 goto cleanup
  • 标准库全是 RAII：string/vector（内存）、fstream（文件）、lock_guard（锁）、智能指针（对象所有权）
  • 思想推广：ScopeGuard、defer 语义、事务回滚对象，几乎所有「确定性释放」都源于它
void f() {
    std::lock_guard<std::mutex> lk(mtx);  // 构造即加锁
    do_work();                           // 抛异常也不怕
}                                        // 离开作用域自动解锁
「资源跟着栈对象走，构造拿析构还，异常也不漏」
Q51什么是左值、右值？移动语义解决什么问题？std::move 做了什么？🔥 高频
  • 左值：有名字、可取地址（变量）；右值：临时值/字面量（将亡值、纯右值）
  • 移动语义（C++11）：对将亡对象窃取内部资源（指针交换）而非深拷贝——vector 传值从 O(n) 拷贝变 O(1) 搬家
  • std::move 不移动任何东西！只是把左值强制转成右值引用（无条件 static_cast<T&&>），真正的移动发生在移动构造/移动赋值里
  • 移动后的对象处于有效但未指定状态，只能重新赋值或析构
  • 搭配：noexcept 移动构造 才能让 vector 扩容时用移动（否则为保证强异常安全退回拷贝）
std::string a = "很长的字符串....";
std::string b = std::move(a);   // a 内部指针直接给 b，O(1)
// 此后 a 为空壳，可重新赋值使用
「move 只是改名挂牌，真正搬家在移动构造」
Q52什么是完美转发？std::forward 与 std::move 的区别？🔥 高频
  • 完美转发：模板函数把参数原样（保持左/右值属性）传给下一层，不产生多余拷贝
  • 关键：万能引用 T&&（模板参数推导时）既能绑左值也能绑右值；但具名参数本身是左值，需还原
  • std::forward<T>(arg)：有条件转换——原来是右值就转回右值，是左值保持左值
  • std::move：无条件转右值；forward 用在模板转发，move 用在明确要移动
  • 典型：emplace_back、make_shared、工厂函数都靠它实现零拷贝传递
template <typename T, typename... Args>
std::unique_ptr<T> make(Args&&... args) {
    return std::unique_ptr<T>(
        new T(std::forward<Args>(args)...));  // 保持实参的值类别
}
「move 无条件，forward 看情况（条件转换）」

07智能指针

Q53为什么需要智能指针？C++11 提供了哪几种？🔥 高频
  • 裸指针三大痛点：忘记释放（泄漏）、重复释放、异常路径漏释放
  • 智能指针 = RAII 包装的指针：析构自动释放，所有权语义显式
  • unique_ptr：独占所有权（零开销，默认首选）
  • shared_ptr：共享所有权（引用计数）
  • weak_ptr：不拥有的观察者（打破循环引用）
  • 选择顺序：能用栈/值就用值 → 独占用 unique → 真要共享才 shared
「独占 unique、共享 shared、观望 weak」
Q54unique_ptr 的特点？为什么说它零开销？🔥 高频
  • 独占：同一时刻只有一个 unique_ptr 拥有对象，禁止拷贝、只允许移动
  • 零开销：不存引用计数，大小 = 裸指针（无自定义删除器时），Release 模式下与裸指针等价
  • 数组特化：unique_ptr<T[]> 自动调用 delete[]
  • 自定义删除器：unique_ptr<FILE, decltype(&fclose)> —— 函数指针类型会进类型、影响大小
  • 传参规则：转移所有权用 by value + std::move；只使用不转移用裸指针/引用
auto p = std::make_unique<Widget>();  // C++14
auto q = std::move(p);                // 转移后 p == nullptr
Widget* raw = q.get();                // 观察不接管
q.reset();                            // 立即释放并置空
「独占可移不可拷，默认首选零开销」
Q55shared_ptr 的实现原理？引用计数是线程安全的吗？🔥 高频
  • 控制块（control block）：堆上独立结构，存强引用计数 + 弱引用计数 + 删除器；所有 shared_ptr/weak_ptr 共享它
  • 拷贝 shared_ptr → 计数原子 +1；析构 → 原子 -1，减到 0 释放对象，弱计数归零再释放控制块
  • 线程安全范围：计数本身是原子的（多线程拷贝/析构不同 shared_ptr 实例安全）；但同一个 shared_ptr 对象的读写不安全，指向的对象访问也要自己加锁
  • 大小 16 字节（对象指针 + 控制块指针），拷贝有原子开销——热路径按 const 引用传
「控制块记双账（强弱），计数原子但对象不加锁」
Q56什么是循环引用？weak_ptr 如何解决？🔥 高频

A 持有 shared_ptr<B>、B 持有 shared_ptr<A> → 两计数永远 ≥1 → 谁也释放不了（典型：观察者、双向链表、父子节点）。

  • 解法：把「弱的一方」（子指向父、观察者、缓存）改为 weak_ptr——只观察不增加强计数
  • 使用前 lock() 升级为 shared_ptr：对象还活着得到有效指针，已死得到 nullptr（判活标准姿势）
  • weak_ptr 也常用于缓存与观察者模式，避免延长生命周期
struct Child; 
struct Parent {
    std::vector<std::shared_ptr<Child>> kids;  // 强持有
};
struct Child {
    std::weak_ptr<Parent> parent;             // 弱回指，破循环
    void use() {
        if (auto p = parent.lock()) { /* 父还在 */ }
    }
};
「强持有弱回指，lock 判活再使用」
Q57auto_ptr 为什么被废弃？
  • C++98 的 auto_ptr 拷贝语义是「拷贝即转移」——与直觉相悖：拷贝后源变空
  • 灾难场景：把 auto_ptr 放进容器，容器内部拷贝导致元素悄悄失效
  • 且无移动语义支撑、不支持数组
  • C++11 用 unique_ptr（显式 move） 取代，C++17 正式删除 auto_ptr
「拷贝却偷家，容器都害怕」——unique_ptr 显式接管
Q58make_shared 和 shared_ptr<T>(new T) 有什么区别？🔥 高频
  • 一次分配：make_shared 把对象和控制块合并在一块内存，少一次堆分配、缓存更友好
  • 异常安全：C++17 前 f(shared_ptr<T>(new T), g()) 可能因求值顺序泄漏；make 版不会
  • 缺点：对象与控制块同块内存，有 weak_ptr 存活时对象内存无法提前释放（要等弱计数归零）——大对象 + 长命 weak_ptr 场景注意
  • 私有构造函数的类 make_shared 无法访问（make 系列缺陷）
「make 一次分配更高效，代价是 weak 赖着不放内存」
Q59多线程下使用智能指针要注意什么？
  • 区分两层：控制块线程安全（原子计数） ≠ 指向的对象线程安全 ≠ 同一个 shared_ptr 实例线程安全
  • 多线程写同一个 shared_ptr 变量：用 std::atomic<std::shared_ptr<T>>（C++20）或加锁
  • 线程间传递：按值拷贝传（各自持实例）+ 对象内部自己同步
  • 注意 shared_from_this 必须在对象已被 shared_ptr 管理后调用（enable_shared_from_this）
「计数安全、对象和实例不安全」——分三层看

08STL 容器与算法

Q60STL 六大组件是什么？🔥 高频
  • 容器：vector、list、map、unordered_map…（数据的家）
  • 算法：sort、find、accumulate…（通用操作，与容器解耦）
  • 迭代器：连接容器与算法的「胶水」，泛化指针
  • 仿函数/函数对象：重载 operator() 的类，可携带状态的「函数」
  • 适配器：stack、queue、priority_queue（容器适配器）；bind/包装器（函数适配器）
  • 分配器：内存分配策略（allocator，一般不碰，pmr 时有戏）
「容算迭仿适分」六件套；算法不认识容器，只认迭代器
Q61vector 的扩容机制？为什么是成倍增长？reserve/resize 区别？🔥 高频
  • 扩容：size == capacity 时，申请新内存（GCC 2 倍、MSVC 1.5 倍）→ 搬移元素（有 noexcept 移动则移动，否则拷贝）→ 释放旧内存
  • 为什么倍增：均摊分析下 push_back 均摊 O(1)；定长增长（+1）会退化成 O(n)
  • 扩容副作用：所有迭代器/指针/引用全部失效——扩容后使用旧指针是经典崩溃
  • reserve(n)：只改 capacity（预留空间防多次扩容）；resize(n)：改 size（会构造/删除元素）
  • 已知大小时 提前 reserve 是最直接的性能优化
「倍增均摊 O(1)，扩容旧针全作废；reserve 借地，resize 造房」
Q62vector 和 list 怎么选？deque 的结构？🔥 高频
维度vectorlist（双向链表）
内存连续（缓存友好）节点分散 + 前后指针开销
随机访问O(1)O(n)
中间插删O(n) 搬移O(1)（已定位时）
迭代器失效插入/扩容全失效只有被删节点失效
  • 实践：95% 场景 vector 更快（缓存局部性碾压链表），list 只在「频繁中间插删且不能随机访问失效」时考虑
  • deque：分段连续（map 指向多个固定块），头尾两端 O(1) 插删，中间 O(n)；是 stack/queue 的默认底座
「默认 vector，两头操作 deque，list 几乎不用」
Q63map 和 unordered_map 的底层与选型？🔥 高频
维度map（红黑树）unordered_map（哈希表）
查找/插入O(log n)平均 O(1)，最坏 O(n)
有序性按 key 有序遍历无序
key 要求可比较（operator<）可哈希 + 可等值比较
迭代器稳定性插入不失效rehash 后失效
  • 红黑树是自平衡二叉搜索树：增删查 O(log n)，最坏可控
  • unordered_map：开链法处理冲突，负载因子超 max_load_factor 触发 rehash（桶数约翻倍）
  • 选型：要有序/范围查询用 map，纯查找用 unordered_map；key 是自定义类型需提供 hash 特化与 ==
「红黑树有序稳定，哈希表平均最快」
Q64迭代器失效的规则？如何安全删除元素？🔥 高频
  • vector/deque/string：插入点之后全失效（扩容则全失效）；删除点之后失效
  • list：仅被删元素失效，其他不动
  • map/set（红黑树）：插入不失效；删除仅被删节点失效
  • unordered_*：插入可能触发 rehash 全失效；删除仅被删节点失效
  • 安全删除姿势：it = c.erase(it)（erase 返回下一个有效迭代器），不要 erase 后 ++it
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) it = v.erase(it);  // 接住下一个
    else               ++it;
}
// 批量删除首选惯用法：
v.erase(std::remove_if(v.begin(), v.end(),
                       [](int x){ return x % 2 == 0; }),
        v.end());
「erase 返回下一站，接住再走不越轨」
Q65为什么有 erase-remove 惯用法？remove 真的删除了吗？
  • std::remove 只是把「要保留的元素前移」并返回新逻辑末尾，容器大小不变（算法层碰不到容器大小）
  • 必须再 erase(逻辑末尾, end()) 才真正删掉，两步合称 erase-remove idiom
  • 复杂度 O(n) 一次搬移，优于循环 erase（每次 O(n) 搬移）
  • C++20 可直接 std::erase_if(v, pred) 一步到位
「remove 只搬家不砍树，erase 才砍」
Q66std::string 的实现了解吗？什么是 SSO 和 COW？
  • SSO（小字符串优化）：短字符串（通常 ≤15/22 字节）直接存对象内部缓冲区，不分配堆——大多数字符串都在栈上解决
  • COW（写时复制）：多个 string 共享一份数据，写时再拷贝——GCC 5 之前采用，C++11 因线程安全与 operator[] 语义已禁止，现在主流实现都是 SSO
  • string 与 char* 互转：c_str()（只读）；拼接查找都有成熟接口；注意 C++20 加入了 starts_with/ends_with
「短串在栈（SSO），COW 已进博物馆」
Q67emplace_back 和 push_back 的区别？🔥 高频
  • push_back(T(args))：先构造临时对象 → 再拷贝/移动进容器（两步）
  • emplace_back(args...)：参数完美转发到容器内存上原地构造（一步，零临时对象）
  • 对 int 等平凡类型两者无差；对 pair/string/大对象 emplace 省一次构造搬运
  • 注意：emplace_back(10, 20) 对 vector<Point> 是调用 Point(10,20)——会「贪婪匹配」任何构造函数，意外调用 explicit 构造时不如 push_back 直白
  • map 的 try_emplace / insert_or_assign 同理按语义选择
「push 先造再搬，emplace 原地开工」
Q68std::sort 用的什么算法？比较函数为什么要严格弱序？
  • 内省排序 introsort：快排为主，递归过深（log n 层）切堆排序，区间小于 16 切插入排序——兼顾平均与最坏 O(n log n)
  • 比较器必须满足严格弱序：comp(a,a) == false、反对称、传递；用 <= 会直接段错误（越界访问）
  • std::sort 要求随机访问迭代器（list 不能用，要用成员函数 list::sort，归并实现稳定）
  • stable_sort 稳定但需额外内存；partial_sort 只要前 K 名 O(n log k)
std::sort(v.begin(), v.end(),
            [](const P& a, const P& b){ return a.x < b.x; });
// 千万别写 a.x <= b.x —— 违反严格弱序
「快排 + 堆 + 插入 = 内省」；比较器只准用 <
Q69priority_queue 是什么？如何自定义比较？
  • 堆（默认 vector 底座 + std::push_heap 系列）的容器适配器；默认 less → 大顶堆，top() 是最大值
  • 小顶堆：priority_queue<int, vector<int>, greater<int>>
  • 自定义类型：传 lambda（C++20 前要 decltype 包裹）或重载 operator<
  • push/pop 均 O(log n)，top O(1)；TopK 问题常客（维护大小为 K 的堆）
「默认大顶堆，greater 变小顶」

09模板与泛型

Q70函数模板和类模板的区别？模板参数推导规则？
  • 函数模板：调用时可自动推导参数类型（显式指定也行）；类模板必须显式指定（C++17 前），C++17 起有 CTAD 构造推导
  • 推导不考：返回类型、非推导上下文（如 T::type）
  • 模板定义通常放头文件（实例化需要看到完整定义）
  • 全特化版本参与重载决议，匹配优先：非模板 > 特化 > 主模板
「函数模板能推导，类模板要指名（CTAD 除外）」
Q71什么是模板实例化？代码膨胀是怎么回事？🔥 高频
  • 实例化：编译器按用到的类型生成一份具体代码（vector<int> 和 vector<string> 是两个不同的类）
  • 隐式实例化（用了才生成）vs 显式实例化（extern template 声明「别处已生成」，减少重复编译）
  • 代码膨胀：每种类型组合一份机器码 → 二进制变大、编译变慢、icache 局部性变差
  • 治理：公共逻辑抽出非模板基类/void* 底座（如 vector<bool> 特化、boost.proxy），模板只在薄壳层
「一套模板 N 份实例」；瘦身靠非模板底座 + extern template
Q72模板特化与偏特化的区别？
  • 全特化：所有模板参数都定死（template<> struct Hash<std::string>）——针对特定类型定制实现
  • 偏特化：只定死部分参数或参数模式（如 vector<T*>、tuple<T, Rest...>）——只对类模板有效，函数模板不能偏特化（用重载代替）
  • 典型应用：traits（is_pointer、iterator_traits）按类型族提供不同行为
「全特化点对点，偏特化类专属；函数模板想偏特化？用重载」
Q73SFINAE 是什么？if constexpr 解决了什么？
  • SFINAE（替换失败不是错误）：模板参数替换失败时静默移出候选集而非报错——用 enable_if 按条件启用/禁用重载
  • 痛点：enable_if 写法晦涩、报错信息天书
  • if constexpr（C++17）：编译期选择分支，未选中的分支不实例化——模板分支逻辑从「元编程黑话」变普通代码
  • C++20 concepts 进一步替代大部分 SFINAE：约束可读、报错可懂
template <typename T>
auto serialize(const T& v) {
    if constexpr (std::is_integral_v<T>) {
        return std::to_string(v);        // T 是浮点时不编译
    } else {
        return std::string(v);           // T 是整型时不编译
    }
}
「替换失败不算错；constexpr if 分支只编一半」
Q74using 与 typedef 的区别？什么是变参模板？
  • using 别名（C++11）与 typedef 等价，但可模板化（alias template），typedef 做不到；对函数指针等复杂类型更易读
  • 变参模板：template<typename... Args> 接受任意个参数，配合折叠表达式（C++17）(args + ...) 一行求和
  • sizeof...(args) 取参数个数；递归展开是 C++14 前的姿势
「using 能带模板，typedef 只是老别名」
Q75C++20 concepts 是什么？比 SFINAE 好在哪？
  • 概念：对模板参数的一组命名约束（template<std::integral T>）
  • 好处：①报错直说「不满足约束 X」而非一千行实例化栈；②约束可组合、可重载（更约束的优先）；③requires 表达式可直接检测表达式有效性
  • 标准库自带：std::integral、std::ranges::range、std::same_as 等
「concepts = 类型约束白话文」

10现代 C++ 新特性

Q76auto 和 decltype 的推导规则？🔥 高频
  • auto：按初始化表达式推导，丢弃引用与顶层 const（想保留写 auto& / const auto&）
  • auto&& 是万能引用：绑左值推导为左值引用，绑右值为右值引用
  • decltype(expr)：推导表达式声明类型但不求值——保留引用与 const；decltype(变量) 与 decltype((变量)) 不同：双括号得到引用！
  • auto 返回值（C++14） 与 decltype(auto) 用于完美转发返回类型
  • 使用规范：类型冗长（迭代器、lambda）用 auto；auto 掩盖值拷贝陷阱（auto x = map["k"] 拷贝）要警惕
「auto 去引用丢 const；decltype 原样拍照不求值」
Q77lambda 表达式的本质？捕获方式有哪些坑？🔥 高频

lambda 是编译器生成的匿名仿函数对象（闭包类实例），捕获的变量是它的成员。

  • 捕获方式：[=] 值捕获（拷贝一份）、[&] 引用捕获、[x]、[x, &y] 混合、[=, &x]、[this]（捕获 this 指针！）
  • 大坑 1：[&] 悬垂引用——lambda 活得比局部变量久（异步回调、存进容器）时引用捕获爆炸
  • 大坑 2：[this] 捕获的是指针，对象析构后回调即悬垂（C++20 用 [*this] 拷贝整个对象）
  • 大坑 3：[=] 隐式捕获 this（C++20 已废弃该写法），成员访问其实是经 this 指针
  • 无捕获 lambda 可转函数指针；有捕获的不能（有状态）
  • mutable：去掉 operator() 的 const，允许修改值捕获的副本（不影响外界）
int x = 10;
auto byVal = [x]   { return x + 1; };  // 拷贝一份 x
auto byRef = [&x] { ++x; };           // 真修改 x
auto gen = [x]() mutable { return ++x; };  // 改的是副本
// 异步场景别 [&]：
auto task = std::async(std::launch::async,
                       [x]{ return x * 2; });  // 值捕获才安全
「lambda 是无名仿函数；异步别引用捕获，[this] 记得判活」
Q78std::function 是什么？和函数指针、lambda 什么关系？
  • std::function<R(Args...)>：类型擦除的「任何可调用物」容器——函数指针、lambda、仿函数、bind 结果都能装
  • 代价：可能堆分配（捕获太多）、调用多一层间接，热路径慎用
  • std::bind：C++11 绑定参数的旧姿势，现代代码几乎都可用 lambda 替代（更清晰更快）；placeholders _1/_2
  • 回调/事件系统接口用 function，模板参数传递可调用物优先用模板 + auto/lambda（零开销）
「function 万能但有税；bind 已过气，lambda 走天下」
Q79optional、variant、any 分别解决什么问题？

Q83std::thread 基本用法？不 join 会怎样？

Q84mutex、lock_guard、unique_lock 的区别？🔥 高频
  • std::mutex：裸锁——必须手动配对 lock/unlock，异常路径必漏
  • lock_guard：构造加锁、析构解锁，最轻量、不可中途解锁——默认选它
  • unique_lock：可延迟锁（defer_lock）、中途 unlock/再 lock、可移动、能配合条件变量——更灵活略有开销
  • scoped_lock（C++17）：一次锁多把锁，内部死锁避免算法——多锁场景必用
  • 其他：shared_mutex 读写锁、recursive_mutex 递归锁（设计坏味道）、timed_mutex 带超时
「默认 lock_guard，配条件变量用 unique_lock，多把锁用 scoped_lock」
Q85死锁产生的四个必要条件？如何预防？🔥 高频

  • 预防（工程三板斧）：
    • ①全局锁序：所有线程按相同顺序加锁（破循环等待）
    • ②std::scoped_lock / std::lock 一次性原子获取多锁
    • ③try_lock + 退避重试（拿不到就放掉已有锁重来，破持有并等待）

Q86条件变量为什么要用 while 循环等待？什么是虚假唤醒？🔥 高频
  • 标准姿势：unique_lock 加锁 → while(!条件) cv.wait(lk) → 处理 → 解锁
  • 为什么 while 不 if：①虚假唤醒——OS 允许无 notify 也醒；②被唤醒到拿回锁之间条件可能又被别的线程消费掉（多消费者）
  • wait 内部：原子地「解锁 + 睡眠」，被唤醒后「重新加锁」再返回
  • notify 前是否持锁：notify_one 可不持（效率高）；唤醒后条件变量仍由 while 重新校验兜底
  • 等待带超时用 wait_for/ until；丢失唤醒的根因是「先 notify 后 wait」——条件本身要用状态变量（谓词）表达

std::condition_variable cv;
bool ready = false;

// 消费者
std::unique_lock<std::mutex> lk(m);
while (!ready) cv.wait(lk);        // 必须 while！
// 生产者
{ std::lock_guard<std::mutex> lk(m);
  ready = true; }
cv.notify_all();
「wait 必裹 while，醒来重查条件再干活」
Q87atomic 的原理？什么是 CAS？和 mutex 怎么选？🔥 高频
  • std::atomic<T>：底层用 CPU 原子指令（lock cmpxchg 等），免锁完成读改写
  • CAS（compare_exchange_weak/strong）：比较并交换——「期望值没变才写入，变了返回失败重试」，是无锁数据结构与自旋的基石；weak 允许伪失败（循环里用 weak，单次用 strong）
  • 常用：fetch_add（计数器）、exchange、compare_exchange；is_lock_free 查询是否真无锁
  • 选型：单变量计数/标志 → atomic（快）；多变量一致性复合操作 → mutex；用 atomic 组合多个状态是并发 bug 高发区
std::atomic<int> cnt{0};
++cnt;  // 原子自增，无锁

// CAS 自旋：无锁更新
int expected = cnt.load();
int desired;
do {
    desired = expected + 1;
} while (!cnt.compare_exchange_weak(expected, desired));
// expected 会被失败时刷新，循环重试
「一个变量 atomic，多个变量 mutex」；CAS 失败就重试
Q88内存序 memory_order 了解吗？
  • 背景：编译器与 CPU 都会重排指令，多核间需要同步约定
  • memory_order_seq_cst（默认）：全局全序，最稳最慢——不确定就用默认
  • acquire（读）/ release（写）配对：release 前的写在 acquire 后都可见——实现自旋锁、发布订阅的主流选择
  • relaxed：只保证原子性不保证顺序——纯计数器可用
  • acquire/release 类似「写屏障 + 读屏障」；面试能讲清为什么需要屏障（可见性 + 重排）即可
「默认最稳，acquire 读 release 写，relaxed 只计数」
Q89call_once 是什么？和静态局部变量初始化什么关系？
  • std::call_once + once_flag：多线程并发调用也保证函数恰好执行一次（其余线程阻塞等它）
  • C++11 起静态局部变量初始化自带线程安全（魔法静态）——这是 Meyers 单例线程安全的依据
  • 两者都能做一次性初始化；静态局部变量更简洁，call_once 适合「时机由外部控制」的初始化
「call_once 全局一次，静态局变量天生安全」
Q90future、promise、async、packaged_task 的关系？
  • future：读端——get() 阻塞取结果（只能取一次），wait/wait_for 轮询
  • promise：写端——set_value 传结果给配对的 future（一诺一期的信道）
  • packaged_task：把「可调用物」打包，执行时结果自动进 future（任务与结果解耦）
  • async：最上层糖——直接「异步执行函数并返回 future」；launch::deferred 惰性 / async 真并发；坑：默认策略的 future 析构可能阻塞等任务
  • 线程池方案常为：任务队列 + packaged_task + future（C++ 标准库暂无线程池，自研或用第三方）
「promise 写 future 读，packaged_task 打包活，async 全包了」

Q97手写一个 String 类（Rule of Three/Five）🔥 高频

考点：深拷贝、自赋值、异常安全、移动语义。要点：copy-and-swap 惯用法可同时优雅解决赋值三问题。

class String {
public:
    String(const char* s = "")                     // 构造
        : data_(new char[strlen(s) + 1]) {
        std::memcpy(data_, s, strlen(s) + 1);
    }
    ~String() { delete[] data_; }                  // 析构

    String(const String& o)                        // 拷贝构造（深拷贝）
        : data_(new char[o.size() + 1]) {
        std::memcpy(data_, o.data_, o.size() + 1);
    }
    String& operator=(String o) noexcept {         // 传值 + swap：自赋值/异常安全全解
        std::swap(data_, o.data_);
        return *this;
    }
    String(String&& o) noexcept                    // 移动构造
        : data_(o.data_) { o.data_ = nullptr; }

    size_t size() const { return std::strlen(data_); }
    const char* c_str() const { return data_; }
private:
    char* data_;
};

template <typename T>
class SharedPtr {
public:
    explicit SharedPtr(T* p = nullptr)
        : ptr_(p), cnt_(p ? new std::atomic<int>(1) : nullptr) {}

    SharedPtr(const SharedPtr& o) : ptr_(o.ptr_), cnt_(o.cnt_) {
        if (cnt_) cnt_->fetch_add(1);              // 计数 +1
    }
    SharedPtr(SharedPtr&& o) noexcept : ptr_(o.ptr_), cnt_(o.cnt_) {
        o.ptr_ = nullptr; o.cnt_ = nullptr;        // 偷家
    }
    SharedPtr& operator=(const SharedPtr& o) {
        if (this != &o) { release(); ptr_ = o.ptr_; cnt_ = o.cnt_;
                          if (cnt_) cnt_->fetch_add(1); }
        return *this;
    }
    ~SharedPtr() { release(); }
    T& operator*()  const { return *ptr_; }
    T* operator->() const { return ptr_; }
    int use_count() const { return cnt_ ? cnt_->load() : 0; }
private:
    void release() {
        if (cnt_ && cnt_->fetch_sub(1) == 1) {     // 减到 0 才释放
            delete ptr_;
            delete cnt_;
        }
        ptr_ = nullptr; cnt_ = nullptr;
    }
    T* ptr_;
    std::atomic<int>* cnt_;
};

template <typename T>
class Vector {
public:
    ~Vector() { delete[] data_; }
    size_t size() const { return size_; }
    size_t capacity() const { return cap_; }
    T& operator[](size_t i) { return data_[i]; }

    void push_back(const T& v) {
        if (size_ == cap_) reserve(cap_ ? cap_ * 2 : 4);  // 倍增扩容
        data_[size_++] = v;
    }
    void reserve(size_t newCap) {
        if (newCap <= cap_) return;
        T* fresh = new T[newCap];          // 简版：构造分配
        for (size_t i = 0; i < size_; ++i) fresh[i] = data_[i];
        delete[] data_;
        data_ = fresh; cap_ = newCap;
    }
private:
    T* data_ = nullptr;
    size_t size_ = 0, cap_ = 0;
};

Q102手写生产者-消费者模型（条件变量版）🔥 高频

考点：条件变量 + while 谓词 + unique_lock 的标准配合，是最经典的并发手写题。

std::queue<int> q;
std::mutex m;
std::condition_variable cv;
bool done = false;

void producer(int n) {
    for (int i = 0; i < n; ++i) {
        { std::lock_guard<std::mutex> lk(m);
          q.push(i); }
        cv.notify_one();               // 唤醒一个消费者
    }
    { std::lock_guard<std::mutex> lk(m); done = true; }
    cv.notify_all();                   // 收工广播
}

void consumer() {
    while (true) {
        std::unique_lock<std::mutex> lk(m);
        cv.wait(lk, []{ return !q.empty() || done; });  // 谓词版 wait
        while (!q.empty()) {           // 醒来尽量多干（持锁期间）
            int v = q.front(); q.pop();
            lk.unlock();               // 处理时放锁
            process(v);
            lk.lock();
        }
        if (done) return;
    }
}
  • 追问点：为什么 notify 前可以先解锁（谓词兜底）；为什么处理数据要放锁（减小临界区）；有界队列用两个条件变量（not_full / not_empty）

Q103手写 LRU 缓存（哈希 + 双向链表）🔥 高频

考点：数据结构组合。unordered_map O(1) 定位 + list 维护访问顺序，get/put 均 O(1)。

class LRUCache {
public:
    explicit LRUCache(size_t cap) : cap_(cap) {}

    int get(int key) {
        auto it = map_.find(key);
        if (it == map_.end()) return -1;
        // 命中：挪到队头（最近使用）
        order_.splice(order_.begin(), order_, it->second);
        return it->second->second;
    }

    void put(int key, int value) {
        auto it = map_.find(key);
        if (it != map_.end()) {                     // 已存在：更新 + 提前
            it->second->second = value;
            order_.splice(order_.begin(), order_, it->second);
            return;
        }
        if (map_.size() == cap_) {                  // 淘汰队尾（最久未用）
            map_.erase(order_.back().first);
            order_.pop_back();
        }
        order_.emplace_front(key, value);
        map_[key] = order_.begin();
    }
private:
    size_t cap_;
    std::list<std::pair<int, int>> order_;          // 头=最新，尾=最旧
    std::unordered_map<int,
        std::list<std::pair<int,int>>::iterator> map_;
};
「map 管定位，list 管顺序；命中提前，满了砍尾」
Q104手写观察者模式（weak_ptr 防悬垂）

考点：多态回调 + weak_ptr 判活（观察者可能先死）+ 回调时避免死锁。

struct Observer {
    virtual ~Observer() = default;
    virtual void onEvent(int) = 0;
};

class Subject {
public:
    void subscribe(std::shared_ptr<Observer> o) {
        observers_.push_back(o);               // 存 weak：不延长生命周期
    }
    void notify(int ev) {
        for (auto it = observers_.begin(); it != observers_.end(); ) {
            if (auto sp = it->lock()) {       // 判活
                sp->onEvent(ev);
                ++it;
            } else {
                it = observers_.erase(it);     // 顺手清理尸体
            }
        }
    }
private:
    std::vector<std::weak_ptr<Observer>> observers_;
};
  • 加分点：指出回调里若再加锁要防死锁；onEvent 里修改 observers_ 的重入问题（可拷贝一份再遍历）
「订阅存 weak，通知先判活，尸体顺手清」
