01 基础语法

Q
说说 Python 是解释型还是编译型语言？🔥 高频

通常说 Python 是解释型 + 动态类型语言，但更准确是「先编译后解释」：

  • 编译过程：源码 → 编译成字节码（.pyc）→ 由解释器逐条执行
  • 动态类型：变量无需声明类型，运行时才确定，a = 1 再 a = "x" 合法
  • 与 C/Java 区别：没有显式编译步骤，不需要「编译 → 链接 → 运行」三步
  • 优缺点：开发快、跨平台；但执行速度慢于编译型语言
源码编译成字节码，解释器边读边执行；动态类型不声明，鸭子能用就行
Q
Python 代码的执行流程是怎样的？🔥 高频
  • ① 源码：.py 文本文件 → ② 词法/语法分析，生成抽象语法树 AST → ③ 编译成字节码 → ④ PVM（Python 虚拟机）逐条执行字节码
  • 字节码缓存在 __pycache__/*.pyc，二次运行跳过编译、启动更快
  • 源码变更后 .pyc 自动失效重建（依据 mtime 校验）
文本→语法树→字节码→虚拟机，四步走；缓存 pyc 提速二次运行
Q
可变对象与不可变对象有哪些？传参有什么影响？🔥 高频
类别对象传参行为
不可变int、float、str、tuple、frozenset、bool函数内修改不影响外部（值传递效果）
可变list、dict、set、bytearray、自定义对象函数内修改会反映到外部（引用传递效果）
  • Python 传参统一是对象引用传递：传的是「指向对象的引用」，不是复制
  • 不可变对象修改时重新创建新对象并绑定新引用，原对象不变
  • 可变对象直接就地修改，所以外部可见；注意函数参数默认值不要用可变对象
传引用不传值：不可变改不了（重建），可变改得动（就地）；默认参数慎用可变类型
Q
深拷贝和浅拷贝有什么区别？🔥 高频
  • 浅拷贝 copy.copy：只复制最外层容器，内部元素仍是同一引用
  • 深拷贝 copy.deepcopy：递归复制所有层级，得到完全独立的对象
  • 常见浅拷贝方式：list[:]、list()、.copy()、copy.copy
  • 深拷贝注意：循环引用也能处理（内部记录已拷贝对象）；复制大对象开销高
a = [[1, 2], [3, 4]]
b = a[:]        # 浅拷贝：外层新 list，内层仍是同一个 list
b[0][0] = 99    # a[0][0] 也变成 99

c = copy.deepcopy(a)  # 深拷贝：完全独立
c[0][0] = 100   # a 不受影响
浅拷贝复制一层壳，深拷贝全层都复制；壳是新壳、瓤是共享 vs 全独立
Q
== 和 is 有什么区别？🔥 高频
  • == 比较值是否相等，调用 __eq__
  • is 比较内存地址（身份）是否相同，即是不是同一个对象
  • 与 None 比较必须用 is None，这是唯一约定俗成的用法
  • 小整数（-5~256）和短字符串有驻留池，相同值可能是同一对象，但不能依赖
a = [1, 2]; b = [1, 2]
a == b  # True  值相等
a is b  # False 不同对象

x = 256; y = 256
x is y  # True（小整数驻留，别依赖这个特性）
== 比内容，is 比身份；判空只用 is None
Q
*args 和 **kwargs 的作用？🔥 高频
  • *args：接收任意多个位置参数，打包成 tuple
  • **kwargs：接收任意多个关键字参数，打包成 dict
  • 可变参数用于：装饰器通用签名、参数透传、不确定参数的接口
  • 定义顺序：普通参数 → *args → 默认参数 → **kwargs；解包时 *list 展开为位置参数，**dict 展开为关键字参数
def f(a, *args, b=1, **kwargs):
    print(a, args, b, kwargs)

f(1, 2, 3, x=4)  # 1 (2, 3) 1 {'x': 4}

nums = [1, 2, 3]
print(*nums)  # 解包：1 2 3
单星收位置成元组，双星收关键字成字典；定义在前，解包在后
Q
什么是鸭子类型（Duck Typing）？
  • 「如果它走路像鸭子、叫起来像鸭子，那它就是鸭子」——不关心对象类型，只关心是否有对应方法/属性
  • 与静态语言的接口不同：不需要显式继承，有该方法即可调用
  • 配合 hasattr()、try/except 实现灵活的多态
  • 优点：灵活、解耦；缺点：出错信息可能不直观（运行时才报 AttributeError）
不看出身看本事：只要会叫就当鸭子，是 Python 多态的体现
Q
global 和 nonlocal 的区别？
  • global：在函数内声明使用模块级全局变量（可跨任意层）
  • nonlocal：在嵌套函数中声明修改外层函数（非全局）的变量，用于闭包场景
  • 不声明直接赋值 = 新建局部变量（这就是「先赋值后引用」报 UnboundLocalError 的原因）
x = 1
def outer():
    x = 10
    def inner():
        nonlocal x  # 修改 outer 的 x
        x += 1
    inner()
    print(x)  # 11
global 管全局，nonlocal 管外一层；闭包改外层变量必用 nonlocal
Q
Python 常用的语法糖有哪些？
  • 推导式：列表/字典/集合/生成器推导式，一行生成容器
  • 切片：s[::-1] 反转、s[::2] 步长
  • 解包：a, b = b, a 交换；a, *rest = lst
  • with 上下文管理器、@ 装饰器、f-string、:= 海象运算符
  • 三元表达式：x if cond else y；any()/all() 判断
推导切片解包三件套，with 装饰 f-string 记牢；一行代码解决的事绝不写三行

02 数据结构

Q
list 和 tuple 有什么区别？🔥 高频
  • 可变性：list 可变（增删改）；tuple 不可变（创建后不能修改）
  • 性能：tuple 更省内存、创建和访问更快（可缓存复用，无过度分配）
  • 用途：tuple 适合「固定结构的数据」，如坐标 (x, y)、函数多返回值；可作 dict 的 key
  • 注意：tuple 里的可变元素（如 list）内容仍可变——不可变是「引用不可变」
  • list 底层是动态数组：预留容量，append 摊还 O(1)；插入/删除中间元素 O(n)
list 可变能改能删，tuple 只读更快更省；元组里的列表管不住
Q
dict 的底层实现原理是什么？🔥 高频
  • Python 3.6+ 的 dict 底层是哈希表 + 紧凑数组，且保持插入顺序
  • 查找流程：对 key 计算 hash → 定位桶 → 比对 key 是否相等 → 命中返回
  • key 要求：必须可哈希（不可变类型可以）；自定义对象需实现 __hash__ 与 __eq__
  • 扩容：装载因子超过 2/3 时扩容（约 4~8 倍），rehash 代价高
  • 查找/插入/删除平均 O(1)，最坏 O(n)（哈希冲突严重时）
hash 定位桶、eq 验身份，平均 O(1)；key 必须可哈希，装到三分之二就扩容
Q
set 和 frozenset 的区别？
  • set：可变集合，支持 add/remove/discard，元素唯一且无序
  • frozenset：不可变集合，创建后不能修改，因此可哈希，能作 dict key
  • 两者都基于哈希表，去重、成员判断 in 都是 O(1)
  • 集合运算：并 |、交 &、差 -、对称差 ^
set 可变管去重，frozenset 只读可哈希；交并差补符号记牢
Q
list.sort() 和 sorted() 有什么区别？🔥 高频
  • list.sort()：原地排序，返回 None，只能用于 list
  • sorted()：返回新列表，可作用于任何可迭代对象（tuple、dict、生成器）
  • 共同参数：key（排序函数）、reverse（降序）
  • 底层是Timsort（归并+插入的混合），稳定排序，最坏 O(n log n)
words = ["banana", "apple", "cherry"]
words.sort(key=len)  # 按长度排序，原地
sorted(words, key=lambda s: s[-1], reverse=True)  # 按末字符降序
sort 原地改、sorted 换新；都可以带 key 和 reverse
Q
列表推导式和生成器表达式的区别？🔥 高频
  • 列表推导式 [x for x in it]：一次性生成完整列表，占内存
  • 生成器表达式 (x for x in it)：惰性求值，边迭代边产生，省内存
  • 数据量大（几十万+）优先用生成器表达式；需要多次遍历/索引再用列表
  • 可加 if 过滤、嵌套 for 展开
方括号全量造，圆括号懒着算；量大用括号，量小用中括号
Q
deque（双端队列）有什么特点？
  • collections.deque 是双向队列：两端插入/删除都是 O(1)
  • 而 list 头部插入/删除是 O(n)，所以「先进先出」场景用 deque
  • 常用方法：append/appendleft、pop/popleft、extend/rotate
  • 线程安全：append/pop 是原子的，可作简单队列；还可用 maxlen 实现滑动窗口/历史记录
两头进出 O(1)，FIFO 用它准没错；加 maxlen 变滚动窗口
Q
queue 模块的三种队列有什么区别？
  • Queue：先进先出（FIFO），最常用
  • LifoQueue：后进先出（LIFO，即栈）
  • PriorityQueue：按优先级出队（内部是堆），元素越小越先出
  • 三者都线程安全，内部用锁 + 条件变量；生产消费模型标准工具
Queue 排队、Lifo 叠盘子、Priority 看堆；多线程传递任务用它最稳
Q
字符串的常用方法有哪些？
  • 切割拼接：split()、join()（注意 join 是字符串调用 list）、strip()
  • 查找替换：find/index、replace、count、startswith/endswith
  • 判断：isdigit/isalpha/isalnum/isupper 等
  • 格式化：f-string（最快最推荐）、format()、% 老式
  • 字符串不可变：所有「修改」都返回新字符串；大量拼接用 join 而不是 +
切 strips 拼 join，找 replace 判 is；不可变所以要 join 攒着拼

03 函数与装饰器

Q
什么是闭包（Closure）？🔥 高频
  • 闭包 = 内层函数 + 外层函数的环境（自由变量）
  • 内层函数引用外层函数的变量，即使外层函数执行完毕，变量仍被保留
  • 实现方式：嵌套函数 + 返回内层函数；核心是「变量绑定」
  • 闭包陷阱：循环中捕获变量会共享最终值，需用默认参数 lambda x=x: x 绑定
def counter():
    n = 0
    def inc():
        nonlocal n   # 修改外层变量
        n += 1
        return n
    return inc

c = counter()
print(c())  # 1
print(c())  # 2  n 被闭包保留
内层函数引用外层变量，外层结束变量不消失；闭包就是「带记忆的函数」
Q
装饰器的原理是什么？写一个计时装饰器🔥 高频
  • 装饰器本质是接收函数、返回新函数的高阶函数，语法糖 @deco 等价于 func = deco(func)
  • 作用：在不修改原函数代码的前提下增强功能（日志、鉴权、缓存、计时）
  • 关键点：保留原函数元信息（用 functools.wraps）
import time
from functools import wraps

def timer(func):
    @wraps(func)             # 保留 func 的 __name__ 等元信息
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.perf_counter()-start:.4f}s")
        return result
    return wrapper

@timer
def work():
    time.sleep(0.1)
装饰器 = 函数换函数；三层结构：外层收函数、中层收参数、内层收调用
Q
带参数的装饰器怎么写？🔥 高频
  • 带参装饰器需要三层嵌套：外层收装饰器参数，中层收函数，内层收调用参数
  • 等价于 @deco(args) → func = deco(args)(func)
def repeat(times):
    def decorator(func):        # 中层：收函数
        @wraps(func)
        def wrapper(*args, **kwargs):   # 内层：收调用参数
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def hello():
    print("hi")
参数装饰器三层楼：最外参数、中间函数、最内调用；wraps 别忘了
Q
functools.wraps 有什么作用？
  • 装饰后的函数若直接返回 wrapper，会丢失原函数的 __name__、__doc__、__dict__ 等元信息
  • @wraps(func) 本质是调用 update_wrapper，把原函数元信息复制到 wrapper
  • 好处：调试栈信息可读、文档字符串保留、help() 正常显示
不套 wraps，函数名全变 wrapper；套上 wraps，名实相符
Q
迭代器和生成器有什么区别？🔥 高频
  • 迭代器：实现了 __iter__ 和 __next__ 的对象，可被 for 遍历
  • 生成器：用 yield 写成的函数或生成器表达式，是迭代器的一种（更易写的迭代器）
  • 生成器特点：惰性求值、保存执行状态、每次 next 恢复执行到下一个 yield
  • 可迭代对象（如 list）不是迭代器，需 iter() 转换；迭代器只能向前、不能回头
迭代器协议：iter 拿自己、next 出下一个；生成器是带 yield 的懒迭代器
Q
yield 的执行原理？🔥 高频
  • 函数体内出现 yield，调用时不会立即执行，而是返回一个生成器对象
  • 每次 next() 从上次暂停处继续执行，到下一个 yield 暂停并返回值
  • 函数结束时抛 StopIteration，for 循环自动捕获
  • yield from 可委托给子生成器，实现扁平化遍历
  • 优势：处理大数据流时省内存，如逐行读大文件
yield 是「暂停键」：遇它停、返回去、下次接着跑；生成器=暂停恢复的艺术
Q
map、filter、reduce 的用法？
  • map(func, it)：对每个元素应用函数，返回迭代器
  • filter(func, it)：保留函数返回真值的元素
  • reduce(func, it)（functools）：把序列累积成一个值，如求和、求积
  • 三者都返回惰性对象，需 list() 消费；现代写法常被推导式替代，但 map/reduce 用于大数据并行语义更清晰
map 变换、filter 筛选、reduce 累积；一变一留一合并
Q
lambda 匿名函数有什么特点？
  • lambda 是单表达式匿名函数：lambda 参数: 表达式
  • 只能写一个表达式，不能含语句（if/for/赋值都不行，只能三元）
  • 常用于临时函数：sorted(key=)、map/filter、按钮回调
  • 注意闭包陷阱：循环中 lambda 捕获的是变量引用，需要默认参数绑定
lambda 一行表达式，无名字无名分；当传参当回调，复杂逻辑别用它
Q
Python 的递归有什么限制？如何优化？
  • 默认递归深度上限约 1000（sys.setrecursionlimit 可调，但物理栈有限）
  • Python 不支持尾递归优化，深递归仍可能栈溢出
  • 优化手段：① 改循环/迭代；② 加记忆化缓存（@lru_cache）；③ 用栈模拟；④ 尾递归改写成迭代
  • 适用场景：树/图遍历、分治（快排、归并）——深度可控时用递归最清晰
递归上限一千层，没有尾调优化；深了改循环、重了加缓存

04 面向对象

Q
Python 面向对象的三大特性？🔥 高频
  • 封装：把数据和方法绑定在类内；_name 约定私有、__name 名称改写（name mangling）实现「伪私有」
  • 继承：子类复用父类代码；支持多继承，用 MRO 决定查找顺序
  • 多态：同一接口不同实现——子类重写父类方法，调用时执行子类版本；配合鸭子类型更灵活
封装藏数据、继承传代码、多态换实现；单下划线是约定，双下划线防误用
Q
__new__ 和 __init__ 的区别？🔥 高频
  • __new__：创建对象（分配内存）的静态方法，第一个参数是 cls，返回实例
  • __init__：初始化对象（设置属性）的实例方法，第一个参数是 self，返回 None
  • 调用顺序：__new__ 先执行返回实例，__init__ 再自动执行
  • __new__ 常用于单例模式、不可变类型子类（如 int/str 子类）
new 负责生（造对象），init 负责养（初始化）；先 new 后 init，单例就改 new
Q
常用的魔法方法有哪些？🔥 高频
  • 对象生命周期：__init__ / __new__ / __del__
  • 字符串表示：__str__（给用户，print 调用）、__repr__（给开发者，交互式显示）
  • 容器协议：__len__ / __getitem__ / __setitem__ / __contains__
  • 运算重载：__add__ / __eq__ / __lt__ / __hash__
  • 其他：__call__（对象可调用）、__enter__/__exit__（with 支持）、__iter__/__next__（迭代器）
生老病死 init del，显示靠 str 调试靠 repr，容器 len getitem，运算重载 add eq
Q
__slots__ 的作用？🔥 高频
  • 默认类实例用dict 存属性，占内存大；__slots__ 用固定大小的数组存属性
  • 声明后：① 省内存（大量实例时明显，如游戏对象）；② 属性访问更快；③ 禁止新增未声明的属性
  • 注意：不自动拥有 __dict__；有 __slots__ 的类不能多继承冲突；需要弱引用要加 __weakref__
slots 定死属性表：省内存、快访问、防乱加；海量对象用它准没错
Q
Python 多继承的 MRO 是什么？🔥 高频
  • MRO（Method Resolution Order）是方法查找顺序，可通过 类.mro() 查看
  • Python 3 使用 C3 线性化算法：保证「子类优先、继承顺序优先、单调性」
  • 菱形继承中，super() 按 MRO 顺序调用，避免重复执行
  • 若继承关系无法线性化会报 TypeError: Cannot create a consistent MRO
MRO 用 C3：子类先于父类，靠前先于靠后；super 沿 MRO 走，菱形不重跑
Q
super() 的用法和原理？
  • super() 返回一个代理对象，按 MRO 找到下一个类，而不是「父类」
  • 单继承：等价于调用父类方法，且自动传 self
  • 多继承：按 C3 顺序依次调用，配合 super().__init__() 可避免菱形重复初始化
  • 经典写法：子类 __init__ 里 super().__init__(...) 再初始化自己的属性
super 不是「找爸爸」而是「沿 MRO 找下一个」；统一用 super 多继承才安全
Q
如何实现单例模式？🔥 高频

三种常见实现：

  • ① 重写 __new__：实例存在则直接返回（最常用）
  • ② 装饰器：用字典缓存类实例
  • ③ 模块级变量：模块天然单例，直接导入共享对象（最简单）
class Singleton:
    _instance = None
    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

s1 = Singleton(); s2 = Singleton()
s1 is s2  # True
new 里判空再创建，有就直接返回；多线程注意加锁
Q
实例方法、类方法、静态方法的区别？
  • 实例方法：第一个参数 self，可访问实例属性和类属性
  • 类方法 @classmethod：第一个参数 cls，只能访问类属性，常用于工厂方法（如 dict.fromkeys）
  • 静态方法 @staticmethod：无 self/cls，像普通函数，只是逻辑上归类，不访问类状态
  • 类方法和静态方法均可由类和实例调用；继承时 classmethod 的 cls 是子类
实例有 self 摸状态，类方法有 cls 摸类，静态方法两手空空当工具函数
Q
Python 如何实现抽象类？
  • 用 abc 模块：继承 ABC，方法加 @abstractmethod
  • 抽象类不能实例化；子类必须实现全部抽象方法，否则也不能实例化
  • 作用：定义接口规范，强制子类实现特定行为（类似 Java 接口）
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...

class Circle(Shape):
    def area(self):      # 不实现会报错
        return 3.14 * self.r ** 2
继承 ABC 加 @abstractmethod，抽象方法不实现就不让实例化
Q
@property 的作用？
  • 把方法伪装成属性访问：obj.x 触发方法，不用 obj.x()
  • 配合 @x.setter、@x.deleter 控制读写删，实现封装与校验
  • 好处：接口不变的情况下修改内部实现（先用属性后加逻辑，不破坏调用方）
方法穿属性马甲，读走 getter、写走 setter；校验逻辑藏里面

05 异常与上下文

Q
try/except/else/finally 的执行顺序？🔥 高频
  • 顺序：try 正常执行 → 无异常则执行 else → 无论是否异常都执行 finally
  • else：没有异常时才执行，用于区分「try 主体成功」后的逻辑
  • finally：无论怎样都执行，常用于释放资源、关闭连接
  • finally 中 return 会覆盖 try/except 的 return；finally 里的异常会覆盖原异常
先 try 探路，except 接招，else 无事发生才走，finally 铁定收尾
Q
如何自定义异常？
  • 继承 Exception（不要直接继承 BaseException）
  • 可定义 __init__ 接收额外信息，方便上层捕获后处理
  • 业务代码中自定义异常比返回错误码更 Pythonic，语义清晰
class InsufficientFundsError(Exception):
    def __init__(self, balance, amount):
        super().__init__(f"余额不足: 需 {amount}, 有 {balance}")
        self.balance = balance

raise InsufficientFundsError(100, 200)
继承 Exception 就能自定义，携带上下文信息更好排查
Q
with 上下文管理器的原理？🔥 高频
  • 原理：进入 with 时调用对象的 __enter__，退出时（无论是否异常）调用 __exit__
  • 典型用途：自动关闭文件、锁释放、数据库事务提交/回滚
  • 可用 contextlib.contextmanager 用生成器快速实现（yield 前是 enter，yield 后是 exit）
  • 多个资源：with A() as a, B() as b: 依次进入、逆序退出
进 with 走 enter，出 with 走 exit，异常也挡不住它收尾；contextmanager 一行搞定
Q
raise 的几种用法？
  • raise 异常对象：主动抛出，如 raise ValueError("...")
  • raise（不带参数）：在 except 中原样重新抛出，保留原堆栈
  • raise ... from ...：链式异常，保留原始异常上下文（cause）
  • 裸 raise 与 raise e 的区别：裸 raise 保留完整 traceback
raise 空手是重抛，from 是把根因串起来；排查问题时 cause 是救命线索
Q
异常捕获的顺序有什么讲究？
  • 捕获顺序：子类异常在前，父类在后；先 except ValueError 再 except Exception
  • 若父类在前，子类异常永远轮不到——因为它已被父类捕获
  • 顶层兜底用 except Exception（能捕获几乎全部业务异常）；不要捕 BaseException（会吞掉 KeyboardInterrupt、SystemExit）
  • 尽量捕获具体异常类型，避免一把抓掩盖 bug
子类在前父类在后，兜底用 Exception；具体异常具体抓，别吞 KeyboardInterrupt

06 并发与异步

Q
什么是 GIL？它有什么影响？🔥 高频
  • GIL（全局解释器锁）：CPython 中同一时刻只允许一个线程执行 Python 字节码
  • 影响：CPU 密集型多线程无法并行，多线程只适合 IO 密集型（等待时释放 GIL）
  • 解决：CPU 密集用多进程（multiprocessing，各自独立解释器）或用 C 扩展/NumPy 释放 GIL
  • GIL 不是 Python 语言的特性，是 CPython 实现的特性；PyPy/Jython 无 GIL
  • 注意：Python 3.13+ 推出自由线程（no-GIL）实验模式
GIL 是一把全局大锁：算数只能单线程跑，等 IO 才放行；要并行上多进程
Q
线程、进程、协程的区别？🔥 高频
进程线程协程
资源独立内存，开销大共享进程内存，开销小同一线程内切换，开销最小
切换内核级，代价高内核级（OS 调度）用户级，主动让出
适用CPU 密集 + 真并行IO 密集（有 GIL 限制）高并发 IO（异步）
通信Queue/Pipe/共享内存共享变量 + 锁直接 await 调用
进程隔离最安全，线程共享省开销，协程切得最勤快；CPU 用进程、IO 用协程
Q
什么是协程？和线程有什么区别？🔥 高频
  • 协程是用户态轻量级线程：由程序自己控制调度，遇到 IO 主动 await 让出控制权
  • 一个线程内可以跑成千上万个协程，切换成本远低于线程
  • 协程是协作式调度（主动让出），线程是抢占式（OS 强制切换）
  • 适合大量网络 IO（爬虫、Web 服务、API 调用）；不适合 CPU 密集计算
协程=同一个线程里自己排队办事；遇 IO 就放手，等数据回来再接上
Q
asyncio 的工作原理？🔥 高频
  • 核心是事件循环（Event Loop）：单线程循环处理任务队列
  • 协程函数（async def）创建协程对象，需 asyncio.run() 启动事件循环
  • await 遇到 IO 时：注册回调 → 让出控制权 → 事件循环去跑别的任务 → IO 完成回调恢复
  • asyncio.gather() 并发执行多个协程；create_task() 创建后台任务
  • 关键：必须用非阻塞 IO 库（aiohttp 等），同步 requests 会阻塞整个循环
事件循环是调度员，await 是让位信号；gather 一拖多，同步库千万别混进来
Q
async / await 关键字的作用？
  • async def 定义协程函数，调用返回协程对象（不会立即执行）
  • await 挂起当前协程等待另一个 awaitable 完成，期间让出事件循环
  • await 只能在 async 函数内使用；异步函数里不能直接调用阻塞同步函数
  • 常见 awaitable：协程对象、asyncio.Future/Task、实现了 __await__ 的对象
async 宣告协程身份，await 说「我去等数据，别人先跑」
Q
多线程中如何保证线程安全？什么是死锁？🔥 高频
  • 共享可变数据要加锁：threading.Lock；读多写少用 RLock（可重入）或 Condition
  • 死锁条件：互斥 + 持有并等待 + 不可剥夺 + 循环等待（四个条件同时满足）
  • 避免死锁：① 固定加锁顺序；② 用 with + 超时（acquire(timeout=)）；③ 尽量用队列替代共享变量
  • 原子操作（如 queue.put、dict 单步赋值）本身安全，复合操作（读-改-写）才需要锁
锁顺序要统一、超时要加上；共享变量少一点，队列传参更安全
Q
多线程场景为什么推荐用 queue 而不是共享列表？
  • queue.Queue 内置锁，put/get 原子且线程安全，无需自己加锁
  • 支持阻塞等待（get(timeout=)、task_done/join），天然适合生产者-消费者模型
  • 共享 list 的 append + pop 分步操作非原子，多线程读写会丢数据/错乱
  • 进程间用 multiprocessing.Queue，异步场景用 asyncio.Queue
queue 自带锁和阻塞，生产消费开箱即用；裸 list 共享是踩雷区
Q
ThreadPoolExecutor 和 ProcessPoolExecutor 怎么选？
  • IO 密集（网络请求、读写文件）→ ThreadPoolExecutor（等待时释放 GIL）
  • CPU 密集（计算、训练）→ ProcessPoolExecutor（绕开 GIL 真并行）
  • 进程池注意：参数需可 pickle，数据拷贝有开销，不适合传大对象
  • 用法一致：executor.map(func, items) 或 submit() + as_completed()
等 IO 用线程池，算 CPU 用进程池；提交任务一把梭，as_completed 收结果
Q
并发场景怎么选型？给一个决策总结🔥 高频
场景推荐方案理由
CPU 密集计算多进程 / C 扩展绕开 GIL 真并行
大量网络 IOasyncio 协程单线程高并发，开销最小
少量阻塞 IO多线程实现简单，等待时释放 GIL
混合型协程 + 线程池组合异步编排 + 阻塞任务扔线程池
算数找进程、等网找协程、杂活找线程；先分清是「等」还是「算」

07 内存与性能

Q
Python 的内存管理机制是怎样的？🔥 高频
  • 核心是引用计数：每个对象记录被引用次数，归零立即回收
  • sys.getrefcount(x) 查看引用数；变量赋值、传入函数、放入容器都会 +1
  • 引用计数缺点：无法处理循环引用（A 引用 B、B 引用 A）→ 需辅助垃圾回收
  • 小对象由内存池（pymalloc）复用，减少系统调用；大对象直接走 malloc
引用计数管大部分：计数归零就回收；查引用 getrefcount，循环引用它管不了
Q
Python 的垃圾回收（GC）机制？🔥 高频
  • 两层体系：引用计数为主 + 分代回收为辅（处理循环引用）
  • 分代回收：对象分 0/1/2 三代，新对象在第 0 代，熬过一轮 GC 升级一代
  • 触发条件：每代分配对象数达到阈值（gc.get_threshold()）时触发对应代回收
  • 算法：标记-清除（标记可达对象，清除不可达）配合分代
  • 可手动 gc.collect()；对象实现 __del__ 且循环引用时回收顺序不确定
引用计数管日常，分代回收清循环；标记可达、清除垃圾，代越老越少查
Q
什么是循环引用？如何避免？
  • 两个对象互相引用且外部不再可达 → 引用计数永不归零 → 内存无法立即释放
  • 分代 GC 最终会回收，但有延迟，大量循环引用会造成内存峰值
  • 避免：① 用 weakref（弱引用不增加引用计数，常用于缓存、回调）；② 打破环（置 None）；③ 用 __slots__ 减小对象
A 抱 B、B 抱 A 谁也放不下手；弱引用不计数，破环靠置空
Q
Python 内存泄漏怎么排查？
  • 常见来源：全局缓存/单例无限增长、闭包误捕大对象、循环引用 + __del__、第三方库持有引用
  • 排查工具：① tracemalloc（按行追踪分配）；② objgraph 生成引用图；③ gc.get_objects() 统计对象类型；④ psutil 监控 RSS
  • 思路：先确认内存持续上升 → 定位增长对象类型 → 用 objgraph 找引用链 → 修复
先看谁在涨，再用 tracemalloc 定位行号，objgraph 画引用链，最后修源头
Q
Python 性能优化有哪些常用技巧？🔥 高频
  • 选对数据结构：成员判断用 set 不用 list；dict 代替多重 if
  • 惰性计算：生成器代替大列表；yield 流式处理
  • 字符串拼接：用 join() 不用 + 循环拼
  • 内置函数优先：map/sorted/max 是 C 实现，快于手写循环；NumPy 向量化替代 Python 循环
  • 减少属性访问：局部变量缓存 obj.method、模块函数 from math import sqrt
  • 缓存：@lru_cache 记忆化重复计算；CPU 密集上多进程 / Cython / C 扩展
set 查得快、join 拼得快、内置函数跑得快、局部变量拿得快；先 profile 再优化
Q
functools.lru_cache 怎么用？
  • 为纯函数（同参同结果）加缓存，用 LRU 策略淘汰最久未用项
  • 用法：@lru_cache(maxsize=128)；maxsize=None 不淘汰（注意内存）
  • 典型场景：递归斐波那契、动态规划、重复计算的纯函数
  • 参数必须可哈希（不可变类型）；cache_clear() 清空缓存
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
纯函数套 lru_cache，算过的不再算；递归成倍提速就靠它
Q
Python 性能分析工具怎么用？
  • timeit：微基准测试，测单段代码耗时（python -m timeit "代码"）
  • cProfile：函数级剖析，统计每个函数调用次数与耗时：python -m cProfile -s cumtime app.py
  • line_profiler：逐行耗时（需 pip 安装），定位热点行
  • memory_profiler：逐行内存占用
  • 原则：先测量再优化，80% 时间花在 20% 代码上，别优化没热点的代码
timeit 测微段、cProfile 看函数、line_profiler 精到行；先量化再动手

08 文件与 IO

Q
open() 的常用模式和编码问题？🔥 高频
  • 模式：r 只读（默认）、w 写入（清空）、a 追加、x 排他新建；+ 加读写；b 二进制
  • 编码：open(path, encoding="utf-8")，不指定时 Windows 默认 GBK 易乱码
  • newline="" 控制换行；二进制模式读写字节（图片、文件传输）
  • 文本读到的 str 与字节流 b"..." 的转换：encode/decode
r 读 w 清 a 追加 x 排他；带 b 是字节流，utf-8 编码写明白防乱码
Q
大文件如何高效读取？🔥 高频
  • 绝不用 read() / readlines() 一次全读（内存爆掉）
  • 逐行迭代：for line in f: 惰性读，每行才占内存
  • 需要分块读二进制：while chunk := f.read(8192): 循环读固定大小
  • 处理超大文本（GB 级）：流式处理或分片 + 生成器封装
with open("big.log", encoding="utf-8") as f:
    for line in f:          # 逐行读，内存只存一行
        process(line)

with open("big.bin", "rb") as f:
    while chunk := f.read(8192):   # 分块读二进制
        process(chunk)
大文件别贪心，一行一行吃；二进制分块 8K 一口
Q
json 序列化常用操作？🔥 高频
  • json.dumps(obj)：对象 → 字符串；json.loads(s)：字符串 → 对象
  • json.dump(obj, f) / json.load(f)：直接读写文件
  • 中文不乱码：ensure_ascii=False；美化输出：indent=2
  • 只支持基本类型（dict/list/str/int/float/bool/None）；自定义对象需 default= 转换函数
  • 注意 tuple → list、dict key 必须字符串
dumps 出串 loads 进，dump/load 管文件；中文 ensure_ascii=False，自定义对象写 default
Q
pickle 和 json 有什么区别？
  • pickle：Python 专属二进制序列化，可序列化任意 Python 对象（函数、类、生成器等）

Q
Cookie、Session、Token 的区别？🔥 高频
  • Cookie：存在浏览器端的小数据，自动随请求携带；有大小限制（4KB）、可被篡改
  • Session：存在服务端，客户端只存 session_id（放 Cookie 里）；服务端可主动失效；分布式需共享存储（Redis）

  • 安全：Cookie 设 HttpOnly + Secure + SameSite；Token 走 HTTPS 防劫持
Cookie 存浏览器、Session 存服务器、Token 随身带签名；要吊销用 Session，要分布式用 Token

类型注解即校验、async 即并发、/docs 即文档；现代 Python API 首选

11 数据库与存储

Q
SQL 和 NoSQL 的区别？🔥 高频
  • SQL（MySQL/PostgreSQL）：结构化表、强约束、事务 ACID、复杂关联查询强；适合金融、订单等强一致场景
  • NoSQL：文档（MongoDB）/KV（Redis）/宽表（HBase）/图（Neo4j）；灵活 schema、易水平扩展；弱一致或最终一致
  • 选择标准：数据结构固定 + 强事务 → SQL；高并发 KV/文档 + 快速迭代 → NoSQL
  • 现代架构常混合使用：MySQL 存核心业务，Redis 做缓存，ES 做搜索
SQL 讲规矩重事务，NoSQL 图快好扩展；核心数据 SQL、热点缓存 Redis
Q
数据库索引的原理？🔥 高频
  • 底层主要是 B+ 树：非叶子节点只存索引、叶子存数据且有序链表，适合范围查询与磁盘 IO
  • 主键索引（聚簇）：叶子存整行数据；二级索引：叶子存主键值，需回表查数据
  • 覆盖索引：查询列都在索引里，免回表（优化技巧）
  • 代价：写操作变慢（要维护索引）、占空间；最左前缀：联合索引按最左列匹配
  • 索引失效：对索引列用函数/运算、隐式类型转换、LIKE '%xx' 前置通配
B+ 树有序好范围查；聚簇带数据、二级要回表、覆盖不用回；最左前缀、别对列做运算
Q
什么是 SQL 注入？如何用 Python 防住？🔥 高频
  • 注入原理：用户输入拼进 SQL，恶意字符串改变语句语义，如 ' OR 1=1 --
  • 防护核心：参数化查询（预编译），让输入只当数据不当代码
  • Python 写法：cursor.execute("SELECT * FROM users WHERE id=%s", (uid,))（不要 % 拼接）
  • ORM（SQLAlchemy/Django ORM）默认参数化，自动防注入；禁止 text() 裸拼用户输入
  • 其他：最小权限账号、输入校验白名单、不把报错细节暴露给前端
永远参数化，绝不拼字符串；占位符 %s 是防弹衣，ORM 帮你穿了
Q
事务的 ACID 是什么？
  • A 原子性：事务要么全成功要么全回滚（undo log）
  • C 一致性：事务前后数据约束不被破坏
  • I 隔离性：并发事务互不干扰（锁/MVCC）
  • D 持久性：提交后修改永久保存（redo log）
  • Python 中：connection.begin() / commit() / rollback()；ORM 用 with 事务上下文
原子要么全做要么全不做，一致约束不破，隔离并发不串，持久断电不丢
Q
ORM 的优缺点？

  • 缺点：复杂查询表达受限（可能生成低效 SQL）、性能有损耗、隐蔽的 N+1 查询问题、学习框架本身有成本
  • N+1 问题：循环查子表导致多次查询，用 joinedload/selectinload 预加载解决
  • 主流：SQLAlchemy（Flask/FastAPI）、Django ORM、Tortoise ORM（异步）
ORM 快而安全，但复杂查询和 N+1 要小心；预加载治 N+1，极端 SQL 手写兜底

Redis 的常用数据结构和使用场景？🔥 高频
  • String：缓存、计数器、分布式锁（SETNX）；Hash：对象/用户信息
  • List：消息队列、最新列表（LPUSH+BRPOP）；Set：去重、点赞、共同好友（交并差）

两数之和（LeetCode 1）🔥 高频

核心思路：哈希表记录「补数」，一遍遍历 O(n)

def two_sum(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        if target - num in seen:      # 补数出现过
            return [seen[target - num], i]
        seen[num] = i                 # 记录当前值的位置
    return []
边遍历边存边找补数；一次循环 O(n)，哈希换时间

反转链表（迭代 + 递归）🔥 高频 
def reverse_list(head):
    prev = None
    cur = head
    while cur:

def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left  = [x for x in arr if x < pivot]
    mid   = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + mid + quick_sort(right)

def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

实现 LRU 缓存（LeetCode 146）🔥 高频

核心：哈希表 + 双向链表——哈希 O(1) 定位，链表 O(1) 维护顺序

from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.d = OrderedDict()

    def get(self, key):
        if key not in self.d:
            return -1
        self.d.move_to_end(key)      # 刚访问 → 移到末尾（最新）
        return self.d[key]

    def put(self, key, value):
        if key in self.d:
            self.d.move_to_end(key)
        self.d[key] = value
        if len(self.d) > self.cap:
            self.d.popitem(last=False)   # 淘汰最久未用（头部）
哈希定位 + 链表排序；get/put 都 move_to_end，超容量弹头部；OrderedDict 秒实现
