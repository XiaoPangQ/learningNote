01 HTML & CSS

Q
什么是 HTML 语义化？为什么要用语义化标签？🔥 高频

定义：用恰当语义的 HTML 标签来组织内容结构，如 <header><nav><main><article><section><aside><footer>。

好处：

  • 可读性：代码结构清晰，开发者一看就懂
  • SEO：搜索引擎更容易识别内容层次和权重
  • 无障碍：屏幕阅读器能更好地解析页面
  • 维护性：即使没有 CSS 也能呈现清晰的文档结构
标签见名知意 → 人能懂、搜索引擎能懂、读屏软件能懂
Q
说一下 CSS 盒模型？🔥 高频

每个元素都由四层矩形区域组成：content（内容）→ padding（内边距）→ border（边框）→ margin（外边距）。

两种盒模型通过 box-sizing 切换：

  • content-box（标准/W3C）：width 只含 content，实际宽度 = width + padding + border
  • border-box（IE）：width 包含 content + padding + border，实际宽度就是 width
开发中通常全局设置 *, *::before, *::after { box-sizing: border-box; }，方便尺寸计算。
content-box 加加减减、border-box 所见即所得
Q
Flex 布局常用属性有哪些？🔥 高频

分为容器属性和项目属性：

容器（父）：

  • flex-direction：主轴方向（row / column / row-reverse / column-reverse）
  • justify-content：主轴对齐（flex-start / center / space-between / space-around）
  • align-items：交叉轴对齐（stretch / flex-start / center / baseline）
  • flex-wrap：是否换行（nowrap / wrap）
  • gap：项目间距

项目（子）：

  • flex: 1：flex-grow:1; flex-shrink:1; flex-basis:0% 的缩写，等分剩余空间
  • align-self：单独控制某个项目的交叉轴对齐
  • order：排列顺序，默认 0，越小越靠前
父管方向对齐换行，子管放大缩小顺序
Q
如何实现元素水平垂直居中？

方案一：Flex（最常用）

.parent {
  display: flex;
  justify-content: center;
  align-items: center;
}

方案二：Grid（最简洁）

.parent { display: grid; place-items: center; }

方案三：绝对定位 + transform（不定宽高）

.child {
  position: absolute;
  top: 50%; left: 50%;
  transform: translate(-50%, -50%);
}

方案四：绝对定位 + margin auto（定宽高）

.child {
  position: absolute;
  inset: 0; margin: auto;
  width: 200px; height: 200px;
}
Flex 三件套、Grid 一句话、绝对定位加位移
Q
什么是 BFC？如何触发？有什么用？🔥 高频

BFC（Block Formatting Context）块级格式化上下文，是一个独立的渲染区域，内部元素的布局不会影响外部。

触发条件（满足任一）：

  • 根元素 <html>
  • float 不为 none
  • position 为 absolute 或 fixed
  • display: inline-block / flex / grid / table-cell
  • overflow 不为 visible（如 hidden、auto、scroll）

作用：

  • 解决 margin 塌陷：父子元素 margin 合并问题
  • 清除浮动：父元素高度塌陷时，overflow: hidden 触发 BFC
  • 阻止元素被浮动覆盖：实现自适应两栏布局
BFC 是个结界——里面的翻不出外面的浪
Q
CSS 有哪些定位方式？区别是什么？
  • static：默认，按正常文档流，top/left 无效
  • relative：相对自身原位置偏移，不脱离文档流
  • absolute：相对最近的非 static 祖先定位，脱离文档流
  • fixed：相对视口定位，脱离文档流，不随滚动移动
  • sticky：滚动到阈值前为 relative，之后变为 fixed（吸顶效果）
position: absolute 不指定 top/left 时，元素停留在原位置（但已脱离文档流），常被忽略。
Q
如何做响应式设计？
  • 媒体查询：@media (max-width: 768px) { ... }
  • 弹性布局：Flex / Grid 自适应排列
  • 相对单位：rem、em、vw/vh、% 替代固定 px
  • 图片自适应：max-width: 100%; height: auto; + <picture> / srcset
  • 视口设置：<meta name="viewport" content="width=device-width, initial-scale=1">
  • 移动端优先：先写小屏样式，再用 min-width 逐步增强
媒体查询加弹性，相对单位视口设

02 JavaScript 核心

Q
this 的指向规则是什么？🔥 高频

this 指向调用时确定，分四种绑定规则（优先级从高到低）：

  1. new 绑定：new 调用的函数，this 指向新创建的实例对象
  2. 显式绑定：call/apply/bind 调用，this 指向指定对象
  3. 隐式绑定：作为对象方法调用，this 指向调用该方法的对象
  4. 默认绑定：独立函数调用，非严格模式指向 window，严格模式为 undefined

特殊情况：

  • 箭头函数没有自己的 this，继承外层作用域的 this
  • DOM 事件处理函数中 this 指向绑定事件的元素
new > 显式 > 隐式 > 默认，箭头函数看外层
Q
什么是闭包？应用场景？有什么问题？🔥 高频

定义：函数与其词法环境的引用捆绑在一起，内部函数可以访问外部函数的变量，即使外部函数已执行完毕。

本质：函数作用域在函数定义时就确定了（词法作用域），而非调用时。

function counter() {
  let count = 0;              // 私有变量
  return function() {
    return ++count;           // 闭包持有 count 引用
  };
}
const c = counter();
c(); // 1
c(); // 2

应用场景：

  • 数据私有化（模块模式、私有变量）
  • 函数柯里化 / 偏函数
  • 防抖节流（持有 timer 变量）
  • React Hooks 中状态的持久化

问题：闭包引用的变量不会被垃圾回收，滥用可能导致内存泄漏。不需要时应手动解除引用。

闭包 = 函数 + 定义时的作用域；能记住出生的地方
Q
说一下原型和原型链？🔥 高频
  • 每个函数都有 prototype 属性（原型对象）
  • 每个对象都有 __proto__，指向构造函数的 prototype
  • 访问对象属性时，自身没有就沿 __proto__ 向上查找，直到 null，这条链就是原型链
function Person(name) { this.name = name; }
Person.prototype.sayHi = function() { return "Hi " + this.name; };

const p = new Person("Alice");
p.sayHi();  // 自身没有 → 沿 __proto__ → Person.prototype 找到

p.__proto__ === Person.prototype           // true
Person.prototype.__proto__ === Object.prototype  // true
Object.prototype.__proto__ === null        // true（链的终点）

关键记忆：

  • p.constructor === Person（constructor 从原型继承）
  • p instanceof Person：沿原型链检查 Person.prototype 是否在 p 的链上
函数有 prototype，对象有 __proto__，找属性沿链往上走，走到 null 就到头
Q
说一下浏览器的事件循环（Event Loop）？🔥 高频

JavaScript 是单线程的，通过事件循环实现非阻塞异步执行。

执行顺序：

  1. 调用栈：执行同步代码，栈空后进入下一步
  2. 微任务队列（microtask）：全部执行完（Promise.then/catch/finally、queueMicrotask、MutationObserver）
  3. 宏任务队列（macrotask）：取一个执行（setTimeout、setInterval、I/O、UI 渲染、MessageChannel）
  4. 执行完一个宏任务后，再清空所有微任务，然后可能渲染，再取下一个宏任务
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => {
  console.log("3");
  Promise.resolve().then(() => console.log("4"));
});

console.log("5");
// 输出：1, 5, 3, 4, 2
每执行一个宏任务后都会清空微任务队列！不是等所有宏任务结束才执行微任务。
同步先走 → 微任务全清 → 一个宏任务 → 再清微任务 → 循环
Q
Promise 的状态和常用方法？🔥 高频

三种状态（不可逆）：

  • pending → fulfilled（成功）
  • pending → rejected（失败）

常用方法：

方法作用失败时
Promise.all(arr)全部成功才成功，返回结果数组一个失败立即失败
Promise.allSettled(arr)等所有完成（无论成败）永远不失败
Promise.race(arr)第一个完成（无论成败）第一个失败则失败
Promise.any(arr)第一个成功的结果全失败才失败

async/await 是 Promise 的语法糖：

  • async 函数返回 Promise
  • await 等待 Promise resolve，以同步写法写异步逻辑
  • 用 try/catch 捕获 rejected
all 全成才成、allSettled 全收尾、race 谁快算谁、any 第一个成功
Q
什么是变量提升？

JavaScript 在执行前会进行编译阶段，将变量和函数声明提升到作用域顶部。

  • var：声明提升，值为 undefined
  • function：整个函数声明提升（可先调用后定义）
  • let/const：也有提升，但存在暂时性死区（TDZ），声明前访问报错
console.log(a);  // undefined（var 提升）
var a = 1;

console.log(b);  // ReferenceError（let 在 TDZ）
let b = 2;
Q
什么是作用域链？

变量查找时，从当前作用域开始，逐层向外层作用域查找，直到全局作用域。这条查找链就是作用域链。

  • 全局作用域：最外层，任何地方都能访问
  • 函数作用域：函数内部声明的变量外部不可见
  • 块级作用域（ES6 let/const）：{} 内部有效

作用域在定义时确定（词法作用域/静态作用域），和调用位置无关。

Q
JavaScript 有哪些数据类型？如何准确判断类型？🔥 高频

8 种类型：

  • 原始类型（7种）：undefined、null、boolean、number、string、bigint、symbol
  • 引用类型：object（含 Array、Function、Date、RegExp 等）

判断方式：

方式适用问题
typeof判断原始类型null 返回 "object"，数组/对象都返回 "object"
instanceof判断引用类型跨 iframe 失效，无法判断原始类型
Object.prototype.toString.call()万能写法较长
Array.isArray()判断数组仅数组
Object.prototype.toString.call(null)       // "[object Null]"
Object.prototype.toString.call([])         // "[object Array]"
Object.prototype.toString.call(() => {})   // "[object Function]"
typeof 判原始、instanceof 判原型、toString 万能
Q
浅拷贝和深拷贝的区别？如何实现深拷贝？

浅拷贝：只复制第一层，嵌套对象仍共享引用。方法：Object.assign()、展开运算符 {...obj}。

深拷贝：递归复制所有层级，互不影响。

  • 简单场景：JSON.parse(JSON.stringify(obj))（不能处理函数、undefined、Symbol、循环引用、Date）
  • 完善方案：递归遍历 + WeakMap 处理循环引用 + 类型判断
  • 项目中：structuredClone(obj)（浏览器原生支持）或 lodash 的 _.cloneDeep()
Q
防抖和节流的区别和应用？🔥 高频

防抖（debounce）：事件触发后等待 n 秒再执行，n 秒内再次触发则重新计时。→ 只执行最后一次。

节流（throttle）：n 秒内只执行一次，无论触发多少次。→ 按频率执行。

防抖 debounce节流 throttle
搜索输入✅ 输入停止后发请求
窗口 resize✅ 调整完再计算
滚动加载✅ 每隔 N ms 检查
按钮防重复提交✅
鼠标移动跟踪✅
防抖等停下来、节流按频率来
Q
什么是事件委托（事件代理）？🔥 高频

原理：利用事件冒泡，将子元素的事件绑定到父元素上，通过 event.target 判断实际触发的子元素。

优点：

  • 减少事件绑定数量，节省内存
  • 动态添加的子元素无需重新绑定事件
document.getElementById("list").addEventListener("click", (e) => {
  if (e.target.tagName === "LI") {
    console.log("点击了:", e.target.textContent);
  }
});
子债父还——把子的事交给冒泡后的父来管

Q
箭头函数和普通函数的区别？🔥 高频
  1. 没有 this：继承外层作用域的 this，不能用 call/apply/bind 改变
  2. 没有 arguments：用剩余参数 ...args 替代
  3. 没有 prototype：不能作为构造函数，不能 new
  4. 不能用作 Generator：不能使用 yield
对象方法、DOM 事件回调、原型方法不适合用箭头函数（this 不符合预期）。

解构赋值的用法？

// name="Alice", myAge=30（重命名）

// 函数参数解构

  console.log(name, age);
}

Q
ES6 Class 和构造函数的关系？

Class 本质上是语法糖，底层仍基于原型链。

  • class 声明不会提升（类似 let）
  • class 内部默认严格模式
  • 方法不可枚举（non-enumerable）
  • 必须通过 new 调用，不能直接执行
  • static 定义静态方法/属性，#field 定义私有字段（ES2022）
  • extends 实现继承，super 调用父类构造/方法
Q
可选链和空值合并运算符？
// 可选链 ?. —— 左侧为 null/undefined 时短路返回 undefined
const city = user?.address?.city;  // 不报错
const fn = obj.someMethod?.();    // 方法不存在也不报错

// 空值合并 ?? —— 只在 null/undefined 时取默认值
const name = input ?? "default";  // 注意：0、false、"" 不会触发

// 区别 || ：|| 对所有 falsy 值都生效
const x = 0 || 10;   // 10
const y = 0 ?? 10;   // 0

04 浏览器 & 网络

Q
HTTP 和 HTTPS 的区别？HTTPS 如何保证安全？🔥 高频

区别：

  • HTTP 明文传输，端口 80；HTTPS 加密传输，端口 443
  • HTTPS = HTTP + SSL/TLS

HTTPS 三大保证：

  1. 机密性：对称加密传输数据（AES），非对称加密（RSA/ECDHE）交换密钥
  2. 完整性：数字签名/MAC 摘要防止篡改
  3. 身份认证：CA 证书验证服务器身份，防中间人攻击

TLS 握手简化流程：Client Hello → Server Hello + 证书 → 密钥交换 → 切换加密通信。

对称加密传数据、非对称换密钥、CA 证书验身份
Q
浏览器缓存机制？强缓存和协商缓存？🔥 高频

强缓存（不发请求，直接读本地）：

  • Cache-Control: max-age=3600（优先级高，HTTP/1.1）
  • Expires（绝对时间，HTTP/1.0，受客户端时间影响）

协商缓存（发请求，服务器判断是否命中）：

  • Last-Modified / If-Modified-Since：对比最后修改时间（秒级精度）
  • ETag / If-None-Match：对比文件指纹（更精确，优先级更高）
  • 命中返回 304 Not Modified，不返回 body

缓存位置（优先级）：Memory Cache（内存，快但短命）→ Disk Cache（磁盘，持久）→ Service Worker。

强缓存不发请求靠 max-age，协商缓存发请求问服务器 304 还是 200
Q
什么是跨域？如何解决？🔥 高频

同源策略：协议、域名、端口三者完全相同才是同源。不同源的请求受浏览器限制（无法读取响应）。

解决方案：

  1. CORS（主流）：服务端设置响应头 Access-Control-Allow-Origin 等
  2. 代理服务器：开发环境 webpack-dev-server / Vite proxy，生产环境 Nginx 反向代理
  3. JSONP：利用 <script> 不受同源限制（仅 GET，已过时）
  4. postMessage：跨窗口/iframe 通信
  5. WebSocket：本身不受同源策略限制
跨域是浏览器的限制，服务端之间请求不存在跨域。CORS 简单请求直接发，非简单请求（PUT/DELETE/自定义头）会先发 OPTIONS 预检请求。
Q
Cookie、Session、Token 的区别？
CookieSessionToken (JWT)
存储浏览器服务端客户端
跨域受限依赖 Cookie header 携带，跨域友好
扩展性—分布式需共享无状态，易扩展
大小4KB—无限制（但别太大）

JWT 结构：Header（算法）. Payload（数据）. Signature（签名），用 . 分隔。Payload 仅 Base64 编码，不要放敏感信息。

Cookie 存浏览器、Session 存服务器、Token 客户端拿着走
Q
从输入 URL 到页面渲染发生了什么？🔥 高频
  1. URL 解析：浏览器判断输入是搜索还是 URL
  2. DNS 解析：域名 → IP 地址（递归查询 + 缓存）
  3. TCP 三次握手：建立连接；HTTPS 额外进行 TLS 握手
  4. 发送 HTTP 请求：请求行 + 请求头 + 请求体
  5. 服务器处理并返回响应：状态码 + 响应头 + 响应体（HTML）
  6. 浏览器解析渲染：
    • HTML → DOM 树
    • CSS → CSSOM 树
    • 合并为 Render 树
    • Layout（布局/重排）：计算位置大小
    • Paint（绘制）：填充像素
    • Composite（合成）：GPU 分层合成
  7. TCP 四次挥手：断开连接（或保持 Keep-Alive）
DNS → TCP/TLS → 请求响应 → DOM/CSSOM → 渲染树 → 布局绘制合成 → 断开
Q
什么是重排（reflow）和重绘（repaint）？如何优化？🔥 高频

重排（回流 Reflow）：元素的尺寸、位置、结构发生变化，需重新计算布局。开销大。

重绘（Repaint）：外观变化（颜色、背景）但不影响布局。开销较小。

重排必定导致重绘，重绘不一定重排。

优化手段：

  • 批量修改 DOM：用 DocumentFragment 或 display:none 后批量操作再显示
  • 避免逐条修改 style，用 class 批量切换
  • 使用 transform 和 opacity（触发合成层，不重排重绘）
  • 避免频繁读取 offsetTop/offsetHeight/getComputedStyle（强制刷新渲染队列）
  • 对动画元素使用 will-change 或 position: absolute/fixed 脱离文档流
改几何重排、改外观重绘；transform 走合成最省事

05 Vue

Q
Vue 的响应式原理是什么？Vue2 和 Vue3 的区别？🔥 高频

Vue2：Object.defineProperty

  • 遍历对象属性，用 getter/setter 劫持数据
  • getter 中收集依赖（Dep 收集 Watcher）
  • setter 中触发更新（notify → Watcher 更新视图）
  • 缺点：无法检测对象属性的新增/删除（需 Vue.set）、无法直接监听数组索引变化、初始化时递归遍历性能差

Vue3：Proxy

  • 用 Proxy 代理整个对象，支持动态新增属性
  • 支持数组索引和 length 变化
  • 惰性响应式（访问到才代理深层），性能更好
  • 配合 Reflect 操作源对象
  • 用 track（依赖收集）和 trigger（触发更新）替代 Dep/Watcher
Vue2 用 defineProperty 逐属性劫持、Vue3 用 Proxy 代理整个对象
Q
虚拟 DOM 是什么？Diff 算法过程？🔥 高频

虚拟 DOM：用 JS 对象描述真实 DOM 结构（tag、props、children）。状态变化时生成新 VNode，与旧 VNode 对比（Diff），计算最小更新量再操作真实 DOM。

Diff 策略（同层比较，不跨层）：

  1. 先比 tag，不同直接替换整个节点
  2. tag 相同，比较 props，更新差异属性
  3. 比较 children：
    • 都有 key：按 key 复用（高效）
    • 无 key：双端比较 / 头尾指针（Vue2）
    • Vue3 使用最长递增子序列算法，减少移动次数
key 必须是唯一且稳定的，不要用数组 index（列表顺序变化时导致错误复用）。
VNode 描述 DOM、Diff 同层比较、key 提升复用

Q
computed 和 watch 的区别？
  • computed：计算属性，基于响应式数据缓存，依赖不变不重新计算。必须 return 值。适合派生数据。
  • watch：侦听器，监听数据变化执行副作用（异步请求、操作 DOM）。不 return。
  • computed 默认懒执行（lazy），watch 默认惰性（可设 immediate: true）
  • watch 可监听多个源、可获取新旧值、支持 deep 深度监听
需要值用 computed，需要做事用 watch。

Q
v-if 和 v-show 的区别？
  • v-if：真正的条件渲染，false 时 DOM 不存在。有更高切换开销。适合不常变化的条件。
  • v-show：始终渲染 DOM，通过 display: none 控制显隐。有更高初始渲染开销。适合频繁切换。
不常变用 v-if、频繁切用 v-show
Q
$nextTick 的原理和使用场景？

原理：Vue 更新 DOM 是异步的（批量缓冲到微任务）。$nextTick 在 DOM 更新完成后执行回调，内部优先使用 Promise.then / MutationObserver / setImmediate / setTimeout。

场景：修改数据后需要操作更新后的 DOM。

this.show = true;
this.$nextTick(() => {
  // 此时 DOM 已更新，可以获取新元素
  this.$refs.input.focus();
});
Q
keep-alive 的作用和生命周期？

缓存不活动的组件实例，避免重复渲染。配合 <router-view> 使用。

  • include / exclude：控制缓存哪些组件（按 name）
  • max：最大缓存数，超出后用 LRU 策略淘汰
  • 被缓存组件独有生命周期：activated（进入时触发）和 deactivated（离开时触发）

  2. Composition API：setup + ref/reactive/computed/watch，逻辑组织更灵活，替代 Options API 的碎片化
  3. 更小体积：Tree-shaking 支持，按需引入
  4. 更好的 TS 支持：源码用 TS 重写
  5. Fragment：组件可有多根节点
  6. Teleport：组件内容传送到 DOM 其他位置（如弹窗）
  7. Suspense：异步组件加载状态
  8. 性能提升：编译时优化（静态提升、补丁标记、事件缓存）
  9. 新生命周期：onMounted/onUpdated/onUnmounted 等
Proxy 响应式、Composition 组合式、Tree-shaking 小体积、TS 原生支持

06 React

Q
JSX 的本质是什么？🔥 高频

JSX 是 React.createElement(component, props, ...children) 的语法糖，经 Babel/TypeScript 编译为 JS 函数调用。

// JSX
<div className="box">Hello</div>

// 编译后
React.createElement("div", { className: "box" }, "Hello")

// 返回 VNode（普通 JS 对象）
// { type: "div", props: { className: "box", children: "Hello" } }

注意：

  • JSX 中 class → className、for → htmlFor
  • style 接收对象而非字符串
  • 必须用 <Fragment> 或 <> 包裹多根元素（React 16+）
Q
React Hooks 的原理和规则？🔥 高频

原理：每个函数组件对应一个 fiber 节点，Hooks 以链表形式存储在 fiber 的 memoizedState 上。每次渲染按调用顺序依次读取对应 hook 的状态。

两条规则：

  1. 只在顶层调用 Hooks：不能在循环、条件、嵌套函数中调用（保证顺序一致）
  2. 只在 React 函数中调用：函数组件或自定义 Hook

常用 Hooks：

  • useState：组件状态
  • useEffect：副作用（DOM 操作、订阅、请求）
  • useMemo：缓存计算结果
  • useCallback：缓存函数引用
  • useRef：持久化引用（不触发渲染）
  • useContext：消费 Context
  • useReducer：复杂状态管理
Hooks 靠顺序存取，不能写在条件循环里；顶层调用、函数组件内调用
Q
useEffect 的依赖数组和清理函数？
useEffect(() => {
  // 每次渲染后都执行
  const timer = setInterval(() => {}, 1000);
  return () => clearInterval(timer);  // 清理函数
});  // 无依赖数组

useEffect(() => {
  // 仅挂载时执行
}, []);  // 空数组

useEffect(() => {
  // 挂载和 a/b 变化时执行
}, [a, b]);

清理函数在组件卸载或下次 effect 执行前运行，用于清除定时器、取消订阅、移除事件监听。

依赖数组必须包含 effect 中使用的所有响应式值，否则闭包会捕获旧值。
Q
setState 是同步还是异步？🔥 高频

React 17 及之前：在 React 事件处理函数和生命周期中，setState 是异步批量更新的（多次调用合并）；在 setTimeout、原生事件监听、Promise 回调中是同步的。

React 18：所有更新都自动批处理（Automatic Batching），无论在什么上下文。

// 函数式更新：基于前一个状态计算
setCount(prev => prev + 1);

// 批处理：只会触发一次重渲染
setCount(c => c + 1);
setFlag(true);
setValue("hi");
React 18 全批处理；要基于前值用函数式更新
Q
什么是 Fiber 架构？解决了什么问题？

解决的问题：React 15 的递归渲染（Stack Reconciler）不可中断，大量组件更新时长时间阻塞主线程，导致卡顿。

Fiber（React 16+）：

  • 将渲染工作拆分为小单元（Fiber 节点）
  • 利用 requestIdleCallback 思想（scheduler 包），在浏览器空闲时执行
  • 可中断、可恢复、可优先级调度
  • 双缓存树（current 树 + workInProgress 树），渲染完成后一次性切换
  • 两个阶段：render 阶段（可中断，找差异）+ commit 阶段（不可中断，操作 DOM）
Q
React 类组件生命周期？

挂载：constructor → static getDerivedStateFromProps → render → componentDidMount

更新：getDerivedStateFromProps → shouldComponentUpdate → render → getSnapshotBeforeUpdate → componentDidUpdate

卸载：componentWillUnmount

错误：componentDidCatch / static getDerivedStateFromError

函数组件用 useEffect 对应挂载/更新/卸载：useEffect(() => { mount; return () => unmount }, [])。
Q
React 性能优化手段？
  • React.memo：包裹组件，props 浅比较避免重渲染
  • useMemo：缓存复杂计算结果
  • useCallback：缓存函数引用，防止子组件无谓更新
  • 代码分割：React.lazy + Suspense 路由懒加载
  • 虚拟列表：react-window/react-virtual 处理长列表
  • key 优化：稳定唯一的 key 帮助 Diff
  • 状态下放/提升：将状态尽量放到需要的子组件，避免整树重渲染
  • 避免内联对象：props 传内联对象每次新建，导致 memo 失效
Q
Redux 的工作流程？
  1. 组件通过 dispatch(action) 发送 action（纯对象 {type, payload}）
  2. store 调用 reducer（纯函数 (state, action) => newState）
  3. reducer 返回新 state（不可变更新）
  4. store 通知订阅的组件重新渲染

三大原则：单一数据源、state 只读、用纯函数修改 state。

Redux Toolkit（RTK）是官方推荐写法：createSlice 简化 reducer/action、configureStore 内置中间件、RTK Query 处理异步请求。

dispatch → reducer → new state → 视图更新；单向数据流

Webpack 的构建流程？🔥 高频

Vite 和 Webpack 的区别？为什么 Vite 快？🔥 高频

Loader 和 Plugin 的区别？
  • Loader：模块转换器，在编译阶段将非 JS 文件（CSS、图片、TS 等）转为 JS。执行顺序从右到左、从下到上。例：babel-loader、css-loader、style-loader。
  • Plugin：插件，基于事件钩子（tapable）在整个构建生命周期执行更广泛的任务（打包优化、资源管理、环境变量注入）。例：HtmlWebpackPlugin、MiniCssExtractPlugin。

Q
什么是 Tree Shaking？如何实现？🔥 高频

在打包时移除未使用的代码（dead code elimination），减小体积。

前提条件：

  • 使用 ES Module（import/export 静态结构），CommonJS 不支持
  • mode 设为 production（自动开启）
  • package.json 中 "sideEffects": false（标记无副作用，可安全摇树）

副作用：模块执行时会影响外部的代码（如 polyfill、全局 CSS）。有副作用的文件在 sideEffects 中声明："sideEffects": ["*.css", "*.polyfill.js"]。

CDN 的原理是什么？

CDN（内容分发网络）在全球部署边缘节点，用户访问时通过 DNS 解析/全局负载均衡返回最近的节点 IP，从缓存直接返回静态资源。

  • 就近访问，降低延迟
  • 减轻源站压力
  • 缓存命中时直接返回，未命中回源拉取
Q
什么是 XSS？如何防御？🔥 高频

XSS（跨站脚本攻击）：攻击者向页面注入恶意脚本，在用户浏览器中执行。

三种类型：

  • 存储型：恶意脚本存入数据库，其他用户访问时执行（危害最大，如评论区）
  • 反射型：恶意脚本在 URL 中，服务端原样返回页面（如搜索结果）
  • DOM 型：前端 JS 不安全地使用用户输入操作 DOM

防御：

  1. 输入过滤/转义：对用户输入进行 HTML 实体转义（< → &lt;）
  2. CSP：Content-Security-Policy 限制脚本来源
  3. HttpOnly Cookie：防止 JS 读取敏感 Cookie
  4. 框架自动转义（React/Vue 默认转义插值）
  5. 避免使用 innerHTML、eval、document.write
转义输入、CSP 限源、HttpOnly 护 Cookie、不用 innerHTML

什么是 CSRF？如何防御？🔥 高频

CSRF（跨站请求伪造）：攻击者诱导已登录用户访问恶意网站，利用浏览器自动携带 Cookie 的机制，以用户身份发起伪造请求。

防御：

  1. CSRF Token：服务端生成随机 token，表单提交时验证
  2. SameSite Cookie：设为 Strict 或 Lax，跨站请求不携带 Cookie
  3. 验证 Referer/Origin：检查请求来源
  4. 敏感操作二次验证：验证码、密码确认
XSS 是注入脚本利用用户对网站的信任；CSRF 是伪造请求利用网站对用户的信任。
CSRF 靠 Token + SameSite + Referer 三重防护

function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);               // 每次触发清除之前的定时器
    timer = setTimeout(() => {
      fn.apply(this, args);            // 延迟执行，保留 this 和参数
    }, delay);
  };
}

// 立即执行版
function debounceImmediate(fn, delay, immediate = false) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    if (immediate && !timer) fn.apply(this, args);
    timer = setTimeout(() => { timer = null; }, delay);
  };
}

// 时间戳版（首次立即执行）
function throttle(fn, interval) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}

// 定时器版（末次也执行）
function throttleTimer(fn, interval) {
  let timer = null;
  return function (...args) {
    if (timer) return;
    timer = setTimeout(() => {
      fn.apply(this, args);
      timer = null;
    }, interval);
  };
}

手写 Promise（核心版）
class MyPromise {
  constructor(executor) {
    this.state = "pending";
    this.value = undefined;
    this.callbacks = [];

    const resolve = (value) => {
      if (this.state !== "pending") return;
      this.state = "fulfilled";
      this.value = value;
      this.callbacks.forEach(cb => this._handle(cb));
    };
    const reject = (reason) => {
      if (this.state !== "pending") return;
      this.state = "rejected";
      this.value = reason;
      this.callbacks.forEach(cb => this._handle(cb));
    };

    try { executor(resolve, reject); }
    catch (e) { reject(e); }
  }

  _handle(cb) {
    if (this.state === "fulfilled" && cb.onFulfilled) {
      cb.onFulfilled(this.value);
    } else if (this.state === "rejected" && cb.onRejected) {
      cb.onRejected(this.value);
    }
  }

  then(onFulfilled, onRejected) {
    return new MyPromise((resolve, reject) => {
      this.callbacks.push({
        onFulfilled: (val) => {
          try {
            const r = onFulfilled ? onFulfilled(val) : val;
            r instanceof MyPromise ? r.then(resolve, reject) : resolve(r);
          } catch (e) { reject(e); }
        },
        onRejected: (err) => {
          try {
            const r = onRejected ? onRejected(err) : err;
            if (!onRejected) { reject(err); return; }
            r instanceof MyPromise ? r.then(resolve, reject) : resolve(r);
          } catch (e) { reject(e); }
        }
      });
    });
  }

  catch(onRejected) { return this.then(null, onRejected); }

  static resolve(val) {
    return val instanceof MyPromise ? val : new MyPromise(r => r(val));
  }
  static all(promises) {
    return new MyPromise((resolve, reject) => {
      const results = []; let count = 0;
      promises.forEach((p, i) => {
        MyPromise.resolve(p).then(val => {
          results[i] = val;
          if (++count === promises.length) resolve(results);
        }, reject);
      });
    });
  }
}

// 递归
function flatten(arr) {
  const result = [];
  arr.forEach(item => {
    if (Array.isArray(item)) result.push(...flatten(item));
    else result.push(item);
  });
  return result;
}

// 指定深度
function flatDepth(arr, depth = 1) {
  return depth > 0
    ? arr.reduce((acc, item) =>
        acc.concat(Array.isArray(item) ? flatDepth(item, depth - 1) : item), [])
    : arr.slice();
}

// 迭代（栈，最简洁）
function flatIter(arr) {
  const stack = [...arr]; const result = [];
  while (stack.length) {
    const item = stack.pop();
    if (Array.isArray(item)) stack.push(...item);
    else result.push(item);
  }
  return result.reverse();
}

手写深拷贝
function deepClone(obj, hash = new WeakMap()) {
  if (obj === null || typeof obj !== "object") return obj;
  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj);
  if (hash.has(obj)) return hash.get(obj);  // 处理循环引用

  const clone = Array.isArray(obj) ? [] : {};
  hash.set(obj, clone);

  Reflect.ownKeys(obj).forEach(key => {
    clone[key] = deepClone(obj[key], hash);
  });
  return clone;
}

手写发布订阅模式（EventEmitter）
class EventEmitter {
  constructor() { this.events = {}; }

  on(event, listener) {
    (this.events[event] ||= []).push(listener);
    return this;
  }

  off(event, listener) {
    if (!this.events[event]) return;
    this.events[event] = this.events[event].filter(fn => fn !== listener);
    return this;
  }

  once(event, listener) {
    const wrap = (...args) => {
      listener(...args);
      this.off(event, wrap);
    };
    return this.on(event, wrap);
  }

  emit(event, ...args) {
    this.events[event]?.forEach(fn => fn(...args));
    return this;
  }
}

手写 call / apply / bind
// call：指定 this + 参数列表
Function.prototype.myCall = function(ctx, ...args) {
  ctx = ctx ?? globalThis;
  const key = Symbol();
  ctx[key] = this;                  // this 是调用函数
  const result = ctx[key](...args);
  delete ctx[key];
  return result;
};

// apply：指定 this + 参数数组
Function.prototype.myApply = function(ctx, args = []) {
  return this.myCall(ctx, ...args);
};

// bind：返回新函数，可传预设参数
Function.prototype.myBind = function(ctx, ...preset) {
  const fn = this;
  return function (...args) {
    // 支持 new 调用
    if (this instanceof fn) return new fn(...preset, ...args);
    return fn.myCall(ctx, ...preset, ...args);
  };
};
给对象挂个唯一 key 调用函数再删掉；bind 是返回闭包 + 支持 new
